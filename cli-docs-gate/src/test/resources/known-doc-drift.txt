# cli-docs-gate - waived documentation drift.
#
# Every line here is a CLI invocation element that this repository's documentation cites and the
# shipped CLI does not define. This file is the drift REPORT, kept where it can be worked off - not a
# mute button:
#
#   * a finding that is NOT listed here fails the build, so drift cannot grow;
#   * a line here that matches NOTHING fails the build, so fixing a document forces its line to be
#     deleted;
#   * the entry COUNT and a DIGEST OF THE ENTRIES are both pinned in CliDocsDriftTest, so this file
#     cannot be rewritten at constant size either. Swapping one line out for another is the move a
#     count alone does not catch.
#
# Format, tab-separated:  <repository-relative path>  command: <command path that does not exist>
#                         <repository-relative path>  option: <option> on <command path>
#
# Keyed by path and drift, never by line number: line numbers are tree-scoped and shift under any
# edit above them. NOTE the consequence, since it bounds what this count means: one line here covers
# EVERY instance of that drift in that file, so 85 entries describe more than 85 broken
# invocations.
#
# Regenerate candidate lines with:
#   mvn -pl cli-docs-gate test    ->  cli-docs-gate/target/cli-docs-gate/drift-keys.txt
#
# WHAT IS LEFT HERE, AND WHY IT IS NOT A SPELLING PROBLEM.
#
# All mechanical drift is now fixed, in two passes. The first fixed 20 direct-adjacency cases
# (`aether blueprint deploy` -> `blueprints deploy`, `aether artifact push` -> `artifacts push`). It
# MISSED ten more that carry an option between the binary and the subcommand
# (`aether -c "$AETHER_URL" artifact push ...`), because it was driven by a text search for the
# literal string - in a check whose whole argument is that text searches do not reach what a parse
# does. The second pass was driven by this gate's own extraction and fixed those ten.
#
# What remains is the product overclaiming its own CLI surface:
#
#   * `aether scale --min/--max/--target-cpu/--target-latency/--cooldown/--auto` - the shipped
#     `aether scale` takes `-n/--instances`, `-p/--placement`, `--wait`, `--timeout`. The documented
#     flags describe AUTOSCALING, a feature claim rather than a spelling.
#   * `jbct init --slice` - the shipped option is `--no-slice`, the INVERSE. A reader who "corrects"
#     the docs gets the opposite behaviour.
#   * `aether blueprint set` and `aether artifact upload` - unlike the ten above, `blueprints set` and
#     `artifacts upload` do not exist either, so there is no mechanical target to rename to.
#   * `aether stream create` and its siblings in in-memory-streams-spec.md - the CLI ships BOTH an
#     `aether stream` and an `aether streams` tree with divergent subcommands (#951). That spec is
#     written against the singular tree throughout; renaming one line to the plural would leave the
#     document internally inconsistent while four sibling commands remain absent under either tree.
#     Resolved by #951, deliberately not by this pass.
#   * The remaining absent commands (`aether aspects`, `topic(s)`, `forge`, `logs`, `workflows`,
#     `landscape`, `cluster audit/heal/api-key/unregister`, `workers health/endpoints`,
#     `nodes decommission`, `jbct add`, ...) are surfaces the documentation describes and the CLI
#     never grew.
#   * One entry is a false positive of this gate, kept rather than hidden: harness-resilience-spec.md
#     waives `aether node`, whose source line is prose PROPOSING the command and saying it does not
#     exist. The gate reads the inline span as an invocation and cannot tell a proposal from an
#     instruction.
#
# Current composition: 85 entries - 29 absent commands, 56 absent options - across
# 34 files, of which 34 are under aether/docs/specs/**.
