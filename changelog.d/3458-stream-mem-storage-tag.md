### Changed (2026-11-22 — #3458 stream-mem M-1: a stream's storage mode exists on the wire)
- **`StreamStorage` (`PERSISTENT`, `MEMORY`, `UNKNOWN`) and `StreamDeclaration.storage`:** a stream's storage mode is the declaration's last component, `Option<StreamStorage>`; `none` means persistent. `UNKNOWN` is last and decode-only, so a mode this build does not know decodes to it instead of throwing, and a config carrying it is refused at the write (`StreamError.StreamStorageUnknown`, 409) instead of being written back. Nothing parses or reads the mode yet. [verified: StreamStorageCodecTest, StreamDeclarationWireTest, StreamStorageWriteGuardTest, StreamErrorStatusTest, SystemTagsTest]
- **Wire flag day (pre-GA, know 7753703955):** `StreamConfigValue` moves from tag 2920 to 3014, and 2920 is retired. The codec is positional with no count or length, so the new trailing component under the old tag would shift `createdAt` for a value written by the other build; a build of the other shape now refuses the value on an unknown tag. The S2a1 parser already writes a non-`none` declaration for every parsed stream, so persisted declarations are no longer all `none`. Second recorded renumber exception, no decoder kept. [verified: StreamDeclarationWireTest.retiredTag2920_isRefusedAsUnknown_andNeverDecoded, tagThisBuildWrites_isUnknownToTheBuildBeforeM1]
- **Wire generation 11 to 12:** the `StreamDeclaration` SHAPE line, the `StreamConfigValue` TAG line and the new `StreamStorage` TAG and ENUM lines change in `wire-assignment-baseline.txt`. Upgrade is stop-the-world (`JoinGenerationGuard.WIRE_GENERATION` bumped from 11 to 12). [verified: JoinGenerationGuardTest.thisBinarysGeneration_isTwelveAfterTheStreamStorageCarrierMove]
