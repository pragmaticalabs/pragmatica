### Fixed (2026-10-10 — HTTP error path leaked the failure's cause chain to clients, and never logged it)
- **A failure wrapper's origin chain could reach the client, and no operator could see it.** When the problem body could not be serialized, `SliceRouter` answered with `HttpError.message()`, which walks the whole chain; the management plane's `ProblemResponses.writeProblem(Cause)` did the same for a chained `HttpError`. Clients now get the status message (or the top cause's message) only, and the slice-error log line carries the full chain. Guarantee: no client-facing error body contains anything below the top cause's message.
