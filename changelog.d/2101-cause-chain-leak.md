### Fixed (2026-10-10 — HTTP error path leaked the failure's cause chain to clients, and never logged it)
- **A failure wrapper's origin chain could reach the client, and no operator could see it.** `HttpError.message()` and a composite's `message()` walk the origin chain; the problem-body fallback, the `ProblemDetail` detail, the management plane's `ProblemResponses.writeProblem(Cause)` and several other client-body producers rendered them directly. Client bodies now render causes through one renderer, `HttpError.clientMessage(Cause)`; the chain goes to the server log only (the slice-error log line carries it in full). Shapes covered: a plain chained cause, an `HttpError` over an `HttpError`, a composite of chained `HttpError`s, a composite inside an `HttpError`, and an `HttpError` inside a composite. `HttpError.clientMessage()` defaults to the status text, so a new implementer cannot leak by omission. A source-scan test fails if a client-body producer renders `cause.message()` directly.
