### Fixed (2026-11-16 — #3300: the blocked-restore warning advised an exit that does not work)
- **`BACKUP_RESTORE_BLOCKED` advised `restore = "fresh"` even over a committed `IN_PROGRESS` restore marker**, where a restart with it changes nothing (a resumed restore never reads `restore`). The warning now names the step that failed (source unreachable, ref unresolved, backup vanished, commit unreadable, document undecodable, history unreadable, incarnation missing) and the exits, chosen by one fact: is a restore marker committed? With none, fix what the step names (the next retry reads the source again) or restart with `restore = "fresh"`. With one, the pinned commit is named; the restore resumes once that commit can be read and restored from the source, and if it cannot be put back there, the only exit is to stop ALL nodes and cold-start with `restore = "fresh"` (discards the partly restored state, whole-cluster stop). The warning does not predict whether a retry or a source fix will clear the block. It is raised again when the failed step changes, not when it repeats. The runbooks (`backup-recovery.md`, `incident-response.md`) carry the same two cases.
