### Fixed (2026-09-14 — #272: @Scheduled cluster lifecycle — SINGLE-mode fires failed when the leader did not host the slice; ALL-mode fired on non-hosting nodes; also #273 item 1, ALL-mode eligibility on a draining node)
- **R12 (SINGLE): a leader that did not host the slice failed every fire with `SENDER_BRIDGE_NOT_FOUND` and wrote a failure state every interval, while the hosting node never saw a call.** The automatic fire is `SliceInvoker.invoke(artifact, method, Unit.unit())`; for a remote endpoint `sendFireAndForget` resolved the request's codec through a LOCAL slice bridge, which a non-hosting leader has none of. The `Unit` request needs no bridge: its wire form is fixed — the single VLQ byte `TAG_UNIT` (0) with an empty body, registered by `FrameworkCodecs.unitCodec` in the node codec that every slice codec layers over (`SliceStore` → `slice.codec(nodeCodec)` → `SliceCodec.sliceCodec(parent, …)`), so the callee's `DefaultSliceBridge.invoke` → `codec.decode(input)` → `CodecHolder.read` → `lookupByTag(0)` reads it back as `Unit` for a zero-argument method. The invoker now encodes a `Unit` fire-and-forget request with the node serializer it already holds and sends it on the EXISTING `InvokeRequest` frame; every other request type still requires a sender bridge. No new frame, tag or codec. - Two review NITs resolved by tracing rather than changing code, recorded because the reasoning is the result. **(a) An ALL-mode timer whose hosting ends is deliberately NOT cancelled**, only skipped per tick by `shouldFire`.
