### Added (2026-09-20 — #1379: atomic guarded KV mutations and canonical snapshots)
- **Leader-guarded multi-key transactions** validate the committed leader and all read/write witnesses before changing any key. A caller-chosen transaction ID correlates acceptance/refusal, including one-key mutations; uncorrelated `LeaderPut` was removed and its never-shipped pre-GA tag 123 is available for reuse. Refusal identifies the transaction, not the conflicting key. Both arms of the read set are pinned: a transaction whose guards are all satisfied is applied, and one carrying a stale guard changes nothing. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreLeaderTransactionTest.java]
- Opt-in ownership fences reject same-epoch owner changes through a single Put or transaction. Bare deletion requires a strictly newer owner-epoch witness; an equal-epoch incumbent witness cannot clear the fence. Plain Put/Remove against `LeaderAuthorized` values is silently dropped without notification; use a correlated transaction for observable refusal. The authorization cannot be downgraded in place either: a write replacing a committed `LeaderAuthorized` value with an unmarked one is refused even inside an authorized transaction, so a derived or defaulted replacement cannot silently reopen the key to bare `Put`/`Remove`; de-authorizing means deleting the key through an authorized transaction. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreAuthorizedMutationTest.java] [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreOwnerFenceTest.java] [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreNotificationIsolationTest.java]
- Explicit canonical serialization stabilizes Map/Set bytes written through framework or generated codecs; custom serializers and hand-written formats retain their own behavior. KV snapshots select the canonical view. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreCanonicalSnapshotTest.java]
- KV reads synchronize with complete batch application; snapshot/forEach/find copy the full store under the monitor (O(n) time and allocation). Notifications release that monitor so readers remain responsive, but competing writers wait on the mutation lock while listeners run. Nested mutations retain FIFO notification order. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreNotificationIsolationTest.java]

- The guarded-KV mutation harness refuses to score against a red baseline: it runs `KVStore*Test` before the first mutation and exits with a diagnostic unless every target class reported and no test failed, so a pre-existing failure inside the selector can no longer be credited as a kill. Failures are counted as `<testcase>` elements rather than the `<testsuite failures>` attribute, which surefire reports as 0 for `@Nested` classes.
- Foundation CI runs its guarded-KV mutation suite only; the complete, separately gated runtime acceptance matrix belongs to #1390. Foundation-only branches no longer report a partial runtime pass.
