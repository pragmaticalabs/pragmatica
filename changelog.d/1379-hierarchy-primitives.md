### Added (2026-09-20 — #1379: atomic guarded KV mutations and canonical snapshots)
- **Leader-guarded multi-key transactions** validate the committed leader and all read/write witnesses before changing any key. A caller-chosen transaction ID correlates acceptance/refusal, including one-key mutations; uncorrelated `LeaderPut` was removed and tag 123 retired. Refusal identifies the transaction, not the conflicting key. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreLeaderTransactionTest.java]
- Opt-in ownership fences reject same-epoch owner changes through a single Put or transaction. Bare deletion requires a strictly newer owner-epoch witness; an equal-epoch incumbent witness cannot clear the fence. Plain Put/Remove against `LeaderAuthorized` values is silently dropped without notification; use a correlated transaction for observable refusal. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreOwnerFenceTest.java] [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreNotificationIsolationTest.java]
- Explicit canonical serialization stabilizes Map/Set bytes written through framework or generated codecs; custom serializers and hand-written formats retain their own behavior. KV snapshots select the canonical view. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreCanonicalSnapshotTest.java]
- KV reads synchronize with complete batch application; snapshot/forEach/find copy the full store under the monitor (O(n) time and allocation). Notifications release that monitor so readers remain responsive, but competing writers wait on the mutation lock while listeners run. Nested mutations retain FIFO notification order. [verified: integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreNotificationIsolationTest.java]
