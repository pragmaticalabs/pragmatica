### Changed (2026-10-02 — #1778: scaffolded deploy scripts no longer push a SNAPSHOT to the write-once cluster repository)
- **`jbct init` generated `deploy-test.sh` and `deploy-prod.sh` that ran `aether artifacts push …:1.0.0-SNAPSHOT`**; the cluster's built-in artifact store now refuses SNAPSHOTs (`400`) and writes each coordinate once, so both would fail. `deploy-test.sh` now stamps a unique RELEASE version per push (`<base>-<short git sha>` from a clean git checkout, else `<base>-<UTC timestamp>`, `DEPLOY_STAMP` overrides), builds and pushes it, and restores the pom on exit; the inner loop keeps working. `deploy-prod.sh` reads the project version, refuses a SNAPSHOT with a clear message (naming `mvn versions:set`) before the confirmation prompt and before any build, and pushes the real release version.
