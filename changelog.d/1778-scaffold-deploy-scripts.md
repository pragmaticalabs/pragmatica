### Changed (2026-10-02 — #1778: scaffolded deploy scripts no longer push a SNAPSHOT to the write-once cluster repository)
- **`jbct init` generated `deploy-test.sh` and `deploy-prod.sh` that ran `aether artifacts push …:1.0.0-SNAPSHOT`**; the cluster's built-in artifact store now refuses SNAPSHOTs (`400`) and writes each coordinate once, so both would fail. `deploy-test.sh` now stamps a unique RELEASE version per push (`<base>-<short git sha>` from a clean git checkout, else `<base>-<UTC timestamp>`, `DEPLOY_STAMP` overrides), builds and pushes it, and restores the pom on exit; the inner loop keeps working. `deploy-prod.sh` reads the project version, refuses a SNAPSHOT with a clear message (naming `mvn versions:set`) before the confirmation prompt and before any build, and pushes the real release version. **Scaffolded projects now build reproducibly:** the generated pom pins `project.build.outputTimestamp`, `jbct:package-slices`, `jbct:generate-blueprint` and `jbct:package-blueprint` honour it (`MavenArchiver.configureReproducibleBuild`), and the slice manifest and `slice-deps.properties` no longer carry a wall-clock stamp or hash-ordered entries (`generated.timestamp` is dropped; nothing read it), so one commit builds byte-identical jars and re-running `deploy-test.sh` on it is the idempotent `200`. `getting-started.md` follows. `[verified: ScaffoldDeployScriptsTest runs the generated scripts against stub mvn/git/aether executables — test script pushing the SNAPSHOT again: 3 red; sha stamp dropped: 1 red; pom not restored: 1 red; prod accepting a SNAPSHOT: 1 red]`
- `[verified: a real project generated from the template and built with `mvn clean package` twice, three seconds apart, in one JVM each, no cluster: all three jars (slice, slice API, blueprint) have the same sha256 across the two builds — and differed on every jar before the changes; pinned in CI by ScaffoldDeployScriptsTest (pom property), ManifestReproducibleTextTest and CollectSliceDepsReproducibleTextTest — the archiver `outputTimestamp` parameters in the three mojos are NOT pinned by a CI test]` `[unverified: against a real cluster — the scripts were run with stub executables; `mvn versions:set`, `help:evaluate` and `aether artifacts push` behaviour is as documented, not run]`
- **`examples/url-shortener` builds reproducibly too:** its pom now pins `project.build.outputTimestamp`, so its fixed `1.0.0` re-push is the idempotent `200`. `[verified: `mvn clean package` twice on the example, no cluster: without the property all 4 jars differed between the builds, with it all 4 sha256 are identical]` Its `deploy-{test,prod}.sh` call `aether artifact push --env ...` and are not changed.
