### Fixed (2026-09-19 — #1289: CoreSwimHealthDetectorTest flakes with ClassCastException, Stopped cast to Running)
- **A fixed SWIM port made a detector test fail whenever another JVM on the host held UDP 9101, and the test then hid the cause behind a `ClassCastException`.** `listenerAttachedBeforeStart_isInvokedByLiveProtocol` started a real detector with self port 9001, so `start()` bound UDP 9101 on the wildcard address. When that port was taken, the bind failed with `BindException: Address already in use` and `start()` resolved as a failure. The FSM then moved `Starting` → `Stopped` via `StartFailed`, which is the correct production behaviour. The test discarded the failed `Result`, polled for `Running`, and cast unconditionally. It also never stopped the detector, so a passing run kept the port bound for the rest of the test JVM. `[mechanism: CoreSwimHealthDetector.start dispatches StartFailed on a failed transport bind; SwimHealthState.Starting maps StartFailed to Stopped]`
- The test now derives its self port from a free ephemeral UDP port. It fails with `start() failed, lifecycle=Stopped: <cause>` when the start fails, asserts `Running` instead of casting, and stops the detector in `finally`. Test-only change; no production behaviour changed.
