### Fixed (2026-11-20 — #3464: backup git reads turn lost output or a failed command into 'absent', so a restore can boot FRESH silently)
- **A restore no longer starts fresh over a backup it could not read**: the restore ref, the history floor and the commit and document reads go through three-valued git reads (present, definitely absent, unreadable); only a definite "no such ref" (exit 2) is absent, and a failed command, a timeout, lost output or a git older than 2.43 blocks the restore with a typed reason. [verified: aether/node/src/test/java/org/pragmatica/aether/node/backup/GitBackupRepositoryTest.java, BackupRestoreCoordinatorTest, KvBackupServiceTest]
- **A ref or commit beginning with `-` is refused before git runs**, and every git call taking a caller's ref passes `--end-of-options` before it (`--` before a path), so `git show --output=<file>` cannot be reached through a ref. [verified: GitBackupRepositoryTest]
