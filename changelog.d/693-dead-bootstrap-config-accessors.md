### Removed (2026-10-18 — #693: six bootstrap-config accessors that nothing read)
- **Dead accessors in the `ClusterBootstrapConfig` tree are deleted, not waived.** `ClusterBootstrapConfig.configVersion`, `RoleSubTable.role`, `InfrastructureConfig.networkingType` (and the `NetworkingType` enum behind it), `TlsDeploymentConfig.certTtl` and the cluster `TimeoutsConfig.drain` were parsed from the cluster TOML into record components with no consumer; each carried a `@ConfigKeyLive("#693: ...")` waiver. The waivers are gone with the fields. A file that still sets `[infrastructure.networking] type`, `[operations.tls] cert_ttl` or `[operations.timeouts] drain` keeps loading and the value changes nothing, as before. The `config_version` format gate is unchanged: it still runs first and refuses an absent, older or newer version. `[verified: aether/aether-config/src/test/java/org/pragmatica/aether/config/cluster/ClusterBootstrapConfigParserTest.java RemovedDeadKeys and FormatVersionGate]`
- **`RuntimeProfile.name` was not dead.** The issue listed it, but `BootstrapPhaseDeploy.sshContainerImage` read it through a method reference the dead-config scanner does not see. The SSH refusal message now names the runtime from the role's `runtimeRef` (the same string, the profile map key) and the component is removed with the rest.
- `docs/reference/bootstrap-config.md` no longer documents `cert_ttl`, `drain` or `[infrastructure.networking] type`; the first two were never honoured.
