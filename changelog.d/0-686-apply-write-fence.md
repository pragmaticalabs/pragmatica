### Changed (2026-11-12 — #686 part A2: write-time fence for cluster config writes)
- **A config write is committed only against the config it was checked against** (#686). The commit used to re-read the stored config at write time and use that as the compare-and-set value, so a competing write landing between the version check and the commit was adopted instead of refused. Apply, scale and upgrade now commit with the value they fenced on. A routed apply also witnesses the auto-heal record the route check read, an absent record included: a flip, or the first write of the key, refuses the commit. [verified: `ClusterConfigRoutesApplyTest$WriteTimeFence`]
- **A refused commit says why** (#686): `VersionConflict` when the config moved, the new typed `AutoHealChanged` (409, with `observed` and `now`) when the auto-heal record moved. Re-run `aether cluster apply` to re-plan.
