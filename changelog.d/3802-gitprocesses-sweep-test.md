### Fixed (2026-11-26 — #3802: the GitProcesses kill-sweep test asserted a read count that depended on host speed)
- **`GitProcessesTest` pins what the fork-window sweep guarantees, not how many reads fit in the freeze's half of the bound** (#3802). It asserted `reads >= 4`; each freeze round spawns a helper process, so on a loaded host the sweep's loop closed at the freeze deadline after three reads (`3 >= 4`). The joins are now scripted (a third member joins only after the second has been killed) and the kill gets a bound no host reaches: the test asserts that every member that joined before the last read is dead and that the last read added no member. A second case delays every read by a second and stays green. Mutants verified red: a sweep that stops one read early, and a sweep that forgets a late joiner. Test-only; no product change.
