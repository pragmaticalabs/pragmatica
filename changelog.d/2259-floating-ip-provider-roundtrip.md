### Fixed (2026-10-18 — #2259: a floating IP's provider did not round-trip through the cleanup ledger)
- **`FloatingIpAssignment.provider()` returned the constant `"cloud"`**, so the provider recorded in `bootstrap-state.json` / `apply-state.json` was always `cloud`. The only user-visible effect was the "could not remove" listing, which printed `provider=cloud` for a floating IP instead of the real provider; no destroy path dispatches on a floating IP's provider. The record now reports the provider it was built with; ledgers written by an older CLI (`"provider": "cloud"`) still load. `[verified: aether/cli/src/test/java/org/pragmatica/aether/cli/cluster/FloatingIpProviderRoundTripTest.java]`
