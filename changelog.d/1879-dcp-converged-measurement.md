### Fixed (2026-11-23 — #1879: DeclarativeConsumerPlacementTest delivered more events than published)
- **The test measured while the cluster was still moving** (#1879). A consumer assignment follows membership: while any node's view was still growing, partition owners and the committed assignment moved, and each move redelivers from the last committed cursor, which `guarantees.md` §4 allows (at-least-once across a move). The suite's settle gates (deployment-map agreement, attachment total of 7 for any candidate set, non-blank owners) held in that window, so 2 of 30 isolated runs on a loaded host counted 26 and 37 events for 25 published. Every measurement now starts from one `clusterConverged()` invariant (every node sees all nodes, the same hosts, the placement owner over the full membership, agreeing assignment rows, attachments equal to the rows naming the node), and the exactly-once test is renamed to state its condition (`declaredConsumer_deliversEachEventExactlyOnce_whileTheAssignmentIsStable`) and fails loudly if the premise is lost. Test-only; no product change. [verified: `DeclarativeConsumerPlacementTest` x30 on the host that reproduced it]
