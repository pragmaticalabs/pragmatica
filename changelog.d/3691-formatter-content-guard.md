### Fixed (2026-11-24 — #3691: the formatter silently deleted comments in several positions)
- **A formatted text is returned only when it keeps the input's comments and tokens** (#3691). `jbct format`, `format-check`, `check` and `process` compared nothing between the input and the printer's output, so a comment before a `;`, after a binary operand or inside a ternary was deleted while the run reported `Errors: 0`. `FlowFormatter.formatParsed` now lexes both texts with the parser's lexer and refuses the file on the first difference of the comment sequence (line and block, trailing whitespace ignored, javadoc re-indentation ignored) or of the non-whitespace, non-comment token sequence. The refusal names the file and the input line of the first lost, added or changed item, the file is left untouched, `format` counts it under `Errors` and exits non-zero, and `check`, `format-check` and `process` fail with the same text. The printer gaps themselves remain open (#3691, #1718); they are now visible refusals instead of silent loss.
