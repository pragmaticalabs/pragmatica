### Added (2026-11-06 — rc6 f2b L1a: workflow engine completion, internal)
- **Workflow run index and durable announce** (internal; the engine has no production caller in `aether/node/src/main`, so it is off by construction). `WorkflowRunIndex` is fed by the KV route and answers `runs()`; ESCALATED/RESOLVED operator warnings are raised from the applied transition on the cluster-events owner, never from replay. Guarantee of the raise: at most once per owner tenure (owner gate, replay bit, before/after pair keyed by run id); an owner hand-off can duplicate or lose it, and the committed run keeps the incident as its detail either way. `workflow-resolved` closes across nodes, so it is published by whichever owner applies the terminal state. The reconciler no longer raises.
- **Keyed workflow admission** (internal). `admit(kind, params, keys, now, requestKey)` derives the run id from the kind and the request key, so a retry after a lost answer returns the same run; the same key with different kind or params is refused as `RequestKeyReused`. `ledger.create` is bounded (default 30 s); a timed-out create is resolved by the keyed read-back, else refused as `Unanswered`.
- **Workflow resolution semantics** (internal, CTO ruling Q4). `WORKFLOW_RESOLVED` is raised only when an ESCALATED run reaches DONE or FAILED, with the outcome in the message, at most once per run per episode; a resume raises the new INFO `WORKFLOW_RESUMED` (`OperatorWarningCode` gains one constant, no recovery pairing). `ABANDONED` is derived from the failed run's own record (`WorkflowRunValue.abandoned(reason)` puts `abandoned:<reason>` in the existing `detail`, so the wire shape is unchanged; no production verb commits one until the abandon verb). The announcer keeps an open-incident set by run id: re-escalating a run whose incident is open raises no second `WORKFLOW_ESCALATED`, and `Announcer.reseed()` rebuilds the set from the committed ESCALATED runs when the node takes the events partition over (and after a state restore), so a new owner resolves an incident whose terminal commit arrives after the takeover. A RESOLVED lost because the terminal commit was applied before the takeover is not recoverable from committed state.
