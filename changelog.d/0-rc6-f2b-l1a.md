### Added (2026-11-06 — rc6 f2b L1a: workflow engine completion, internal)
- **Workflow run index and durable announce** (internal; the engine has no production caller in `aether/node/src/main`, so it is off by construction). `WorkflowRunIndex` is fed by the KV route and answers `runs()`; ESCALATED/RESOLVED operator warnings are raised from the applied transition on the cluster-events owner, never from replay. Guarantee: at most once per committed transition, lost only if the owner dies between apply and raise. The reconciler no longer raises.
- **Keyed workflow admission** (internal). `admit(kind, params, keys, now, requestKey)` derives the run id from the kind and the request key, so a retry after a lost answer returns the same run; the same key with different kind or params is refused as `RequestKeyReused`. `ledger.create` is bounded (default 30 s); a timed-out create is resolved by the keyed read-back, else refused as `Unanswered`.
- **Workflow resolution semantics** (internal, CTO ruling Q4). `WORKFLOW_RESOLVED` is raised only when an ESCALATED run reaches DONE or FAILED, with the outcome in the message, at most once per run per episode; a resume raises the new INFO `WORKFLOW_RESUMED` (`OperatorWarningCode` gains one constant, no recovery pairing). `ABANDONED` is reserved in the outcome type until the ledger has an abandon verb.
