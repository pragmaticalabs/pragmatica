### Added (2026-11-09 — #2960: an owner whose catch-up sources are all stalled now tells the operator)
- **`stream-owner-catchup-stalled` operator warning** (#2960). When every source an owner can catch up from has been demoted for answering short without progress (#2954), the round ends in `SOURCE_STALLED` and the owner stays SYNCING, never activating below the target. That terminal state now raises one CRITICAL warning per episode instead of only a WARN per source per tick, and `stream-owner-catchup-progressing` closes it when the owner's head advances, the catch-up (or the promotion gate's own catch-up) activates the owner, no source is ahead any more (including a stalled survivor that left and an owner that self-promotes), the partition is quarantined, a peer is found cut before its first event, or the stream is removed. The close is level-triggered: `PartitionBackfill#reconcileStalled` re-derives every open warning from live state (the stream exists, this node is still a registered replica and the owner of the partition, it is not quarantined, a source's stall counter stands at the bound) on every backfill round, every replica-set reconcile pass and every redrive tick, so a route no round visits (this node removed from the partition's replica set, ownership moved away) still closes it, within one pass or tick; the warning is raised only for a stream that still exists, so a stream destroyed under an in-flight round leaves none. `demoteStalled` now settles its promise through `replaceResult`, so an exception in its stall bookkeeping fails the round instead of leaving it unresolved.
