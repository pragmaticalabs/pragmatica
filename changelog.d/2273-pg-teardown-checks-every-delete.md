### Fixed (2026-10-18 — #2273: pg-firewall.sh destroy discarded the firewall delete response and logged OK on a 409)
- **A refused firewall delete reported success and left the firewall.** `tools/pg-firewall.sh destroy` threw away the delete response, so a 409 (firewall still attached) logged `destroyed` and exited 0. The delete response is now checked: a refusal prints the API error, names the firewall (`could not delete firewall '<name>' (id=<id>)`) and exits 2; a refused detach is named as a warning. `provision-test-pg.sh --destroy` already counted failed deletes; it now also names the server or SSH key it could not remove. `[verified: script-gate/src/test/java/org/pragmatica/scriptgate/PgFirewallDestroyTest.java, ProvisionTestPgDestroyTest.java]`
