### Fixed (2026-10-29 — #1385: quiet partitions never committed their cursor; #2223, #2224: tier reads)
- **A burst that ended inside a checkpoint cadence was never committed** (#1385). The periodic commit ran only from a delivery, so an ungraceful move replayed the burst from the last commit. The first ack after a commit now arms one trailing-commit timer; when it fires, a cursor still ahead of the last commit has its commit requested. [verified: `StreamConsumerRuntimeTest$QuietPartitionCommit`]
- **A forwarded tier read could be labelled a ring read** (#2223). An owner whose ring was closing answers its tail as `-1`, which no offset is below, so the read closed the consumer's `stream-consumer-behind-ring` episode. `EpochRead` now carries where the read was served from (`RING`, `TIER`, `UNKNOWN`); an unknown tail neither opens nor closes the episode. [verified: `StreamReadRouterTest`]
- **A tier read racing retention could skip events** (#2224). If retention removed the cursor's segment between the sealed-end lookup and the range lookup, the read returned the next segment's events with no error. It now answers `CursorExpired(fromOffset, firstOffset)`. [verified: `TieredReaderRetentionRaceTest`]
