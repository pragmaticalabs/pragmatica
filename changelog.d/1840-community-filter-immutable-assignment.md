### Fixed (2026-10-03 — #1840: per-edge community filter cost, implicit governor candidacy, reassignable community)
- **Every SWIM health edge on a worker copied and scanned the whole KV snapshot.** `CommunityMembershipFilter` now reads a per-community candidate index in `CommunityMemberDirectory`, maintained from committed directive puts, removals and restores; an edge costs O(alive view + community candidates) and takes zero KV snapshots. A committed directive change also refreshes the nomination view, so it no longer waits for the next SWIM edge. [verified: `CommunityMembershipFilterPerEdgeCostTest` (zero snapshots and entries scanned at N = 200 / 1,000 / 10,000, with a counting control)]
- **Governor candidacy is explicit.** A candidate is a node whose committed directive has role WORKER and names the community; a core is excluded by role, not by an empty community. [verified: `CommunityMembershipFilterTest.communityAliveMembers_coreRoleDirectiveNamingTheCommunity_isNotACandidate`, `CommunityMemberDirectoryCandidatesTest`]
- **The core's claim acceptance refuses a core-role nominee.** The refusal was unpinned. [verified: `GovernorAuthorityTest.coreRoleNominee_claimIsRefused_byRoleNotByCommunity`]
- **A committed community assignment can no longer be changed (H11).** `KVStore` refuses, in the applier on every replica, a write that changes the committed non-empty community of an `ActivationDirectiveValue` (new marker `CommunityFenced`); an identical community and a first write pass, and a refused `LeaderTransaction` applies none of its mutations. Removal paths are unchanged. [verified: `KVStoreCommunityFenceTest`, `GovernorAuthorityTest.communityReassignmentByPut_isRefusedAtCommit_directiveUnchanged_claimStillGranted`]
- [unverified: directive removal followed by creation in another community is still possible; the identity-lifetime guarantee needs the removal rule (#1840 item 3)]
