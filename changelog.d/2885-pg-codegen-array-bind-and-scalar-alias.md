### Fixed (2026-11-08 — #2885, #2886: pg-codegen array bind spread and scalar column inference)
- **A sole array parameter was spread into separate bind parameters (#2885).** Generated calls on all six kinds (unit, single, optional, list, long, boolean) now pass an array-typed parameter as `(Object) (param)`, so it stays one bind parameter (`= ANY(?)`). `[verified: aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/ScalarAliasAndArrayBindTest.java]`
- **The scalar column was found by scanning the SQL text for ` AS ` (#2886).** `SELECT CAST(count(*) AS int) AS n` inferred `int`, `FROM t AS o` inferred `o`, and a quoted alias inferred an empty name. The column now comes from the parse tree (`QueryValidator.selectOutputColumnNames`): the alias of the first target, for `SELECT` and `RETURNING`; the string scanner is deleted. `selectOutputColumnNames` reads only the statement's own targets (a subquery in the target list no longer counts) and no longer names an unaliased expression after a column inside it. `[verified: ScalarAliasAndArrayBindTest, QueryValidatorTest]`
- **BREAKING:** a `@Query` method that reads one value (`Long`, `Boolean`, a scalar, a document) from an unaliased expression such as `SELECT count(*) FROM t` now fails the build with "add an alias" (`SELECT count(*) AS n FROM t`). Generated CRUD `count`/`exists` methods are unaffected.
- **An alias spelled like a keyword or type word (`name`, `text`, `user`, `timestamp`, `int`, `json`, ...) was read as the column `???` (#2894).** The label's own lexeme is now taken (folded to lower case unless quoted), and a label with no lexeme fails the build instead of yielding a placeholder. `[verified: ScalarAliasAndArrayBindTest, QueryValidatorTest, CstExtractorTest, ReturnTypeMappingValidationTest]`
