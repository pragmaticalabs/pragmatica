### Fixed (2026-11-08 — #2885, #2886: pg-codegen array bind spread and CAST scalar column)
- **A sole array parameter was spread into separate bind parameters (#2885).** Generated `db.update(...)` and `db.query*(...)` calls now pass an array-typed parameter as `(Object) (param)`, so it stays one bind parameter (`= ANY(?)`). `[verified: aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/ScalarAliasAndArrayBindTest.java]`
- **`SELECT CAST(x AS int) AS n` inferred the scalar column `int` (#2886).** The scalar column is now the alias after the last `AS` outside every parenthesis in the first select item (and in a `RETURNING` item); a `FROM t AS o` alias no longer counts. An unaliased `CAST(...)` follows the function-call rule and infers `cast` (Postgres names it after the target type's internal name, e.g. `int4`, which is not derivable): alias such items. `[verified: ScalarAliasAndArrayBindTest]`
