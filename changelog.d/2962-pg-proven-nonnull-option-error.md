### Fixed (2026-11-09 — #2962 pg-codegen: a proven non-null query output read into an `Option<T>` record component fails the build)
- **BREAKING (build behaviour): a `@Query` output the analyzer PROVES non-null that is read into an `Option<T>` record component is now a build error.** Declared types must match proven nullability in both directions (#2889 rejected the nullable-into-plain case). The error names the method, the output, the proof (which rule of the proven set fired: a `NOT NULL` column, a top-level `WHERE` conjunct that rejects NULL, `EXISTS`/`NOT EXISTS`, an ungrouped `count(..)` scalar subquery, `count(..)`, a non-NULL literal, `COALESCE` with a proven last argument, ...) and the fix: declare the plain type `T`. An output that is not proven non-null may still be read into `Option<T>`. A scalar `Promise<Option<T>>` return is unaffected: there `Option` is the row wrapper (no row), not a NULL holder. `[mechanism: OutputNullability.Nullability.NonNull carries the proof; check in QueryAnnotationProcessor.validateFieldOutputs]`
