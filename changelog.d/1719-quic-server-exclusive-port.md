### Fixed (2026-09-30 — #1719, #1015: a second socket could silently share, and on Linux take over, a node's QUIC cluster port)
- **The QUIC cluster port is now bound exclusively.** The server bound it with `SO_REUSEADDR`, so any other reuse-enabled socket on the host (another node, another process) bound the same port without error. On Linux the later socket then received every datagram for the port: the node went deaf mid-stream with nothing failing, which is the signature of #1727's lost lane writes (reproduced 3/3 on Linux by a reuse bind on the acceptor's port mid-burst). [verified: integrations/consensus/src/test/java/org/pragmatica/consensus/net/quic/QuicServerPortExclusiveTest.java — an intruder's bind mid-burst is refused and every write is delivered]
- **A taken port now fails the start loudly.** A second node on an occupied cluster port used to start and collide invisibly, so the `BindFailed` guard could never fire (#1015). It now fails with `BindFailed` naming the port. [verified: integrations/consensus/src/test/java/org/pragmatica/consensus/net/quic/QuicServerPortExclusiveTest.java]
- Forge's startup port preflight (#1008) still checks the whole range before any node is created; its documentation, the Forge guide and the lifecycle runbook now describe the exclusive bind.
- [unverified: whether this closes #1727; it is the leading explanation, and the delivery instrument (#1733) will show whether the signature recurs]
