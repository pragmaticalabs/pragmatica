### Fixed (2026-09-04 — #273: scheduled tasks could overlap themselves and accepted unparseable schedules)

- **Fixed-rate (`interval`) scheduled tasks now skip a fire instead of running concurrently with a still-in-flight execution of the same task.** A skipped fire is counted in a new `skippedOverlaps` field rather than silently dropped [verified: `aether/aether-invoke/src/test/java/org/pragmatica/aether/invoke/ScheduledTaskManagerTest.java#fixedRate_overlappingFire_recordsSkipInsteadOfDoubleExecution`]. Cron tasks already re-schedule after the previous execution completes rather than after launch, so they have nothing to skip; `skippedOverlaps` never increments for them.
- **An invalid `interval` or `cron` string in a slice's schedule config now fails slice activation** instead of silently registering an unparseable schedule. Validation runs at activation time — the earliest point architecturally possible, since the schedule string is per-node config invisible to blueprint DSL validation — and the failure surfaces through the existing `DeploymentFailed` WARNING event path, naming the task, the offending string, and the parser's error [verified: `aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/node/fsm/NodeDeploymentStateScheduledTaskValidationTest.java`].
- Added `skippedOverlaps` to the scheduled-task state API and docs (`management-api.md`, `resource-reference.md`).
- **Not addressed by this change** (tracked as ticket remainder, see PR description): drain-awareness for in-flight scheduled executions (depends on the unimplemented FSM sub-state from #189), leader-change hand-off of an in-flight execution's `inFlight` guard, and cron clock-skew across nodes.
