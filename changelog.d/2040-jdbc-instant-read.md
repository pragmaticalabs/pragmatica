### Fixed (2026-11-24 — #2040: the JDBC module could write an `Instant` but had no matching read)
- **`JdbcResults.getInstant(ResultSet, int|String)` reads a `timestamptz` or `timestamp` column as an `Option<Instant>`** (#2040). pgjdbc's `getObject(col, Instant.class)` is unsupported, so the `Instant` bound by `JdbcParameters` (#2031) had no read-side partner. The accessor reads through a UTC calendar, so a `timestamp` column is interpreted as UTC, mirroring the write binding, and a written instant reads back equal on any JVM zone; SQL `NULL` is `Option.none()`. [verified: `JdbcOperationsPostgresInstantTest` live-PostgreSQL round trip under `Asia/Tokyo`, both column types, self-skips without Docker]
