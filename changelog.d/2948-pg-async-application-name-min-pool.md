### Added (2026-11-09 — #2948: pg-async connector had no application_name and no warm minimum pool)
- **The postgres-async transport now names its sessions and warms its pool.** New optional `application_name` on a `[database]` section is sent in the startup message of every session, so `pg_stat_activity.application_name` attributes server-side load to a datasource, node or benchmark arm. Unset, it defaults to `aether-<node id>` (the node publishes the id it resolved at boot in the `aether.node.id` system property), else `aether-<datasource name>`; a derived name over 63 characters is cut. The name reaches the server as printable ASCII: every other code point (control characters, non-ASCII letters, emoji) is sent as `?`, so `pg_stat_activity` shows exactly what the connector sent instead of PostgreSQL's `\xNN` rewrite. `pool_config.min_connections` (already in the config, but ignored by this transport) now opens that many sessions at provisioning and returns them to the pool. Honoured by `PgSqlConnectorFactory` and `AsyncSqlConnectorFactory`; the JDBC, R2DBC and jOOQ-async factories are unchanged. `[verified: aether/resource/db-async/src/test/java/org/pragmatica/aether/resource/db/async/PgApplicationNameLiveTest.java]`
- **Warm-up is best effort (FER).** A database unreachable at provisioning, or slower than `connection_timeout`, leaves the pool to open sessions on demand and provisioning still succeeds: the guarantee is "first requests usually skip connection setup", not "`min_connections` sessions are open". Single attempt, no retry. `[verified: aether/resource/db-async/src/test/java/org/pragmatica/aether/resource/db/async/PgPoolWarmUpTest.java]` The wait is bounded by `pool_config.connection_timeout`.
- **Invalid configuration is refused at load.** `application_name` must be non-blank, at most 63 UTF-8 bytes and free of NUL; `pool_config` must satisfy `0 <= min_connections <= max_connections` and `max_connections >= 1`. Breaking for a config that set `max_connections` below the default `min_connections` of `4` without setting `min_connections`: it now fails to load; set `min_connections` explicitly. `[verified: aether/resource/api/src/test/java/org/pragmatica/aether/resource/db/ApplicationNameAndPoolBoundsTest.java]`
- The bundled pg-async driver (`integrations/db/postgres-async`) gains `ConnectibleBuilder.applicationName(String)` and a startup-message `application_name` parameter. `[verified: StartupMessageEncoderTest]`
- Warm-up hands each session back to the pool as it opens and opens at most `max_connections` sessions; a warm-up that expires with hung connection attempts no longer keeps later connections from real requests. `[verified: PgPoolWarmUpPoolTest]`
