### Fixed
- The management API now answers a caller's mistake with a 4xx instead of 500 on routes whose errors were plain, status-less causes: the missing or invalid fields of the alert, observability, DHT, metrics-backfill, certificate-configure and scheduled-task-inject routes (400), the dev-mode gates of the same routes (403), a node-role change that the immutable role refuses, an already-reached cluster version and a superseded gossip-key rotation (409), and a subsystem not available on this node (503).
- The status of a management error now comes from one place (`ManagementStatus`): a cause no rule covers still answers 500 but is logged once per type, and a stream refusal that reaches the funnel keeps its class status. A test iterates every cause type of the management plane, so a new unclassified cause fails the build.
- A raw stream engine refusal reaching the management funnel now answers its class status on every route except stream publish; publish keeps 500 for everything but the pre-append refusals (a publish is not idempotent, so only those may invite a retry). The Maven protocol routes send their other failures through the same funnel. All 85 changed statuses are listed in `aether/docs/reference/management-error-statuses.md`.
- A stream publish refused before anything was written for lack of capacity (`ReshufflePaced`, `MaterializeBudgetExceeded`, and the memory, sealing and segment-tier shortages) now answers the retryable 503 when the publisher is the partition owner, as it already did when the publish was forwarded (#1980).
