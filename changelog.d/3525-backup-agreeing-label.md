### Fixed (2026-11-26 — #3525: a core node with `[backup]` off was an ungated submitter during an undecided restore)
- **A core node whose `[backup]` setting differed from its peers' ran without the restore gate**, so it could submit cluster-state writes while the restore was still undecided. Every core node now advertises `backup=enabled` in its Hello labels when `[backup]` is enabled (absent when off) and names that label to the L1 join guard, so a node whose setting differs from a handshaken core peer's is refused at start with `ConsensusError.LabelAgreementRefused`. [mechanism: `BackupAgreement` is the single constant behind both the stamp and `NodeConfig.agreeingLabels()`] [verified: `aether/ember/src/test/java/org/pragmatica/aether/ember/EmberBackupAgreementTest.java`]
- Absent means off, so two nodes with `[backup]` off agree, and so does a `[backup]`-off node with a node of a version that predates the label. A `[backup]`-on node does not agree with such an old node; upgrades are stop-the-world. Operator recovery: set `[backup]` identically on every core node and restart the refused node.
- The guard now waits, without a deadline, for a quorum of core handshakes before a node casts a ballot (L1 behaviour, active for Aether nodes from this change): a core booted with fewer than a quorum of peers reachable stays pending.
