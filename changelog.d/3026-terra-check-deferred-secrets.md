### Fixed (2026-11-24 — #3026: terra:assemble --check required deployment secrets at build time)
- **`terra:assemble` ran the launcher's `--check` through the launch path, so an HS256 distribution (`[jwt] algorithm = "HS256"`) failed the build unless `TERRA_JWT__SECRET` was present in the build environment.** `--check` now loads the plan with deployment secrets deferred: everything known at build time (keys, modes, `auth_schemes`, slice selection, a secret that is supplied but too short or blank) is still checked, and an absent `jwt.secret` is reported in the check log as `Runtime input not supplied (required at launch): jwt.secret` instead of failing. A launch still refuses a missing secret (`JWT HS256 mode requires jwt.secret`), and a plan loaded for checking refuses `start()` with `Runtime inputs not supplied: jwt.secret`. Limit: `jwt.secret` is the only deployment-time input Terra's host settings require, so it is the only one deferred. `[verified: terra/launcher DeferredRuntimeInputsTest]`
