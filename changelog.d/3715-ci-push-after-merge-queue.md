### Changed (2026-11-25 — #3715: a push CI run repeated the merge queue's run on the same commit)
- **A push to `main` or `release-*` no longer re-runs CI on a commit the merge queue just tested.** `push-dedupe` now looks up a `merge_group` run of `ci.yml` with the same head SHA and conclusion `success`; when one exists every job is skipped (under the existing non-required "duplicate push run, skipped" names) except `forge-tests`, which still runs because it saves the Maven cache on push and caches are scoped by ref. A direct push, a failed or unfinished queue run, a failed lookup or an unreadable reply runs everything, as before. The decision is `.github/scripts/push-dedupe.sh`. `[verified: tools/test_push_dedupe.py]`
