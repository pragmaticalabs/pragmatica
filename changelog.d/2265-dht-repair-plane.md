### Changed (2026-10-18 — #2265: upload overhaul A6: the DHT repair plane works at disk scale for every keyspace)
- **Anti-entropy digests no longer read values.** Each engine keeps a stamp beside every value — owner epoch, HLC version, tombstone flag, value CRC32 and length — and the digest a replica answers is computed over those stamps (`StorageEngine.stampsForPartition`, `DHTNode.stampDigestOf`). The memory engine computes the CRC once per write. A digest round now reads zero values on both sides [verified: `DHTRepairPlaneTest.StampDigests.digestRound_readsNoValue_onEitherSide`]. The stamp digest also tells apart two replicas holding the same bytes at different stamps, which the value digest treated as in sync; the next round converges them.
- **Migration, survivor rebalance and the departure push travel in pages.** A pull is a sequence of `MigrationPageRequest`s with a resumable key cursor; each answer carries at most one page budget (default 16 MiB, configurable through `RepairPlane.usePageBudget`, always at least 1 MiB below the 32 MiB cluster frame). Rebalance and departure pushes are split into pages of the same budget, read one page at a time, and departure pages leave one after another, each once the previous is acked; unsent pages count as at risk when the push budget expires. A 200 MiB partition now migrates in 14 pages of at most 15.0 MiB as encoded [verified: `DHTRepairPlaneTest.PagedMigration`, `DHTRepairPlaneTest.DeparturePush`]. Before this change a partition above the frame could not be transferred at all.
- **Verified single-replica read for content-addressed keys, hedged and freshness-gated.** `DHTClient.getContentAddressed(key, sha256)` asks the local replica first, then the other replicas in ring order: the next one as soon as the previous answered with a miss or has not answered within the hedge delay (200 ms by default, `RepairPlane.useHedgeDelay`). The first copy whose SHA-256 matches wins. A copy that fails the hash check is never returned. When no replica has a verified copy the quorum read decides, within what is left of ONE operation timeout: the verified phase may use half of it, and the fallback the rest. One silent replica now costs about the hedge delay (201-206 ms measured, where it cost a third of the timeout); the worst case, a corrupt local copy and two silent replicas, ends at the operation timeout (2,008-2,014 ms measured at 2 s, where it took about 1.7x) [verified: `DHTRepairPlaneFaultTest.HedgedVerifiedRead`]. `existsContentAddressed` takes the same path, so a tier's `exists` agrees with its `get` [verified: `DHTRepairPlaneFaultTest.ExistsAgreesWithGet`, `DhtStorageTierTest.Addressing`]. AHSE's `DhtStorageTier` uses both for plaintext tiers; encrypted tiers (ciphertext, authenticated by `EncryptingStorageTier`) and every ordinary key keep the quorum read [verified: `DHTRepairPlaneTest.VerifiedRead`, `StorageFactoryEncryptionTest.createAll_encryptedDhtTier_readsThroughTheQuorumPath_andDecrypts`].
- **A removed block stays readable for a short, bounded time, under any fault.** A replica that missed a remove could serve the removed block's (correct) bytes until its own next anti-entropy round. A replica now answers a verified read only while it is FRESH for the partition: within the last freshness window (K = 2 anti-entropy intervals, 60 s at defaults) its own rounds synced it with at least max(1, RF − W) co-replicas, each authoritative for the partition (not catching up) [verified: `DHTRepairPlaneFaultTest.WhatCountsAsASync`]. An acknowledged remove reached W replicas, so syncs with RF − W co-replicas include one holding the tombstone, and that sync delivers it. Each sync is stamped with the time from which it vouches for the peer's state, so the bound is per mechanism. A digest match is stamped when the answer arrives, which is at most one exchange after the peer computed it (an unanswered digest is dropped at the first round at least one interval after it was asked); after the replica's last digest match before the remove, the block stays readable for at most one freshness window plus that exchange. A paged pull is stamped when its FIRST page was asked, and a pull resumed across rounds keeps that time: after the replica's last pull begun before the remove, the block stays readable for at most one freshness window, and a pull interrupted before the remove and completed after it does not re-open the window [verified: `DHTRepairPlaneFaultTest.WindowStaysClosed.resumedPull_completedAfterTheRemove_doesNotReopenTheWindow`]. A legacy whole-partition pull carries no readiness, so it repairs but is no sync. Freshness is measured on each node's monotonic clock, so a wall-clock step cannot stretch the window [verified: `DHTRepairPlaneFaultTest.WindowStaysClosed.wallClockStepsBack_theClosedWindowStaysClosed`]. Measured: without a fault the stale replica's next round ends it (about one interval, 30 s); under an asymmetric partition, ring disagreement, or a stale replica whose store fails to apply its pulls, the block is served at 59 s and not at 60.001 s; a stale replica whose partition is catching up serves no verified read at all [verified: `DHTRepairPlaneFaultTest.RemovedBlockWindow`]. The verified read travels as a new wire type, `VerifiedReadRequest` (tag 2176); peers recorded as legacy are skipped [verified: `DHTRepairPlaneFaultTest.HedgedVerifiedRead.legacyReplica_isNeverAskedAVerifiedRead`].
- **Rolling upgrades keep repair working.** The new requests are new wire types (tags 2163-2165 and 2176); an older node drops them as an unknown type. A node that asks a legacy digest or pull question is recorded as legacy, and this node then repairs with it in the legacy protocol, both ways. The record never latches: every round each peer held as legacy also gets one stamp-digest probe, a current peer answers it, and that current evidence clears the record and outweighs legacy questions for one freshness window. Two current nodes return to the stamp protocol in either restart order [verified: `DHTRepairPlaneTest.MixedVersions`, `DHTRepairPlaneTest.MixedVersionCatchUp`, `DHTRepairPlaneFaultTest.LegacyNegotiation`].
- **New gauges**: `aether.dht.repair.deficit.partitions` (partitions catching up or diverged and not yet repaired), `aether.dht.repair.pages.sent`, `aether.dht.repair.bytes.sent`, `aether.dht.repair.legacy.peers`, `aether.dht.repair.legacy.exchanges`, `aether.dht.read.verified.fallbacks`, `aether.dht.read.verified.mismatches`, `aether.dht.read.verified.quorum.fallbacks`.
- Unchanged: replication factor, quorum defaults, consistency of ordinary keys, and the in-memory engine's durability.
