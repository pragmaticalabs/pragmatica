### Changed (2026-10-18 — #2265: upload overhaul A6: the DHT repair plane works at disk scale for every keyspace)
- **Anti-entropy digests no longer read values.** Each engine keeps a stamp beside every value — owner epoch, HLC version, tombstone flag, value CRC32 and length — and the digest a replica answers is computed over those stamps (`StorageEngine.stampsForPartition`, `DHTNode.stampDigestOf`). The memory engine computes the CRC once per write. A digest round now reads zero values on both sides [verified: `DHTRepairPlaneTest.StampDigests.digestRound_readsNoValue_onEitherSide`]. The stamp digest also tells apart two replicas holding the same bytes at different stamps, which the value digest treated as in sync; the next round converges them.
- **Migration, survivor rebalance and the departure push travel in pages.** A pull is a sequence of `MigrationPageRequest`s with a resumable key cursor; each answer carries at most one page budget (default 16 MiB, configurable through `RepairPlane.usePageBudget`, always at least 1 MiB below the 32 MiB cluster frame). Rebalance and departure pushes are split into pages of the same budget, read one page at a time, and departure pages leave one after another, each once the previous is acked; unsent pages count as at risk when the push budget expires. A 200 MiB partition now migrates in 14 pages of at most 15.0 MiB as encoded [verified: `DHTRepairPlaneTest.PagedMigration`, `DHTRepairPlaneTest.DeparturePush`]. Before this change a partition above the frame could not be transferred at all.
- **Verified single-replica read for content-addressed keys.** `DHTClient.getContentAddressed(key, sha256)` reads the local replica first, then one replica at a time, returns the first copy whose SHA-256 matches, and falls back to the quorum read only when no single replica has a verified copy. A copy that fails the hash check is never returned. AHSE's `DhtStorageTier` uses it for plaintext tiers; encrypted tiers (ciphertext, authenticated by `EncryptingStorageTier`) and every ordinary key keep the quorum read [verified: `DHTRepairPlaneTest.VerifiedRead`, `DhtStorageTierTest.Addressing`, `StorageFactoryEncryptionTest.createAll_encryptedDhtTier_readsThroughTheQuorumPath_andDecrypts`]. One accepted difference for content-addressed keys: a replica that missed a remove can serve the removed block's (correct) bytes.
- **Rolling upgrades keep repair working.** The new requests are new wire types (tags 2163-2165); an older node drops them as an unknown type. A node that asks a legacy digest or pull question is recorded as legacy, and this node then repairs with it in the legacy protocol, both ways, until it sends a current-protocol message [verified: `DHTRepairPlaneTest.MixedVersions`, `DHTRepairPlaneTest.MixedVersionCatchUp`].
- **New gauges**: `aether.dht.repair.deficit.partitions` (partitions catching up or diverged and not yet repaired), `aether.dht.repair.pages.sent`, `aether.dht.repair.bytes.sent`, `aether.dht.repair.legacy.peers`, `aether.dht.repair.legacy.exchanges`, `aether.dht.read.verified.fallbacks`, `aether.dht.read.verified.mismatches`, `aether.dht.read.verified.quorum.fallbacks`.
- Unchanged: replication factor, quorum defaults, consistency of ordinary keys, and the in-memory engine's durability.
