### Fixed (2026-10-18 — #1568: jbct lint: TOT-02 misses List::getFirst; REC-01 BER gloss; config not a layer)
- **`JBCT-TOT-02` now flags `List::getFirst` / `List::getLast` (any receiver) and `Iterator::next` in mapper position, and `JBCT-STY-05` no longer steers code into that gap.** The rule resolved a method reference only against types declared in the same file, so an imported JDK type fell through; the partial accessors are now recognised by name (bare `get` stays out, it over-matches `Supplier.get`). `STY-05` skips a lambda whose body is `getFirst()`/`getLast()`, which `JBCT-TOT-01` already reports.
- **`JBCT-REC-01` reads tags only from comments, honours the comment above a method, and teaches the book's meaning.** A tag spelled in a string literal (`"FER"`) used to count as a recorded reason; the comment block directly above an absorbing method (comment and annotation lines, ended by a blank line) now counts as that method's reason, where before both of two absorbing methods were flagged even with a `// FER:` above one; the message defines BER as Backward Error Recovery (compensate by an inverse action) and FER as Forward Error Recovery (degrade and continue). The legacy spelling `best-effort` is still accepted as a reason; it names FER, and removing it would void existing justifications.
