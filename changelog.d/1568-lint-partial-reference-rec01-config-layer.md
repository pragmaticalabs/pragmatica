### Fixed (2026-10-18 — #1568: jbct lint: TOT-02 misses List::getFirst; REC-01 BER gloss; config not a layer)
- **`JBCT-TOT-02` now flags `getFirst` / `getLast` references on the JDK receivers whose accessor is partial, and `next` references on iterators, in mapper position, and `JBCT-STY-05` no longer steers code into that gap.** The rule resolved a method reference only against types declared in the same file, so an imported JDK type fell through. The receiver set is fixed: `List`, `ArrayList`, `LinkedList`, `CopyOnWriteArrayList`, `Vector`, `Deque`, `ArrayDeque`, `BlockingDeque`, `LinkedBlockingDeque`, `ConcurrentLinkedDeque`, `SequencedCollection`, `SequencedSet`, `LinkedHashSet`, `SortedSet`, `NavigableSet`, `TreeSet`, `ConcurrentSkipListSet` for `getFirst`/`getLast`; `Iterator`, `ListIterator` and `PrimitiveIterator.OfInt`/`OfLong`/`OfDouble` for `next`. Dotted and generic receivers are matched, a receiver declared in the same file is resolved by its own body (a total `Pair::getFirst` stays clean), `fold`'s success mapper (second argument) and field initializers are scanned, and a reference inside a Stream pipeline is exempt exactly where the lambda form is (JBCT-TOT-01). The check is textual: the Stream exemption is statement-scoped, and the `fold` match can misfire on a nested call in the failure mapper (documented on the rule). Bare `get` stays out, it over-matches `Supplier.get`. `STY-05` skips a lambda whose body is `getFirst()`/`getLast()`, which `JBCT-TOT-01` already reports.
- **`JBCT-REC-01` reads tags only from comments, honours the comment above a method, and teaches the book's meaning.** A tag spelled in a string literal (`"FER"`) used to count (a quote inside a comment, `// "FER": ...`, does not hide it) as a recorded reason; the comment block directly above an absorbing method (comment lines, including a multi-line block comment or Javadoc, and annotation lines, including a multi-line argument list; ended by a blank line) now counts as that method's reason, where before both of two absorbing methods were flagged even with a `// FER:` above one; the message defines BER as Backward Error Recovery (compensate by an inverse action) and FER as Forward Error Recovery (degrade and continue). The legacy spelling `best-effort` is still accepted as a reason; it names FER, and removing it would void existing justifications.
- **Only a top-level `config` package is a bootstrap layer segment** for `JBCT-ARCH-01`, matching the book's `domain/usecase/adapter/config` layout; a `config` nested below another layer segment (`adapter.config`, `domain.config`) stays in that layer, and the third-party root-group gate still keeps a foreign `...config` package from rank-flagging. `[verified: jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/rules/CstMapperMethodReferenceRuleTest.java, CstAbsorbedFailureRuleTest.java, CstArchDirectionRuleTest.java, jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/CstLinterTest.java MethodReferencePreferenceTests, jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/layer/LayerClassifierTest.java]`
