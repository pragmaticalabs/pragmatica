### Fixed (2026-11-06 — #2806: stop-drain quiesce could run on the thread that resolved the wait)
- **`DeploymentWiring.leaveQuorum` only started a pooled task and then mapped its result**, and promise continuations run inline on the resolving thread, so when the task finished first the quiesce (and the node's blocking teardown chained after it) ran on the react executor or timeout scheduler thread that resolved the wait, a product defect in the #2688 stop order, not a test timing artefact.
- The quiesce is now itself the pooled step started once the wait has resolved, in both orderings (wait resolved before or after the call). The order guarantee is unchanged: PASSIVE routed, drain, wait for the queued reactions, then quiesce. `[verified: aether/node/src/test/java/org/pragmatica/aether/node/deployment/Fsm2SystemTest.java StopDrain]`
