### Fixed (2026-09-30 — #1757: replacement cores minted by different leaders never counted each other, so leaders over-provisioned a phantom extra core)
- **SWIM gossip dropped member labels, and since #1390 a member counts as a core only with `role=core`.** `SwimMessage.MembershipUpdate` gains a trailing `labels` component, populated from the stored member and applied when a member is learned by gossip; a resident member with no labels adopts a gossiped update's labels (first-non-blank-wins), one that has labels keeps them, and a label-less gossiped state change no longer erases them. [verified: integrations/swim/src/test/java/org/pragmatica/swim/SwimGossipLabelsTest.java, aether/node/src/test/java/org/pragmatica/aether/node/SwimGossipRoleReachTest.java, aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/membership/ntt/LeaderReconcilerTest.java] (real `SwimProtocol` into the real `MembershipFsm`; not run on a multi-node cluster)
- **The Hello's labels now reach the membership layer for topology-known peers too**, not only for unknown ones; topology discovery is still started only for unknown peers. [verified: integrations/consensus/src/test/java/org/pragmatica/consensus/net/quic/QuicClusterNetworkTest.java] (two real QUIC networks)
- #1390's core-role rule is unchanged. Pre-GA wire change: `MembershipUpdate` gains `labels` (tag 49 unchanged); the wire baseline is re-recorded. [verified: aether/node/src/test/java/org/pragmatica/aether/node/SwimMessageLabelsCodecTest.java, aether/node/src/test/java/org/pragmatica/aether/node/WireAssignmentTripwireTest.java]
- **A node's own steady-state gossip now carries its labels.** The only ongoing gossip about a node is its own self-ALIVE, which had no labels, so a replacement that joined later never learned an earlier replacement's role (measured: R2 saw R1 with no labels for the whole run). `SwimProtocol` keeps the labels given to `announceJoin` and includes them on every self update. [verified: integrations/swim/src/test/java/org/pragmatica/swim/SwimLateJoinerLabelsTest.java] (real `SwimProtocol` instances on an in-memory network with real timers, the incident's join order)
- **SWIM datagrams are now size-budgeted.** Labels make updates larger, and a Ping with 12 realistic labelled updates (2476 B) exceeded the 2048 B receive buffer and was silently lost ("Failed to decrypt gossip"). Piggyback packing now adds updates until an estimated 1240 B is reached (1400 B datagram ceiling: 1500 B MTU less headers with slack for tunnels, less 160 B for envelope and AES-GCM framing); the rest go in later rounds, and the update that did not fit is sent first next round. The receive buffer is set explicitly to 2048 B (it was Netty's implicit default), an outgoing datagram over the ceiling logs a WARN, and a received datagram that fills the buffer logs an ERROR. [verified: integrations/swim/src/test/java/org/pragmatica/swim/SwimDatagramBudgetTest.java, aether/node/src/test/java/org/pragmatica/aether/node/SwimMessageLabelsCodecTest.java] (the estimate is checked against the production codec; not measured on a real network)
