### Fixed
- `GovernorCommitWindowTest` no longer races the wall clock (#2748). Its timer tests enqueued several commands inside a real 30 ms window and slept 250 ms inside a real 400 ms one, so a pause of the test thread (load, GC) longer than the window closed it between two enqueues and split the batch, or let the next window's timer fire before the assertion. `GovernorCommitWindow` now takes its timer as a parameter (production still passes the shared scheduler), and the tests start the timers themselves, so each test chooses the order of "enqueue" and "window elapses". One test keeps the shared scheduler on a single enqueue to pin the production wiring.
