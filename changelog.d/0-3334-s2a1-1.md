### Changed (2026-11-18 — #3334: stream declaration model on `StreamConfig`; `StreamConfigValue` wire flag day)
- **Breaking, wire (pre-GA flag day):** `StreamConfig` gains an optional last component, `declaration` (the stream's `[retention]`, `[truncation]` and `[hot]` sections and `expected_ingress`), and the committed `StreamConfigValue` moves from wire tag 1647 to 2920. Tag 1647 stays pinned under a retired name that resolves to no class, so it is never reused. A node of this release refuses an older node's `StreamConfigValue` on an unknown tag, and an older node refuses this release's. No decoder for the old tag is kept, so a `StreamConfigValue` stored by an older release is not readable by this one; the upgrade is a coordinated replacement of every node, with the streams created again. [mechanism: `SystemTags` pins 2920 to `StreamConfigValue` and 1647 to `StreamConfigValueRetiredRc6`; the baseline `aether/node/src/test/resources/wire-assignment-baseline.txt` records both]
- Nothing parses or enforces the declaration yet: every `StreamConfig` built by this release carries `none` (each factory and `DEFAULT` pass `none`; the copy methods carry the receiver's value over), so stream behaviour is unchanged. The declaration's defaults (`max_age` 24 h, `max_bytes = max(1 GiB, P x 2 x seal_merge_bytes)`, `mode` any, the hot window from `RingGeometry`) are defined in `DeclarationDefaults`. [mechanism: unit-tested only, `StreamConfigTest.Declaration`, `StreamDeclarationWireTest` (node codec round trip), `DeclarationDefaultsTest`]
