### Added (2026-10-23 — deployment state machine rewrite, phase 3 P3-F: engine marker restore and mixed clusters, retired identities, suspicion window, admission seam)
- **A restore leaves the deployment engine marker as the backup has it.** The restore's finish removes a marker the backup does not carry (a pre-phase-3 backup restores a LEGACY cluster) and replaces one it carries differently, in the same transaction as the incarnation and the `RESTORED` marker. The path where a leader without `[backup]` mints both keys mid-restore cannot finish today (#1533: the finish's incarnation write is refused by the version fence); its two arms are disabled beside an enabled tripwire that goes red when it finishes.
  [verified: `aether/node/src/test/java/org/pragmatica/aether/node/backup/BackupRestoreCoordinatorTest.java`]
- **A terminated node's directive and departure record leave together.** Under FSM2 the cluster topology manager's confirmed reap (B18) and the operator `--force` clear (B19) remove the node's `ActivationDirectiveKey` and `NodeDepartureKey` in one leader transaction, record first, each expecting the value read; under LEGACY they remove nothing. Community placement COMPLETE removes the record in its own transaction too. A source tripwire is red when a new file deletes a directive (#1842's writer must retire the record with it).
  [verified: `aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/cluster/TerminationRetirementTest.java`, `aether/node/src/test/java/org/pragmatica/aether/node/NodeReplacementRealRegistryReapTest.java`, `aether/node/src/test/java/org/pragmatica/aether/node/deployment/RetirementGateTest.java`, `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/RetiredIdentityReadersTest.java`, `aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/cluster/CommunityPlacementReconcilerTest.java`, `aether/node/src/test/java/org/pragmatica/aether/node/DirectiveDeletersTripwireTest.java`]
- **The FSM2 core suspicion window counts every term a dead core stays listed.** The core view is MEMBER + SUSPECT, so the window adds the probe lead (`(maxCores - 1)` periods), two probe timeouts and the membership's `splitTimeout` to the sampling interval and the tick; `maxCores` is the configured `coreMax`, or the cluster size when it is unset `[guess]`. The bounds are checked against a model built from SWIM's own constants, and a core listed exactly that long is never counted.
  [verified: `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/SettingsSourcedTest.java`, `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/JoinedEvidenceTest.java`, `aether/node/src/test/java/org/pragmatica/aether/node/deployment/SuspicionLagCoresTest.java`]
- **The deployment engine reads tokens and incarnations through one admission seam**, built before membership and bound to it late; a read before membership is bound is counted, and a booted node counts none.
  [verified: `aether/node/src/test/java/org/pragmatica/aether/node/DeploymentWiringBootTest.java`, `aether/node/src/test/java/org/pragmatica/aether/node/deployment/AdmissionSeamReadersTest.java`]
- **FSM2 consumes no `SelfShutdown` input** (it is never produced): a stopping node writes nothing, and its peers depart it through `NodeRemoved`, as under LEGACY.
  [verified: `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/ArchitectureTest.java`]
- **The engine marker is pinned across processes.** Ember takes a per-node engine override; a Heavy forge class runs a misconfigured newcomer in each direction (it refuses itself, writes nothing of its engine, and no other node exits) and FSM2 members that are up before the lineage mint (they wait and never refuse). The `CommunityKey` writers (the cluster FSM and community placement) are pinned not to lose a write in any order.
  [verified: `aether/forge/forge-tests/src/test/java/org/pragmatica/aether/forge/Fsm2EngineMarkerMixedClusterTest.java`, `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/CommunityKeyWritersInterleaveTest.java`]
- **Named limit.** No newcomer leads in the mixed-cluster arms: a joining core was not seen admitted as a voter in the harness, so the arms assert that the closed newcomer is never admitted.
