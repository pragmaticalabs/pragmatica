### Changed (2026-11-20 — #1611: Ember start-failure record-before-signal order pinned in one handler)
- **The failing node's record and the abort signal now share ONE `onFailure` handler.** The order was already correct in `EmberCluster.start` when both handlers were registered before `start` resolved; it now lives in one package-visible method, `recordFailureThenSignal`, whose single handler puts first, then signals, so a `start` that resolves mid-registration can no longer reorder them. `EmberClusterStartFailureOrderTest` pins it with a delayed map put (signalling before the put turns it red). This is a pin and refactor, not a reproduced defect: the former window was not reproducible in a test.
