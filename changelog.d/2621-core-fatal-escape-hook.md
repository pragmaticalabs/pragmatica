### Added (2026-11-03 — #2621: core Promise fatal-escape hook)
- **An `Error` escaping a `Promise` continuation was visible only as an ERROR log line.** A non-`VirtualMachineError` (an `AssertionError`, a `LinkageError`) became a failed `Result`, and a `VirtualMachineError` was rethrown on whichever thread ran the continuation, often an executor thread nobody watches. No host could react.
- `Promise.installFatalEscapeHandler(FatalEscapeHandler)` installs one process-wide handler, which receives every `Error` (VME or not) escaping an `onResult`/`onSuccess`/`onFailure` handler, a `map`/`flatMap`/`fold` transformation or an `async` consumer, as a `FatalEscape` (continuation kind, error, origin frame, thread name). A `RuntimeException` never reaches it; its handling is unchanged. `[verified: core/src/test/java/org/pragmatica/lang/FatalEscapeHookTest.java]`
- Explicit install only: nothing happens unless a host's entry point installs a handler, so a library user's JVM keeps the existing behaviour. A second install while one is held is refused with `FatalEscapeError.ALREADY_INSTALLED`; only the returned `Registration` can uninstall. `[verified: FatalEscapeHookTest$Slot]`
- Escapes before the first install in the process are kept (the first 16, the rest counted) and replayed, once each, to the first handler installed. After any uninstall, an escape with no handler is logged and counted in `Promise.unownedFatalEscapes()`, never buffered for a later handler. `[verified: FatalEscapeHookTest$Buffer]`
- A handler that throws is contained (one ERROR line; the escape proceeds unchanged), and an error escaping a continuation run by the handler itself does not reach the handler again. `[verified: FatalEscapeHookTest$Containment]`
- Delivery is once per continuation boundary crossed, not once per `Error` object: a rethrown `VirtualMachineError` that crosses N boundaries (a continuation resolving another promise whose continuation throws it) is delivered N times, the same object each time; a handler that must act once per error compares `FatalEscape.error()` by identity. `[verified: FatalEscapeHookTest$Delivery#rethrownVme_crossingTwoBoundaries_isDeliveredOncePerBoundary]`
- The hook cannot change an escape's own handling: whatever it throws (a `StackOverflowError` on a nearly exhausted stack) is dropped in `escaped()`, and its class is initialised by `PromiseImpl`'s static initialiser on an ordinary stack. Before this, a first `Error` escape that was a deep `StackOverflowError` could fail the hook class's initialisation for the JVM's life, after which every later `Error` escape threw out of `escaped()` and left its batch of dependents unresolved. `[verified: FatalEscapeFreshJvmTest, fresh child JVMs with -Xss1m and -Xss4m; red at the PR head without the fix (verifier v2621: 12/12 poisoned), green with it]`
- No cost per completion: the hook is called only from `PromiseImpl.escaped`, which runs inside the catch at a continuation boundary; `resolve`, `push`, `processActions` and `runAll` are unchanged. The one-time cost is the hook class's initialisation when `PromiseImpl` loads. `[mechanism: the diff to Promise.java touches escaped(), the PromiseImpl static initialiser, and adds two static interface methods]`
- `testing`: `FatalEscapeRecorder`, a JUnit 5 extension that installs a recording handler before each test, uninstalls it after, and logs a WARN naming the test when unowned escapes rose since the previous teardown. An escape delivered to the recorder after its test's teardown (the uninstall race stated on `Registration.uninstall`) is not recorded; it logs a WARN naming the error, the continuation and the finished test. `[verified: FatalEscapeRecorderTest#escapeDeliveredAfterTeardown_warnsNamingErrorAndTest]` `[verified: testing/src/test/java/org/pragmatica/testing/FatalEscapeRecorderTest.java]`
