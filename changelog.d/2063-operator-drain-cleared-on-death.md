### Fixed (2026-10-18 — #2063: operator drain entries never leave DrainCommandRegistry)
- **A node that was drained, left and came back under the same id was told to drain again.** An operator-commanded drain stayed in the leader's `DrainCommandRegistry` for the life of the process: the only removal paths covered drains the topology manager started itself, and node ids come from config, so a rejoin under the same id inherited the old command. The entry is now cleared on the membership FSM's transition into DEAD, the departure the drain was for (`AetherNode.clearOperatorDrainOnDeath`, called from the existing transition listener). Not changed: a node that restarts and is recovered by a higher-incarnation `SwimHealthy` before it ever reaches DEAD keeps its entry, and the per-node tracking entries for nodes that never report READY again (N2 in the ticket) are not touched. `[verified: aether/node/src/test/java/org/pragmatica/aether/node/AetherNodeOperatorDrainClearTest.java]`
