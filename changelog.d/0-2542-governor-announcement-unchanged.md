### Fixed
- A governor announcement that equals the committed one (governor, member list, address, term and community epoch; the announcement time and the core's once-a-second generation counter it carries are not compared) is no longer committed again when a SWIM membership edge asks for it (#2542). It had been the bulk of the core's commits: a median 91% of an event's mutations, about 150 for one worker crashing at N=50. The governor's 30 s re-announce timer still re-commits it, so `announcedAt`, the freshness window the core reads and the sweeps that run on each committed announcement keep their cadence. `GovernorAuthorityMessage.Request` gains a `refresh` flag, set only by that timer.
- The governor authority now submits the announcements that fall in one 50 ms window (up to 16) as one command list, one per community, instead of one consensus round each (#2542, the batch rule). Each transaction keeps its own witnesses and is accepted or refused on its own; a repeated write for one community by the same governor collapses to the latest, and a competing claim by another governor closes the window first.
