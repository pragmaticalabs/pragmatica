### Changed (2026-10-18 — #2226: generated JSON codecs for slice payloads, replacing the Jackson path)
- **Value objects on slice HTTP are now unwrapped when nested:** a single-component record with a factory is written as its bare value inside another value (a record component, a collection element, a map key or value), not `{"value": ...}`, and decodes through its own factory. A value object that is the whole request body or response stays a JSON object of its component (`{"payload": ...}`), also decoded through the factory, so a top-level body is never a bare scalar. A refusal from the factory is a 400. The slice-route Jackson fallback applies the same rule through `JsonMapper.valueObjectJsonMapper()`. `defaultJsonMapper()` is unchanged. `[verified: jbct/slice-processor-tests/src/test/java/com/example/wireform/GeneratedRouteWireFormTest.java, integrations/json/jackson/src/test/java/org/pragmatica/json/ValueObjectModuleTest.java, aether/http-routing-adapter/src/test/java/org/pragmatica/aether/http/adapter/SliceRouterWireFormParityTest.java, integrations/serialization/json-tests/src/test/java/org/pragmatica/serialization/json/tests/CombinatorAgreementTest.java]`
- **Request bodies decode strictly.** Required fields are enforced, and `null` is rejected for non-`Option` fields. Skipped unknown values are validated against the full grammar. Invalid UTF-8, a BOM, lone surrogate escapes, non-canonical UUIDs and nesting deeper than 1000 levels are rejected. `[verified: integrations/serialization/json-tests/src/test/java/org/pragmatica/serialization/json/tests/StrictDecodingTest.java]`
- **`SliceCodec.writeString` now uses the JDK UTF-8 encoder.** It is byte-identical to the previous output except for malformed UTF-16, where Netty wrote invalid UTF-8. `[verified: integrations/serialization/api/src/test/java/org/pragmatica/serialization/SliceCodecTest.java]`
