### Fixed (2026-09-14 — #1152: `singlePeerFaulty_notIsolation_backlogNotExpiredOnReconnect` kept NODE_B alive only at Awaitility's poll cadence, so a late poll latched isolation)
- **Test-only.** No production code changes.
- **The keepAlive rode the assertion poll.** `keepAlive(NODE_B)` ran inside the `await().until(...)` lambda, so NODE_B's outstanding probe was answered once per Awaitility poll (100ms by default) against a budget of `probeTimeout` 20ms (direct) + 20ms (indirect) before SUSPECT, then a 60–300ms LHM-scaled suspect window. On a loaded runner one late poll let NODE_B expire, both peers were FAULTY, `detectSelfIsolation` latched, and the test's premise (`NODE_B … isNotEqualTo(FAULTY)`) failed before it reached the assertion it exists for. [mechanism: `SwimProtocol.handleProbeTimeout` → `markSuspect` → `expireSuspectIfOverdue` → `transitionToFaulty` → `detectSelfIsolation`; the investigation measured 4/200 cold-JVM reds at load 77–114, each preceded by `self-isolation detected`]
- **NODE_B's liveness now carries no timing constant.** `AnsweringTransport` (a `RecordingTransport`) answers every `Ping` sent to NODE_B with the matching `Ack` before `send` returns, on the sending thread. `SwimProtocol.probeTarget` registers the pending probe before it sends, so the ack is accepted as verified alive-evidence before `scheduleProbeTimeout` even runs — independent of the poll, of the scheduler, and of host load. The test wires the protocol as the transport's handler explicitly (`transport.start(port, protocol)`, what `CoreSwimHealthDetector` does; `SwimProtocol.start` does not), and the "reconnection evidence after the verdict" step waits for one more transport-delivered ack instead of hand-feeding one. A dedicated ticker was rejected because any cadence is still a constant that a saturated runner can breach; a synchronous responder has none. [verified: harness with the test's config and seeding, 100 iterations per arm at load 80–92 — old shape with the poll stretched to 300ms: 2/100 NODE_B FAULTY + isolation latched; new shape at 100ms and 300ms polls: 0/100 and 0/100, zero `self-isolation detected` lines. The real nested class, one cold JVM per iteration through the platform launcher, against a `PiggybackBuffer` carrying the #1151 lock so mode 1 is excluded: before, 2/200 reds at load 88–148, both `NODE_B stays alive … Expecting FAULTY not to be equal to FAULTY` with `self-isolation detected`; after, 0/200 at load 77–158]
- A control assertion pins the instrument: at least one transport-delivered ack to NODE_B has happened by the time NODE_A is FAULTY (the probe schedule alternates targets and NODE_A needs three ticks). The four poll-cadence helpers this test was the only user of (`keepAlive`, `deliverVerifiedAckFrom`, `pendingSeqFor`, `addrOf`) are removed with it. [verified: with the not-isolated guard removed from `SwimProtocol.clearIsolationOnReconnect`, the test reddens at `The first-hand FAULTY for NODE_A is buffered for normal dissemination` (0 > 0) 2/2 — the transport's acks reach the P2 seam; intact 2/2 green]
