### Added (2026-11-24 — #3658: one backend-selection seam for cache and idempotency stores, part 1)
- **Cache and idempotency stores now obtain their backend through one seam** (`CacheBackends`) instead of each factory building a DHT backend directly. A new optional `backend` key (`memory` | `dht`, `[guess: key name and values, #3658]`) names the store; absent, it follows `mode` (`LOCAL` -> `memory`, `DISTRIBUTED`/`TIERED` -> `dht`), so existing sections behave as before.
- Typed, terminal refusals at slice start: `UnknownBackend`, `ModeConflict` (`LOCAL` with `dht`, `DISTRIBUTED`/`TIERED` with `memory`), and `BackendUnavailable` for `dht` on Terra (subsumes #3654); the cause names the backend and store (`UnknownBackend`), the store, mode and backend (`ModeConflict`), or the backend, store and runtime (`BackendUnavailable`), and the provisioning wrapper adds the section `[verified: terra/examples/src/test/java/org/pragmatica/terra/example/TerraExamplesTest.java]`.
- Not in this part: `terra:assemble --check` refusal, the pub-sub seam and in-memory topic delivery contract, Redis.
