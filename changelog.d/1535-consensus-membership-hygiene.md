### Fixed (2026-10-18 — #1390 hygiene, #1535: fail-open leader eligibility, silent inbound refusals, silent membership drops, dead code, GCP claim, wall-clock deadlines)
- **Leader eligibility no longer fails open before voters install.** `LeaderElectionContext.isEligible` returned `true` for every node until `installVoters` ran. It now follows the configured cluster in that window (everyone stays eligible only when no cluster is configured). Pinned by `LeaderElectionContextTest`.
- **Inbound refusals are counted and logged.** Messages refused by origin binding, the inbound message policy or the fault filter were counted as received and then dropped at TRACE. Each predicate now has its own counter (`quic_inbound_unbound_drops_total`, `quic_inbound_policy_drops_total`, `quic_inbound_fault_filter_drops_total`) on `/api/v1/metrics/transport` (not yet on the Prometheus surface, which exposes only 11 transport counters: D-05), and the first two log a WARN on the first and every power-of-two occurrence. Pinned by `QuicInboundRefusalCounterTest` (real QUIC on loopback).
- **Refused process evidence no longer rewrites the member descriptor.** `MembershipFsm.onGovernorHealthy` / `onWorkerAdmissionHealthy` merged the descriptor before the boot-token, DEAD/DEPARTING and stale-evidence gates, so a refused report still overwrote the member's address. The descriptor is now merged only after the report is admitted, and a malformed report is logged instead of silently dropped. Pinned by `MembershipRefusedEvidenceDescriptorTest`.
- **GCP insert errors are read.** `insertInstance` returns a long-running operation; a rejected insert comes back as HTTP 200 with an `error` member that was never read, so a failure surfaced as a readiness timeout. `Operation` now decodes the error and `GcpComputeProvider.createFrom` fails with it. Only an error already present on the insert response is read: the operation is not polled to completion, so a failure GCP reports later still surfaces as a readiness timeout. The "insertInstance is atomic" comment and WARN text are corrected.
- **Community placement deadlines read an injected clock.** The drain deadline, the readiness timeout and the availability retry in `CommunityPlacementReconciler` take a `LongSupplier` (epoch milliseconds; production passes the wall clock, kept wall-clock because the stamps are replicated through the KV).

### Removed (2026-10-18 — dead code left by #1390, #1535)
- `TopologyManager.superMajoritySize()`, `ConsensusMetrics.recordFastPath` and `RabiaMetricsCollector.recordFastPath` (no caller since the engine stopped taking the fast path), and `CommunityPlacementPlanner.distributeWorkerOrCommunity` with its private helpers.
- **Retained on purpose:** the wire field `fastPathCount` / `consensus_fast_path_total` is still exported and now always reads 0, so no management-API or Prometheus vocabulary changes in this fix. Removing it is a separate API decision.
