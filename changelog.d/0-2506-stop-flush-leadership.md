### Fixed
- A graceful stop now runs the KV backup stop flush on every node that holds the full state, not only the leader: a whole-cluster stop demotes the leader as its peers go, and the node that acked a write need not be the leader, so a write acked at revision r reaches the backup head if at least one node that applied r completes its flush. A head strictly ahead within the same incarnation covers the node (no warning); a head at a higher incarnation, a failed push or an overrun still raises `BACKUP_STOP_FLUSH_FAILED`, naming git's own words. A push that loses a race (git's `[rejected]` status line, or the server's `[remote rejected] (failed to update ref)`) is decided again in a loop until the 10 s stop deadline or the stop, instead of twice; a second rejection against a remote head that did not move is permanent. An interrupted git is killed with its owner, and a stopped node raises no `BACKUP_COMMIT_FAILED`. Workers (a `[worker]` configuration or a `role=worker|spot` label) hold the metadata projection, or under the live replica feed a replica without the cluster configuration, so they only stop and log one INFO line (#2506).
