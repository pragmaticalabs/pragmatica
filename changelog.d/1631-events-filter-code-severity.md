### Added (2026-11-25 — #1631: filter cluster events by code and severity)
- **`GET /api/events` takes `code=` and `severity=`, and `aether events` takes `--code` and `--severity`.** `code` keeps the events whose `details.code` equals it (exact, case-sensitive; an unknown code lists nothing, it is not an error). `severity` is a MINIMUM (`WARNING` keeps `WARNING` and `CRITICAL`), case-insensitive; any value other than `INFO`, `WARNING` or `CRITICAL` (`UNKNOWN` included) is refused with 400. An event whose own severity is `UNKNOWN` (a level an older node cannot name) passes every severity filter. Both filters combine with AND and apply to whatever the `sinceEpoch`/`sinceSeq` cursor selected. `aether/docs/reference/management-api.md` and `cli.md` document both.
- **Known limit, not changed here:** `aether events --since` sends `since=`, which the server does not read (it reads `sinceEpoch`/`sinceSeq`), so `--since` does not narrow the list.
