### Fixed (2026-11-17 — #3321: tests that guess a port free, two kinds)
- **`UnreachableClusterExitTest`, `ClusterHttpClientDrainStateTest.await_realClosedPort_completes` and `HttpClientErrorTest.send_toAPortNothingListensOn_failsWithConnectionFailedCarryingTheConnectException` no longer guess a free port** (#3321, same defect as #3319). They bound a server socket, read its port and closed it before connecting; a parallel module (`-T 1C`) could be handed that port in between and the connect then succeeded. They now hold the port for the whole test with `UnreachablePort` (moved from the redis test sources to `test-logging`, which all three modules already use in test scope), so on Linux the connect is refused by construction. Test-only; no production change. [verified: `HttpClientErrorTest` under a port-grabbing load, 20 rounds: old form 3 red, new form 0 red; `UnreachablePortTest`]
- **Second kind: six tests asserted "the server under test did not bind" by probing a port they had guessed free** (#3321): `ServerTlsFailClosedTest` (tcp), `HttpServerTlsStartupTest`, `AetherNodeBrokenTlsBootTest`, `ManagementServerTlsFailClosedTest`, `AppHttpServerTlsFailClosedTest` and `AppHttpServerRotationRaceTest`. A process that took the guessed port made `connect` succeed and the test fail for a reason unrelated to TLS. The five refusal tests now HOLD the port themselves and assert the typed TLS refusal (a bind attempt on the held port would surface as a bind error instead); the rotation test's "closed" probe now requires a TLS handshake presenting the rotated certificate, which no other process can answer. The held-port helper is the wrong tool for this kind and is not used. Test-only. [verified: with a rival listening on the guessed port, the old forms fail 10 of 10 affected tests and the new forms 0, cloudbb-4]
- `test-logging` now also holds socket helpers; the module description says so, the name is unchanged (a rename would touch every consumer).
