### Fixed (2026-11-08 — #2902 #2903: two aether/node test flakes)
- **`KvBackupService.stopFlushed` resolves its promise only after the stop has run** (#2903). The stop ran as an `onResultRun` action, after the result was visible, so a caller that awaited the promise could see it resolved while `isLeader()` was still true (about 1 run in 5 of `stopFlushed_reportsAndStillStops_whenTheFlushOverrunsItsDeadline`, bigboy). The stop now runs inside the transformation. [verified: `KvBackupServiceTest$GracefulStop#stopFlushed_isNotResolved_whileTheStopIsStillRunning` (latch-held stop, red on the old code)]
- **`ClusterTestPortsTest` controls no longer race other allocators** (#2902). The test chose a free window port without the cross-JVM lock and took it only after the occupying socket was released, so any port another JVM had locked (or bound) made the "released, accepted again" control fail. The test now locks the port first (`ClusterTestPorts.reserve`) and the allocation attempt adopts that lock. Test code only.
