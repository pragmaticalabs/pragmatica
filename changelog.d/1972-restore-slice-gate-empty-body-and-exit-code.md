### Fixed (2026-10-18 — #1972: harness restore_cluster_baseline slice-gate FAIL with `{}` body after a suite deletes its blueprint; run exits 0)
- **The restore slice gate failed on the one body that means "nothing deployed".** The management API serialises with `NON_EMPTY` (`JsonCodecAdapter`), so an empty slice list is the body `{}`, not `{"slices":[]}`; `_restore_slices_gate` read any body without a `"slices"` key as "unreadable" and failed after its full budget when a suite had deleted its own blueprint. A body that is exactly the empty object now passes (no slice to gate on); an empty body, an error body or anything else is still a failure, and a test pins the serialiser setting the reading depends on. `[verified: aether/tests/integration/test/test-restore-slices-gate.sh G12-G15]`
- **A restore that failed after the LAST suite did not fail the run.** `run_cluster_b_suites` only set `aborted`, which turns later suites into `skipped-unrecoverable`; with no later suite nothing recorded the failure and the process exited 0 with a FAIL in the log. The failed restore now writes its own `failed` record, so the run exits non-zero wherever in the sequence it happens. `[verified: aether/tests/integration/test/test-restore-failure-fails-run.sh X1-X5; the stub run of the unfixed runner exits 0 on X1]`
