### Fixed (2026-11-21 — #3512: the cluster and TCP integration tests now prove what they claim)
- **`MessageSemanticsIT` delivers a reconnected node's own stale-phase proposal and votes to the cluster and checks that each one is answered by sending that node the decision of the ballot's own phase (phase and value, agreed by two replicas), that a later value of the key is not regressed, and that the cluster keeps committing; the duplicate-delivery test counts put notifications, so a batch applied twice is caught (a Put is idempotent, the stored value alone cannot tell).** The new `RabiaStalePhaseGuardsTest` pins each stale-phase guard alone: a stale proposal, round-1 vote or round-2 vote leaves the completed slot's state unchanged, and a duplicate decision of a slot whose data was cleaned is not applied again. `TestCluster` gained `reconnect`, a per-node record of delivered proposals, votes and decisions, `deliver`, and a per-key put counter. `ByzantineBehaviorsIT` is renamed `CrashFaultBehaviorsIT`, with test names and logs that say what it does: one node crashes and the remaining quorum keeps committing (Rabia tolerates crash faults, n >= 2f+1). `Server.port()` now reports the bound port, so a server configured with port 0 says which port the OS assigned; `ServerIT` binds port 0, connects to the reported port, bounds every wait and lost its `TCP_INTEGRATION_TESTS` gate, so it runs in CI under `-T 1C`.
