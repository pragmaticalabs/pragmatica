### Changed (2026-10-15 — #2201: streams and durable-entity limits stated; overclaiming documents corrected)
- **`known-limitations.md` now states the streams and durable-entity limits** until the spec-first overhaul tracked in #2201 lands: a lagging declarative consumer stalls on `CursorExpired`; sealed-tier retention is a node-wide 24 h; sealing writes one segment per evicted event; the default 128 MiB stream memory budget fits about 50 partition rings per node; production replication is not batched; a retried durable-entity `update` that missed its replication barrier applies twice; the transactional cursor path is unwired.
- **Corrections to earlier changelog entries** (those entries are history and stay as published):
  - The durable-entity timers entry (#351) said a timer survives "the whole cluster restarting". It survives a node restart and an owner handover; a whole-cluster restart restores from `[backup]`, which withholds entity checkpoints, so entity state, timers included, restarts empty (`BackupRestoreCoordinator.warnEntityCheckpointsNotRestored`, `operators/runbooks/backup-recovery.md`).
  - The Phase 1 "Transactional cursor commits ... exactly-once semantics" entry: `PgTransactionalCursorCommit` has no production caller, so no stream path is exactly-once.
  - The Phase 1 "Batch replication" entry: the node builds the non-batching `ReplicationManager.replicationManager`; `batchingReplicationManager` has no production caller.
  - The Phase 1 "Consumer group coordination" entry: join/leave writes `ConsumerGroupKey` records that no read consults, and the status response lists members, not partitions.
- **Documentation corrected to match:** a topic `idempotencyKey` sets the message ID and does not deduplicate on publish; feature-catalog row 138 is now Partial; the management API and CLI consumer-group examples no longer show partitions. `[mechanism: each correction cites the code in known-limitations.md and guarantees-corrections-needed.md D22-D26]`
