### Fixed
- A node no longer re-files its `DhtReplicationReportKey` on every configuration version it applies (#2545). A scale or policy event had every node write it again, N+5 core writes per event and the only term linear in N. The leader reads `appliedVersion` only as "at or above the open change's version", so a newer applied version is filed only when it reaches the version of an open change the node knows (a core reads the change record, a worker is told by its projection); a changed caught-up version or replica flag is always filed. The worker-metadata tick still retries a report whose submission failed.
