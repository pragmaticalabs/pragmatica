### Fixed (2026-09-14 — #280: retry was idempotency-blind, logging leaked request/result content, metrics flags were ignored)
- **R26 — the retry interceptor retried every failure.** `RetryMethodInterceptor` handed each call to core `Retry`, which stops only on `Cause.Terminal`; a slice's own business verdict (`InsufficientFunds`) is unclassified and was re-driven as eagerly as a timeout, on methods that may not be idempotent. The interceptor cannot tell a business failure from an infrastructure one by origin, so retry is now **opt-in by classification**: core gains `Cause.Transient` (`isTransient()`, the mirror of `Cause.Terminal`), and `RetryConfig` gains `retry_on` — `TRANSIENT` (default: only a cause that declares itself transient is retried; an unclassified failure is returned after the first attempt) or `NON_TERMINAL` (the behaviour before this change, for a method whose failures are all infrastructural but not yet classified). A refused cause is returned WITHOUT entering `Retry`, so a business failure is neither re-driven nor logged as a retry giving up. `max_attempts` counts calls at the method, the first included. [verified: `RetryInterceptorPredicateTest` (`aether/resource/interceptors`) — unclassified failure: 1 attempt under the default (was 3, red at the base), original cause returned; `Cause.Transient` failure: 3 attempts; `NON_TERMINAL` opt-in retries the unclassified failure; a budget of 1 makes no retry; transient-then-success returns the success. Mutations: widening `TRANSIENT` to non-terminal reddens the unclassified pin; dropping the remaining-budget guard reddens the budget-of-1 pin] [verified: `RetryConfigTomlBindingTest#config_retryOn_bindsFromToml`, `#config_omittedRetryOn_fallsBackToTransient`]
- **BEHAVIOUR CHANGE.** A retry-intercepted method whose failure is an UNCLASSIFIED cause is no longer retried; only a `Cause.Transient` is. Existing `@Retry`-style declarations over unclassified causes stop retrying unless the section sets `retry_on = "NON_TERMINAL"` (explicit opt-in — retrying an unclassified failure is a decision, never a default, the #665 rule) or the cause is classified. When the default declines a cause it logs ONE DEBUG line through SLF4J (`org.pragmatica.aether.resource.interceptor.RetryMethodInterceptor`) naming the cause type and the policy, so a retry that "stopped working" is findable without being a per-business-failure WARN. [verified: `RetryInterceptorPredicateTest` — default declines an unclassified cause (1 attempt), retries a `Cause.Transient` (3), `NON_TERMINAL` retries the unclassified (3), a `Cause.Terminal` is never retried under either policy (1 each); reverting the policy or the budget guard reddens the named pin] `RetryConfigTomlBindingTest`'s end-to-end fixture failed with a generic cause whose MESSAGE said "transient" and whose type said nothing; it now implements `Cause.Transient` — the fixture says what the prose always claimed.
- **Classification pass — every cause family a retry interceptor can see, and what the default now does with it.** The space: causes a slice method can return at CALL time — its resource clients' errors, invocation errors when it calls another slice, core utility errors, and its own business verdicts. Node-internal, CLI, Forge, provisioning-time and config-binding families (`SliceLoadingFailure`, `ResourceProvisioningError`, `ConfigError`, `TopicConfigError`, `EntityProvisioningError`, `DeploymentError`, `AbTestDeploymentError`, WAL/segment/replication internals…) never reach a slice method's result and are out of the space. Legend: **T** = now `Cause.Transient` (retried by default); **X** = `Cause.Terminal` (never retried); **U** = unclassified (retried only under `NON_TERMINAL`).
