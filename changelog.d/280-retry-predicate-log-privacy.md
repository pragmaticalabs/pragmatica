### Fixed (2026-09-14 — #280: retry was idempotency-blind, logging leaked request/result content, metrics flags were ignored)
- **R26 — the retry interceptor retried every failure.** `RetryMethodInterceptor` handed each call to core `Retry`, which stops only on `Cause.Terminal`; a slice's own business verdict (`InsufficientFunds`) is unclassified and was re-driven as eagerly as a timeout, on methods that may not be idempotent. The interceptor cannot tell a business failure from an infrastructure one by origin, so retry is now **opt-in by classification**: core gains `Cause.Transient` (`isTransient()`, the mirror of `Cause.Terminal`), and `RetryConfig` gains `retry_on` — `TRANSIENT` (default: only a cause that declares itself transient is retried; an unclassified failure is returned after the first attempt) or `NON_TERMINAL` (the behaviour before this change, for a method whose failures are all infrastructural but not yet classified). A refused cause is returned WITHOUT entering `Retry`, so a business failure is neither re-driven nor logged as a retry giving up. `max_attempts` counts calls at the method, the first included. [verified: `RetryInterceptorPredicateTest` (`aether/resource/interceptors`) — unclassified failure: 1 attempt under the default (was 3, red at the base), original cause returned; `Cause.Transient` failure: 3 attempts; `NON_TERMINAL` opt-in retries the unclassified failure; a budget of 1 makes no retry; transient-then-success returns the success. Mutations: widening `TRANSIENT` to non-terminal reddens the unclassified pin; dropping the remaining-budget guard reddens the budget-of-1 pin] [verified: `RetryConfigTomlBindingTest#config_retryOn_bindsFromToml`, `#config_omittedRetryOn_fallsBackToTransient`]
- **Behaviour change, stated:** a retry-intercepted method whose failures are unclassified is no longer retried. Set `retry_on = "NON_TERMINAL"` on that section to keep the old behaviour, or classify the cause (`implements Cause.Transient`). `RetryConfigTomlBindingTest`'s end-to-end fixture failed with a generic cause whose MESSAGE said "transient" and whose type said nothing; it now implements `Cause.Transient` — the fixture said what the prose always claimed. No cause in this repository is marked transient yet; that classification pass (SMTP/HTTP timeouts and refusals, `ResourceCapacityExhausted`) is a follow-up and is named in the report.
- `jbct-lint`'s `CauseHierarchies` recognises `Cause.Transient` as a mixin alongside `Terminal`/`Wrapped`, so a record `implements X, Cause.Transient` is a cause variant to the linter. [mechanism: one-word widening of `QUALIFIED_MIXIN`; `jbct-lint` 786 tests green]
- **R28 — logging.** `LogConfig.logConfig(name[, level])` defaulted `logArgs`/`logResult` to `true`, logging every request's and result's `toString()` unredacted; both now default to `false` (the TOML binder treats every field as mandatory, so this reaches programmatic callers). Every injection point logged through one logger named `LoggingMethodInterceptor`; each now logs through `LoggerFactory.getLogger(config.name())`, so one method's level is tunable. [verified: `LoggingInterceptorPrivacyTest` — defaults, and the logger's name equals the configured name (read reflectively, red at the base with the class name); reverting `LogConfig` reddens the two default pins, reverting the interceptor reddens the logger pin]
- **R28 — correlation gap, noted not fixed:** the interceptor chain runs below `InvocationContext` (`aether-invoke`, which `resource-interceptors` cannot depend on), so entry/exit lines carry no request-id. Stated in `resource-reference.md`. [design intent — unverified]
- **R28 — `MetricsConfig.recordTiming` / `recordCounts` were bound and ignored** (a timer always, a counter never). `record_timing` now selects the timer `<name>.<outcome>` and `record_counts` a counter `<name>.<outcome>.count` — a separate meter name because Micrometer refuses two meter types under one id. [verified: `MetricsInterceptorFlagsTest` — timing off records no timer; counts on records a counter of 1; timing on / counts off records only the timer; reverting the interceptor reddens the first two]
- **R27 — NOT in this change and stated as left:** circuit-breaker and rate-limit metrics are a feature (owner: "Deferred post-GA: retry metrics"); the per-node scope of the rate limiter is already documented in the RateGuard section.
- `resource-reference.md`: `retry_on` row and example; `max_attempts` says "the first included"; `log_args`/`log_result` rows say the content is unredacted and personal until proven otherwise; `record_counts` names its meter.
