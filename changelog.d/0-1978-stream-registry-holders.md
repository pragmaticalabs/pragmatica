### Fixed (2026-10-29 — #1978, #2160: stream references were a shared count that lost and leaked references)
- **Two nodes acquiring the same stream at once lost a reference, and a crashed holder's reference was never dropped** (#1978, #2160). The registry kept one absolute count per stream, so concurrent acquirers overwrote each other, a release could remove an entry another holder still needed, and a recovery re-drive left one reference too many. A reference is now one key per holder, `(stream, node, artifact, attempt)`: acquire puts its own key, release removes only that key, the count is the number of keys, and a node that leaves membership has its slice keys removed by a sweep: on the departure edge of a core (`NodeRemoved`) or a worker (`WorkerLeaveDecision`), and by the leader's level reconcile when a node still holding was absent on two passes 30 s apart. Operator and framework registrations are cluster-owned and never swept. Every removal is witnessed by the value it read and a re-acquire writes the key's next version, so a late release or a lagging sweep cannot remove a reference taken again; an acquire over a holder-less record writes its own template, so a deleted stream's metadata does not come back. Both deployment engines build the same holder keys (the legacy node FSM and the FSM2 slice-leg builders). Flag day (pre-GA, no bridge): two new KV types with hand-assigned wire tags (2191, 2192; the holder value carries its acquire time and version); a cluster upgraded in place does not carry the old counts over, so a registered stream has no holder until it is registered again and is listed as absent.
