### Fixed (2026-10-29 — #1978, #2160: stream references were a shared count that lost and leaked references)
- **Two nodes acquiring the same stream at once lost a reference, and a crashed holder's reference was never dropped** (#1978, #2160). The registry kept one absolute count per stream, so concurrent acquirers overwrote each other, a release could remove an entry another holder still needed, and a recovery re-drive left one reference too many. A reference is now one key per holder, `(stream, node, artifact, attempt)`: acquire puts its own key, release removes only that key, the count is the number of keys, and a node that leaves committed membership has its keys removed by a sweep. Flag day (pre-GA, no bridge): two new KV types with hand-assigned wire tags (2191, 2192); a cluster upgraded in place does not carry the old counts over, so a registered stream has no holder until it is registered again and is listed as absent. [verified: `KvBackedStreamRegistryHoldersTest`, `StreamRegistrySweepWiringTest`, `WireAssignmentTripwireTest`]
