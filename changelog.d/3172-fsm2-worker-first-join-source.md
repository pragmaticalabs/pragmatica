### Fixed (2026-11-13 — #3172: FSM2 placed a worker's first join in a stray `default` community)
- **A worker's first join could be placed in `default-w-0`, which is sticky.** The cluster FSM read the member source from the seam snapshot, and the sample taken behind the join can be coalesced past it by the mailbox (`offerCoalescing` moves the newest sample to the tail). `WorkerJoin` now carries the source read at enqueue time from the descriptor the seam poller samples, on both the admission and the placement-record re-drive routes, and the handler overlays it on the snapshot before placement; a blank or absent source never replaces a snapshot value. [verified: `WorkerJoinSourceTest`, `WorkerJoinSourceOverlayTest`]
- A join with no source anywhere is still placed in `default-w-0`; an enabled tripwire test pins that. [verified: `WorkerJoinSourceOverlayTest`]
