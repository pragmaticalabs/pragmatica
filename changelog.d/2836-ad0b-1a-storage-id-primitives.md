### Added (2026-11-20 — #2836: storage identity primitives in the storage module)
- **Snapshots carry the id of the storage that wrote them, and a restore refuses a foreign one.** `SnapshotConfig` takes an optional `storageId` (`withStorageId`); a snapshot written with one gets a `storageId=` header line (outside the hashed body, format stays 2), and `restoreFromLatest` fails with `SnapshotError.StorageIdMismatch` when the chosen snapshot names a different id, without falling back to an older file on the same volume. A snapshot with no id, or a configuration with none, restores as before. Nothing sets an id yet, so behaviour is unchanged until the identity step supplies one. [verified: `StorageIdentityPrimitivesTest$Header`, `StorageIdentityPrimitivesTest$Restore`]
- **`openLog` refuses the storage's own file names.** A log name whose first `/`-segment is `STORAGE_ID`, `CLAIM`, `LOCK` or `aside` fails with `StorageError.ReservedLogName`; stream log names such as `aside@1/0` stay legal. [verified: `StorageIdentityPrimitivesTest$ReservedLogNames`]
- A failing block write or directory force fails the durable `put` and leaves no lifecycle record. [verified: `StorageIdentityPrimitivesTest$DurablePut`]
