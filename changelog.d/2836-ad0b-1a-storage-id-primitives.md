### Added (2026-11-20 — #2836: storage identity primitives in the storage module)
- **Snapshots carry the id of the storage that wrote them, and a restore refuses a foreign one.** `SnapshotConfig` takes an optional `storageId` (`withStorageId`, which now returns `Result<SnapshotConfig>` and refuses an id that is empty, holds a control character or is not valid UTF-8 with `SnapshotError.InvalidStorageId`); a snapshot written with one gets a `storageId=` header line (outside the hashed body), and `restoreFromLatest` fails with `SnapshotError.StorageIdMismatch` when the chosen snapshot names a different id, without falling back to an older file on the same volume. The parser applies the same id rule. A snapshot with no id, or a configuration with none, restores as before. Nothing sets an id yet, so behaviour is unchanged until the identity step supplies one. [verified: `StorageIdentityPrimitivesTest$Header`, `$Restore`, `$StampLineIntegrity`]
- **Format boundary: a stamped snapshot is `format=3`, an unstamped one stays `format=2`.** `format=3` REQUIRES the `storageId` line: a file whose line was removed or whose key was corrupted is refused (restore reports `NothingRestorable`, the cause is logged as `StorageIdMissing`) instead of restoring as unstamped. `format=2` and the unversioned layout never required it and still restore as unstamped. A build without this change refuses `format=3` and falls back to an older retained file; pre-GA, rollback is unsupported. The write-time read-back now compares the id and the format too. [verified: `StorageIdentityPrimitivesTest$FormatBoundary`, `$StampLineIntegrity`]
- **`openLog` takes one grammar and refuses the storage's own file names.** A log name is accepted only if its `/`-separated segments each start with a letter, digit, `_` or `-` and continue with those, `.`, `@` or `:` (ASCII only, no `.` or `..` segment, no empty segment, backslash or whitespace), else `StorageError.InvalidLogName`. Only then is its first segment compared, case-insensitively, with `STORAGE_ID`, `CLAIM`, `LOCK` and `aside`, else `StorageError.ReservedLogName`; stream log names such as `aside@1/0` and `topic:orders/0` stay legal. [verified: `StorageIdentityPrimitivesTest$ReservedLogNames`]
- A failing block write or directory force fails the durable `put` and leaves no lifecycle record. [verified: `StorageIdentityPrimitivesTest$DurablePut`]
