### Added (2026-11-14 — #2895: HS256 JwtSigner for issuing login tokens)
- **`JwtSigner` issues HS256 tokens the #2880 verifier accepts** (#2895). It is built from the same `JwtConfig` the verifier reads (shared secret, issuer, audience) and refuses JWKS mode or a missing secret. `sign(JwtClaims)` yields a compact JWS with `sub`, `iat`, `exp`, and `iss`/`aud` when configured, plus the caller's extra claims; extras may not set registered claims. The MAC is the verifier's own HMAC-SHA256 primitive. Tokens are not revocable: valid until `exp`, and there is no revocation list. The signer holds one secret and writes no `kid`, so there is no key rotation: changing the secret invalidates every issued token at once. Lifetime is bounded (ten years) and every failure is a typed `SecurityError`; `JwtSigner` is an interface and the only way to get one is `jwtSigner(...)`, which refuses JWKS mode, a missing secret and a secret under 32 bytes. [verified: `JwtSignerTest` round-trips through the real `JwtSecurityValidator`: a different secret, an expired token, a wrong `iss` or `aud` are refused]
