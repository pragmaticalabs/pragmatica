### Fixed (2026-10-18 — #2257: storage metadata snapshot does not escape ref names)
- **A content or consumer-group name containing `=`, `|`, a newline or a leading `#`, or an empty name, made the snapshot it landed in unrestorable** (or silently dropped the name), and once every retained snapshot held such a name the node refused to boot. The streams instance snapshots on every seal, so the retained files turned over within minutes.
- Snapshots are now written as `format=2`: ref names are percent-encoded (UTF-8 bytes as `%XX`, a lone surrogate as `%uXXXX`), so every name round-trips, including the empty one. The integrity hash covers the epoch, every lifecycle line and every ref line (name and target) exactly as written, with delimiters.
- A snapshot is parsed back through the restore path before its file is committed; one that does not read back equal is refused at write time with an ERROR log, and the previous snapshot and `LATEST` stay in place.
- Files written before this change (no `format` header) are still restored and verified under the old hash, so an existing node is not bricked; new writes are always `format=2`. The old layout keeps its limits: a file that lost a name stays unrestorable and restore falls back to the next retained file. `[verified: integrations/storage SnapshotNameEscapingTest, SnapshotNameCodecTest]`
