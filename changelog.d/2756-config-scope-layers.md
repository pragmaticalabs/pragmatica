### Fixed (2026-11-24 — #2756: removing a node-scoped config value dropped the cluster-wide one)
- **`DynamicConfigManager` kept one overlay entry per dotted key for both scopes**, so removing this node's override also removed the cluster-wide value from the overlay, and a cluster-wide put after a node-scoped put overwrote the override (at load, `KVStore.snapshot()` iteration order decided). The two scopes are now separate layers: the overlay holds the node-scoped value if present, else the cluster-wide one, and a remove clears only its own layer. `[verified: DynamicConfigManagerScopeLayersTest, 12 cases incl. both load orders]`
