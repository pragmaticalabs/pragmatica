### Fixed (config)
- A reloaded configuration provider no longer loses secret resolution. `SecretResolvingConfigurationProvider.reload()` returned the delegate's new provider undecorated, so reading it served raw `${secrets:...}` placeholders. The reload now re-resolves with the same resolver: a rotated secret is observed, repeated reloads keep the decorator, and a resolution failure fails the reload naming the key and secret path, never the value (#1326).
- Sibling: `DynamicConfigurationProvider.reload()` reloaded its base, discarded the result and returned `this`, so the returned provider still read the pre-reload base (and a secret-resolving provider over it re-resolved stale content). It now returns a provider over the reloaded base that shares the live overlay, so a write through either instance is visible through both. A reloaded source that is not a `ConfigurationProvider` is wrapped as one before its secrets are resolved (#1326).
