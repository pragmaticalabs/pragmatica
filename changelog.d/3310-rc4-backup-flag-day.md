### Changed (2026-11-17 — #3310: rc4 backups are not restorable into rc5)
- **Breaking: a backup written by rc4 does not restore into rc5.** Every rc4 backup holds stream-configuration records (`RetentionPolicy` wire tag 712 expected, 17 carried) and, when auto-heal is configured, an auto-heal state record whose layouts rc5 does not decode, so a restore under `[backup] restore = "auto"` ends in `backup-restore-blocked` at the step `document undecodable`. Flag day (pre-GA, no users): no legacy-shape decoders are added and no fixed build is offered for this case. `restore = "fresh"` remains the way to start an rc5 cluster at an rc4 site; it abandons the rc4 backup. The blocked-restore warning now says, on the decode step only, "The backup holds a record this release cannot decode; a backup written by an incompatible release (a backup written by rc4 read by rc5 is one) is one known cause, a damaged backup is another." The backup runbook has a "Backups across releases" section.
