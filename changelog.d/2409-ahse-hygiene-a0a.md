### Changed (2026-10-24 — #2409: AHSE hygiene, manifest framing, GC placement, block size)
- **Manifests are binary and versioned, and name nothing.** The content store's chunk manifest is now a version byte, the chunk size, the total size, the SHA-256 of the whole content and the chunk ids, inside the store's own envelope; the object name is no longer embedded, so no name needs escaping. A manifest is recognised only by the ref and envelope kind the store itself wrote, never by content, so a direct upload whose bytes are a valid manifest of any format reads back verbatim. Manifests written by an earlier 1.0.0-rc5 development build (name-prefixed) are refused as unreadable rather than guessed at, and deleting or overwriting such a name does not release its chunks (pre-GA, earlier development builds only); a rollback to a build from before this change cannot read manifests written after it (`MANIFEST_PARSE_FAILED`); the pre-envelope text format is still read for names stored before the trusted namespace existed. [verified: `ContentStoreManifestFramingTest`, `ContentStoreTest`]
- **Garbage collection of `content` and `artifacts` is no longer leader-pinned.** Local refcount GC deletes only from the node's own tiers, so every node now reclaims its own orphaned blocks after the grace period once it reports ready, whether or not it ever led. Leader election and demotion no longer start or stop it. [verified: `StorageMaintenanceWiringTest`]
- **A storage instance refuses a block over its maximum size** with `BlockTooLarge`, before claiming or writing anything, on `put`, `putRef` and `swapRef`. The limit is per instance, `[storage.<name>] max_block_bytes` (a positive integer, 16 MiB by default); the `streams` instance keeps no cap. A `ContentStore` whose `chunkSizeBytes` would make blocks over its instance's limit (the chunk plus 7 bytes of envelope, more when compressed) is refused when it is provisioned, naming both values, and so is a `chunkSizeBytes` below 1; the default 4 MiB chunk is unaffected. A manifest whose stored chunk id length is negative or runs past the bytes it holds is refused as unreadable (`MANIFEST_PARSE_FAILED`) without allocating that length. [verified: `StorageInstanceMaxBlockSizeTest`, `ContentStoreConfigBlockLimitTest`, `ContentStoreFactoryTest`, `ConfigLoaderTest`]
- **`StorageInstance.put(content, BlockMetadata)` is removed**, with `BlockMetadata` and the unused `StorageBlock`: the parameter was ignored.
