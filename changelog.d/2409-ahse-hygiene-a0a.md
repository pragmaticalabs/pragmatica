### Changed (2026-10-24 — #2409: AHSE hygiene, manifest framing, GC placement, block size)
- **Manifests are binary and versioned, and name nothing.** The content store's chunk manifest is now a version byte, the total size and the chunk ids, inside the store's own envelope; the object name is no longer embedded, so no name needs escaping. A manifest is recognised only by the ref and envelope kind the store itself wrote, never by content, so a direct upload whose bytes are a valid manifest of any format reads back verbatim. Manifests written by an earlier 1.0.0-rc5 development build (name-prefixed) are refused as unreadable rather than guessed at; the pre-envelope text format is still read for names stored before the trusted namespace existed. [verified: `ContentStoreManifestFramingTest`, `ContentStoreTest`]
- **Garbage collection of `content` and `artifacts` is no longer leader-pinned.** Local refcount GC deletes only from the node's own tiers, so every node now reclaims its own orphaned blocks after the grace period once it reports ready, whether or not it ever led. Leader election and demotion no longer start or stop it. [verified: `StorageMaintenanceWiringTest`]
- **A storage instance refuses a block over its maximum size** (16 MiB by default) with `BlockTooLarge`, before claiming or writing anything, on `put`, `putRef` and `swapRef`. The `streams` instance keeps no cap. [verified: `StorageInstanceMaxBlockSizeTest`]
- **`StorageInstance.put(content, BlockMetadata)` is removed**, with `BlockMetadata` and the unused `StorageBlock`: the parameter was ignored.
