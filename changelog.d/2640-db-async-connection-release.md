### Fixed (2026-11-08 — #2640: db-async transactional and batch never returned their pooled connection)
- **`PgAsyncSqlConnector.transactional` and `batch` borrowed a pooled connection and never closed it**, so a pool of N was exhausted by N transactions and every later request waited forever. Both now return the connection on every exit (success, callback failure, commit failure, a throwing callback); the callback's own cause is what the caller sees. `subscribe` returns its connection when the subscribe fails and when the subscription is unlistened. `pinned` was already correct (it closes its dedicated connection). `[verified: aether/resource/db-async/src/test/java/org/pragmatica/aether/resource/db/async/PgAsyncSqlConnectorConnectionReleaseTest.java]` `[mechanism: PgConnection.close() runs the pool's onRelease; commit and rollback do not release]`
- Limit: a subscription whose `unlisten` fails keeps its connection (it is still listening); the connection is not handed to another borrower.
