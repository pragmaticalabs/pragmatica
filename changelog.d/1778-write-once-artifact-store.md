### Changed (2026-10-02 — #1778: the built-in artifact store is write-once, takes no SNAPSHOT, and archives instead of deleting)
- **A coordinate in the built-in artifact store is written once, compared by content.** `PUT /repository/...` of IDENTICAL content (size, MD5 and SHA-1) is idempotent (`200`, `"status":"already-present"`, nothing uploaded or rewritten; it also re-asserts the file and version registrations, so a first deploy that died between the metadata write and the list writes completes on retry). `PUT` of DIFFERENT content to a stored coordinate was answered `already-present` while silently keeping the old bytes; it is now refused with `409` naming the stored and the offered SHA-1, and the stored content is kept. The existence check is unchanged in one respect that matters: a failed check never deploys (`503` + `Retry-After` when transient, #1795). `[verified: ArtifactStoreWriteOnceTest, MavenProtocolHandlerWriteOnceTest — each pin reddens when its hunk is reverted (conflict check reverted: 3 red; failed check treated as absent: 1 red; re-assertion removed: 1 red)]`
- **`-SNAPSHOT` versions are refused (`400`) by the built-in store**, for every file including Maven's timestamped names, before anything is written. SNAPSHOTs stay available in development and Forge through the Local repository. **This breaks the documented scaffold flow:** `jbct init` generates `deploy-test.sh`/`deploy-prod.sh` that `aether artifacts push …:1.0.0-SNAPSHOT`, and the project's own default version is `1.0.0-SNAPSHOT`; a cluster deploy now needs a release version (docs updated in `getting-started.md`). The generated scripts themselves are NOT changed here. `[verified: ArtifactStoreWriteOnceTest#NoSnapshot, MavenProtocolHandlerWriteOnceTest, MavenFileRoundTripTest#timestampedSnapshotDeploy_isRefusedForEveryFile_andStoresNothing — SNAPSHOT check reverted: 3 red]`
- **Nothing in the store is ever removed or rewritten.** `ArtifactStore.delete` is gone; the metadata key and the new archive marker are written once, and the versions list and file list are grow-only sets (an entry can be added or flagged archived, never dropped or un-flagged). Rewrites of a list key on one node are serialized, so concurrent publishes through one node never lose a version. `[verified: ArtifactStoreWriteOnceTest#GrowOnlyVersions, #GrowOnlySetTests, #NeverResurrected.store_neverRemovesOrRewritesAKey_acrossDeployArchiveAndRedeploy — sequencing removed: 2 red; flag-clearing add: 1 red; merge as overwrite: 2 red]`
- **`GET maven-metadata.xml` lists only versions that are stored and not archived**; the Forge `PUT /api/repository` route now reports a refused push (`400`/`409`) as a failure instead of "Deployed". `[verified: MavenProtocolHandlerWriteOnceTest, DeploymentRoutesRepositoryPutTest — Forge status check reverted: 2 red]`
