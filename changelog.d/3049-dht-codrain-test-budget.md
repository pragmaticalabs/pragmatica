### Fixed (2026-11-11 — #3049: DHTDepartureStaleDrainSetTest lost 16 last copies once)
- **Test-only flake: the co-drain harness pushed with a 50 ms wall-clock budget.** `DeparturePushRun` abandons a page whose window ended before its first send, so a host stall past 50 ms lost a page; production uses `DeparturePushTuning.DEFAULT` (10 s base, 5 s sole extra) and reports an abandoned sole copy as data at risk. The harness now uses a 30 s budget and routes held messages under one monitor (a resend sent during the flush could be orphaned). No production code changed.
