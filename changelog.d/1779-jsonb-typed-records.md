### Changed (2026-10-24 — #2401: infer the json/jsonb document mapping from the schema; refuse String binds to json/jsonb)
- **No `@Jsonb` where the schema knows the column.** A record or enum, or `Option` of one, without a `ValueMapping` is read and written as a JSON document (an enum as its JSON string) where the schema knows its column is `json`/`jsonb`: CRUD row-record components and condition parameters, components of a record expanded into `VALUES (:record)` / `SET :record`, and `@Query` parameters paired with the column. Pairing reads the statement's syntax tree: the n-th value of every `VALUES` row of an `INSERT` that names its columns, `SET` items (in `UPDATE` and `ON CONFLICT .. DO UPDATE`), and comparisons with a column (`=`, `<>`, `<`, `>`, `IN (..)`, `LIKE`, `BETWEEN`, `IS DISTINCT FROM`). Comments, whitespace and letter case never change a pairing: unquoted identifiers fold to lower case, quoted ones keep theirs, and the table is the statement's own target, never a table named in a tail. A cast parameter is not inferred. **An insert that names its columns no longer expands a record parameter:** `INSERT INTO t (c) VALUES (:p)` with a record `p` binds `p` as one value (a document on a `json`/`jsonb` column) instead of rewriting the statement into a second column list, which could only fail to parse; `INSERT INTO t VALUES (:record)` still expands. `@Jsonb` stays required for `@Query` results, a record parameter bound whole, and parameters the tree does not pair (`@>` operands, function arguments, other expressions). `[verified: aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/JsonbMappingTest.java, aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/JsonbPostgresRoundTripTest.java]`
- **`String` binds to json/jsonb are compile errors.** A `String` is sent as `varchar`, which `json`/`jsonb` refuse unless the driver reuses a statement prepared for the same SQL with an untyped parameter (fixed separately in #2402). A `String` paired with a known `json`/`jsonb` column, or a CRUD insert/save value or condition on one, is refused unless the SQL casts it (`:doc::jsonb`, `CAST(:doc AS jsonb)`). A `String` with an occurrence that is neither paired nor cast, in an `INSERT`, `UPDATE` or `DELETE` whose target table has a `json`/`jsonb` column, is refused too, even when it is meant for a text column (`INSERT .. SELECT :p`, `lower(:p)`, `:p || :q`, `INSERT INTO t VALUES (..)` without a column list); cast it or compare it with its column. A `SELECT` is not checked this way. A parameter inferred as a document that is also paired with a non-json column is refused. `String` reads stay allowed. **Breaking:** an interface that binds a `String` this way no longer compiles. The `comprehensive-persistence` and `pg-showcase` examples did, and now map their jsonb columns to records. `[verified: JsonbMappingTest.java]`
### Added (2026-10-23 — #1779: map jsonb/json columns to typed records in the async Postgres path)
- **`@Jsonb` maps a `json`/`jsonb` column to a record.** Put it on a row-record component, a `@Query` method (its single result column) or a parameter. The generated factory encodes and decodes the document with a codec generated at compile time by the same generator the slice router uses for HTTP bodies. It uses no reflection and no Jackson, and its defaults are fixed: deploy-time JSON settings never change stored documents. The holder is `<Interface>JsonCodecs`, beside the factory. `[verified: aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/JsonbPostgresRoundTripTest.java, aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/JsonbMappingTest.java]`
- **`JsonText` binds to `json` and `jsonb` alike.** The async connectors register one text converter. A `JsonText` parameter has no declared type, so the server types it from the column or operator (`@>`). A `String` parameter is declared `varchar`: a `jsonb` column refuses it when the statement is prepared fresh, but accepts it when the connection reuses a statement prepared earlier for the same SQL with an untyped parameter, so neither outcome can be relied on; where the schema knows the column, the code generator now refuses such a bind at compile time (#2401, above). `[verified: aether/resource/db-async/src/test/java/org/pragmatica/aether/resource/db/async/JsonTextConverterTest.java, JsonbPostgresRoundTripTest.java]`
- **Nullable columns as `Option<T>`.** An `Option<T>` row component reads SQL `NULL` as empty through the new `RowAccessor.getOptional`. Before, such a component was a compile error. An `Option<T>` parameter binds empty as `NULL`. `T` is a column type, a value object or a `@Jsonb` document. `[verified: JsonbMappingTest.java, JsonbPostgresRoundTripTest.java, aether/slice-testkit/src/test/java/org/pragmatica/aether/testkit/fake/MapRowAccessorTest.java]`
- **Compile-time checks.** A `@Jsonb` type the codec generator cannot handle fails the build with the generator's reason. The escape hatch is a hand-written `ValueMapping<T, JsonText>`. A `@Jsonb` target whose known column (CRUD table, `WHERE column = :param`) is not `json`/`jsonb` also fails the build. `[verified: JsonbMappingTest.java]`
