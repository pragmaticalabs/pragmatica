### Fixed (2026-11-08 — #2868: FSM2 never removed a departed seed core's rows)
- **FSM2 classes a directive-less seed core as a core** (#2868). A seed core never receives an activation directive, and the live membership views that otherwise mark it a core drop it when it departs. When its `NodeRemoved` edge arrived while the new leader's cluster FSM was still Dormant (and was dropped), the absence backstop classed the node an unassigned worker, which is unjudgeable without community rosters, so no inferred departure was recorded and its slice rows stayed. The cluster FSM settings now carry the configured core nodes (`seedCores`, read only by the absence class); the J5 seed skip (`seedNodes`) is unchanged. A departed seed core is now judged absent against the core view and recorded STALE after `B_rm`, and C17b removes its rows. [verified: `BackstopTest` seed-core cases, `Fsm2DerivationsTest` seed-core wiring pin]
