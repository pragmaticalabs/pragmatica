### Fixed (2026-11-21 — #3557: MembershipFsm per-member timers outlived the node)
- **A stopped node left its membership timers firing.** `MembershipFsm` had no `close()`, so the join grace, the eviction backstop, the DEPARTING timeout and the rejoin re-offer of every tracked member stayed armed on the JVM-wide `SharedScheduler`; a join-grace deferral re-armed itself every window with no cap, and in a shared test JVM the timers of earlier classes kept logging `Join-grace reaper DEFERRED ... re-arming` for over 30 minutes.
- `MembershipFsm#close()` cancels all four timer kinds for every tracked member, and the node's stop path calls it. A task that was already running when the close happened is a no-op, because each task reads the member's closed flag first (`cancel(false)` cannot stop a running task), and a member first observed after the close arms nothing. The rejoin re-offer now keeps its handle so it can be cancelled. `[verified: aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/membership/fsm/MembershipFsmCloseTest.java]` `[verified: aether/node/src/test/java/org/pragmatica/aether/node/deployment/StopSequencePinTest.java]`
