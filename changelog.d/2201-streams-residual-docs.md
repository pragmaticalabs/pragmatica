### Changed (2026-10-18 — #2201: residual streams documentation and javadoc corrected to match the code)
- **`guarantees.md` no longer cites a `clampedToHead` that does not exist.** A consumer whose stored cursor is above the partition head after a restart without a WAL is not clamped to the head: the owner answers a cursor of a replaced lineage with `EpochDiverged(resumeAt)`, the offset where the new epoch began, and the consumer re-reads from there, so the new records at those offsets are delivered. The no-WAL loss window is stated as the events acked since the last completed seal. `[mechanism: ConsumerRuntimeState.rewind, EpochValidation.admit; pinned by NoWalRestartConsumerRedeliveryTest]`
- **`publish(msg, idempotencyKey)` stamps an identity; the log does not deduplicate.** The `Publisher` and `MessageContext` javadoc and the `DurableTopicPublisher` blank-key message no longer say the key is what deduplication matches on, and the stale "messageId is not yet delivered to subscribers" note is gone: a subscriber that declares the context-carrying handler shape receives the message ID and deduplicates itself. The blank-key failure message changed text; no code matches on it.
- **`known-limitations.md` and `14-consistency-and-partitions.md` no longer describe code that was replaced.** The streaming substrate is not all-RAM (WAL, sealing to segment tiers, sealed-tier retention); a blueprint's inert stream keys are refused per alias at deploy, not discarded with an empty binding set (#1336); declarative consumers resume from a consensus-KV checkpoint; durable-entity create, update and delete are wired.
- **Correction to an earlier changelog entry** (that entry is history and stays as published): the Phase 1 "Segment compression" and "Segment encryption" entries say they are "Configured per stream via `StreamConfig.compression` / `encryptionKeyId`". Neither per-stream key reaches the segment write path: the deploy validator reads both, and refuses a non-default value naming the key (`StreamResourceValidator.guardStreamConfig`); segments are written uncompressed. The timers and exactly-once corrections are already carried in the entry of 2026-10-15 (#2201).
- **Stale "all-RAM" and "lagging consumer stalls" text removed.** Feature-catalog rows 179, 180, 181, 190 and the summary row no longer say the cold tier is never populated or that STRONG creation fails on a NOOP eviction listener; `known-limitations.md` drops the "lagging consumer stalls on `CursorExpired`" limit and `guarantees.md` states that the declarative-consumer runtime reads the sealed tier (PR-0a, #2201 C-16).
