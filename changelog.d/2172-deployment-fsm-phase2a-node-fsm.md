### Added (2026-10-12 — #2172: deployment state machine rewrite, phase 2a: the pure node FSM)
- **A pure node deployment FSM**, `NodeFsm.step(model, input) -> (model', effects)`, in the new package `org.pragmatica.aether.deployment.node.machine` (module `aether-deployment`), beside the old `NodeDeploymentState`. It implements spec section 3.4: the Dormant and Active outer states, the Rebuild with the own-row incarnation sweep (N0), the transition table N1 to N19, the version-fenced observed writes with their retry and FAILED cycles, the tombstone Remove, the last-replica guards and the re-drive rule (R-6.0). Effects are data (`Submit`, `Route`, `Warn`, `Log`, `Schedule`, `Cancel`, `Metric`, `LocalOp`); the wall clock is injected and every timer, write and local step carries the FSM incarnation, so a stale one is dropped.
- Nothing calls it: the old node FSM, `NodeArtifactKey` and its readers are untouched and no `AetherNode` wiring changes, so this phase changes no behaviour. [mechanism: no production caller of `NodeFsm`]
- The node-side rows of the spec's new-test table (NT-44 to NT-78 and the node halves of NT-87, NT-93, NT-97, NT-104, NT-109, NT-112 and NT-123) are asserted on the pure step function, with the real `KVStore` applier behind the node's observed key and a real `BootTokens` registry for every incarnation arm. [verified: `aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/node/machine/NodeFsm*Test.java`]
