### Added (#280 R27 — circuit breaker and rate limit interceptors are metered)
- **`[circuit-breaker.*]` and `[rate-limit.*]` now emit Micrometer meters** tagged `slice` and `section`: `aether.interceptor.circuit_breaker.state` (gauge), `.transitions` (counter, `from`/`to`, counted by the breaker itself at every change), `.rejected`; `aether.interceptor.rate_limit.admitted` and `.rejected`. A node without a registry, or a call path without slice attribution, provisions the interceptor without meters. The meters are removed when the slice unloads, so a redeploy leaves one set bound to the live instance. Scope is per node: a cluster of N nodes admits `max_requests x N` calls per window.
- **New `ResourceSection` provisioning-context extension** (resource-api): a per-slice factory can read the section it is provisioned for. The node-shared pool path (#2973) never carries it.
- **`CircuitBreaker` reports its state changes** (core): `CircuitBreaker.StateListener` and a builder overload `timeSource(TimeSource, StateListener)` / factory overload take a listener called once per state change; the existing builder chain and factory behave as before.
