### Changed (2026-11-20 — #420: the artifact-content binding carries a block manifest; flag day, whole-cluster restart)
- **Breaking: `ArtifactContentValue` gains a `blocks` manifest and moves to wire tag 2990** (#420). The record carries one `byte[]` of 32 bytes per 64 KiB chunk, the raw SHA-256 block ids in chunk order, and compares it by content (`equals`, `hashCode` and `toString` over the array; the array is copied on construction and on access), so a state transfer does not re-deliver every binding as a changed value. Tag 2118 is retired. A node of an older build fails the new value on the unknown tag instead of decoding it and dropping the tail. Flag day (pre-GA, no users): a mixed cluster is unsupported, no legacy decoder is kept, and the upgrade is a whole-cluster restart followed by a re-upload of artifacts.
- **A backup written before this change does not restore, and EVERY backed-up kind of state in it is abandoned, not only artifacts.** Its artifact lines carry tag 2118, so the document fails to decode as a whole: a restore under `[backup] restore = "auto"` is blocked (`backup-restore-blocked`, step `document undecodable`) and cluster-state writes stay refused (`RestorePending`) until a restore decision is committed. The operator step: (1) stop every node; (2) point `[backup]` path/remote at a new empty repository, or move the old backup branch aside (it stays in git history); (3) start with `restore = "fresh"`; (4) re-apply blueprints and config; (5) confirm the first flush writes. The other order does not work: `restore = "fresh"` against the OLD remote leaves the cluster serving but backing up nothing, because every flush decodes the old head, fails, and stops at `HEAD_UNREADABLE` (`BACKUP_REMOTE_UNREADABLE`), and `aether backup declare-genesis` is refused `HeadUnreadable` there. The backup runbook's "Backups across releases" section has the steps.
