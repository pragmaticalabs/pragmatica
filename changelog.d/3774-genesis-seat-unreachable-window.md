### Fixed (2026-11-26 — #3774: genesis-seat-unreachable named a healthy seat that was still connecting)
- **What was wrong:** the `genesis-seat-unreachable` warning was decided by one read of the connected peers at the genesis install. The seat whose report completed the agreement could still be mid-handshake there (its report arrived on its own link before this node's dial to it attached), so a healthy seat was named, sending the operator to a node that was fine; the engine retracted it about 150 ms later.
- The install now only records the unconnected seats as suspects. A suspect that connects, or leaves the roster, within the next two consecutive engine ticks (the same stall and idle-probe ticks that close the warning) is dropped without any warning; a seat still unconnected after them is named as before, so a seat that is dead from genesis is named within two ticks. Formation is not blocked. A seat that takes longer than those two ticks to attach is still named, and closes as before when it connects `[mechanism: RabiaEngine#confirmUnconnectedGenesisSeats]` `[verified: integrations/consensus/src/test/java/org/pragmatica/consensus/rabia/GenesisSeatUnreachableTest.java, aether/ember/src/test/java/org/pragmatica/aether/ember/EmberGenesisSeatUnreachableTest.java]`.
