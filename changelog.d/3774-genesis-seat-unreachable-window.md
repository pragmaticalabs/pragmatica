### Fixed (2026-11-26 — #3774: genesis-seat-unreachable named a healthy seat that was still connecting)
- **What was wrong:** the `genesis-seat-unreachable` warning was decided by one read of the connected peers at the genesis install. The seat whose report completed the agreement could still be mid-handshake there (its report arrived on its own link before this node's dial to it attached), so a healthy seat was named, sending the operator to a node that was fine; the engine retracted it about 150 ms later.
- The install now only records the unconnected seats as suspects and arms its own one-shot deadline, 5 seconds after the install (a guess, not a measurement: a seat that is only mid-handshake attaches in milliseconds). At the deadline each suspect is decided once, by a single read of the connected peers: connected, or left the roster, it is dropped without any warning; still unconnected, it is named. So a seat that is dead from genesis is named about 5 seconds after the install, whatever state the engine is in (it needs no activation, no phase and no tick), and never earlier; a seat that connects and drops again between the install and the deadline is judged by the deadline read alone. Formation is not blocked. A seat that needs longer than 5 seconds to attach is still named, and the warning closes when it connects, which the consensus ticks of an activated node check (an engine that installed genesis and never activates names the seat but does not close the warning).
