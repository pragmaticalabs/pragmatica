### Fixed (2026-11-12 — #1697: a restarted replica holding less could never lower the owner's replicated view)
- **The owner's per-replica ack view is now monotone only within one replica boot.** `ReplicateAck` carries the replica's boot token; within one owner epoch the registry keeps the max for acks of the same boot (and for token-less owner-side evidence), and replaces the row, a lower value included, when a different boot token arrives. A same-NodeId restart that holds less no longer leaves the view over-counting. [verified: `DefaultReplicationManagerAckOrderTest` (NT-144/145/145b), `ReplicationMessageCodecTest#replicateAck_roundTrips` (NT-146); 12 of 12 mutations red]
- **Wire flag day:** `ReplicateAck` (tag 100) gains a trailing `bootToken:long`. The codec is positional and there is no bridge (pre-GA): old and new nodes misdecode each other's acks, so upgrade by replacement.
- Documented residual: an ack from a superseded boot delivered after the new boot's ack replaces the view until the current boot's next ack replaces it back (tokens are unordered). Production restarts carry a new NodeId, so this concerns same-id Forge/Ember restarts only.
