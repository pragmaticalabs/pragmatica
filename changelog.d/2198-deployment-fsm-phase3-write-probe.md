### Added (2026-10-14 — #2198: deployment state machine rewrite, phase 3 tracer PR A: the write probe)
- **A dropped observed write is resubmitted within seconds, not at the 35 s attempt bound.** While a node's observed write is in flight, a `WRITE_PROBE` timer fires 2 s, 6 s and 14 s after each attempt's submission (at most 3 per attempt). A probe re-reads the applied mirror; if the row is absent it rebuilds the batch from the current mirror with the same builder steps (never replaying the batch built at first submission) and resubmits it at the same version under its own correlation, without consuming an attempt. `WRITE_CONFIRM` stays the give-up bound. Each resubmission and each `WRITE_CONFIRM` expiry emits a log line (`write-probe-resubmit` at INFO, `write-confirm-timeout` at WARN) and a `submissions_total` arm (`probe_resubmit`, `confirm_timeout`). A probe resubmission's own settlement is counted under `kind="observed_probe"` (same `outcome` values), so the `kind="observed"` arms stay the attempts' alone. Nothing is wired to the FSM yet: this changes no behaviour of a running cluster. **Named limit:** a batch stuck inside the consensus engine is not fixed, because the identical resubmission can merge into it.
  [verified: `aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/node/machine/NodeFsmWriteProbeTest.java`]
- `NodeFsmEffect.Submit` gains `probe` (0 for an attempt's own submission, the 1-based probe index for a probe resubmission); `NodeFsmTimings` gains the probe schedule; `NodeFsmTimings.from` is now the `nodeFsmTimings(DeploymentTimeouts, TimeSpan)` overload.
