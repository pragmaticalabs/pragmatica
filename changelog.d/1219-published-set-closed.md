### Fixed (2026-09-29 — #1211, #1219: the release skipped the resource artifacts that published modules depend on)
- **The resource family is published again.** `aether/resource/pom.xml` set `skipPublishing` in `<build><plugins>`, so all of its modules (including `resource-api`, `artifact-repo` and the db, http, interceptor and notification resources) inherited it. Meanwhile `node`, `aether-deployment`, `aether-metrics`, `aether-stream`, `aether-invoke`, `aether-storage`, `ember` and `pg-codegen` depend on them at compile scope: 18 unresolvable edges in the published set. The inherited skip is removed.
- **A new gate refuses an unclosed published set.** `tools/check-publish-closure.py` walks the reactor and requires every published module's in-reactor compile/runtime dependencies, and its parent pom, to publish too. It takes a dependency's managed scope when none is declared, treats an empty `<relativePath/>` as "no local parent" and accepts a local parent only if its artifactId matches, and checks every reactor module whatever its groupId. CI runs it on every PR: "examined 117 published module(s) and 361 in-reactor dependency edge(s): 0 violation(s)". [verified: `tools/test_publish_closure.py` — restoring the inherited skip turns the repository check red with 18 violations]
