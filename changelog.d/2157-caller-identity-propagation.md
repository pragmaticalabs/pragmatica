### Added (2026-11-09 — #2157: the caller's identity crosses slice-to-slice calls)
- **A slice method's `SecurityContext` parameter is the caller's identity on every hop.** At the edge the generated route takes it from the request the edge validated (`RequestSecurity.securityOf`), never from `SecurityContextHolder`, so an asynchronous step before the handler cannot lose it; across a slice-to-slice call the generated proxy carries the `SecurityContext` argument beside the payload as `InvokeRequest.caller`, and the receiving method gets it (a `Principal` beside it gets its principal). An unauthenticated caller travels as "no identity" and arrives as the anonymous context. [verified: `GeneratedCallerPropagationTest` in `slice-processor-tests`, `PrincipalPropagationTripwireTest` in `aether-invoke`]
- **Identity, never authorization.** No route security on the receiving node reads a propagated context. [mechanism: `InvocationHandler` binds nothing from `InvokeRequest.caller`; `SecurityContext.securityContext(Option<CallerIdentity>)` delivers an anonymous or foreign identity as the anonymous context]
- **Wire change (pre-GA, additive):** `InvokeRequest` gains a last component `caller: Option<SecurityContext>` under a new wire tag (644). Tag 642 keeps decoding the previous shape (`LegacyInvokeRequest`), as a request with no caller: an invocation from a node of the previous build during a rolling upgrade reaches a `SecurityContext` parameter as the anonymous context instead of failing to decode. A node of the previous build cannot read tag 644, so calls in that direction still fail until it is upgraded. [verified: `InvokeRequestWireCompatibilityTest` in `aether/node`, decoding the bytes the previous build wrote]
- `SecurityContext.toString()` no longer prints claim values.

### Fixed (2026-11-09 — #2157 review)
- **A slice-to-slice call with two or more payload parameters failed before it was sent** (`No codec registered` for the proxy's request record): the caller's generated proxy encoded the call as a record that no codec covered, so every such call failed, whether its parameters were `RequestHeaders` and a business record beside a `SecurityContext`, or a `Principal` beside a business record. The proxy's payload record is now a member of the generated factory, and the caller's codec writes it under the wire tag of the record the callee decodes it as, with the same components in the same order. [verified: `GeneratedCallerPropagationTest` in `slice-processor-tests`, through the real codecs and `DefaultSliceBridge`]
- A method that takes a `Principal` and no `SecurityContext` keeps the `Principal` in the payload on a slice-to-slice call.
