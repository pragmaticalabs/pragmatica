### Changed
- **FLAG DAY (pre-GA): the node ids of CLOUD nodes no longer embed the cluster** (owner ruling, G1). They are `aether-node-<ulid>` instead of `aether-<cluster>-node-<ulid>`, because the Hetzner server name `<cluster>-<nodeId>` already carries the cluster, and repeating it capped cluster names at 11 characters. The budget (validation rule PF-36, computed per configuration: cluster + 1 + the longest id the configured sources and roles can be given, at most 63) now allows a typical cluster name of **24** characters; `production-eu` (13) is 52 in total and passes. `[verified: aether/aether-config/src/test/java/org/pragmatica/aether/config/cluster/ClusterBootstrapConfigValidatorTest.java, aether/environment-integration/src/test/java/org/pragmatica/aether/environment/OperationIdTest.java]`
- Changed everywhere a cloud id is minted: auto-heal core replacements (`LeaderReconciler`) and node replacements (`NodeReplacementWiring`) by the SOURCE of the node being replaced (`ClusterTopologyManager.nodeIsCloudBacked`; a cluster with a Docker core and a cloud worker pool mints each pool its own shape), the ids `cluster apply` mints for cloud sources, and a cloud provider's self-minted id (`ProvisionContext.resolveNodeId`). **Docker is unchanged**: compose seeds, container names, `DockerCores`, `DockerComputeProvider` replacements and the apply path for Docker sources keep `aether-<cluster>-node-...`, because a container name is unique per Docker daemon and several clusters share one (RFC-0015).
- What an earlier rc5 cluster sees: nodes already running keep their ids (the id is opaque and found by the `aether-node-id` label); a replacement minted after the upgrade gets the new shape, so one cluster holds both shapes until each old node is replaced, which can be a long time (an old node keeps its id for as long as it runs). Nothing parses the cluster out of an id (`LeaderReconciler` reads only the trailing ULID), so both shapes work side by side. A replacement that reuses an operator-chosen old-shape id keeps it, so with a long cluster name its server name can exceed 63 and is refused typed before any create. A halted apply ledger written before the upgrade re-issues its recorded (old-shape) id: with a long cluster name that old id plus the cluster can exceed 63 and is refused typed before any create.
