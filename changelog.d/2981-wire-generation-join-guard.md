### Changed (2026-11-11 — #2981 step 6: wire-generation join guard; upgrade is stop-the-world)
- **Upgrade hazard: the fence/lease records change the consensus wire encoding, so a mixed-version cluster is not supported.** Stop every node, then start every node on the new build. An older node cannot decode the new lease keys/values or the four-field `EpochStart`, and fails at its first apply of one. `aether/upgrade.sh` now says so.
- **A new node refuses to start when a core member that has completed its handshake runs a LOWER wire generation** (`WIRE_GENERATION = 2`, advertised as the `wire-generation` Hello label; no label after handshake = generation 1). The error names the member and both generations. A member that has not handshaken is unknown, never older: the guard waits for it up to 10 s (`JOIN_GENERATION_WAIT`, a marked guess), then proceeds, deciding only over the members that did handshake; a cold start is never refused. It runs once per engine start in `handleClusterActive`, before the node's first sync, not through the activation-gate authorizer. [verified: `JoinGenerationGuardTest`, `RabiaEnginePreSyncCheckTest`]
- The guard protects only the NEW node: an old binary restarted into an upgraded cluster has no guard and is stopped only by the operator procedure.
