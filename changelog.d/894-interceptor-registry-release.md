### Fixed (2026-10-01 — #894: cache and idempotency interceptor factories never pruned their name-keyed registries)
- **`CacheInterceptorFactory` and `IdempotencyInterceptorFactory` kept every cache / store name they ever provisioned.** Each held a factory-level map keyed by name (the idempotency factory two: store and in-flight claims) that only `provision` wrote and nothing removed, so a node accumulated one entry per distinct name over its lifetime. Neither factory overrode `ResourceFactory.close`, so unloading an interceptor reached the default "no close convention" outcome and released nothing.
- **One mechanism for both factories: `SharedByName`, a holder-counted registry.** `provision` acquires a hold on the backend shared under the name and returns the interceptor built over it; `close` releases that hold; the name is removed when its LAST holder is released, so interceptors sharing one backend keep it until all of them are gone. Holders are tracked by identity, not `equals` — the interceptors are records, and two provisioned under the same config and key extractor compare equal while being two holds — and that identity index makes release idempotent: releasing one instance twice cannot consume a sibling's hold. The idempotency store and its claims now share one entry, so they live and die together. [mechanism: `SharedByName.acquire`/`release`, `CacheInterceptorFactory.close`, `IdempotencyInterceptorFactory.close`] [verified: `InterceptorRegistryReleaseTest` — per factory: sole holder released prunes; first of two released keeps the entry, second prunes; double release of one holder keeps the sibling's; equal-by-value holders counted separately; a provision after pruning gets a fresh backend; plus 8 threads × 2,000 acquire/double-release rounds against a live anchor hold never split the shared value and leave exactly the anchor's hold]
- **`CacheMethodInterceptor` carries its `cacheName`** (`Option<String>`, set by the factory, absent when built directly over a backend) for the fail-open log lines that name the cache; the three-argument constructor is kept.
- Scope: release is driven by `ResourceFactory.close`, the provider's unload path. [unverified: an interceptor dropped without `close` still keeps its name alive — nothing reclaims a hold on garbage collection]
