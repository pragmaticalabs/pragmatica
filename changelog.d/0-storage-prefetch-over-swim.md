### Added
- Cross-node block prefetching is wired into production storage. Each `artifacts`/`content` instance gets a prefetch manager that counts reads of its blocks (`StorageInstance.get` reports every hit), wakes when the node reports ready, and once per SWIM probe round hands its hottest blocks to application gossip, which sends them to ONE random ALIVE peer in a datagram of its own (new `SwimMessage.AppGossip`, wire tag 2171; the hint payload `StoragePrefetchGossip` is 2172/2173) rather than piggybacked on Ping/Ack. A receiving node routes the hints to the instance they name and prefetches each block with `StorageInstance.warm`, at most `prefetch_max_in_flight` (default 4) at a time; excess, cooldown and unknown-instance hints are dropped and counted, never queued. Accepted application gossip is rate-limited to 8 datagrams per second. `GET /api/v1/storage/{name}` reports the counters under `prefetch`. `[storage.<name>] prefetch = false` switches it off per instance and `prefetch_max_in_flight` sets the in-flight cap; `streams` prefetches its own segments and takes no part.
- `GET /api/v1/storage/{name}` reports the prefetch gossip's own counters under `gossip` (datagrams sent, accepted and dropped, hints for an unknown instance, undecodable bytes, hint lists trimmed to fit), so an operator can see hints lost to the datagram budget.
### Fixed
- A prefetch now fetches. It was `exists` followed by `get`, and `exists` on the cluster-shared tier is true for every block ever written, so it returned without fetching; and the one test claiming otherwise asserted a `get` that succeeds with or without prefetch.
- A block deleted on a node while that node was prefetching it is no longer brought back by the prefetch: a prefetch whose block is deleted during its fetch stores nothing and leaves no record.
