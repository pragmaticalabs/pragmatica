### Added (2026-10-18 — #962: the Management API takes its own optional `[management] security_mode`; #1121: `security_mode = "none"` leaves it fully open, and the #573 claim that said otherwise was false)
- **`[management] security_mode` (`"api-key"` or `"none"`) decouples the Management API from `[app-http]`.** Absent, the management plane inherits `[app-http] security_mode`, so a configuration that does not set it behaves as before, with one exception: **behaviour change**, an unrecognised `[app-http] security_mode` (a typo, which used to read as the default `api-key`) is now refused at load and the node exits 65. Set, it is independent of the application plane: `api-key` protects the management plane while the application plane is `none`, and `none` opens the management plane while the application plane authenticates. Any other value is **refused at load** (`jwt`, which the management plane does not have, or a typo), naming the key, the value and the allowed values; an unrecognised `[app-http] security_mode` is refused the same way instead of silently reading as the default (#1455: refuses, never drops) [verified: `ManagementSecurityModeTest`, `MainConfigGivenBootTest`]. The `[app-http.api-keys.*]` tables and the cluster bootstrap admin key stay shared by both planes. A disabled `[app-http]` is still replaced by the fail-closed default (#573), but an explicit `[management] security_mode` is kept [verified: `ManagementSecurityModeTest`, `MainAppHttpResolutionTest`, and `ManagementSecurityModeWiringBootTest` on a booted node with the two planes in opposite modes].
- **Bootstrap pre-flight PF-24 judges the management plane's EFFECTIVE mode.** It refuses a management port open to `0.0.0.0/0` while the plane is unauthenticated, and used to read only `[app-http] security_mode`: `[management] security_mode = "none"` on a public port passed it, and `[app-http] none` with `[management] api-key` was refused although the plane is protected. It now resolves the mode as a node does (`[management]` when present, else `[app-http]`, same parser). PF-24 also refuses, at bootstrap and before any server is provisioned, a `security_mode` no node can honour (`[management]` `jwt`, or an unrecognised value in either section), with the loader's own parse and wording [verified: `ClusterBootstrapConfigValidatorTest`, PF-24 cases].
- **`forge run` honours `[management] security_mode` from the sibling `aether.toml`**, independently of its key gate: the embedded nodes' management plane takes the configured mode, else inherits the app-HTTP mode as before. An explicit `api-key` management mode with no key declared is refused at start (exit 1, naming the file, the setting and the fix), since Forge's own control calls would get 401 [verified: `ForgeServerSiblingConfigWiringTest`].
- **Every management refusal names the plane and, for authorization, the axis** (`Management API ...`; `authorization_role`, versus the `roles` that gate app-HTTP routes) [verified: `ManagementServerSecurityCouplingTest`].
- **`security_mode = "none"` leaves the Management API fully open; the #573 comment and changelog claim that `denyUnlessPublicValidator` refuses non-public routes there was false.** The management server never consults a validator when security is disabled (local, forwarded, websocket and Maven push paths). The dead validator and the false comment are removed from `AetherNode`, and the startup WARN now says the plane is fully open and how to protect it. This corrects the #573 entry ("The management plane now uses `denyUnlessPublicValidator`...") for the `none` arm; the entry's other claims stand. The open behaviour is pinned [verified: `ManagementServerSecurityCouplingTest.securityDisabled_anonymousPush_isServedWithoutConsultingTheValidator`].
- Docs: `management-api.md` documents the new key and the shared keys, with an example of a key that passes on one plane and fails on the other; its default `authorization_role` is `VIEWER` (it said `ADMIN`; `cli.md` likewise), and the "no keys means open" sentences (Authentication, WebSocket) are replaced by the fail-closed default; the App HTTP Security section says its mode is the management plane's default; `SECURITY.md` and the draft `rbac-spec.md` describe the key.
