### Fixed
- **`publish-batch` answers `207 Multi-Status` for any batch that is not fully `PUBLISHED`, with the body unchanged** (#1354). It answered `200` for every batch the route ran, so a client that read only the status misread a partial batch, or one where nothing was published, as success. The status is now derived in one place, `PublishBatchResponse.httpStatus`, from the item statuses: every item `PUBLISHED` is `200`; anything else (a refused item, an `OUTCOME_UNKNOWN` item, `published: 0`) is `207`. `ManagementRouter` writes a `StatusBearingResponse` value's declared status instead of a fixed `200`. Stream-level refusals keep their own `400`/`409`; an empty batch stays `200`. Clients that treated every `2xx` as success and ignored `notPublished` should now read `notPublished`; a client that matched exactly `200` must also accept `207`. [verified: `StreamApiRoutesPublishBatchTest`, five over-HTTP cases through `ManagementRouter`]
