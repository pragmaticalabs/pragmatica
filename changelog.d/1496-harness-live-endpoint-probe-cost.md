### Fixed (2026-09-24 — #1496: once the pinned node was killed, every harness management call waited 2s first, and a previous run's endpoint record could be read)
- **Every management call paid a 2s timeout after the pinned node died.** `_resolve_live_endpoint` always probed the pinned endpoint first; with several CTM replacements a single cloud endpoint enumeration cost about 14s. On cloud it now tries this run's last-known-live endpoint first. [verified: `aether/tests/integration/test/test-cloud-helpers.sh` — reverting the order makes the dead pinned endpoint the first probe]
- **The live-endpoint record was not scoped to a run,** so a file left by an earlier run could name an IP since recycled to a different cluster, which would answer with the shared API key. The record is now keyed by a per-run `AETHER_RUN_ID`. [verified: same file — an unscoped name probes another run's endpoint]
