### Fixed (2026-09-24 — #1496: once the pinned node was killed, every harness management call waited 2s first, and a previous run's endpoint record could be read)
- **Every management call paid a 2s timeout after the pinned node died.** `_resolve_live_endpoint` probed the pinned endpoint on every call; with several CTM replacements one cloud endpoint enumeration cost about 14s. On cloud it now remembers, per run, that the pin failed and skips it for `CLOUD_PIN_RETRY_S` (default 30s). The pin is still preferred when alive, so the documented resolution order is unchanged. A remembered live endpoint that turns out dead is forgotten instead of being re-probed on every call. A malformed record, or a non-numeric `CLOUD_PIN_RETRY_S`, is treated as expired or defaulted to 30s. Before this, it aborted the calling `$(...)` before any probe. The fallback scan no longer re-probes the dead pin under node-1's own address. When every other node is dead, a skipped pin is probed once as the last resort, so a pin that revives inside the window is still found. [verified: `aether/tests/integration/test/test-cloud-helpers.sh` — each of these fails its own case: removing the skip, the window expiry, the forgetting, the record clear on a revived pin, the same-pin guard, the record validation, the scan's pin skip, or the last-resort re-probe]
- **The live-endpoint record was not scoped to a run,** so a file left by an earlier run could name an IP since recycled to a different cluster, which would answer with the shared API key. Endpoint state is now keyed by `AETHER_RUN_ID`, minted once in `lib/common.sh`, and removed on every exit path, including `--skip-teardown` and `--keep-on-failure`.
