### Fixed
- A node that boots after a gossip-key rotation can now join (#1200). The leader that mints it (auto-heal, scale-up, cloud and Docker) reads the current key from the replicated rotation record and delivers it with the cluster secret as a credential file (`AETHER_GOSSIP_KEY_FILE`, value `<keyId>:<base64>`); a node provisioned by hand takes it from `AETHER_GOSSIP_KEY` or `AETHER_GOSSIP_KEY_FILE`. The delivered key is the node's only gossip key, so the `cluster_secret`-derived key is still never accepted after a rotation. A malformed value refuses the boot.
- A node that is given no key no longer sits silent: if it has neither joined nor decrypted a single gossip datagram 10 minutes after SWIM started, it exits with a `FATAL` line "Gossip-key divergence suspected" naming the cause and the remedy. The seed nodes now raise the operator event `gossip-key-unknown-from-peer` (subject: the sender's address) when a peer's gossip arrives under a key they do not hold, with `gossip-key-peer-decrypted` as its recovery.
- Known limits: nothing returns the current key to an operator who provisions by hand, and a second rotation that lands while a node boots leaves it on the previous key until the rotation record replays. See SECURITY.md.
