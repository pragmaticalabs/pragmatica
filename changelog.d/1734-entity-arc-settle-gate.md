### Fixed (2026-10-11 — #1734: durable-entity ownership converged late, or never, under a changing hosting set)
- **The leader minted entity-arc owners from whatever hosting set was committed at tick time, so every late registration was an owner change.** Registrations arrive one per node as each node provisions the slice, and an autoscaler adds and removes hosts. Each owner change is a fence bump with no readiness handoff, so a change every few seconds kept the new owner's not-held window open. `EntityOwnershipReconciler` now holds a per-keyspace settle gate on the fingerprint of the hosting set (partition count plus registered hosts that are live members). Only the reconciler changed: not the writer, not the epoch scheme, not `CommittedPartitionOwnerSource`.
- **What the gate does:**
  - Once the fingerprint has been unchanged for 2 tick intervals of time, 10 s at the 5 s tick (`SETTLE_TICKS`), owners are HRW over the set, as before.
  - While it has not settled, an arc whose committed owner is still a registered, live host keeps that owner, even if HRW now prefers a newly joined host.
  - An owner that left the members or retracted its registration is replaced at once; failover is never gated.
  - An arc with no record is minted only after the set settles, or after 6 tick intervals of time (`FIRST_MINT_CEILING_TICKS`, 30 s at the 5 s tick) without settling. The ceiling mint raises the operator warning `entity-ownership-unsettled-mint` (WARNING, subject the keyspace, message gives the number of set changes seen and the ceiling), once per unsettled run. Existing owners are never moved while unsettled.
  - [verified: aether/node/src/test/java/org/pragmatica/aether/node/EntityOwnershipReconcilerTest.java, nested `SettleGate`] (unit-level, through the real ownership writer over a committing store; the Forge pin below is the live-path evidence). With the gate off (`settleTicks` 0) the same first scenario mints on the first pass, so the zero is the gate's doing.
- **Guarantee, stated precisely.** Owners converge to HRW(registered hosts that are live members) once that set has been quiet for 2 tick intervals of time. While it is not quiet, no owner changes except failover of an owner that left. A first mint is delayed by at most 6 tick intervals of time. No claim under a perpetually oscillating set, other than that unminted arcs are minted once at the ceiling and then stay put. This bounds the rate of owner changes; it does not bound write refusal and is not a readiness handoff: a moved arc's new owner can still be named before its ring is held, and its `OwnerTransitioning` window is unchanged. Both thresholds are measured on an injected monotonic clock, never counted in passes, because an event kick (retract, committed registration removal) is a pass that takes no time and counting it let three back-to-back kicks settle and mint a set that had been quiet for milliseconds. The quiet period is observed at pass granularity, so on a loaded scheduler it can stretch by up to one tick interval. [verified: `EntityOwnershipReconcilerTest.SettleGate.kicks_afterARegistration_doNotSettleTheSet`] (unit-level) The 2 and 6 are marked guesses, one constant each, no config knob.
- **Operator recovery.** None to take: the warning is informational and the state clears when the hosting set is quiet for 2 tick intervals of time. If it recurs, the cause is a hosting set that keeps changing (autoscaler flapping, a slice that provisions slowly); #1734 option (d), scale hysteresis for entity-declaring slices, is the separate remedy.
- **Docs.** `entity-ownership-unsettled-mint` is added to the code list in `aether/docs/reference/management-api.md`.
