### Fixed (2026-09-04 — #680: scheduled-task execution counters went stale on the automatic-fire path)

- **`nextFireAt`, `totalExecutions`, and `consecutiveFailures` were never updated when a scheduled task fired on its own timer** — only the manual `/api/v1/scheduled-tasks/trigger` route did a real read-modify-write against the prior KV state; the automatic fixed-rate and cron paths wrote a fresh, un-accumulated state value on every fire, silently discarding the running counts. Both paths now read the prior `ScheduledTaskStateValue`, compute a real `nextFireAt` (interval and cron alike), and accumulate `totalExecutions`/`consecutiveFailures` the same way the manual route already did [verified: `aether/aether-invoke/src/test/java/org/pragmatica/aether/invoke/ScheduledTaskManagerTest.java` — `FireBehavior` nested class].
- **`consecutiveFailures` now resets to `0` on the next successful execution**, mirroring the manual-trigger route's existing behavior [verified: same test class].
- Docs updated: `aether/docs/reference/management-api.md` (JSON examples) and `aether/docs/slice-developers/resource-reference.md` (Execution State table, `nextFireAt` no longer described as cron-only).
