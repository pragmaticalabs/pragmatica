### Fixed (2026-11-26 — #3796: refusals on the stream routes)
- **A refused verb on a known management path is `405` with an `Allow` list, not `404`** (#3796). Any path the management server answers for some method, called with another (a `POST` to `/api/v1/engine-streams/{key}/events`), answered `404 File not found`, which a client cannot tell from a mistyped path or an unknown stream. It now answers `405 Method Not Allowed` with `Allow: GET` (the methods that path answers). A path no method owns stays `404`. [verified: `ManagementServerMethodNotAllowedTest`]
- **`GET .../read/{partition}` of a partition the stream does not declare is `400`, not `503`** (#3796). `/read/7` of a 2-partition stream answered `503 not yet promoted`, which invites a retry that cannot succeed; it is now the caller's error, as on `.../partitions/{partition}`. [verified: `StreamRoutesNonHolderTest`]
- Documented: the declared-partition check on the read route, that `/info` and `/consumers` read the same owner bounds (the lag window after a stream is created), what the raw engine-key routes return, and that they have no CLI command.
