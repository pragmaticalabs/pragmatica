### Fixed (2026-09-29 — #1100: `jbct lint --format json|sarif` reported a coverage-gap run as a clean document)
- **`jbct lint --format json` and `--format sarif` now state the run's coverage inside the document.** A run that could not parse a collected file (exit 2) used to emit `[]` / `results: []` with no in-document signal, so a SARIF uploader that ignores the exit status recorded a clean scan for files nobody analysed. A run that found no Java files emitted the same empty document (and exits 0). [verified: jbct/jbct-cli/src/test/java/org/pragmatica/jbct/cli/LintCommandMachineFormatTest.java — both gap shapes fail the documented clean-scan predicate, a complete clean run passes it]
- **Breaking (pre-GA, no shim): `--format json` is now one object, not a bare array:** `{ "collected", "examined", "skipped": [{file, reason}], "diagnostics": [...] }`. SARIF gains `runs[0].invocations[0]` with `executionSuccessful` (false when a file was skipped) and `toolExecutionNotifications` (an `error` per skipped file; a `warning` when no files were found). The clean-scan `jq` predicates are in `jbct/README.md`.
