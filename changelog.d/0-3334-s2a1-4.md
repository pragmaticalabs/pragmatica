### Added (2026-11-21 — #3334: a stream's retention change is announced)
- **A committed config that changes a running stream's storage declaration now raises one `stream-retention-changed` event.** It is derived in the stream announcer from the committed config Put, compared with the declaration the node enforces, so a rejoin replaying the Put, an unchanged declaration, a stream not held on the node and a new incarnation raise nothing. The event carries the old and new bounds and an id that is a pure function of the committed Put, so two nodes deriving it agree. The node's router carries it to the cluster-events aggregator, which publishes it through the committed gate. [verified: `StreamRetentionChangedRouteBootTest`, `StreamIsrAnnouncerTest`]
