### Added (2026-11-21 — #3334: a stream's retention change is announced)
- **A committed config that a node adopts over a different enforced retention declaration now raises one `stream-retention-changed` event.** It is raised from the stream manager's adopt site, the one call that replaces the config a node enforces (#3554), so there is no event without an adoption: a refused Put, a first commit (hydration), an unchanged declaration and a new incarnation raise nothing. The event carries the bounds the node enforced before and the adopted ones, and an id built from the stream, incarnation, the Put's `createdAt` and both bounds, so nodes with the same enforced history raise the same id; nodes whose enforced configs diverged raise different ids. The node's router carries it to the cluster-events aggregator, which publishes it through the committed gate. [verified: `StreamRetentionChangedRouteBootTest`, `RetentionChangedAtAdoptSiteTest`, `StreamIsrAnnouncerTest`]
