### Fixed (2026-11-15 — #3262: the legacy B7 leader toggle no longer lets a parked activate erase a parked deactivate)
- **On a LEGACY node whose engine-marker guard is closed, a CDM `activate` (this node elected) parked after a `deactivate` (leadership moved away) no longer replaces it; both run, in order, when the guard opens.** An Active legacy `ClusterDeploymentState` ignores the `activate` alone, so the node kept its old incarnation. A later `deactivate` still supersedes the whole parked sequence. New `DeploymentWiring.legacyGatedLeaderToggle` carries B7 (wiring row `B7.LeaderChange -> legacy+gate+toggle`) through `EngineMarkerGuard.whenOpenAfterParked` (#3253). Reachable only while a LEGACY node's guard is closed (an FSM2 marker committed) and leadership changes twice inside that window. `[mechanism: Fsm2SystemTest$Bindings, in-JVM against the wiring hook; DeploymentWiringBootTest pins that AetherNode binds B7 through it]`
