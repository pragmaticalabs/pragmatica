### Added (2026-10-29 — #686, #1726: `aether cluster apply --resume` continues the ledger and `--rollback` terminates what it recorded)
- **`--resume` now continues the halted apply instead of replacing its ledger and re-creating everything.** Every node the ledger intended is looked up at its provider by label before anything is created: a node that exists is adopted (no create), and a node found on none of 12 listings, spaced a sixth of the provisioning timeout apart, is marked ABSENT and never retried under the same id. A lookup that fails refuses and creates nothing. Finished actions are skipped, a partly done action creates only the remainder, and an apply-label audit runs before the ledger is closed: a VM that landed late is adopted and named, a ledger VM that is gone is recorded as gone. A ledger the commit protocol has aborted refuses `--resume` (use `--rollback`); a ledger in COMMITTING lets exactly one of the two verbs through, decided by what the cluster's config says. [verified: `ApplyResumeTest`, `ApplyReconcilerTest`, `ApplyCommitRecoveryTest`]
- **`--rollback` is implemented.** It terminates the recorded VMs newest first; each must carry both `aether-cluster=<cluster>` and `aether-apply=<apply id>` (a VM found under other labels is refused and named, never terminated); a node that joined is drained first, bounded to 120 s, and an unreachable cluster is said and the terminate goes ahead; absence is decided by listing the provider, not by a terminate error. A failed terminate leaves the row TERMINATE_FAILED, names the VM STILL RUNNING AND BILLED with its removal command, exits non-zero and keeps the ledger; a second `--rollback` retries only what is left. It is refused once the config is committed. [verified: `ApplyRollbackTest`, `ClusterApplyRollbackCommandTest`]
- The lost-reply failure message now tells the operator to run `--resume`, which does the lookup it promises. A ledger row keeps its position when it changes state (rollback walks the list newest first), and the audit no longer calls a VM that merely lost its apply label "gone".
