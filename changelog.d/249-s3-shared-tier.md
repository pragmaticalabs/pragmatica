### Added (2026-10-18 — part of #249: S3-compatible shared storage tier from configuration)
- **A storage instance's shared last tier is now chosen by `[storage.<instance>.shared] kind = "dht" | "s3"`.** `dht` stays the default and today's behaviour; a config without the section is unchanged. `s3` builds the S3-compatible `RemoteTier` (endpoint, region, bucket, prefix, `path_style`, `credentials = "env" | "file:<path>" | "instance"`, `max_inflight`, `request_timeout`); inline secrets are refused at load (any case, dotted keys and sub-tables included), and every malformed section is a typed refusal naming the instance and key. `"dht-durable"` is reserved and refused until the durable DHT phase lands. [verified: `aether/aether-config` `ConfigLoaderSharedTierTest`]
- **Boot probe: a configured S3 tier that cannot be admitted fails storage construction.** PUT, GET (bytes must match) and DELETE of `<prefix>.aether-probe/<nodeId>`; unreachable endpoint, refused credentials, missing bucket or a differing read-back stop the boot naming instance, endpoint and bucket. [verified: `aether/node` `StorageFactorySharedTierBootTest` (default build), `StorageFactoryS3SharedTierTest` (`@Tag("S3")`, MinIO)]
- **`isDurable()` is true only for the tier built from config**, so an acknowledged write means the bucket answered the PUT with 200 — the provider's durability, not Aether's. The streams instance cannot take S3 in this release (stream storage is redesigned separately), so #249's durable backing for stream storage and its restart-survivability test remain open. One object per block, no multipart; at most `max_inflight` requests in flight; each bounded by `request_timeout`; an unreachable or failing provider is a retriable `Unavailable`, never an absent block; a refusal is a terminal `Rejected`. [verified: `integrations/storage` `RemoteTierDurableTest`, `RemoteTierS3IntegrationTest` (`@Tag("S3")`)]
- **Encryption wraps the S3 tier as it wraps the DHT, with the local disk's guards**: the bucket holds ciphertext; a keyring-less boot over a marked prefix is refused; enabling encryption over a prefix that already holds objects is refused; and `<prefix>.encryption-enabled` is written only after every instance of the boot passed its guards (#852), so a refused boot stamps no bucket. [verified: `StorageFactoryS3SharedTierTest`]
- Credentials resolve through `AwsCredentialsProvider` (environment, AWS shared-credentials file, EC2 instance profile over IMDSv2 with refresh before expiry); there is no AWS SDK in the tree. They never appear in a log line or a refusal. Operator reference: `aether/docs/reference/configuration.md` § Shared Storage Tier Configuration.
