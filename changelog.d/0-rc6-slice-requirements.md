### Changed (2026-11-05 — rc6 §3.1: slice capacity requirements and the leader's combiner)
- **`aether scale` sets a floor, not a raw count.** Each source of capacity demand now commits its own requirement record (`SliceRequirementKey`, one per slice and source): the autoscaler writes `REACTIVE`, `aether scale -n <n>` writes `OPERATOR`, and `aether scale --release` (API: `"release": true`) removes it. `SCHEDULED`, `CAMPAIGN`, `PREDICTIVE` and `RECOVERY` are defined with no writer yet. The autoscaler and the operator no longer overwrite each other's count ("last write wins").
- **The leader's combiner is the only writer of a target's instance count after its creation**: `target = clamp(max(minAvailable, every unexpired requirement), 3, maxInstances, placeable capacity)`, evaluated with the evaluation time as an input and requirements read in a fixed order. It runs on every requirement put or remove, on every target put (a republish arrives this way), at the earliest requirement expiry and on leader takeover, and writes through the #2662 fence plus a witness on every requirement of the slice [mechanism: compare-and-set on the target value read; only the leader runs the combiner]. With no unexpired requirement the current count stands.
- **Version writers carry the committed count.** A/B variant and conclusion writes and a deployment start over an existing target change its version only; the variant no longer drops to 3 instances. The blueprint's declared count still seeds a new target.
- **Scale route:** a requirement above the slice's `maxInstances` is refused with `400`; the response adds `target`, the count the committed requirements combine to (before the leader's placeable-capacity bound).
- Requirement records of a slice whose target is removed (its blueprint deleted) are removed by the leader, witnessed on the target's absence.
