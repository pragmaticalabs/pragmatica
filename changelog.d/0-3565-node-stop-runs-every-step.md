### Fixed (2026-11-21 — #3565: a failed `leaveQuorum` skipped every later step of `AetherNode.stop()`)
- **`AetherNode.stop()` was a `flatMap` chain headed by `leaveQuorum`, so a failed leave skipped the FSM2 close, the components' stops, the listeners, the slice invoker, storage and the cluster node**, leaving the node half-stopped with its timers, servers and cluster node running (#3565). The whole stop is now one ordered step list in `NodeStopSequence`: once the stop begins, every step runs exactly once, in order, whatever any earlier step returned. Each failure is logged under its step's name and the promise `stop()` returns resolves with the FIRST failure (success when none failed).
- Behaviour change: a failed HTTP listener or shared-resource close (#1612, #903) was logged and swallowed; it is now also the stop's result (the later steps still run). Callers that treat a failed node stop as best-effort (`EmberCluster`) already `recover` it.
- Not covered: a step that throws (rather than returns a failure) still ends the run at that step.
