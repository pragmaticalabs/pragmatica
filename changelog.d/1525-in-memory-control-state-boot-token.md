### Changed (2026-09-26 — #1525 / #1528, resolves #1519: nodes aborted at boot on cloud for want of a consensus_path)
- **#1525 — #1390's durable control storage is removed; cores and workers run in-memory Rabia** (owner ruling, session 28). The vote write-ahead log, local boot recovery and the `cluster.consensus_path` requirement are gone, so a node assembles from the shipped image config with no control-storage path. [verified: aether/node/src/test/java/org/pragmatica/aether/node/ShippedConfigBootTest.java] (single-node assembly; a cloud bootstrap has not been re-run)
- **#1468's fail-closed outcome is preserved:** a node whose own persisted snapshot cannot be restored never activates, logs the failure at ERROR, and reports it as the authority failure in its voter reconfiguration status. What no longer holds: under #1390 such a node never started a sync round; it now enters synchronization (and stays fenced). The assertions pinning "no sync round" were removed because they pinned #1390's boot-recovery mechanism, which no longer exists — not the ruled outcome. [verified: integrations/consensus/src/test/java/org/pragmatica/consensus/rabia/RabiaOwnRestoreFailureTest.java] (single engine)
- **A configured `[backup]` path is again the consensus persistence**, as before #1390, and a snapshot saved with voter authority headers decodes on restore. [verified: aether/node/src/test/java/org/pragmatica/aether/node/ConsensusSnapshotEncodingTest.java]
- **#1528 — terminal removal is the identity model: a per-process random boot token replaces the durable producer counter.** SWIM ANNOUNCE and membership updates, metric observations, cluster-sync pongs, community health and worker admission carry it, compared by equality only. A same-token process heals as before; a different token for a known NodeId marks the known process dead and refuses the new one. Membership DEAD/DEPARTING ignore process evidence, and refusals are counted and logged. `[mechanism: SwimProtocol boot-token gate; MembershipFsm process-evidence gate]` — pinned by `SwimBootTokenTest` and `MembershipEvidenceDomainTest`, not yet run on a multi-node cluster. **Recovery action:** replace a dead node under a fresh NodeId; restarting it under the old NodeId is refused. A whole-cluster restart is unaffected.
- **#1528 — the boot token also gates the QUIC transport and consensus dispatch (#1545 fix round).** SWIM and the QUIC transport share ONE per-node registry. The Hello handshake carries the token and is admitted by both acceptor and dialer; a different token for a known NodeId retires it, whichever layer sees it first, and SWIM marks the known process FAULTY. A retired NodeId is never attached (fresh, RECONNECT of an EVICTED/SUSPECT peer, or any tombstone re-admission), never dialed, and its inbound traffic — as connection peer or relayed protocol sender — is dropped before Rabia (`quic_boot_token_drops_total`). A new process under a killed core's NodeId therefore cannot restore quorum. [verified: aether/ember/src/test/java/org/pragmatica/aether/ember/EmberSameIdentityRelaunchTest.java] (in-JVM Ember cluster, real QUIC/SWIM/Rabia; both the new-address and same-address relaunch)
- **A refused process learns it was refused and exits.** Peers answer a refused Hello with `HelloRefused` and a refused ANNOUNCE with `IdentityRefused`; the refused node logs ERROR ("this NodeId belongs to a retired process; start with a fresh identity") and exits through its exit hook (production: non-zero, `halt(2)`), so orchestration and the CTM see a failed node. [verified: aether/ember/src/test/java/org/pragmatica/aether/ember/EmberSameIdentityRelaunchTest.java] (in-JVM; the Ember exit hook stops and removes the node)
- **Refusals are exported** on `GET /api/v1/metrics/transport` and the Prometheus transport surface: `boot_token_refusals_total` (SWIM + QUIC Hello), `quic_boot_token_drops_total`, `membership_process_evidence_refusals_total`.
- **Readiness, drain acknowledgement, community health and metric evidence are pinned to the first boot token seen** for a NodeId; evidence from a different token is ignored, never installed as a fresh entry. [mechanism: equality check at each evidence consumer]
- **A partitioned-but-live process (same token) still heals** over the real transport and counts toward quorum again. [verified: aether/ember/src/test/java/org/pragmatica/aether/ember/EmberSameIdentityRelaunchTest.java]
- Pre-GA wire changes: `SwimMessage.Announce`, `MembershipUpdate` and `NetworkMessage.Hello` gain a trailing `bootToken`; new `NetworkMessage.HelloRefused` (tag 1705) and `SwimMessage.IdentityRefused` (tag 1706); system tags 1693/1694 (`VotingJournalCheckpoint`/`VotingJournalRecord`) are retired.
