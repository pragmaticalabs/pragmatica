### Fixed (2026-09-21 — #1098: Option-returning config readers conflate a malformed value with an absent key)
- **A config value that was present but unparseable read the same as a key that was never configured**, so `port = "80x"` bound the slice's default and nothing was logged or refused — on `ctx.config().get*`, on the record binder (a malformed `int`/enum/`TimeSpan` component became `SectionNotFound`, which is exactly what let the record's `DEFAULT` instance stand in), on the exponential-backoff sub-fields, and on every boolean reader, where `Boolean.parseBoolean` read `"yes"` as a silent `false`.
- Every typed optional reader now answers `Result<Option<T>>` — the core "optional with validation" shape: absent → `Success(None)`, present but malformed → a `ConfigError.TypeMismatch` naming the key and the raw value. Applies to `ConfigSource`/`ConfigurationProvider.getInt/getLong/getDouble/getBoolean`, `ConfigService.getInt/getBoolean` (both implementations), and the slice-facing `ConfigFacade.getInt/getLong/getDouble/getBoolean` (every implementation, including `NodeDeploymentManager`'s adapters, whose failures also name the slice). `getString` stays `Option<String>`; a string cannot be malformed. `[verified: integrations/config/config-service/src/test/java/org/pragmatica/config/MalformedValueReaderTest.java, aether/slice-api/src/test/java/org/pragmatica/aether/slice/DeployedConfigFacadeTest.java, aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/node/ConfigServiceConfigFacadeNumericTest.java]`
- The record binder refuses a malformed component by name and value instead of substituting the `DEFAULT` instance: only `SectionNotFound` (a genuinely absent key or section) may fall through to the derived-name and `DEFAULT` fallbacks; every other failure — a malformed primitive, `TimeSpan` or enum value, an `Option<primitive>` component that does not parse, a nested record's own refusal, an unknown key — now propagates. Booleans accept only `true`/`false` (any case). `[verified: integrations/config/config-service/src/test/java/org/pragmatica/config/ProviderBasedConfigServiceMalformedValueTest.java]`
- `require*` reports a malformed value as malformed, never as "Required config key not found". `[verified: aether/slice-api/src/test/java/org/pragmatica/aether/slice/DeployedConfigFacadeTest.java]`
- The generated factory no longer wraps the typed `get*` reads in `Result.success(...)`, so a malformed optional value fails the section's `Result.all(...)` chain — `Fatal.ConfigurationFailed` at activation, and a logged, unapplied update on the `@ConfigUpdate` re-parse. Generated-structure change recorded in `envelope-versioning.md` under the GA freeze (no stamp bump). `[verified: jbct/slice-processor/src/test/java/org/pragmatica/jbct/slice/SliceProcessorTest.java — generated-content pins; the runtime activation failure itself is the existing #761 path]`
- Breaking (pre-GA, no shim): callers of the typed `get*` readers receive `Result<Option<T>>` instead of `Option<T>`. `TomlDocument`'s own typed getters (`integrations/config/toml`, ~80 bespoke-parser call sites across 6 modules) keep the old shape and are `[unverified: not covered by this change — filed as a follow-up]`.
