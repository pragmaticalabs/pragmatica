### Fixed (2026-10-04 — #1727: QUIC lane stall after a large loss burst, pinned)
- **The recurring #1727 lane stall was a quiche defect, fixed by the Netty 4.2.18 bump (#1793).** Netty 4.2.9 bundled quiche `5ea8d8e`, whose packet-number length omitted RFC 9000 A.2's sign bit (cloudflare/quiche#2180, fixed by `094896852c`, bundled from Netty 4.2.10). After 128 or more lost packets in a row, the peer mis-decoded every packet number, failed AEAD and dropped each packet silently, so writes the sender saw succeed were never delivered while both channels stayed active. Reproduced in-JVM on Linux 6 of 240 times on 4.2.9 and 0 of 240 on 4.2.18, interleaved. `QuicNativeLibraryFloorTest` now fails if `netty-codec-native-quic` drops below 4.2.18. `[verified: integrations/consensus/src/test/java/org/pragmatica/consensus/net/quic/QuicNativeLibraryFloorTest.java — red with -Dnetty.version=4.2.9.Final]`
- **A silently black-holed cluster link is bounded and surfaces as a disconnect.** QUIC's idle timeout is disabled on cluster links, so the transport never closes a link whose inbound path is dead; the network's receipt-evidence liveness TTL (`pingInterval × 8`) does. The deaf side evicts the link and closes it, and the other side sees the close and re-dials. Writes already handed to quiche on that link are discarded with it, so a caller that treats a transport hand-off as delivery can still lose them. `[verified: integrations/consensus/src/test/java/org/pragmatica/consensus/net/quic/QuicClusterNetworkBlackHoleTest.java — red with the TTL sweep disabled]`
