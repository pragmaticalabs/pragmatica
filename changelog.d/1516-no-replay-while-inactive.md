### Fixed (2026-10-19 — #1516: a node that cannot activate replayed notifications and ran restore hooks on every sync round)
- **A sync restore on a node whose activation is refused no longer replays notifications or runs the `onStateRestored` hooks on every sync round; it announces once, when the node first serves.** When the re-persist after a restore fails (or the node is outside the electorate, or its participation record cannot be written), `activate()` is refused and the node retries on the next sync round. Each round still replayed the state machine's synthetic notification burst and ran the post-restore hooks, so a consumer received the same world once per round from a node that was not ACTIVE, which broke the invariant that a notification implies ACTIVE. The restore is now installed silently and marked unannounced; the replay and the hooks run exactly once, on the latest installed state, at the first write of a serving state (`Idle`, `InPhase` or `Observing`) by any path (activation, resume from `Paused`, promotion, an observer advancing on a Decision), which now all go through one function. A node fenced for good never serves and never announces; a node that resumes from a pause without a second restore still announces what it restored. [verified: `RabiaNoReplayWhileInactiveTest`]
- Together with the bounded exit of a permanently fenced node (#1468), this closes #1516's two defects. The fence itself still does not clear in-process when the disk recovers: recovery is by restart.
