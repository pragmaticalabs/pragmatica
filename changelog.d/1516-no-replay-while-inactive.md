### Fixed (2026-10-19 — #1516: a node that cannot activate replayed notifications and ran restore hooks on every sync round)
- **A sync restore on a node whose activation is refused no longer fires the notification replay or the `onStateRestored` hooks.** When the re-persist after a restore fails (or the node is outside the electorate, or its participation record cannot be written), `activate()` is refused and the node retries on the next sync round. Each round still replayed the state machine's synthetic notification burst and ran the post-restore hooks, so a consumer received the same world once per round from a node that was not ACTIVE, which broke the invariant that a notification implies ACTIVE. The restored state is still applied silently; the replay and the hooks now run only after the engine has actually left `Syncing` (active, or observing), so a restore that does activate replays exactly once, as before. [verified: `RabiaNoReplayWhileInactiveTest`]
- Together with the bounded exit of a permanently fenced node (#1468), this closes #1516's two defects. The fence itself still does not clear in-process when the disk recovers: recovery is by restart.
