### Fixed (2026-09-30 — #1737: app routes answered 500 for a transient refusal)
- **A slice HTTP route whose handler failed with a `Cause.Transient` refusal (e.g. a stream partition not yet promoted on this node) answered 500, indistinguishable from a server fault.** It now answers 503. `ErrorMapper.defaultMapper()` maps an unmapped transient cause to 503; `SliceRouter` re-derives a 500 left by a slice's generated mapper through it; `AppHttpServer`'s local-route failure fallback does the same. Non-transient failures and `PublishOutcomeUnknown` stay 500; no `Retry-After` is set (the Management path sets none). `[verified: SliceRouterTransientStatusTest, AppHttpServerLocalRouteFailureStatusTest — each 503 pin reddens when its hunk is reverted]`
- `StreamRoutesPublishMemoryExceededTest` pinned 500 for `STREAM_MEMORY_EXCEEDED` through `ErrorMapper`; that cause is transient, so the test now pins 503. The Management-API publish path does not use `ErrorMapper` and is unchanged.
