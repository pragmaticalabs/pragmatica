### Removed (2026-11-21 — #3530: four persisted key types had no writer left)
- **Breaking: `JoinDeadlineKey`, `DrainDeadlineKey`, `WorkerSliceDirectiveKey` and `ClusterPhaseKey` are deleted, with their values `JoinDeadlineValue`, `DrainDeadlineValue`, `WorkerSliceDirectiveValue` and `ClusterPhaseValue`** (#3530). No production code reads any of them, and none has a writer: `WorkerSliceDirectiveKey` and its value were written by `CommunityPlacementPlanner` until #1535 (2026-10-19), the other three never had one. The only references were the exhaustive classification switches (`ReplicaFilter`, `WorkerMetadataIndex`), the test that listed `WorkerSliceDirectiveKey` among the runtime keys, and the wire tag pins. The `ClusterPhase` enum stays: the status endpoint and the topology manager use it, derived by `ClusterPhaseView`.
- **Wire:** the eight tags (keys 1098, 1104, 1111, 1137; values 1612, 1618, 1625, 1658) stay pinned in `SystemTags` as retired, so they are never reused, and `WIRE_GENERATION` moves from 7 to 8 because the baseline loses their TAG and SHAPE lines. A node of an older build that receives one of these tags fails it as an unknown tag.
- **Restore:** a KV snapshot or backup document that holds any of the eight retired tags or the four retired keys makes the WHOLE restore fail, and never skips the entry: the snapshot decode throws, and the backup is refused `Blocked(DOCUMENT_UNDECODABLE)` (its line is `UnrecognisedKey`). A snapshot taken by an rc4-era node can hold a `WorkerSliceDirectiveKey` (its writer existed until #1535), so restoring it at this build fails entirely. Pre-GA and breaking; there is no migration.
