### Fixed (2026-09-14 — #910: a cache-tier put failure failed a write-through put that was already durable)
- **`StorageInstance.promoteToNextCacheTier` logged a cache-tier failure as "skipped" and then `flatMap`ped the failure through**, so the caller's `put` failed after the durable tier had already accepted the bytes: the caller was told its durably stored data was lost, the claim was released and the bytes orphaned (two-tier) or a stale record survived (three-tier), exactly as the ticket traces. The chain now `recover`s a cache-tier failure to unit — the durable write has succeeded by the time any cache tier is asked, so a cache failure is an accelerator failure, not a data failure — continues with the next cache tier, and the log line says what happens: the promotion FAILED and the block stays durable, served from the durable tier. Still DEBUG: a cache tier that is full is a normal steady state on a hot node, and a per-put WARN there is the #718 flood.
