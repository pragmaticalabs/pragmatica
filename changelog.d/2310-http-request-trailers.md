### Added (2026-10-19 — #2310: HTTP request trailers are dropped on HTTP/1.1 and HTTP/3; no API exposes them)
- **Handlers can now read request trailers.** `HttpRequest.trailers()` returns them as `Headers`, and returns empty when the client sent none. HTTP/1.1 fills it from the chunked trailer section. HTTP/3 fills it from the trailing HEADERS frame. Before this change, a trailing HEADERS frame on HTTP/3 was dropped (before the upload hardening it replaced the request's header section, so the handler saw `GET /` with the trailer fields as its headers). [verified: `integrations/net/http-server` `HttpRequestTrailersTest`]
- **Trailers stay separate from the headers, and forbidden fields are discarded.** Trailers are never merged into `headers()`. The new `Headers.trailers(Map)` drops every name in `Headers.FORBIDDEN_TRAILER_FIELDS`: the framing, routing, authentication, request-modifier and content-format fields that RFC 9110 §6.5.1 says cannot be acted on after the body. The request is still served. [verified: `HeadersTrailersTest`, `HttpRequestTrailersTest`]
- **Field names are case-folded with `Locale.ROOT`, and names that differ only in case merge.** The folding applies to `Headers` (header and trailer names, and lookups), the HTTP/1.1 and HTTP/3 field maps, `HttpMethod` parsing, `ForwardedRequestContext`'s method, and the header-mode version lookup in `SliceRouter`. Before, the JVM default locale was used: under `tr-TR`, `AUTHORIZATION` folded to `authorızatıon` and slipped past the forbidden-name filter, and `options` did not parse. Names such as `x-a` and `X-A` are one field, and their values are kept in arrival order; before, `Headers` kept only the last variant's values. [verified: `HeadersTrailersTest`, `LocaleIndependenceTest`, `HttpRequestTrailersTest`, `RequestContextImplTrailersTest`, `SliceRouterHeaderModeShapeTest`]. `Headers.fromSingleValueMap` no longer folds names before the merge, so single values of names that differ only in case are kept together too; it has no production caller.
- **The slice-facing views re-apply the forbidden-name policy.** `SliceRequestContext` and `ForwardedRequestContext` filter the decoded trailer map again, so a forged or buggy peer cannot hand a slice a forbidden trailer. Only a slice that reads the raw `HttpRequestContext.trailers()` map sees what arrived on the wire. [verified: `SliceRouterTrailersTest`, `ForwardedRequestContextTrailersTest`]
- **An over-limit trailer section is refused, never dispatched.**
  - HTTP/1.1: a request whose header and trailer sections together exceed the decoder's 8192-byte limit is now answered `431` and the connection is closed. An over-long request line is answered `414`, and any other request the decoder could not read `400`. Before this, Netty's aggregator passed such a request on with its failure attached, and the server dispatched it: an over-limit trailer section reached the handler as a complete request without its trailers, and an over-limit header section arrived as a placeholder `GET /bad-request`.
  - HTTP/3: Netty's 8192-byte per-section `SETTINGS_MAX_FIELD_SECTION_SIZE` already ended the connection. This change adds no code there and adds a test for it.
  - [verified: `HttpRequestTrailersTest` (an over-limit trailer section on each transport)] [mechanism: in Netty 4.2.18, `HttpObjectDecoder` resets its header parser once per message, not once per section, and `MessageAggregator` emits a message that failed to decode with the failure attached; the combined-section and `/bad-request` cases are traced, not tested]
- **The trailers reach Aether slices, Terra routes and management routes, including across a forward.** `HttpRequestContext` gains a `trailers` component, filled by `AppHttpServer`, `ManagementServer` and `TerraHttpServer`, and read back by `SliceRequestContext` and `ForwardedRequestContext`. `RequestContext.RequestContextImpl` and the management router's adapter pass trailers on. [verified: `AppHttpServerTrailersTest` (production node codec), `SliceRouterTrailersTest`, `ManagementServerForwardDispatchTest`, `ManagementRouterTrailersTest`, `ForwardedRequestContextTrailersTest`, `RequestContextImplTrailersTest`, `TerraHttpServerTest`]
- **Wire change:** `HttpRequestContext`'s SHAPE line in `wire-assignment-baseline.txt` gains `trailers` after `body`. A node on an earlier build cannot decode an HTTP forward from a node on this build, and the reverse also fails. Upgrade every node before relying on HTTP forwarding across versions.
