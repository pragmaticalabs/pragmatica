### Fixed (2026-11-14 — #2600: Stream consumers of a WORKERS_ONLY slice never attach: partitions stay unconsumed with no error)
- **A declarative stream consumer whose slice is ACTIVE only on worker nodes was never assigned a partition.** The consumer manager's candidate set was the core-only reconciled view, so a worker could not be a candidate. The candidate set is now that view united with the membership FSM's worker-tier counted members (`MembershipFsm.workerCountedMembers`, role `worker` or `spot`, MEMBER + SUSPECT); stream owners stay on cores. `[verified: aether/node StreamConsumerManagerTest$WorkerTier]` `[verified: aether/ember EmberWorkerStreamConsumerTest]` (whether a worker consumer's reads reach the stream owner through forwarded reads under FSM2, end to end, is `[unverified]` and tracked as a separate issue).
- **The silence is now a warning.** A slice ACTIVE on nodes that are none of them a live candidate raises `STREAM_CONSUMER_NO_LIVE_CANDIDATE`, from the leader only (one warning per declaration, like the leader-only assignment writer). The check is level-triggered: every reconcile pass re-derives it, and `STREAM_CONSUMER_CANDIDATE_RESTORED` (same subject) is raised once when the gap is gone, with the reason in its message: a live candidate again, leadership moved, the declaration is no longer evaluated (removed or colliding), the slice is no longer deployed, or the manager stopped. A slice still LOADING raises nothing, and an empty assignment list (membership or stream config not yet resolved) neither raises nor closes. `[verified: StreamConsumerManagerTest$WorkerTier#reconcile_raisesOneWarning_whenTheSliceIsActiveButNoHostIsLive]` `[verified: StreamConsumerManagerTest$WorkerTier#reconcile_raisesNothing_onAFollower]`
