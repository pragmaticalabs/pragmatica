### Changed (2026-11-05 — rc6 f5b: per-source provisioning breaker, auto-heal switch on worker and community paths)
- **The provisioning circuit breaker is one per source binding.** A source whose provisions fail three times in a row opens only its own breaker; another source keeps provisioning. Triggers act on the right source: `setDesiredCount` and a node joining reset the source concerned, a leader handoff and the NORMAL phase transition reset all, and only a provider-side provisioning failure counts against its own source. A capacity-admission refusal and an unresolved source are not provider failures: neither is counted, each keeps its own backoff window (one provisioning timeout; a committed configuration change ends an unresolved one) and is reported through its own operator warning (`provision-admission-deferred`, `core-replacement-source-unresolved`). `GET /cluster/topology/circuit-breaker` keeps its aggregate fields and adds `sources`; `GET /cluster/provisioning` adds the same under `circuitBreaker.sources`; the reset takes an optional `{"source": "<name>"}` (CLI: `--source`) and resets every source without it. [verified: ClusterTopologyManagerPerSourceBreakerTest]
- **Auto-heal disabled now holds the worker and community paths too.** The worker/spot reconcile makes no provision or terminate, and the community placement begins no operation, on the cluster's own initiative; the operator is told once per source/role or community (`auto-heal-scaling-held`) and enabling auto-heal resumes them (`auto-heal-scaling-resumed`). Not held: an operator-directed retirement, and a desired count or community `target_size` changed while auto-heal was disabled: the disable records each source/role's count and each community's `target_size`, and only a commit that changes that subject's own value releases it (with `auto-heal-scaling-resumed`). The disable is one transaction fenced on the configuration it read; a configuration change in between refuses it. `AutoHealStateValue` gains `disabledAtConfigVersion` and `disabledAtScaling`. [verified: ClusterTopologyManagerWorkerReconcileTest, CommunityPlacementReconcilerTest, ClusterTopologyManagerAutoHealDurabilityTest]
- **BREAKING (pre-GA flag day): the persisted `AutoHealStateValue` changes shape.** It gains `disabledAtConfigVersion`, and the codec is positional, so a build before this change cannot read a disable record written by this build, and this build cannot read one written before it (an rc5 snapshot or log that holds a disable record). Upgrade by coordinated replacement: do not run a mixed cluster, and re-issue any auto-heal disable after the upgrade. `[verified: wire-assignment-baseline.txt AutoHealStateValue SHAPE line]`
