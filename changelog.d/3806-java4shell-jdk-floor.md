### Security (2026-11-26 — #3806: CVE-2026-114938 "Java4Shell", an out-of-bounds write in the x86-64 Base64 decode intrinsic on AVX-512 VBMI CPUs)
- **The shipped images pin Temurin 25.0.5.1 and fail their own build below it; the node and Forge refuse to start on a vulnerable JVM on a VBMI host** (#3806). `aether-node`, `aether-forge`, the legacy `aether/forge/Dockerfile` and the `build-and-push.sh` image build from an exact `eclipse-temurin:25.0.5.1_2-*` tag (was the floating `25-*`) and run a build-time `java.version` check against `ARG JDK_FLOOR`. `JvmVulnerabilityGate.verdict` (a pure function of runtime version, os arch, CPU-flags source and the intrinsic-disabled flag) is called first in the node's `Main` and in `ForgeServer`, before the config is read and any listener binds: below 25.0.5.1 on x86-64 with `avx512vbmi` it refuses (names the CVE and the fix); with `-XX:-UseBASE64Intrinsics`, read live from `HotSpotDiagnosticMXBean`, it starts with a warning; unreadable `/proc/cpuinfo` warns and never refuses; a fixed JDK or a non-x86 host starts silently. `JdkFloorPinnedTest` ties the Dockerfiles to `JvmVulnerabilityGate.JDK_FLOOR`. Not changed: the cloud-init `temurin-25-jre` install (skipped when any JDK 25 exists; the gate covers such a host) and the `maven:3.9-eclipse-temurin-25` tag in `tools/quickstart-check.sh`.
