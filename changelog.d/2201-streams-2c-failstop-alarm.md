### Added (2026-11-03 — #2201: streams PR-2c, a WAL fail-stop raised no alarm and was not gauged)
- **A stream partition whose WAL fail-stopped refused every publish while nothing told an operator** beyond the pull field `wal.failStopped` (D-01).
- The fail-stop raises `storage-wal-fail-stopped` (CRITICAL) once per partition log with the subject `stream[partition]`, through a listener the partition manager registers when it opens the log, in place of the instance-level report [verified: aether/aether-stream/src/test/java/org/pragmatica/aether/stream/PartitionFailStopTest.java, WalFailStopObservabilityTripwireTest.java; integrations/storage/src/test/java/org/pragmatica/storage/AppendLogSectionStateTest.java].
- Every later publish to the partition is refused with `PartitionFailStopped` before it takes an offset [verified: PartitionFailStopTest.java]. Recovery: replace the node (management API `wal.failStopped`).
- `storage-wal-writable` (INFO, new) closes the partition's fail-stop only when the same WAL is reopened under the same node id (a whole-cluster restart; a replaced node never reopens it, because a node id never returns) and accepts its first durable write: the fail-stop leaves a mark file `<partition>.failstopped` beside the WAL, best-effort (a volume that refused the fsync may refuse the mark, and then no recovery is raised), and the reopen that finds it raises the recovery once, on every open path, and deletes the mark; deleting the log deletes its mark too [verified: PartitionFailStopTest.java `failStopThenRestart_firstDurableWrite_raisesTheRecoveryOnce`, `failStopThenRestart_hydratedPartition_raisesTheRecovery`, `failStopThenRestart_lazilyMaterializedPartition_raisesTheRecovery`; integrations/storage/src/test/java/org/pragmatica/storage/AppendLogFailStopMarkTest.java]. The instance-level `storage-wal-fail-stopped` (a log with no partition owner) still has no recovery.
- Gauge `aether.streams.wal.failstopped`: partitions on this node whose WAL fail-stopped, 0 from boot [verified: aether/node/src/test/java/org/pragmatica/aether/api/ManagementServerStreamSeamGaugeTest.java; aether/ember/src/test/java/org/pragmatica/aether/ember/EmberWalFailStopNodeTripwireTest.java `walFailStopOnTheOwner_isGauged`]. Ownership does not step down on a fail-stop (out of scope, spec Q7(i)) [verified: EmberWalFailStopNodeTripwireTest.java `walFailStopOnTheOwner_ownershipTripwire_ownerDoesNotMove`].
