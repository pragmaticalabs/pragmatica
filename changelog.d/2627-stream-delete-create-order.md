Stream delete then create of one name no longer deletes a stream reported as created (#2627): every `StreamConfigKey` submission for a name (create Put, publish-path auto-create Put, destroy Remove) now goes through a per-name commit lane and is submitted only after the previous one for that name settled, so a Remove can no longer commit ahead of or behind the Put it was issued against. `createStream` also reads the applier's answer to its Put: a Put the life fence refused is reported as `STREAM_ALREADY_EXISTS`, never as success.
