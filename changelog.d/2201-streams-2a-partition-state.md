### Fixed (2026-11-01 — #2201 PR-2a: a stream's per-partition state ends with its life; #1811: the materialization drain no longer blocks behind a head that does not fit)
- **A stream removed and created again under the same name starts clean.** Removing a stream (destroy, a committed config removal, or the idle reaper) now drops all of its per-partition state on this node: the replica epoch verdict, the owner's reported visible position, the catch-up install bookkeeping, the cut generation, the durable-flag dedup, the repair report state and the quarantine marker. Before, most of it outlived the stream, and a re-created stream of the same name inherited it; in particular config removal and the reaper left the quarantine marker behind, which fenced the new stream's fresh log so that a replica could never reach CAUGHT_UP. `[verified: StreamPartitionStateLifetimeTest$RecreatedStreamStartsEmpty, RecreatedStreamReachesCaughtUpTest (in-JVM, one manager)]`
- **A committed life that replaces this node's losing proposal inherits none of its state.** When a stream create on this node loses to another node's committed incarnation, the state recorded under the name while the proposal was local is dropped before the committed life is opened. `[verified: StreamPartitionStateLifetimeTest$LosingLifeReplaced (in-JVM, one manager)]`
- **#1811: a queued materialization that no longer fits the off-heap budget no longer blocks its class.** The drain takes the first queued partition of the class that fits; the skipped one keeps its place and is offered first on the next pass. `[verified: MaterializationSchedulerTest (in-JVM, one manager)]`
- **Internal:** the manager's per-partition state is extracted into `PartitionState` (held per stream in `StreamEntries`) and its scheduling state into `MaterializationScheduler`; no public signature changes.
- **Known limit L-20:** a large queued partition can wait while smaller ones are materialized; its wait is bounded only by budget being released (see `known-limitations.md`).
