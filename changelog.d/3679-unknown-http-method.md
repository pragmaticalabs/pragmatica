### Fixed (2026-11-24 — #3679: HTTP ingress treated an unknown method as GET)
- **An unknown HTTP method is refused with 501, not answered by the `GET` handler** (#3679). `NettyHttpServer`, `RequestGate` (HTTP/1.1) and `Http3Server` folded a method outside `HttpMethod` to `GET`, so `PROPFIND /path` was routed, authorized, audited and answered as `GET`. Each now refuses it with 501 Not Implemented (RFC 9110 §15.6.2) on the request head, before the classifier and any handler; an absent HTTP/3 `:method` pseudo-header is answered 400. The server has no HTTP/2 listener. `HttpMethod.fromString` now delegates to `HttpMethod.httpMethod`, and that parser folds case over ASCII letters only (`POſT` was read as `POST`); the request contexts of `http-routing` and `http-routing-adapter` take the method from the matched route instead of re-parsing it with a `GET` fallback. A method the route table knows but the route does not allow stays 405.
