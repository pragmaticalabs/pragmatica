### Added (2026-11-18 — #3345: leader-side records of a held DHT drain, internal and not wired yet)
- **Internal: the leader-side record of a held drain** (#3345). The state is kept per (node, episode): open, then closed by exactly one of four closings (delivered, loss accepted, dead, superseded), and a closed episode stays closed: a later report of it, or of an older episode, is ignored. A report of a newer episode of the same node closes the open older one as superseded (naming the successor and carrying the last report's counts) and opens the new one. The unit raises the at-risk warning and re-raises it until the raise lands, raises each closer until it lands, and takes the decision to accept a loss: the override is checked against the episode's own last report (kept after the live view drops it), the acceptance is relayed only after its record landed, a record that did not land is a typed refusal and can be retried, and a delivered report that arrives first wins. Report time is read from a monotonic source and an older report never overwrites a newer one. A new leader latches from the landed event log; until the first held report after a seeding gap (an evicted at-risk event, a new owner of the log partition) `heldLatched` is false. No node reports a held drain yet and nothing calls this unit, so nothing changes at run time. [verified: 49 unit tests; 21 mutants, each red]
