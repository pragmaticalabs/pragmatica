### Fixed (2026-11-19 — #3292: the Hetzner ingress-firewall check failed open when the cluster label was lost or the cluster name was long)
- **Provisioning now fails closed when a cluster's ingress firewall cannot be identified** (#3292). A firewall that lost its `aether-cluster` label was invisible to the label selectors, so a replacement server was created with no firewall association; it is now found by its `aether-<cluster>-` name in the unselected firewall listing (only unlabelled firewalls count, so another cluster's firewalls do not block auto-heal) and the provision is refused with a typed cause. For cluster names of 56+ characters the name prefix is cut at the 63-character firewall-name bound, as the name itself is, so the name match no longer misses. A failed unselected listing refuses too. [verified: `HetznerComputeProviderTest$FirewallAssociationTests` (label-loss, long-name and listing-failure cases red on the old check)]
