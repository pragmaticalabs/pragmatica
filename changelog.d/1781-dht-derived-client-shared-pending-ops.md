### Fixed (2026-09-30 — #1776: derived DHT clients never received remote replies)
- **A `DistributedDHTClient` derived with `scoped()` or `withResolveFallbackObserver()` could not complete a read whose reply came from a remote node.** Each derived instance owned a separate `pendingOps` map, while `AetherNode` routes DHT replies to one instance only, so the reply found no collector and the read waited out its timeout. The cache and idempotency SPI client (scoped with `CACHE_DEFAULT`, RF1, 30 s) was affected: a key owned by a remote node was a 30 s miss in the cache, and failed the request in the idempotency store, which has no recover on `get`.
- **Derived instances now share the base client's `pendingOps`.** Correlation IDs are globally unique, so a reply resolves the collector that issued it whichever instance receives it. Replication factor, quorum sizes, timeout and scope stay per instance.
- `DistributedDHTClientDerivedReplyTest` delivers the reply through the base client's `onGetResponse` to a derived instance's read (the router's path), with a base-read control and a per-instance-config pin.
- **A request whose peer never answers no longer stays in the reply table.** Entries were removed only on a reply, a refusal or a departure, so a replica that stayed silent (after a quorum success, a fast-fail or a timeout) or a silent replacement read left its entry in the shared map for good. Each entry now lives until every reply of its operation has arrived or the operation timeout has passed since the request was sent, whichever is first. It is not dropped the moment the operation completes, because a reply landing after the quorum still feeds the late-stale evidence of a write and the late value a read discarded, both of which wait for all replies for at most that timeout. Expiry and a late reply arbitrate on the atomic `pendingOps.remove`, so exactly one of them owns the entry. [verified: `DistributedDHTClientPendingOpsTest.timedOut*`, `silentReplicaAfterQuorum_*`, `lateReplyInsideTheWindow_*`, `silentReplacementRead_entryExpires`] `DistributedDHTClientPendingOpsTest` also pins Put, Remove and Exists replies delivered through the base client to a derived one.
