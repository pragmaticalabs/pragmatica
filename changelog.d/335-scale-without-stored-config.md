### Fixed (2026-09-04 — #335: scale against a cluster with no stored config answered 500)

- **`POST /api/v1/cluster/scale` against a fresh, unconfigured cluster (e.g. right after a `docker compose down -v` volume wipe) answered HTTP 500 `{"detail":"No cluster configuration stored"}`.** The cause was `ClusterConfigRoutes`'s shared `ConfigNotFoundError`, a plain `Cause` with no HTTP status override, defaulting to 500 through `ProblemResponses.resolveStatus`.
- **Bootstrap-on-scale was considered and ruled out.** A `ScaleRequest` carries only `source`/`role`/`count`/`expectedVersion` — none of the cluster name, semver version, distribution strategy, zones, or deployment settings a `ClusterConfigValue` requires, all of which the #290 formation-bootstrap path derives from a fully parsed `aether-cluster.toml`. Synthesizing those from a scale request would fabricate a cluster identity nobody declared.
- **The route now refuses with a typed `ClusterConfigError.NoConfigToScale`, HTTP 409**, naming the actual recovery (`aether cluster bootstrap <aether-cluster.toml>`, then retry the scale) with the request's own source/role/count filled in — never a 500, never a guess. The stored-config path is unchanged [verified: aether/node/src/test/java/org/pragmatica/aether/api/routes/ClusterConfigRoutesScaleNoConfigTest.java].
- Docs updated: `management-api.md`'s `POST /api/v1/cluster/scale` Conflicts section and `cli.md`'s `aether cluster scale` section both now state the no-config 409 and its recovery command [mechanism: docs cross-checked against the same message text the route emits].
