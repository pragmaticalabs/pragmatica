### Fixed (2026-09-30 — integration harness: node logs are captured at the first [FAIL] and before destructive restarts)
- **A failed test's node logs no longer depend on surviving until suite end.** In run 1, `Kill_node_during_active_load` failed and a later S20 full-drain rebootstrap recreated every container before the suite-end capture ran, leaving no log from the failing window. `log_fail` now captures every node's log at a test's first `[FAIL]` (once per test) into `failure-logs/<suite>/<test>/<stamp>-first-fail/`, and `restart_all_nodes` and the cloud reap capture into `<stamp>-before-<step>/` first when the suite already has a `[FAIL]`. [verified: `aether/tests/integration/test/test-failtime-capture.sh`]
- Harness only; pass/fail semantics are unchanged. The cloud-reap hook is pinned by source order, not by execution. [unverified: no cloud run has exercised the hooks]
- The fail-time capture reads `BOOTSTRAP_CLUSTER_NAME` (exported per suite) when `CLUSTER_A_NAME`/`CLUSTER_B_NAME` (plain variables of the runner process) are absent, so it reaches the cloud VMs from a test process. It is bounded (30s per VM, a timeout on the docker branch, at most 6 first-fail captures per suite) and warns when a capture holds no node logs. [verified: `aether/tests/integration/test/test-failtime-capture.sh` T8-T11]
- The capture writes nothing to stdout or stderr, so a caller's `$(fn 2>&1)` around code that hits `log_fail` receives unchanged data; its own notes go to `failure-logs/<suite>/failtime-capture-notes.txt` (and the terminal, when there is one). [verified: `test-failtime-capture.sh` T12]
