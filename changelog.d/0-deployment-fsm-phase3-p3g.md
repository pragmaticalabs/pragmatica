### Fixed (2026-10-24 — deployment state machine rewrite, phase 3 P3-G)
- **An FSM2 deploy no longer submits its target batch twice.** The intake re-drive of an open apply treated a target put that was still in flight as missing, so the first reconcile after a publish sent the declaration's batch again, and the applier refused it: one wasted round and one `refused_version` per deploy. The re-drive now skips a base while a target put for it is in flight, whatever its version, since both would expect the same committed target. The put stops counting as in flight when it commits, or when it fails, expires or is dropped while the leader is suspended and an open apply will re-drive it. A put no open apply re-drives, and a refused put, stay with the awaited-target watch, which re-sends them at its bound, as before.
  [verified: `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/TargetRedriveTest.java`, `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/LifecycleTest.java`, `aether/node/src/test/java/org/pragmatica/aether/deployment/cluster/fsm2/SlBlueprintTest.java`]

### Added (2026-10-24 — deployment state machine rewrite, phase 3 P3-G)
- **`aether_deployment_fsm_applies_total{fsm}` counts the leader's `apply(List)` calls**: one per apply that left for the consensus engine, none for an empty step or one the pre-submit check withheld. A leader round is one apply. This counter stands in for committed consensus batches while one apply = one batch is unverified. `submissions_total` still counts transactions.
  [verified: `aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/wiring/ClusterFsmInterpreterTest.java`]
- **E-01 asserts the leader's round budget**: exactly `2 + 2·S·I` transactions and at least 4 applies for a clean deploy; drain splits are timing-dependent and measured, not bounded (4 to 7 applies observed, 8 transactions every run).
  [verified: `aether/forge/forge-tests/src/test/java/org/pragmatica/aether/forge/Fsm2DeployE01Test.java`]
