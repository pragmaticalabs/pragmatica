### Fixed (2026-11-24 — #2811: replacementCeiling(CORE) read the first cloud source by name, not the replacing node's source)
- **A core replacement's in-flight ceiling is read from the source it is dispatched to** (#2811). It was the first cloud source declaring `core`, sorted by name, whichever source the departed node belonged to: with two cloud sources declaring `core` a replacement in the second got the first one's `replacement_ceiling` (expiry dropped the in-flight entry, the deficit re-dispatched, and the leader minted a duplicate it then drained as surplus, plus extra VM billing), and a Docker core replacement got the cloud ceiling instead of the ten-minute default. `ClusterTopologyManager.replacementCeiling(role, departed)` now resolves the source through the same `healSource` as `provisionReplacement`, so ceiling, zones, instance type and provider ride one source; when that source cannot be resolved it answers the longest ceiling over the sources declaring the role, which never abandons a replacement early. A new leader's inherited entries carry no departed node, so they take the same single-source or longest-ceiling answer. Stale comments that said a refusal or `SOURCE_UNRESOLVED` is counted as a provisioning failure are corrected (it is paced by its own refusal window and never counted).
