### Added (2026-11-13 — #3162: Fray interleaving test for SharedPools)
- **`SharedPools.closeAll` racing `acquire` and a view's `stop` is now explored by Fray (PCT scheduler) on the real code.** The test pins: no view handed out was made after its pool was closed, an acquire started after node stop returned is refused, and every opened pool closes exactly once. It runs on demand only: `mvn test -Pfray -pl aether/resource/api` (the profile builds Fray's instrumented JDK; the default build neither compiles nor runs the `FrayTest` class). `[verified: SharedPoolsFrayTest, 300 iterations green at head, red against the pre-fix SharedPools]`

### Fixed (2026-11-13 — #3171: SharedPools never hands out a view of a pool node stop already closed)
- **A holder racing node stop could receive a view of a pool the drain had already closed.** `SharedPools` now sets the stop flag before the drain registers any close, and after making a view re-reads the flag: a view made while the flag was still clear came from an open pool and is handed out; otherwise the view is discarded and the holder fails with `ProviderClosed`. `[verified: SharedPoolsAdmissionRaceTest.closeAllDuringProvisioning_holderFailsWithProviderClosed_notAViewOfAClosedPool red without the fix, SharedPoolsFrayTest]`
