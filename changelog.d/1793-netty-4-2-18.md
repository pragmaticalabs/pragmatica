### Changed (2026-10-01 — #1793: Netty 4.2.9.Final to 4.2.18.Final)
- **`netty.version` is `4.2.18.Final`.** `netty-codec-native-quic` follows transitively through `netty-codec-http3`; quiche is 0.29.2. Carries the 4.2.15 security batch (23 CVE fixes, including codec-http3 and quic-classes) and the 4.2.18 QUIC/QPACK/io_uring fixes. Operator note: Netty requires an `X509ExtendedTrustManager` when QUIC hostname verification is enabled (4.2.18).
- **QUIC clients keep chain verification only, no hostname match.** Netty 4.2.11 (#16426) turned hostname verification on by default for QUIC clients; nodes dial by IP and certificates carry no IP SAN, so every cluster handshake failed with `CERTIFICATE_VERIFY_FAILED`. `QuicSslContextFactory.withoutHostnameVerification` restores the 4.2.9 behaviour on both client builders; peer identity stays with the Hello check (#1758). Real verification (IP SANs plus a verified server name on dial) is future work. `[verified: integrations/net/tcp/src/test/java/org/pragmatica/net/tcp/QuicClientHostnameVerificationTest.java — mutation: removing the opt-out turns both tests red]`
