### Changed (2026-11-25 — #3333: the hot window is clamped to the replay-window share, `expected_ingress` and a per-group `latest` are refused as not yet available)
- **Behaviour change, hot window clamp with a warning:** after every refusal of the floors, a `hot.max_bytes` (written or defaulted) above the per-partition replay-window share is lowered to the share and stored so in the resolved declaration, with one warning (`hot-window-clamped`) that names both values and the key that sets the share. `hot.max_count` is never clamped, and with no share computable at parse (an age bound only) nothing is clamped. `retention.mode = "all"` with `retention.max_count` raises a warning (`retention-all-count-sized-by-max-event`) naming `(max_count / P) x max_event_size`; `any` raises none. These are parse warnings, not operator warning codes: the deploy validator reports each as a response warning whose rule is its id, for the streams it accepts. [mechanism: unit-tested, `StreamConfigParserClampTest`, `StreamResourceValidatorTest.DeclarationWarnings`]
- **Behaviour change, refusal:** `expected_ingress` under `[streams.<alias>]` is now a known key that is refused whatever its value (`not-yet-available`, release S5, where the footprint plan reads it), instead of an unknown key; nothing is stored, and the check runs after every other refusal. [mechanism: unit-tested, `StreamConfigParserClampTest`]
- **Behaviour change, refusal:** a per-group `auto_offset_reset` under `[streams.<alias>.consumers.<group>]` is now read: `earliest` is accepted (every group starts there today, so nothing is stored), `latest` is refused (`not-yet-available`, release S1a), any other value is a malformed value. The dashed spelling is refused naming the snake_case key. The same gate applies to the consumer tables of an external stream. Before, the key was ignored silently. The stream-level `auto_offset_reset` is unchanged; its refusal text now points at the per-group key. [mechanism: unit-tested, `StreamConfigParserClampTest`, `InertStreamConfigParityTripwireTest`]
- **Added:** `max_event_size`, `hot.max_bytes` and the other size keys accept `KiB`, `MiB` and `GiB` as spellings of `KB`, `MB` and `GB` (1 KiB = 1 024 bytes), in any case. [mechanism: unit-tested, `StreamConfigParserClampTest`]
