### Changed (2026-10-18 — #2243: the networking docs and transport javadoc described a different transport than the code)
- **Documentation corrected, no behaviour change.** The architecture and operator networking pages said HTTP/3, 0-RTT, a handshake with capabilities, a Ping/Pong heartbeat, a 30 s idle timeout, 16 MB / 4 MB flow control, four stream types with short-lived streams, a per-stream queue of 100, a Fury-serialized envelope, and a quorum decision inside the transport. The code is raw QUIC (ALPN `aether-cluster/1`), no 0-RTT configured, a `Hello` of NodeId, address, labels, boot token and intended peer, a one-way `KeepAlive`, no idle timeout, 64,000,000 / 32,000,000 byte flow control, eight long-lived lanes, a per-peer offline buffer, and length-prefixed generated-codec frames. Both pages now say that; `quic-transport-spec.md` is marked superseded.
- Added a cluster transport row to `guarantees.md` (best-effort, unacknowledged, per-lane FIFO only for frames written once to one live stream) and entries to `known-limitations.md` for certificate rotation (a restart of the QUIC server), the 32 MiB state-transfer bound and the 10,000-frame offline buffer. The "a dead NodeId never returns" statements are restated precisely (a different process is refused; the same process the cluster wrongly declared dead can be re-admitted).
