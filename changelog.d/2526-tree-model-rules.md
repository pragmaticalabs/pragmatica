### Added (2026-11-25 — #2526: jbct-lint: package-tree rules replace the rank and slice-internal layering checks, step P3)
- **`JBCT-TREE-01` (no sideways import inside the package tree) and `JBCT-TREE-02` (a main file is declared under `[project] basePackage`)** (#2526), WARNING, business mode only. The tree root is `[project] basePackage` of the source root and nothing else; `[lint.tree] exclude` globs keep a package out of the tree. A business source root whose base package is missing, has an `io` or `shared` segment after its first, or covers no main file is refused: the TREE rules do not run for it, the code rules still run and report, `jbct lint` exits 2 and the Maven goal fails with the same text (infrastructure, format-only and disabled roots never read the key). Each run prints a `JBCT-TREE-0n: judged K of N file(s)` coverage line, `0 of N` included.
### Removed (2026-11-25 — #2526)
- **`JBCT-ARCH-04` (slice-internal imports) and `JBCT-ARCH-01`'s layer-rank check are deleted**; `JBCT-ARCH-01` keeps its domain-framework check. `JBCT-TREE-01` replaces ARCH-04.
### Changed (2026-11-25 — #2526)
- **A `[lint.rules]` key that is no registry ID refuses the configuration load**, naming the key and value; a retired rule names its replacement (`JBCT-ARCH-04` -> `JBCT-TREE-01`, `JBCT-SEAL-02` -> `JBCT-CAUSE-01`). Before, such a key changed nothing silently. `jbct:generate-blueprint` reads the same configuration, so it stops on such a key too.
