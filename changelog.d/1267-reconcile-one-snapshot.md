### Performance (2026-09-19 — #1267: consumer reconciliation re-collected every declaration once per desired subscription)
- **Each reconcile pass rebuilt the full declaration list once per desired subscription key, including keys that were already active**, and re-filtered every durable-topic subscription each time. That was S+1 collections per pass for S desired keys, and `dropStale` ran `contains` over a `List`.
- A pass now reads ONE declaration snapshot, groups it once by `(stream, group)`, and resolves every key against that map. The desired set is a `LinkedHashSet`. Resolution now reads the same snapshot the collision check was computed from, so a pass can no longer mix two snapshots. [mechanism: `StreamConsumerManagerTest.ReconcilePasses.reconcile_readsTopicDeclarationsExactlyOnce_perPass` asserts one `TopicGroupDeclarationSource` read per pass. It read 5 at `ccba0dba5` for S = 4, and goes RED when resolution re-collects per key]
- **A test changed because it pinned the old mechanism.** `declarationFor_refusesToPickAWinner_whenACollisionAppearsBetweenTheTwoDeclarationReads` drove a collision that landed between a pass's two declaration reads. With one read per pass, that interleaving no longer exists. The test is now `reconcile_readsOneSnapshotPerPass_andRetractsOnTheNextPass_whenACollisionLandsBetweenPasses`. It asserts one registry read per pass, and that the next pass retracts the attachment as soon as the collision becomes visible. The refusal branch in `declarationFor` stays as a fail-closed backstop that no single-snapshot pass reaches.
