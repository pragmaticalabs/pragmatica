### Added (2026-10-28 — #2450 A3-0: durable anchors)
- **Storage tiers and instances can keep durable anchors**: small versioned records that a cold boot reads to find a namespace's catalog root when there is no consensus state and no `[backup]`. Nothing writes them yet; the catalog (A3-3) will.
  - `StorageInstance.putAnchor(name, version, value)` writes the version to every durable tier at once and resolves only when all of them have, the acknowledgement rule of a block write (#1567). A local-disk tier forces the file and then its directory; an S3 tier resolves on the provider's 200. Non-durable tiers (memory, in-memory DHT) are skipped. An instance with no durable tier refuses.
  - `StorageInstance.latestAnchor(name)` asks every durable tier and returns the highest version. A tier that cannot answer fails the read rather than giving a partial view.
  - A durable tier that does not implement anchors refuses, rather than reporting "no anchor" and losing the names anchored on it.
  - On S3 the newest version is the first key of a one-key LIST (version keys are fixed-width and inverted), so it is one LIST and one GET however many versions exist. This requires read-after-write LIST and ascending key order: AWS S3 general-purpose buckets and MinIO provide both, AWS directory buckets do not. [unverified: other S3-compatible stores]
  - On an encrypted instance the anchor value is encrypted like a block, bound to the anchor's name and version. A version written before a key rotation reads after it.
  - **Fails closed on corruption.** If the newest version on a tier is damaged (checksum, length, a copy of another version, a value that does not decrypt), or two tiers hold different values for one version, the read fails with `AnchorCorrupt`/`AnchorDiverged`. No older version is returned in its place. A new operator warning, `storage-anchor-corrupt` (CRITICAL), is raised once per tier and anchor, and closed by `storage-anchor-readable` (INFO) when that tier's newest version reads back whole again. Accepting a version is an explicit operator action, designed in A3-3.
  - Anchors live under `anchors/` on a tier and are not counted in a disk tier's used bytes.
  - [verified: `AnchorTierTest`, `EncryptingAnchorTest`, `StorageInstanceAnchorTest`]
- **`[storage.<instance>] anchor_retention`** (default 8, at least 2, refused at load otherwise): after version `v` is written, versions below `v - anchor_retention` are pruned in the background, at most one prune per anchor at a time. A prune failure is logged and counted and never fails the write. The default is provisional, pending the catalog commit benchmark. [verified: `ConfigLoaderTest`, `StorageMaintenanceWiringTest`]
