### Performance (2026-09-19 — #1264: stream read routers were rebuilt on every partition read)
- **Every partition read built a fresh `ForwardingReadRouter`** — its `LinearizableOwnerServe`, two capturing lambdas and a bound method reference — `partitionCount` times per `fetch(from, max)` on the typed path (`PartitionedStreamAccess`) and once per call on the raw path (`StreamReadRouter`).
- The typed path now builds its router once, at construction; the raw path builds one router per `ReadPreference` into an `EnumMap`, once, because the preference varies per call there. Every input is a `final` field. [mechanism: `ReadRouterCachingTests.readRouter_returnsIdenticalRouter_acrossTypedReads` and `readRouter_returnsIdenticalRouterPerPreference_acrossRawReads` in `PartitionedStreamAccessTest` assert object identity across reads; each goes RED when its path is reverted to per-call construction]
- **Ownership is not frozen by the cache.** The router caches the mechanism, not the answer: the owner resolver still runs at route time. [mechanism: `fetch_forwardsToNewOwner_whenTypedOwnerChangesBetweenReads` and `read_forwardsToNewOwner_whenRawOwnerChangesBetweenReads` swap the resolver's owner between two reads and assert the second read forwards to the new owner; each goes RED under a mutation that memoizes the resolver's first answer.
