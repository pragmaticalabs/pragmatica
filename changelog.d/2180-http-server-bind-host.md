### Added (2026-11-25 — #2180: HttpServerConfig can bind a single local address)
- **`HttpServerConfig.withBindHost(host)`** (#2180). Both the HTTP/1.1 and the HTTP/3 server bound the wildcard address, so a service could not limit its exposure at the socket level (LAN-only, loopback-only). An optional bind host narrows the listening socket to one local address; none, the default, binds every interface as before. A host that is blank or does not resolve fails the start with the typed `HttpServerError.BindHostUnresolved` (the owned event loops are released first) instead of falling back to every interface. The record gained a trailing `Option<String> bindHost` component, so its 11-argument canonical constructor is replaced by a 12-argument one (no caller in the repository used it; the 9-argument constructor remains); `httpServerConfig(name, port)` and every `with*` are unchanged for callers. [verified: `HttpServerBindHostTest` (a loopback-bound listener refuses the machine's other address on TCP, and on UDP by ICMP port-unreachable; the default serves it), `HttpServerConfigTest`]
