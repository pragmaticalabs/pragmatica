### Added (2026-11-25 — #2180: HttpServerConfig can bind a single local address)
- **`HttpServerConfig.withBindHost(host)`** (#2180). Both the HTTP/1.1 and the HTTP/3 server bound the wildcard address, so a service could not limit its exposure at the socket level (LAN-only, loopback-only). An optional bind host narrows the listening socket to one local address; none, the default, binds every interface as before. A host that is blank or does not resolve to an address fails the start with the typed `HttpServerError.BindHostUnresolved`, and one that resolves to an address this machine does not own fails in the bind as `HttpServerError.BindFailed`, which now carries the host (`Failed to bind to <host>:<port>: ...`; unchanged without one); the owned event loops are released first in both cases, instead of falling back to every interface. The record gained a trailing `Option<String> bindHost` component, so its 11-argument canonical constructor is replaced by a 12-argument one (no caller in the repository used it; the 9-argument constructor remains); `httpServerConfig(name, port)` and every `with*` are unchanged for callers.
