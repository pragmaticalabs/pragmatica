### Changed (2026-11-15 — #2767: FSM2 is the default deployment engine)
- **New clusters run the FSM2 deployment engine by default** (#2767, FSM replacement plan F6). `AetherNodeConfig` and the Ember/Forge harness selector default to FSM2; the test harness (Ember/Forge) still selects LEGACY through its own engine property until LEGACY is deleted (F7); that property is a test-harness setting, and a production node has no engine setting. A cluster's committed engine marker still decides: a node whose configured engine disagrees refuses itself (`deployment-engine-mismatch`). [mechanism: one default at `AetherNodeConfig` and one at `EngineSelector`; unit tests `EngineSelectorTest`, `EmberClusterDefaultEngineTest`, `AetherNodeConfigRedactionTest`]
- **A backup without an engine marker (rc4 and earlier) restores into the running engine** (plan 3.2 delta (a)). The restore's finish keeps a marker minted locally during the restore, or mints the restoring node's own engine marker; it no longer removes the marker, which left an FSM2 cluster reading LEGACY and refusing every node. [mechanism: the marker arm of the restore finish targets the backup's marker, else the local one, else the running engine's; `BackupRestoreCoordinatorTest`, no multi-node failure injection]
- **Stop-the-cluster upgrade: an rc4 cluster cannot be upgraded in place.** Every node on the new binary reads "incarnation present, marker absent", refuses itself with `deployment-engine-mismatch` and exits. The path is a new cluster on the new build plus a restore of a backup into it. Pre-GA: no migration path is provided.
