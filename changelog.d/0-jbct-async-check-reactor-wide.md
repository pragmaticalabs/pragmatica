### Changed (2026-10-21 — JBCT-ASYNC-01 runs in every aether and integrations module; pure factories are not effects)
- **`jbct-async-check` is now a `provided` dependency of the `aether` and `integrations` parent poms**, so javac discovers it in every module of those trees that compiles Java without its own `annotationProcessorPaths` (the slice modules already list it in their processor paths). Findings stay at WARNING; a module opts out with `-Ajbct.async.severity=off`. `core`, `jbct`, `examples` and `terra` are not covered by this change: `core` because `jbct-async-check` tests against it (a dependency would be a reactor cycle).
- **Building a value is not an effect.** `Cause.promise()`/`result()`, `Promise.success/failure/ok/err/resolved/unitPromise/promise` and `Unit.unit()` are no longer reported when a callback only builds and discards one (their arguments are still scanned). Found by the reactor-wide verification: `SchemaMigrations:107` reported `calls Cause.promise(...)`.
- Publish-set doc: the reactor total is 177 modules (39 publish, 138 skip), matching the root build; it said 178.
