### Fixed (2026-11-06 — #2777: `WaveExecutorReplaceBeforeRetireTest` flake, test-only)
- **The replace-before-retire test took its URL scheme from a process-wide endpoint another test class had left behind** (#2777). The drain and readiness URLs get their scheme from `ClusterHttpClient.resolveEndpoint()` (the static `ENDPOINT_OVERRIDE`, else the operator's registry); when a class that ran earlier in the same JVM left an `https://` endpoint there, the three drain-wait tests sent to `https://...` and failed their `http://` address assertions after the 4 s of drain polling. The leaker was `ClusterDestroyCommandTest.TargetApiKey`, which restored the API key but not the endpoint `installTargetOverrides` installs; it now restores both, and the replace-before-retire test also pins an `http` endpoint in `@BeforeEach` (and restores it) so it no longer depends on any earlier class or the operator registry. No production file changed. [verified: whole cli package red on the old test, green with the pin; class mutation removing the pin goes red]
