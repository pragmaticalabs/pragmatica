### Fixed (2026-09-29 — #1633: a record field typed by a `@Codec` sealed interface generated code that did not compile)
- **A `@Codec` record may now have a field whose type is a `@Codec` sealed interface.** The generated record codec called `<Interface>Codec`, but the processor emits codecs only for the permitted subtypes, never for the sealed parent, so the generated source failed to compile. Such a field is now written with its runtime subtype's own tag and read back by that tag, the same way an `Object`-typed or generic field is. No existing generated codec changes: before this fix, a record with such a field did not compile at all. [verified: integrations/serialization/codec-processor/src/test/java/org/pragmatica/serialization/codec/CodecProcessorTest.java — `recordWithSealedInterfaceField_compiles_andRoundTripsEachSubtype` compiles the record and round-trips a value of each subtype through a real `SliceCodec`; the generated code failed to compile before the fix]
