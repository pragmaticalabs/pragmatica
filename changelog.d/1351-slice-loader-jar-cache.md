### Fixed (2026-09-20 — #1351: closing a slice class loader poisoned the JVM's shared jar cache; every later blueprint apply of that artifact 500'd)
- **Unloading a slice could make every later deploy of the same artifact fail `zip file closed` for the rest of the node's JVM.** `URLClassLoader.getResourceAsStream` reads through the JVM-shared cached `JarFile` and registers it in the loader's closeables, so `SliceStore.cleanup` closing the slice loader after a `META-INF/slice/*.manifest` read closed a jar every other reader shares — and a `jar:` open racing that close re-cached the closed instance permanently `[mechanism: JDK JarURLConnection.connect getOrCreate → getEntry → cacheIfAbsent; only URLJarFile.close evicts]`. Surfaced as 7 forge-test failures on PR #1277.
- Slice, shared-library and framework class loaders — and the throwaway loader that pre-reads `resources.toml` — now read resources with `useCaches=false`: the jar handle is private and closed with the stream, and the loader's reads never touch the shared cache `[verified: aether/slice/src/test/java/org/pragmatica/aether/slice/UncachedResourceClassLoaderTest.java, SliceStoreTest.buildSliceCompositeFromClassLoader_readingOwnJarToml_leavesTheSharedJarUsable — unit-level; the race itself is not deterministically inducible and is covered by the mechanism]`.
- The manifest readers in `NodeDeploymentState` and `TopologyParser` that swallowed the failure at DEBUG now WARN, naming the artifact, the manifest path and the exception; a jar with no manifest stays quiet `[verified: aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/node/fsm/NodeDeploymentStateManifestReadFailureTest.java (the LOAD → ACTIVE chain with a loader that fails every read: 3 reactive + 1 config-update + 1 stream-role WARN; and with a loader answering null: no "Could not read" WARN), aether/slice/src/test/java/org/pragmatica/aether/slice/topology/TopologyParserManifestReadFailureTest.java (both branches)]`.
