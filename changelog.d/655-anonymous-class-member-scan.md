### Fixed (2026-09-29 — #655: member scans counted anonymous-class methods and local records as the enclosing type's own members)
- **JBCT-ORD-01 no longer ranks an anonymous class's methods as members of the enclosing type.** An anonymous class body has no type node of its own, so an anonymous implementation returned from a use-case factory read as "`execute` after the factory", and an anonymous class in a constant's initializer read as a method before the next constant. Member scans (`FileTypeClassifier.directMethods`) now stop at a code block, a variable initializer or an enum constant. A genuinely misordered member of the type itself is still reported. [verified: jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/rules/CstMemberOrderingRuleTest.java — `AnonymousClassMembers`]
- **A step interface with a record declared inside a default method is still classified as a step interface.** Only a type in the interface's own member list disqualifies it. [verified: jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/filetype/FileTypeClassifierTest.java]
- Linting all 2,400 main-source files in this repository gives byte-identical output before and after the change.
