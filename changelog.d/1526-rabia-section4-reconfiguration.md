### Changed (2026-09-27 — #1526: voter reconfiguration follows Rabia §4; genesis waits for the full roster)
- **#1390's certified voter handoff could wedge permanently once cores run in-memory Rabia (#1525):** with voters {A,B,C}, C dead and D replacing it, losing B after the barrier left A frozen awaiting a checkpoint transfer only B could send. The barrier, checkpoint transfer, certificates and installation acknowledgements are removed; their wire tags 115, 118, 119, 121 and 122 are retired, never reused.
- A voter change is now a Rabia §4 special command, `ReconfigurationCommand(baseEpoch, target)`, carried on `Propose`/`Decision`: Weak-MVC agrees slot R and the target roster governs from R+1 on every replica, including one that applies R late. A single add, a single remove and a one-slot replacement are expressible; a change must retain a majority of the target from the current roster. A decided command whose base epoch has passed is a deterministic no-op. The common coin is seeded by slot plus epoch. [mechanism: slots are strictly sequential, so no replica votes in R+1 before applying R] — pinned in-JVM by `RabiaReorderedDeliveryTest` (the {A,B,C}→{A,B,D} scenario keeps deciding with {A,D}; it wedges at the previous head) and `RabiaVoterReconfigurationTest`; not yet exercised on a live cluster [design intent — unverified].
- An added voter adopts a newer epoch from one live responder in the configuration it claims, and repairs a missed slot R from any peer that completed it. The reconfiguration promise completes when the command is applied; retirement and the next `CoreVoterReconciler` change wait until nothing is pending and every added member has been seen voting past R.
- **Genesis no longer aborts assembly when a configured core is late:** `cluster.genesis_voters` is optional, and without it a node waits, re-reading its discovered core membership every two seconds until it names exactly the configured count (`GENESIS_PENDING` in node status). A blank id in `cluster.genesis_voters` still fails boot. A sync response carrying a different roster at the same epoch is refused. Recovery action for a node stuck in `GENESIS_PENDING`: make every configured core reachable, or set `cluster.genesis_voters`.
- Node status `voterReconfiguration` now reports `stage`, `installedEpoch`, `installedVoters`, `targetVoters`, `effectiveSlot`, `awaitingCatchUp` and `failure`; the certificate witness counts and barrier slot are gone.
