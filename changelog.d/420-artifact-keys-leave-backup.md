### Changed (2026-11-20 — #420: the artifact keys leave the backup; flag day, whole-cluster restart)
- **Breaking: `ArtifactVersionsKey` and `ArtifactContentKey` are no longer backed up** (#420, RR-4). `isBackedUp()` returns false on both, in one commit, so a backup carries no artifact line. A backup written before this change holds artifact lines; decoding one is refused `KeyNotBackedUp` and the restore stops as `document undecodable`, the same operator step as in the artifact-record entry (point `[backup]` at a new empty repository and start with `restore = "fresh"`). The codec keeps the two key bindings so that an old line is named `KeyNotBackedUp` rather than failing as an unknown key; no skip rule is added.
- **The trade:** after a restart the operator re-uploads artifacts and rebuilt jars are accepted, and the version listing and the archived flags are gone, so an archived version can be published again (R-17). This applies to backups the in-memory ruling for the artifact store.
