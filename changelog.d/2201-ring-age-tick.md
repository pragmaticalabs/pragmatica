### Changed (2026-10-18 — #2201 A-07 follow-up: the ring now applies the stream's declared max-age)
- **Behaviour change: events older than a stream's `max-age` now leave the in-memory ring on a 60 s node tick, even when the ring is not full.** Until now the age limit was never applied to the ring (`OffHeapRingBuffer.evictByAge` had no production caller); the ring kept events until capacity pressure and `max-age` governed the sealed tier alone. `StreamPartitionManager.evictRingsByAge`, scheduled by `AetherNode` every `RING_AGE_TICK_INTERVAL` (60 s), calls `evictByAge` on each materialized ring of a stream that declares a finite age (owner and replica rings alike), and hands the evictees to the sealer exactly as space eviction does, so every evicted event is still sealed and a consumer positioned older than `max-age` reads it from the tier. Owner ruling Q8 A (`600fe6686a`).
  `[verified: RingAgeTickTest (evicts and seals the old events, spares the fresh ones, a refused hand-over keeps them); RingAgeTickBootTest (AetherNode arms the tick on a booted node)]`
- **Who is affected:** `time`-, `size`- and `compound`-typed streams and API-created streams with the default policy (24 h); in general every non-entity stream whose config carries a finite max age, which includes durable-topic streams (their declared retention is a max age), their dead-letter streams (14 d) and the cluster-events stream (24 h by default). Not affected: `count`-typed streams (a `[streams.x]` section with no retention key declares no age, so the tick skips it) and durable-entity `entity:` rings. A stream whose retention mode this node cannot read (`UNKNOWN`, written by a newer node) is skipped, the same fail-closed stance as the sealed tier. Only `evictByAge` is wired; `applyRetention` and the tier-aware path stay unwired. Granularity is the tick: an event leaves the ring up to 60 s after it passes `max-age`, and one tick hands over at most 10,000 events or 8 MiB of event data per ring (the hand-over copies the evictees while the ring holds its append lock), so a larger backlog drains one batch per tick; space eviction still bounds the ring meanwhile. A `compound` stream under `retention-mode = "all"` is cut by age alone.
  `[mechanism: the entity exclusion and the skip of Long.MAX_VALUE are pinned by RingAgeTickTest through the sweep count and the untouched rings; the entity fixture arms the tier-aware branch (updateLastSealedOffset) so a tick that reached it would be seen]`
- **Behaviour change for `GET /api/events` (the cluster-events view):** `ClusterEventAggregator.events()` reads from the retained ring tail by design, so its window is now bounded by the stream's max age (24 h by default) instead of by ring capacity alone; older events are no longer listed.
- **Two client reads stay ring-only, so they no longer see events older than `max-age`** (they saw them before, until capacity pressure): (1) the management stream read (`StreamApiRoutes`, through `StreamReadRouter.readLocal` -> `readServing`): an explicit `offset` below the ring tail answers `CursorExpired` (HTTP 410); a read with no offset starts at the ring tail (retried once from the earliest offset the engine names), so it returns the retained window and no 410; (2) a `LINEARIZABLE` read forwarded to the committed owner (`LinearizableOwnerServe`, bound at `AetherNode` to `readServing`): below the tail it answers the owner's `CursorExpired` `[mechanism: traced, not run]`. Making them fall through to the sealed tier is a larger change (epoch admission, owner gate) and is not part of this PR. Durable-topic consumers and the pull API do fall through.
- **The dead-letter inspection (`DeadLetterHandler.read`) is a latent API with no operator route yet; this PR changes it so it cannot report a failure as an empty list.** It now returns a `Promise` that carries the cause: a seal still in flight fails with `SealInFlight` (transient), a refused owner gate or an unverified replica fails with its own cause, and the read goes through the validated tiered read, so dead letters that left the ring are served from the sealed tier, oldest first. If retention has reclaimed the oldest dead letters the read starts at the earliest offset still held (the reclaimed ones are gone by the DLQ's own max age). A node that holds no DLQ stream for the topic (its committed config not applied yet) fails with `StreamNotFound` rather than listing nothing. Before: an empty list on every one of those failures, and a plain ring read from offset 0 that listed nothing once the ring tail had moved past 0. Limits: same-node inspection (no routing to the owner), at most `maxCount` entries, no paging.
