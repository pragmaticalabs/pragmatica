### Fixed (2026-10-12 — #2162, #2163, #2164: three node-deployment FSM defects)
- **#2162: one replica unloading no longer stops stream consumption cluster-wide.** `doUnpublishStreamSubscriptions` removed the cluster-scoped `StreamRegistrationKey` unconditionally, so a rebalance, drain or scale-down that unloaded ONE replica of a slice with a declarative `[streams.X]` consumer made every node's `StreamConsumerManager` detach it, with no error and the other replicas still ACTIVE. The removal now takes the `artifactHostedElsewhere` guard the scheduled-task unpublish already had; the last replica still removes the registration. [verified: `NodeDeploymentStateStreamGuardAndLoadChainTest.peerStillHosts_streamRegistrationSurvivesThisReplicasUnload`, with `lastReplicaUnload_removesStreamRegistrations` and `scheduledTaskUnpublish_withPeerHosting_removesNothing` as controls]
- **#2163: a consensus write failure at LOADING or LOADED no longer condemns a healthy artifact.** The exhausted retries of those two writes raised an untyped cause, which the PERMANENT disposition of `handleLoadingFailure` (#930) recorded as a fatal `UnexpectedError`, so an infrastructure stall could roll a blueprint back under `ALL_OR_NOTHING`. The two writes of the load chains (the LOAD chain and the KV-convergence redeploy) now type their failure `Intermittent.Timeout`; a genuine load failure is still fatal. The shared `updateSliceStateWithRetry` is deliberately unchanged. [verified: `loadingWriteFails_isNotFatal`, `loadedWriteFails_isNotFatal`, control `genuineLoadFailure_isStillFatal`] [unverified: the KV-convergence redeploy chain has no test of its own]
- **#2164: a slice reactivated after a quorum flap receives runtime config changes again.** Reactivation rebuilt the per-slice `ConfigNotificationManager` empty and never re-registered the slice, so later `config set` calls silently never reached a `[config-update]` slice until it was redeployed. Reactivation now runs `registerAndNotifyConfig`, so the slice also gets one initial notification per reactivation. Stream registrations and refs need no re-publication (cluster KV state and refcounts that suspension does not touch). [verified: `configChangeStillReachesSliceAfterQuorumFlap` with its in-test control; `streamRegistrationSurvivesQuorumFlap_withoutRepublish` pins the refuted arm]
