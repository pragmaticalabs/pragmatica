### Fixed (2026-11-15 — #3284: committed-batch ledger grew without bound under a repeated identical batch)
- **A batch committed again and again with identical commands (a forwarding node's `Noop` cursor barrier) was never evicted from the Rabia committed-batch ledger, and every correlation id it was ever committed with stayed held** (#3284). Batch ids are content hashes, so each repeat refreshed the entry to newest and added one id. The ledger now remembers the correlation ids of its last 65,536 records: each id is recognised for exactly the 65,535 records that follow its own (a window of 65,536 records including its own), whether or not its batch id repeats, so the ledger's total size is bounded by those records. The window counts records, never time, so replicas that applied the same slots hold the same entries.
