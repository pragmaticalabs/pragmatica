### Fixed (2026-11-24 — #2363: jbct init/update installed AI tools from unpinned main, not the user's JBCT version)
- **`jbct init` and `jbct update` no longer install the AI tools from the tip of `main`.** The installer derives the tag `ai-tools-v<jbct version>` from the running build's own version (`AiToolsRef`) and fetches the tools at the commit that tag points at; `jbct update` moves to the tag of the new version, even when it points at the same commit as the old one. The installed ref is recorded as `<tag>@<commit>` in the cache stamp `~/.jbct/cache/ai-tools/.ref` (init) and `.claude/.ai-tools-version` (update), and both commands print it. A tag the repository does not carry is reported by name (`AiToolsRefError.TagNotFound`; `jbct init` exits non-zero) and a `-SNAPSHOT` or unknown-version build is refused naming the tag looked for (`UnreleasedBuild`); neither falls back to `main`, and an offline run reuses a cache only when it holds this build's own ref. The tag `ai-tools-v<version>` must exist in `siy/coding-technology` before a release ships. Cache stamps written before this change (bare commit sha, file `.sha`) are not recognised and are refreshed once. A refresh of the init cache removes its stamp, then its `skills/` and `agents/`, before the first file is written, so a file another ref (or `main`) left behind is never installed under this ref's stamp, and a refresh that dies half-way leaves no stamp; `jbct update` removes `.claude/.ai-tools-version` before its first file for the same reason. Limit: `jbct update` does not delete project files that a newer ref dropped (`.claude/` also holds your own skills and agents); `jbct init --no-ai` is not affected. [verified: `AiToolsRefTest`, `AiToolsInstallerPinTest`, `AiToolsUpdaterPinTest` (jbct-init)]
