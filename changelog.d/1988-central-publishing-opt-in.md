### Fixed (2026-10-07 — #1988, #1989: Maven Central published modules that should never ship, and one module broke the release build)
- **Publishing is opt-in.** The root now skips every module (`skipPublishing=true` in the Central plugin's `<pluginManagement>`, and `maven.deploy.skip=true` for a module the plugin is not bound to); a module publishes only when its own pom declares the plugin with `<skipPublishing>false</skipPublishing>`, and a parent pom that publishes while its children do not marks it `<inherited>false</inherited>`. Before, only the seven poms that set `skipPublishing` were excluded: about 30 set `maven.deploy.skip`, which the Central plugin ignores, so `script-gate`, `cli-docs-gate`, `test-plan-witness` and `pg-test-corpus` were published, and so was every new module. The published set is now 33 of 147 modules, the closure of what `jbct init` and `jbct add-persistence` generate (`docs/release/maven-central-publish-set.md` decides every module).
  [verified: `tools/check-publish-effective-pom.py` agrees with Maven's own effective poms for all 147 modules (33 publish, 29 bound and skipped, 85 unbound); `tools/test_publish_closure.py`]
- **The published set is gated at build time, not only in CI.** A `-DperformRelease=true` build runs `tools/check-publish-closure.py` at `validate`: a published module that depends (compile or runtime, not optional) on an unpublished one, or whose parent pom is unpublished, fails the build; so does a decision table that differs from the poms, and a parent-less module that does not skip the default deploy.
  [verified: green on the tree (33 modules, 46 edges); red when `slice-api` is given a compile dependency on `node` (`BUILD FAILURE`, "slice-api (compile) depends on node, which is not published"), green again once removed]
- **`examples/step-composition` no longer stops the release reactor.** Its javadoc failed on unquoted `@OnOrderEvent`/`@ResourceQualifier` in `///` comments; it is skipped from publishing and its own `maven.deploy.skip` stays, because it is a standalone pom the root's defaults cannot reach (the first full `deploy` measured that: the default deploy ran and failed).
  [verified: `mvn clean install -DperformRelease=true` over all 147 modules, BUILD SUCCESS]
- **`pg-codegen` and `pg-schema` no longer drag `pg-test-corpus` to consumers.** It holds SQL fixtures that no `src/main` or `src/test` file reads by name; its managed scope is now `test`, so it is not published.
- **Javadoc jars carry no web fonts** (`--no-fonts`): `slice-annotations` 4,149,912 bytes to 104,949, and none of the 122 javadoc jars of a full install holds a `woff` entry. The 33-module bundle is 612 files and 15.8 MB with the default checksums, 408 files with `checksums=required`.
  [verified: a local `deploy` to a sink on `127.0.0.1`, bundle opened and counted]
- **A plain `mvn deploy` uploads nothing to Central.** The Central plugin's `publish` execution is bound to `${central.publish.phase}`, `none` by default and `deploy` in the `release` profile, so only `-DperformRelease=true` signs, gates and uploads (before, a plain deploy sent an unsigned bundle, and with `autoPublish` that is an irreversible publish from a casual command). The execution must name its goal: declaring it without `<goals>` silently disabled the upload in a release build too.
  [verified: sink on `127.0.0.1`, `-pl core -am`: plain `deploy` uploaded 0 bytes and ran no `publish`; `-DperformRelease=true deploy` uploaded one signed bundle (2,159,297 bytes, 5 `.asc`); the goal-less variant uploaded nothing in a release build, which the control caught]
- **The closure gate fails closed on shapes it cannot evaluate**: a reactor module imported as a BOM, a property in a `groupId`, a default-active profile (`activeByDefault`, `jdk`) that changes dependencies or the Central entry, and a non-literal `skipPublishing`/`inherited`. Its `NOT CLOSED` lines now survive `mvn -q` (the build failure message carries them).
  [verified: `tools/test_publish_closure.py` 26 tests; the four new refusals go red when the check is removed; `mvn -q clean package -DperformRelease=true` with `core` set to skip prints all 17 lines]
- **One Central plugin version.** `jbct/` and `aether/` pinned 0.9.0 over the root's 0.10.0 for 23 of the 33 published modules; both pins and a duplicate plugin entry in `jbct/pom.xml` are gone, so 0.10.0 applies everywhere (the newer line, and the one the bundle measurement above used for the root and `integrations/`).
  [verified: `help:effective-pom` for all 147 modules before/after differs only in the version, and no module's bound/skip verdict changed]
