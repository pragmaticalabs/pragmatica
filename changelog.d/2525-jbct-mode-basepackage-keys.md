### Added (2026-11-17 — #2525: JBCT `[lint] mode` and `[project] basePackage` configuration keys)
- **`jbct.toml` gains `[lint] mode` and `[project] basePackage`.** `mode` is `business` (the default) or `infrastructure`; `format-only` and `disabled` are refused as not yet supported. `basePackage` is the project root package. Both fold per key through the `jbct.toml` chain; the chain now starts at the checked path's module directory, never the working directory. `jbct lint`, `check`, `score` and `format` take `--mode`, and the Maven goals take `-Djbct.mode`, each overriding every file layer. `add-slice`, `add-event` and `add-persistence` write the derived `basePackage` when the module's `jbct.toml` has none, and the generated templates carry both keys. [verified: `jbct/jbct-core/src/test/java/org/pragmatica/jbct/config/JbctModeConfigTest.java`, `jbct/jbct-cli/src/test/java/org/pragmatica/jbct/cli/CliModeOverrideTest.java`]
- **`lint`, `check`, `score` and the Maven goals build their `LintContext` through one factory (`LintContext.fromConfig`)**, so the mode and `basePackage` reach every rule's context; the CLI used to drop both. [verified: `jbct/jbct-cli/src/test/java/org/pragmatica/jbct/cli/CliLintContextTest.java`, `jbct/jbct-core/src/test/java/org/pragmatica/jbct/lint/LintContextTest.java`]
- **`basePackage` refuses a Java keyword or literal segment (`com.class.orders`) and a non-string TOML value (`basePackage = true`, `nan`)**, naming file, key and value. [verified: `jbct/jbct-core/src/test/java/org/pragmatica/jbct/config/JbctModeConfigTest.java`, `jbct/jbct-core/src/test/java/org/pragmatica/jbct/config/SourceRootConfigTest.java`]
