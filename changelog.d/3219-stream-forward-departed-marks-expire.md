### Fixed (2026-11-24 — #3219: stream forward handler: departed-requester marks are never expired for nodes that do not return)
- **A node removed from the cluster and never heard from again stayed in the stream forward handler's departed-requester set for the life of the process**, so the set grew with the number of distinct departed node ids rather than with the live cluster. The mark is needed only while a refused reply to that node can still be re-sent (the re-send chain ends within 4.5 s); it now expires after 10 s. A node that returns earlier still clears its own mark on its next request, and an expiry removes only the departure it was scheduled for, so a node removed again keeps its newer mark.
