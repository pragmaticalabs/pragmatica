### Changed (2026-11-07 — #2713: the requirement combiner's A/B fence)
- **BREAKING (pre-GA flag day): two new KV wire types, tags 2225-2226** (`AbTestBaseKey`, `AbTestBaseValue`; `wire-assignment-baseline.txt`). A node of an earlier build cannot decode them (the codec refuses an unknown tag), and every A/B test write of this build carries one, so a mixed-version cluster must not run A/B tests [mechanism: unknown-tag refusal]. Upgrade by coordinated replacement.
- **A/B test writes are one transaction with a per-slice index of the slice's live tests** (`ab-test-base/<slice>`, each live test as `id=STATE`, sorted; absent while none is live). Creation, every state transition and the end of a test write it; the last live test ending removes it. The leader's requirement combiner witnesses the index at the value it read (absent included), so an A/B test created or moved between the combiner's read and its commit refuses the combination, and the combiner's rebuild sees the canary and holds the slice [mechanism: compare-and-set witness on the index in the combiner's leader transaction; `AbTestIndexTest`]. Before, a test created in that window could have its variant scaled to the full combined count.
- Existing A/B records need no migration: the index is derived from the slice's A/B records on every write, so a slice whose live tests predate it gets a complete entry at its next A/B write; until then the index is absent, and every write that could start a canary writes it [mechanism: derived on write; `AbTestIndexTest.backfill_*`]. A/B records written by an earlier build through a backup restore behave the same way.
