### Changed (2026-10-22 — #2385: the Forge API port key is `forge_port`)
- **`[cluster] dashboard_port` in `forge.toml` is renamed to `forge_port`.** The key sets the port of Forge's own HTTP API; its old name outlived the web dashboard it was named after. There is no alias: a `forge.toml` that still sets `dashboard_port` is refused at load with `[cluster] dashboard_port was renamed to forge_port; rename the key in forge.toml`, rather than ignored, which would have run Forge on the default port (8888) without a word. The examples and the `jbct init` project template carry the new key. The `FORGE_PORT` environment variable and the `--port` argument are unchanged. In code, `EmberConfig.dashboardPort()` is `forgePort()`, `EmberConfig.DEFAULT_DASHBOARD_PORT` is `DEFAULT_FORGE_PORT` and `Ember.withDashboardPort` is `withForgePort`. [verified: `aether/ember/src/test/java/org/pragmatica/aether/ember/EmberConfigForgePortTest.java`, `jbct/jbct-init/src/test/java/org/pragmatica/jbct/init/SliceProjectInitializerTest.java` `initialize_validParams_forgeTomlCarriesForgePortKey`]
- **Forge no longer starts on its defaults when the `--config` file (or `FORGE_CONFIG`) does not load.** A `forge.toml` that failed to load (a renamed key, a malformed value, a syntax error) was logged at ERROR and replaced by the built-in defaults, so Forge started on port 8888 with every setting of the file dropped. It now stops before anything is created, with exit code 1 and a `FATAL` line naming the file and the cause. Running without `--config` or `FORGE_CONFIG` is unchanged. [verified: `aether/forge/forge-core/src/test/java/org/pragmatica/aether/forge/ForgeServerForgeConfigRefusalTest.java`]
