### Fixed (2026-10-18 — #2237: the cleanup-ledger parser dropped unknown resource types and read missing VM/container ids as empty)
- **A ledger entry this CLI could not interpret was skipped, and the next append erased it.** `parseSingleResourceNode` ended in `default -> null` and both consumers (`bootstrap-state.json`, the apply-state ledger) skipped nulls, so an older CLI re-saved a newer CLI's file without the newer entry, and destroy could report success while the resource kept billing. An unknown or missing `"type"` now fails the load naming the type, like an unusable `CloudFirewall` entry already did. `[verified: aether/cli/src/test/java/org/pragmatica/aether/cli/cluster/BootstrapStateJsonBackCompatTest.java, BootstrapStatePersistenceAppendResourceTest.java]`
- A `ProvisionedVm` without `resourceId` and a `DockerContainer` without `containerId` read as `""` and reached the provider as `terminate("")`; they now fail the load naming the entry type and the field. No schema-version field is added (a format decision).
- **A legacy ledger that holds a blank-id entry now refuses to load as a whole.** A `ProvisionedVm` / `DockerContainer` entry whose `resourceId` / `containerId` is absent, empty or whitespace-only used to load with an empty id; it now fails the load of the entire file (`bootstrap-state.json` or `apply-state.json`), and so does an entry of an unknown or missing `"type"`. To repair: open the named file under `~/.aether/clusters/<cluster>/`, fill in the entry's id (the provider console lists the resource), or delete the resource by hand and remove the entry, then retry; the error names the entry type and the field.
- The refusal is applied wherever the ledger is read before it is written: `apply --resume` / `--rollback` report the refusal instead of "Nothing to resume/rollback", a fresh apply refuses to overwrite an unreadable `apply-state.json`, and the deploy phase fails instead of saving over an unreadable `bootstrap-state.json`. `[verified: aether/cli/src/test/java/org/pragmatica/aether/cli/cluster/ApplyStateLedgerRefusalTest.java, BootstrapPhaseDeployLedgerRefusalTest.java]`
