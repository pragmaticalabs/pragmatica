### Added (2026-09-08 — #944: documented CLI invocations are diffed against the live picocli CommandSpec, and drift fails the build)

- **`cli-docs-gate` compares this repository's documentation against the command surface the CLIs actually define.** It constructs the real `CommandLine` objects for `aether` and `jbct` and walks `CommandSpec`, rather than scraping `@Command` annotations out of `.java` files. A text scrape cannot see `@Mixin` contributions (`AetherCli` mixes in `OutputOptions`, so `--format`/`--output` exist with no annotation in `AetherCli.java`), the options `mixinStandardHelpOptions` synthesises, or picocli's built-in `AutoComplete.GenerateCompletion` — whose command name `generate-completion` appears nowhere in this repository's source and which the gate nevertheless found and reported as an undocumented shipped subcommand. `[verified: org.pragmatica.clidocs.CliDocsDriftTest, 6 tests green; aether generate-completion is listed in cli-docs-gate/src/test/resources/undocumented-commands.txt]`
- **What it examined, not merely that it passed: 230 Markdown documents, 1060 fenced shell blocks (1526 skipped by language), 29334 inline code spans, 919 CLI invocations extracted, 219 commands enumerated (aether 200, jbct 19).** Every run prints these, and the run refuses to pass below floors of 100 documents / 300 invocations / 100 commands. A gate that exits green having examined nothing is the failure this repository has hit before; the counts are therefore the result, and the exit status alone is not one. The corpus is defined as every `*.md` under the root MINUS an explicit exclusion list, never as an include-list of globs — a glob that stops matching after a directory rename would turn the gate green forever. `[verified: mutation — changing the corpus filter from `.md` to `.mdx` collapses the sweep and the run fails with "below the floor" (exit 1), against an unmutated exit 0]`
- **The documentation asserted 34 commands and 57 options that the shipped CLIs do not define, across 35 files.** These are not typos and were not rewritten as if they were: `aether scale --min/--max/--target-cpu/--target-latency/--cooldown/--auto` describes autoscaling, while the shipped `aether scale` takes only `-n/--instances`, `-p/--placement`, `--wait` and `--timeout`; `aether ab-tests create -a … --variants …` names two options that both do not exist, the real ones being `--version-a`, `--version-b`, `--split` and `-n/--instances`. The sharpest case is **`jbct init --slice`, which is documented in five files and is the INVERSE of the shipped `--no-slice`** — a reader following it gets the opposite of what the text promises, which no rename could have repaired. All 91 are enumerated in `known-doc-drift.txt`; deciding which side is wrong is a product call, not a spelling correction. `[verified: InitCommand declares --no-slice and no --slice; AetherCli.ScaleCommand declares -n/--instances, -p/--placement, --wait, --timeout and none of the documented autoscaling flags]`
- **21 invocations were mechanically wrong and are fixed here**: `aether blueprint {deploy,apply,list,status,delete}` → `blueprints` (14), `aether artifact push` → `artifacts push` (6), and one example invoking a binary called `aether-cli` when the executable is `aether`. Enumerating every occurrence before substituting is what kept the fix honest: `aether blueprint set` and `aether artifact upload` look like the same error but have no plural counterpart either, so they were left alone rather than corrected into a second name that also does not exist. `[verified: pre/post counts balance — 20 singular forms replaced, 14 `blueprints` + 6 `artifacts push` present after, 1 unsafe form deliberately remaining]`
- **A shipped command that no documentation mentions also fails the build.** 11 are baselined, 7 of them `jbct` subcommands (`add-persistence`, `check-sheet`, `fix-slice`, `migrate`, `obligations`, `shape-census`, `update`) out of that CLI's 18. `[verified: mutation — deleting `jbct migrate` from the baseline turns the run red with "not baselined"]`
- **Neither list can be used to silence new drift.** Both are keyed by path plus the drift itself rather than by line number, and both are shrink-only: a finding absent from the list fails, a list entry that matches nothing fails, and the entry COUNT is asserted exactly, so appending a line to make a new finding pass does not work. Widening either list means editing a constant in the test, in the same commit, where a reviewer sees it. Without that last property the gate would advise rather than enforce. `[verified: mutation — introducing a new fake command AND appending its matching waiver line still fails ("only 91 are allowed"); fixing a documented option and deleting its waiver line without lowering the constant also fails ("now lower WAIVED_FINDINGS to 90")]`
- **The gate states its own blind spots on every run** rather than leaving them unknown: one command declares both subcommands and positionals (`aether deploy`), under which an invented subcommand reads as an argument; option values, positional shapes, clustered short options, and fenced blocks outside the shell language allow-list are not validated. `[verified: CliDocsDriftTest.gate_blindSpots_areEnumerated prints the set and its size on every run]`
