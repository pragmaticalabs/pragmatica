### Changed (2026-10-29 — #2201 PR-0b part 2: an expired sealed segment's block leaves every tier, the DHT included; part of #2258)
- **BREAKING (pre-GA flag day): every new sealed-segment block starts with an identity header** (`MAGIC2`: the stream's life, the partition and the offset range, then the provenance slice and the events). A new node reads every older form; an old node misreads a new block as events, so a mixed cluster must not share segments. Upgrade by coordinated replacement. `[verified: SegmentProvenanceTest]`
- **Fixed: an expired segment's block was never removed from the cluster-shared DHT tier, so every node's heap grew without bound under any stream workload** (#2258). Retention now releases an expired segment's ref with shared-delete authority, and the streams instance's own collection run (every minute, at most 10,000 blocks or 60 s a run) deletes the block from every tier, the DHT first, once the release is in a durable metadata snapshot and two minutes have passed. The header is what makes this safe without a cluster-wide reference count: two refs name one block only when they name the same segment. A block written before the header, or released after a restart before its mark was learned and failing the identity check, keeps its shared copy. `[verified: StreamSegmentDhtReclaimTest (production streams construction, 600 expired segments gone from the DHT in one run, a young one kept); SharedDeleteCollectionTest; SegmentSharedDeleteTest]`
- Stream floors and consumer cursors are written to node-private tiers only; nothing reads their shared copy, and a cursor commit no longer writes a DHT block (up to about one per second per delivering group and partition before). Without a private durable tier the write falls back to every tier and is counted.
- An explicit stream destroy releases the stream's segments the same way, and their blocks leave the DHT. Adopting a new life of a stream releases no other life: other lives are kept and announced (`know:` `d19f755873`), and a stream destroyed while a node was down stays on that node until retirement records exist (PR-8j/#2458).
- At restart, a segment ref at or below its partition's durable reclaim floor (left by a crash between the floor write and the release) is no longer served; it is released and collected.
- New operator warnings: `stream-segment-delete-failing` after three consecutive collection runs with a failed delete (the DHT write quorum unreachable), closed by `stream-segment-delete-recovered`.
- Metadata snapshots carry the shared-delete authority as a lifecycle flag; a build without the flag refuses such a snapshot and falls back to an older retained one (downgrade only). A downgraded node whose only retained snapshots carry a flag refuses to start with empty metadata. A crash after the shared delete leaves the private copy and a flagged orphan; the next run finishes it. `[verified: the old reader (rc5 base f9a3893de9) restores a mixed set from the older snapshot and refuses an all-flagged one; CrashBetweenTiersTest]`
- Not yet: the bound on the DHT tier and its byte accounting (PR-0b part 3, which closes #2258).
