### Changed (2026-11-08 — #263 C-04/C-09: an owner batches the events it replicates, and sends them off the append section)
- **The node batches replication.** The owner's replication manager is now the batching one: a partition's events go to its replicas as one `ReplicateEvents` per batch of up to `[streaming] replication_batch_max_events` (100) events or `replication_batch_max_delay` (1 ms), where before every single publish sent one message per event per replica. The first event of an idle partition is sent at once and opens the window, so an isolated publish waits for no window. The message saving needs several publishes per window on one partition: below roughly 1,000 events/s per partition, or with a slow WAL fsync, about as many messages leave as before `[mechanism: closed-loop arithmetic, overhaul 7.2 L-04]`. `[verified: EmberReplicationBatchingTest#singlePublishes_areBatchedIntoFewerMessages on a 3-node Ember cluster without a WAL (its C-04 tripwire deleted); StreamAssemblyReplicationBatchingTest (NT-204); ProductionReplicationBatchingTest]`
- **Replication is encoded and sent off the owner's append section, in offset order.** The section only hands the event over; a per-partition FIFO send lane encodes and sends it on a flusher thread. Before, a size flush or an epoch flush sent on the publishing thread inside the section, and a window flush could be overtaken by its successor's size flush (a gap the replica repaired by backfill). `[verified: ProductionReplicationBatchingTest]`
- **A batched event takes the direct path's send**: frame-size chunks (#1287) and the re-send of a frame the transport provably did not write (#2820). An owner-local `publishBatch` is still one run on the wire. `[verified: ProductionReplicationBatchingTest#batchRefusedByTheTransport_isSentAgain, #batchAboveTheChunkBudget_isSentAsConsecutiveChunks, #run_followsThePartitionsOpenBatch_asOneMessage]`
- With a WAL the message ratio depends on the disk's fsync latency and is measured, not gated (`EmberReplicationBatchingWalMeasurementTest`).
