### Fixed (2026-11-21 — #3560: SWIM tests asserted straight after the asynchronous `onMessage`; test-only)
- **SWIM tests deliver every message through `SwimProtocol.deliverForTest`, which waits until the message is applied** (#3560). Since #3529 `onMessage` only enqueues when another thread is draining (the probe tick), so a test that asserted on the next line could read the state before the message ran (`SwimProtocolTombstoneTest.gossipReAdd_atHigherIncarnation_supersedesTombstone_andIsAllowed` failed that way on CI). All bare `onMessage` calls in the swim tests and in the aether tests that drive a protocol were migrated; the four-plus simulated network hops that run inside a task keep the bare call, each marked `ASYNC-DELIVERY:` with its reason. `SwimDeliveryGuardTest` fails the build on any other bare call in a test that drives a protocol. Production `onMessage` and `execute` are unchanged and never wait.
