### Fixed (2026-09-29 — #1429: an invalid optional value-object config value threw out of the generated factory)
- **A present but invalid value for an optional value-object config component (`Option<Url>`, any `Option<T>` whose `T` has a JBCT `Result<T>` factory) no longer throws out of the generated slice factory.** The generated code unwrapped it with `.expect("optional T value validated at config load time")`, but nothing validated it at load time, so a malformed value threw across the `Result` boundary on activation and inside `@ConfigUpdate` handling. It now fails the section's `Result.all(...)` chain with `T`'s own cause, the same as a malformed typed read since #1098. An absent value is still `none()`. [verified: jbct/slice-processor/src/test/java/org/pragmatica/jbct/slice/SliceProcessorTest.java — `should_fail_the_factory_result_not_throw_for_an_invalid_optional_value_object` loads and calls the generated factory; with the generator change reverted it throws `IllegalStateException` instead]
