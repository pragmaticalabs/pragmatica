### Fixed (2026-11-24 — #1654: genesis dead-seat warning is true in both auto-heal states)
- The `genesis-seat-unreachable` warning no longer always says auto-heal will replace the seat. The remedy sentence is chosen when the warning is raised from the node's live auto-heal state: on, it names the bound (startup cooldown plus provisioning timeout) within which a replacement is expected; off, it says no replacement will be provisioned and names the manual remedy (restart the node, or enable auto-heal). It is not raised again when the state changes later `[verified: GenesisSeatRemedyTest, GenesisSeatUnreachableTest]`.
- Ember: a genesis seat that was agreed and then never connects is named in the cluster event log while the two live cores still form, and auto-heal replaces it `[verified: aether/ember/src/test/java/org/pragmatica/aether/ember/EmberGenesisSeatUnreachableTest.java]`. At genesis the auto-heal key is absent (on), so an Ember run reaches the heal-on arm only; the heal-off arm is pinned at unit level `[unverified: heal-off on a real cluster]`.
