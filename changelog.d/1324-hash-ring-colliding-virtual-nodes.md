### Fixed (2026-09-29 — #1324: `ConsistentHashRing` overwrote colliding virtual nodes)
- **Two virtual nodes that hash to the same ring point now share it.** The ring kept one node per point, so the later insertion overwrote the earlier. Identical memberships then placed partitions differently by insertion order, and removing either node deleted the shared point even while it belonged to the other. A point now holds every node there in the nodes' natural order: the smallest is the primary, and a replica walk yields the rest in that order. Removal takes a node off the point, and the point goes only when nobody holds it. [verified: integrations/dht/src/test/java/org/pragmatica/dht/ConsistentHashRingCollisionTest.java — a real collision under the ring's own hash (`node-89#99` = `node-1698#10`); opposite insertion orders place all 1,024 partitions identically; removing either node keeps the other's point; three of its five tests fail on the old ring]
- **Placement without a collision is unchanged.** Over 300 random rings of 3–12 nodes (150 virtual nodes each, no collision among them), the old and new ring gave identical replica sets for all 307,200 partition lookups. Control: on the colliding pair the old ring placed 34 of 1,024 partitions differently by insertion order. A ring that has a collision may move those partitions once, to the deterministic owner, when nodes run this version.
