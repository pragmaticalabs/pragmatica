### Fixed (2026-11-24 — #946 `ANY_REPLICA` read: a caught-up replica answers from its own copy when every selected peer cannot be asked)
- **`GET /api/events` read-back no longer fails under one dead peer.** `ForwardingReadRouter` forwarded an `ANY_REPLICA` read to a random caught-up peer, retried once on another, and returned the failure; a degraded cluster emitted its failure events (#926) that a consumer then could not read. When the pick and its retry both could not be asked (timeout, unavailable forwarder, `PARTITION_NOT_LOCAL`) and the reading node is itself a caught-up replica, the read is answered from the local copy: the same `min(durable, owner-reported)` replica row as the forwarded read, eventual, no read-your-writes. A node that is not a caught-up replica, or a peer's typed answer (unknown stream, expired cursor), still returns the cause. One predicate (`couldNotAsk`) now serves the owner forward and the replica forward. Operator: when the cause is returned, route the read to a replica node (or retry once this node is caught up), or act on the typed answer's status. The `LINEARIZABLE` no-committed-record fallback runs the same route and inherits the degrade.
