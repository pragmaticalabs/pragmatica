### Changed
- **A Hetzner server is now named `<cluster>-<nodeId>`** (lower case; the cluster-scoped operation id) and carries the same value in the label `aether.op`, beside the unchanged `aether-node-id=<nodeId>`, so Hetzner's per-project name uniqueness refuses a second server for the same create (G1-a; measured: a duplicate name is refused atomically with `409 uniqueness_error`, and names are case-sensitive). The cluster scopes the name because a Hetzner project is shared by clusters and bootstrap node ids (`<source>-<role>-<i>`, e.g. `eu-1-core-0`) are unique only within one cluster. `[verified: aether/environment/hetzner/src/test/java/org/pragmatica/aether/environment/hetzner/ClusterScopedNamingTest.java, HetznerComputeProviderTest.java (OperationNamingTests)]`
- A refused name whose holder carries the create's cluster and node-id labels is a typed `AlreadyExists`, not a failed create: the core path adopts it as an OBSERVED reservation. A holder that is not the create's is a typed `NameHeldByOther`, never adopted. No second create follows either. `[verified: aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/cluster/CapacityControlledLifecycleTest.java]`
- **Cluster names on Hetzner are limited to 11 characters** (validation rule PF-36): the minted node id `aether-<cluster>-node-<ulid>` is 39 characters plus the cluster name, and the server name repeats the cluster, so `<cluster>-aether-<cluster>-node-<ulid>` must fit Hetzner's 63. A longer name is refused at validation (and, for a cluster already running, typed before any create), never truncated. Other providers are not limited. A node id that cannot name a server (upper case, over 63 characters) is refused before the create; AWS, GCP, Azure and Docker refuse an operation id they are handed instead of ignoring it.
