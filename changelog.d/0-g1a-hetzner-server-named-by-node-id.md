### Changed
- **A Hetzner server is now named by its node id**, lower case, and carries the label `aether.op` beside `aether-node-id`, so Hetzner's per-project name uniqueness refuses a second server for the same create (G1-a; measured: a duplicate name is refused atomically with `409 uniqueness_error`, and names are case-sensitive). `[verified: aether/environment/hetzner/src/test/java/org/pragmatica/aether/environment/hetzner/HetznerComputeProviderTest.java (OperationNamingTests)]`
- A refused name whose holder carries the create's cluster and node-id labels is a typed `AlreadyExists`, not a failed create: the core path adopts it as an OBSERVED reservation. A holder that is not the create's is a typed `NameHeldByOther`, never adopted. No second create follows either. `[verified: aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/cluster/CapacityControlledLifecycleTest.java]`
- A node id that cannot name a server (upper case, or longer than 63 characters, which a cluster name over 24 characters produces) is refused before the create. AWS, GCP, Azure and Docker refuse an operation id they are handed instead of ignoring it.
