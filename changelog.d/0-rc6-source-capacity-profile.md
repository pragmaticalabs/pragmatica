### Added (2026-11-05 — rc6 §8.1: source capacity profile and first-class fleet cap)
- **`[source.<name>]` gains `lead_time` (per-role sub-table), `max_nodes`, `preference`, `cost_class` and `fallback`.** Defaults: lead time by provider (hetzner 65s measured; aws/gcp/azure 2m and non-cloud 30s unmeasured), no per-source limit, preference 100, `ondemand`, `allow`. A malformed value is refused at load naming the key; `cost_class = "spot"` is refused (PF-37) off a cloud source and on providers without a spot arm. The fields are parsed, validated, diffed and persisted only; source selection that reads them is a later change. [verified: `aether/aether-config/src/test/java/org/pragmatica/aether/config/cluster/SourceCapacityProfileTest.java`]
- **`[cluster] max_nodes` is a first-class cluster field.** Rendered into every node's `[cluster] max_nodes`, so `NodeLifecycleManager.provisionNode` enforces the same value as before. `[source.<name>.node_config.cluster] max_nodes` is now refused (PF-38); move it to `[cluster]`. [verified: `SourceCapacityProfileTest` overlay and PF-38 cases]
