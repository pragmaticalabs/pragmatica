### Fixed (2026-10-18 — #1170: a boot refused by the post-formation DHT marker check left disk encryption markers behind)
- **A boot refused after cluster formation by the DHT encryption-marker check no longer leaves the `.encryption-enabled` markers it stamped.** `createAll` commits every encrypted instance's disk marker before the node starts, and the DHT check can only run after formation, so a definite refusal used to strand those markers; backing the instance out to `encrypted = false` then tripped its own reverse guard on a marker no ciphertext justified.
- The refusal is returned unchanged; the markers this boot stamped are removed first. A marker from an earlier boot, and any directory that already holds a block, keep their marker, because the marker is what stops a plain boot reading framed ciphertext as content.
- Bound: the empty-directory check and the delete are not atomic against a concurrent block write; the node is already failing to start when it runs.
