### Fixed
- A core now remembers the NodeIds it retired across a restart (#2429). Previously the boot-token registry was process memory, so once every core that held a retirement had restarted, a process for the retired NodeId was admitted again. A retirement is written to the core's local identity ledger (`identity/<node-id>/ledger` beside the artifacts `disk_path`) before the refusal is answered, and loaded before admission opens. A ledger that cannot be written under an explicitly set `disk_path` stops the node from starting; under the default path the node starts without the protection and raises `identity-ledger-not-durable`. Workers hold no ledger.
