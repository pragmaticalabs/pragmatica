### Fixed (2026-10-12 - `EmberSameIdentityRelaunchTest` window opened 120 s late and read the killed original's membership record)
- **`relaunchedSameIdentityProcess_*` could fail on any PR with "the survivor re-admitted the refused identity as a member during the window" (#2165, run 38189775550).** The test waited for the relaunched process's start promise, which never resolves for a refused process, so the readmission window always opened `START_BOUND` = 120 s after the relaunch. Its first sample then read the survivor's membership record for the NodeId, which belongs to the killed original until the survivor registers its death; on the failing run that record still said `Member`, and no live process had been admitted (the refused process exited 0.5 s after launch). The test now waits, before the relaunch, for the survivor to register the original's death (failing with the stuck state named if it never does), then for the refused process's exit, and only then samples the 90 s window. The window therefore opens right after the refusal, about 100 s earlier, and the test runs about 100 s shorter. The product defect behind a stuck `Member` record is #2173, fixed in the same change (see that fragment). The failing run's exact interleaving (a formed cluster, no organic link close) was not reproduced, so this does not prove that run's red fixed.
