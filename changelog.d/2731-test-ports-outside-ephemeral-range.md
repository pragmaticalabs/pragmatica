### Fixed (2026-11-06 — #2731: ClusterTestPorts picks cluster ports from the ephemeral range and releases them before boot)
- **Node tests could lose their cluster port between allocation and boot**: candidates came from `DatagramSocket(0)` (the kernel ephemeral range) and the probe sockets were released, so any outgoing socket on the host, or another JVM's probe, could take the port before the node bound it.
- `ClusterTestPorts` now issues from a window outside the host's ephemeral range (read at class init; Linux `61000-65535`, failing loudly when no window of 1000 ports exists) and holds every issued port (cluster and SWIM) under an exclusive OS file lock in `/tmp/aether-test-ports/` for the JVM's life; the OS drops the lock when the JVM dies, so there is no stale-lock cleanup. Probes bind the wildcard address, as the node does. [verified: `aether/node/src/test/java/org/pragmatica/aether/node/ClusterTestPortsTest.java` — `portsHeldByAnotherJvm_areNeverIssued_untilThatJvmDies` (two JVMs), `issuedPorts_lieInTheWindow_outsideTheEphemeralRange`, the occupied-candidate skips with released-port controls, and the red control `legacyAllocator_leavesItsPortTakeableByAThirdParty`]
- Residual: a process that does not use the lock directory and binds an explicit port inside the window can still collide [mechanism: the lock is cooperative; a repo grep of 61000-65535 finds no such port].
