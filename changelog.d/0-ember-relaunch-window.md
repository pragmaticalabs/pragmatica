### Fixed (2026-10-12 - `EmberSameIdentityRelaunchTest` window opened 120 s late and read the killed original's membership record)
- **`relaunchedSameIdentityProcess_*` could fail on any PR with "the survivor re-admitted the refused identity as a member during the window" (#2165, run 38189775550).** The test waited for the relaunched process's start promise, which never resolves for a refused process, so the readmission window always opened `START_BOUND` = 120 s after the relaunch. Its first sample then read the survivor's membership record for the NodeId, which belongs to the killed original until the survivor registers its death; on the failing run that record still said `Member`, and no live process had been admitted (the refused process exited 0.5 s after launch). The test now waits for the refused process's exit, then for the survivor to stop counting the original as `Member`, and only then samples the 90 s window, so a return to `Member` is a re-admission. The test runs about 100 s shorter. No production code changed.
