### Fixed (2026-10-12 - `EmberSameIdentityRelaunchTest` window opened 120 s late and read the killed original's membership record)
- **`relaunchedSameIdentityProcess_*` could fail on any PR with "the survivor re-admitted the refused identity as a member during the window" (#2165, run 38189775550).** The test waited for the relaunched process's start promise, which never resolves for a refused process, so the readmission window always opened `START_BOUND` = 120 s after the relaunch. Its first sample then read the survivor's membership record for the NodeId, which belongs to the killed original until the survivor registers its death; on the failing run that record still said `Member`, and no live process had been admitted (the refused process exited 0.5 s after launch). The test now waits, before the relaunch, for the survivor to register the original's death (failing with the stuck state named if it never does), then for the refused process's exit, and only then samples the 90 s window. The window therefore opens right after the refusal, about 100 s earlier, and the test runs about 100 s shorter. No production code changed. Separately, the same read exposed a product race: a relaunch whose QUIC connect supersedes the killed original's link before the survivor sees that link close leaves the survivor's membership record for the NodeId at `Member` indefinitely, because the boot-token retirement is a death-path removal that feeds the membership FSM nothing and the SWIM verdict is deferred by cold-boot suppression and then dropped when the retired member is swept. This change does not fix that.
