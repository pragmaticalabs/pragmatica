### Added (2026-11-14 — #2898: Conduit (RealWorld) on Terra as a permanent nightly acceptance app)
- **A complete third-party API suite now runs against a Terra application every night.** `terra/conduit-acceptance` vendors Conduit as Terra slices; `run-acceptance.sh` starts PostgreSQL and the app and runs the upstream Hurl suite (13 files, vendored byte-identical at realworld-apps/realworld commit `25588846c314b15a5e427ffe816e6b4af7be68c7`, hash-checked by `check-vendored.sh`), exiting non-zero on any failure. It runs in the `conduit-acceptance` job of `heavy-forge.yml` (nightly and manual only) and a red night is reported through the `heavy-nightly` issue. [verified: `terra/conduit-acceptance/run-acceptance.sh` green on the unmodified app, red with the injected defects]
- Error-response body assertions are rewritten to the RFC 9457 `detail` (32 cases) because Terra answers problem details; the 12 `token: is missing` cases are exempt by name (the framework auth gate wording says Bearer); see `terra/conduit-acceptance/README.md`. A malformed login email is a 422 before the credential lookup, as the current upstream spec expects.
- Project-owned requests in `terra/conduit-acceptance/local/hurl` (pagination order for every listing and the feed; forged, `alg=none`, expired and wrong-scheme tokens answer 401) run after the vendored suite, which stays unmodified. The runner now refuses a busy `APP_PORT` (exit 2) instead of running against whatever listens there; `check-fail-closed.sh` pins that.
