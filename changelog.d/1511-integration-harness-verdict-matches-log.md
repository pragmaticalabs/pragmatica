### Fixed (2026-09-29 — #1511, #1512: the integration harness reported a pass its own log contradicted)
- **A `[FAIL]` logged from a background worker or outside any test no longer disappears from the suite tally (#1511).** The per-test latch was a shell variable, so a subshell's increment never reached it and a cleanup failure was never counted: suites 02y and 02w printed `1 passed, 0 failed` over a logged failure. Every `[FAIL]` is now also appended to a per-run file shared with subshells; `run_test` counts the lines its test added, and `print_summary` counts the rest against the suite and names them. [verified: `script-gate/src/test/java/org/pragmatica/scriptgate/IntegrationHarnessTallyTest.java` — the real `lib/common.sh`; the pre-fix library turns it red]
- **02w's "checkpoint driver alive" can no longer pass over an empty node set (#1512).** `wait_for` evaluates its predicate in a fork, so the node count it collected never reached the caller, and the PASS line read "across 0 node(s)". The test now collects again in its own shell and asserts on that read. [verified: `IntegrationHarnessTallyTest.checkpointDriverAlive_emptyNodeSet_fails`, `…_reportsTheNodesItActuallyChecked` — the pre-fix function turns both red]
