### Fixed (2026-10-18 — #279 item 3: distributed cache entries now expire)
- **`DHTCacheBackend` stamps the configured TTL on every entry it stores.** The DHT has no expiry primitive, so each stored value is now a 4-byte self-identifying header (three `0xFF` bytes and a format version), the writer's wall-clock expiry (8 bytes, epoch millis), then the encoded value; a read past that instant is a miss. DISTRIBUTED and TIERED caches use `ttl_seconds`; the distributed idempotency store uses `retention_seconds`.
- **Bounds.** Expiry is lazy: an entry nobody reads again stays in the DHT until it is read, overwritten or removed. A read that finds an expired entry removes it, after re-reading it once to confirm it is unchanged. The DHT has no compare-and-remove, so a fresh put of the same key landing between that re-read and the remove is lost. The window is set by the quorums: when R + W <= RF (the replicated DHT the idempotency store uses) a read quorum need not include the replicas holding an acknowledged put, so the window lasts until that put has replicated, i.e. the replication lag, not one round trip. A failure of the re-read or the remove fails the get rather than reporting a miss; for the idempotency store that means a retry can re-run the method. It compares clocks across nodes, so skew moves the effective expiry by that skew (a node ahead sees entries expire early, one behind sees them live late; for idempotency, early means a retry inside the retention window can re-run the method). A TIERED promotion starts a fresh L1 TTL, so a value can be served for up to one extra TTL from L1 after its L2 entry expired. Entries written before this change cannot start with the header (a type tag is at most 3 bytes and ends in a byte with the high bit clear), so they read as a miss and are removed with the same re-read and the same window.
- **Not in this change.** Cross-node invalidation for TIERED caches stays deferred, as before.
