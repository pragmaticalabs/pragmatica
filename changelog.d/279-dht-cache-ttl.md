### Fixed (2026-10-18 — #279 item 3: distributed cache entries now expire)
- **`DHTCacheBackend` stamps the configured TTL on every entry it stores.** The DHT has no expiry primitive, so each stored value is now the writer's wall-clock expiry (8 bytes, epoch millis) followed by the encoded value; a read past that instant is a miss and removes the entry. DISTRIBUTED and TIERED caches use `ttl_seconds`; the distributed idempotency store uses `retention_seconds`.
- **Bounds.** Expiry is lazy: an entry nobody reads again stays in the DHT until overwritten or removed. It compares clocks across nodes, so skew moves the effective expiry by that skew. A TIERED promotion starts a fresh L1 TTL, so a value can be served for up to one extra TTL from L1 after its L2 entry expired. Entries written before this change have no expiry prefix and read as a miss, then are removed.
- **Not in this change.** Cross-node invalidation for TIERED caches stays deferred, as before.
