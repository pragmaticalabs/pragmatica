### Fixed (2026-10-11 — a leader change mid-replacement trimmed a healthy follower)
- **A voter is removed only on observed evidence of failure.** A freshly elected leader ranked every voter it had not yet observed as unready, so its heal could drop a healthy voter during a replacement swap and the surplus trim then drained it (`FAILED_KEPT_BOTH`). Now a voter is healed only when it was observed in a state other than READY and SYNCING (SYNCING is what a healthy follower reports across a leader change) or membership holds it Dead or Departing, and a Dead voter's stale READY entry no longer shields it; a never-observed voter is never healed away, however long the leader has led. A surplus trim (more voters than configured) is a size reduction, not a heal: it removes failed voters first, then never-observed ones, then healthy ones (id order only breaks ties), and never runs while a replacement swap is in progress. A swap's leaver is always the original. [verified: `CoreVoterReconcilerTest`, `FailedVoterEvidenceTest`, and `EmberVoterHealTest` (kill a voter in a 5-core cluster: it is replaced within the bound; emptying the evidence argument at the `AetherNode` call site turns it red)]
- **A startup config race, or an inventory initialization still in progress, defers instead of rolling back.** A replacement that began before the bootstrap source configuration was committed was rolled back with "Committed source configuration required for fleet inventory". Provisioning now waits for the configuration, bounded by the provisioning deadline, and a configuration that never appears ends the replacement with a cause naming the missing committed configuration. [verified: `NodeReplacementEnvTest`]
