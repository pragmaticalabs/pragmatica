### Fixed (2026-11-08 — #1971, #1938: a non-owner copy's doubted prefix comes from the committed epoch history)
- **A non-owner stream copy is judged by every epoch its own history records** (#1971, I-24). `StreamPartitionManager` now reads the committed `StreamPartitionOwnershipValue.epochStarts()` through the new `CommittedEpochStarts` seam (a required argument of the production factory, replacing the never-bound `EpochStartSource`). A copy a compare verified for an epoch is doubted from the lowest committed start after that epoch; any other copy is doubted from the lowest offset at which a committed epoch after one of its recorded epochs re-assigned that epoch's records (a copy with no history counts as older than every kept start), so a current-epoch record appended on top of a replaced prefix no longer makes the prefix trusted, also after a restart. The lowest start after an epoch is used, not the first listed, on this path and on the consumer's epoch-validated resume (`EpochValidation`). A judge that read an older current epoch no longer replaces a newer epoch's verdict. Records below the doubt start are served as before; a copy that follows the current epoch is not doubted; a doubt is re-judged on every call, so it lifts when the start it waits for is committed. [verified: `StreamPartitionManagerEpochStartsTest`, `EpochValidationTest` (mutations: current-epoch-start only, history ignored, newest-epoch lineage, first-listed start, stale-judge guard dropped, all red)]
- **A WAL replica fed by an owner that keeps no log is attributed to the committed epochs** (#1938, I-25). When the committed owner answers a backfill with a vouched-empty history (`PartitionBackfill` routes only that answer through the new `AlignedRecovery.applyOwnerAttributed`), the replica installs the provenance of the committed epochs up to the page end (rule `coversFrom == epoch`, spec #1569 section 7.5.1a; encoded by the encoder an owner with a log uses), so the next re-verify no longer compares the copy as `HISTORY_MISSING`. An empty history from any other source (a survivor, a WAL copy whose log records none) stays empty. [verified: `WalReplicaOfLoglessOwnerTest`, `CommittedProvenanceTest`]
- Limits: a folded committed entry (`coversFrom != epoch`) yields no entry, so its range stays undefined (`HISTORY_INCOMPLETE`); with no committed history the behaviour is the old one (doubted from 0, empty slice stays empty); the owner-side half of #1938 (a log-less owner serving records) is not changed.
