### Fixed (2026-11-08 — #1971, #1938: a non-owner copy's doubted prefix comes from the committed epoch history)
- **A non-owner stream copy is doubted from the start of the earliest committed epoch after its own lineage** (#1971, I-24). `StreamPartitionManager` now reads the committed `StreamPartitionOwnershipValue.epochStarts()` through the new `CommittedEpochStarts` seam (a required argument of the production factory, replacing the never-bound `EpochStartSource`). The lineage is the copy's verified epoch, else the newest epoch its own log recorded, else unknown (older than every kept start). Records below that start are served as before; a copy that follows the current epoch is not doubted; a doubt is re-judged on every call, so it lifts when the start it waits for is committed. [verified: `StreamPartitionManagerEpochStartsTest` (mutations: current-epoch-start only, history ignored, lineage fallback dropped, sticky doubt all red)]
- **A WAL replica fed by an owner that keeps no log is attributed to the committed epochs** (#1938, I-25). When the catch-up source vouches an empty history, `installProvenance` installs the provenance of the committed epochs up to the page end (rule `coversFrom == epoch`, spec #1569 section 7.5.1a; encoded by the encoder an owner with a log uses), so the next re-verify no longer compares the copy as `HISTORY_MISSING`. [verified: `WalReplicaOfLoglessOwnerTest`, `CommittedProvenanceTest`]
- Limits: a folded committed entry (`coversFrom != epoch`) yields no entry, so its range stays undefined (`HISTORY_INCOMPLETE`); with no committed history the behaviour is the old one (doubted from 0, empty slice stays empty); the owner-side half of #1938 (a log-less owner serving records) is not changed.
