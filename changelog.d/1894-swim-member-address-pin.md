### Security (2026-10-04 — SWIM: pin each member's address to its process identity)
- **A member's SWIM address is now pinned to its process identity, and an address change is refused and reported.** The pin is the first source address that announced the member and then answered a probe as that member. An ANNOUNCE from the pinned address behaves as before. An ANNOUNCE for a pinned member from any other address is refused whole (no reply, no probe or QUIC address change, no tombstone clear) and raises the `swim-member-address-conflict` operator warning (WARNING), throttled to one event per member per 60 s. Gossip that carries another address for a pinned member is ignored for the address (the state it carries is still applied) and raises the same warning; a member re-admitted through gossip gets the pinned IP. [verified: integrations/swim `SwimAnnounceSourcePinTest` — unit level, through the real protocol with a fake transport; no multi-node proof of the event reaching `/api/events`]
- **An ANNOUNCE from an address with no pin yet earns that address one empty probe and nothing else.** Tombstone clear, introduction, the QUIC dial hint and the membership-snapshot join ack now wait for a valid ack (right sequence, naming the announced member, from the probed address). A joining node therefore gets its join ack one round trip later. [verified: `SwimAnnounceSourcePinTest.firstContact_*`]
- **Changed: the mid-life address refresh is removed.** A live process whose IP changes (for example a container reconnected to a Docker network with a new address) is no longer adopted on its next ANNOUNCE; peers keep probing the pinned address and report the conflict. A replacement process runs under a fresh NodeId and is pinned afresh; replace the node, never restart it under the old NodeId. Local docker-mode partition tests that reconnect a container with a new address see the refusal instead of a refresh; firewall-style partitions keep the address and are unaffected. The docker-mode partition suite (`12-network/test-partition-quorum-gate.sh`) now reconnects with `docker network connect --ip <same address>`, which needs the fixed subnets now set on the `aether-a-network` / `aether-b-network` compose networks (an existing network must be removed once so it is recreated with the subnet). [mechanism: `routeByAddressPin`; `SwimProtocolTest.handleAnnounce_knownMemberReAnnounceFromNewSourceIp_*`]
- **A process token is admitted only when the member's own answer carries it.** The source of an ANNOUNCE is probed, and its token is admitted (a genuinely new process is then refused, as before) only when the answer carries that token; otherwise nothing is retired and `swim-member-identity-conflict` is raised (WARNING, throttled per member). Gossip no longer retires a member: only the member's own answer to this node's probe does. Every Ack now carries the sender's own identity first, and probe sequences start at an unpredictable per-process offset. [verified: `SwimAnnounceSourcePinTest.oldTokenAnnounce_*`, `newProcessWithTheSameId_*`, `ack_alwaysCarriesThisProcessesIdentityFirst`, `firstContact_ackOfAnEarlierProcessLife_*`; `SwimBootTokenTest.differentToken_*` — unit level] [unverified: a mixed-version cluster; an older node's Ack carries no identity, so its ANNOUNCE is not confirmed]
- Local docker-mode partition suite (12-network S05/S06): the cluster networks now have fixed subnets and the reconnect restores the container's address with `docker network connect --ip`. [verified: the reconnect mechanism on a scratch network, same address restored; harness self-tests pass] [unverified: the suite itself, not run]
- No wire change: the ANNOUNCE and Ack shapes are untouched. Failure-almanac row and `OPERATOR_WARNING` code list updated.
- **The join-announce loop now stops on the join ack, not on an inbound Ping.** The seed's address-candidate probe is an ordinary Ping; stopping on it ended the joiner's retries before the seed had accepted the ANNOUNCE, so a lost Ack to that probe left the joiner un-introduced for good. The loop now runs until the sequence-0 join ack arrives, and a seed with nothing to tell sends one empty sequence-0 Ack so the loop can still end (CodeRabbit review on this PR). [verified: `SwimProtocolTest.announceJoin_inboundPingReceived_keepsAnnouncing`, `announceJoin_joinAckReceived_cancelsAnnounceLoop`, `SwimJoinSyncTest.announceReply_withNothingToTell_*`; unit level, all three red against the previous stop condition]
