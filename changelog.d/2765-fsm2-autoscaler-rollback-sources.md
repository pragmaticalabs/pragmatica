### Fixed (2026-11-12 — #2765: FSM2 F5b, autoscaler and #1573 auto-rollback sources on FSM2)
- **On an FSM2 cluster the autoscaler and #1573 automatic rollback read slice state that FSM2 never writes** (`NodeArtifactKey`), so the all-instances-failed detector saw no ACTIVE instance and automatic rollback was silently off, and the control loop's scaling gates never saw a slice load or activate.
- Under FSM2 both now read the current `SliceObservedKey` rows (a row from a process other than the admitted one is stale and reads as absent; an unknown token reads as current). LEGACY keeps its sources unchanged. The binding is recorded as `B22.*` in the W-15 wiring baselines. `[verified: aether/forge/forge-tests/src/test/java/org/pragmatica/aether/forge/AutoRollbackOnAllInstancesFailedFsm2Test.java]` (Heavy; every #1573 scenario on a three-node FSM2 Ember cluster).
- The rollback record stays the guarded leader transaction of #2622, and every `SliceTargetKey` writer (autoscaler, rollback, FSM2's own rollback) writes against the value it read, so of two racing writes from the same committed value at most one commits. `[mechanism: expected-value mutations in one LeaderTransaction]`
