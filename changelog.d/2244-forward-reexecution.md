### Fixed (2026-10-18 — #2244: a forwarded non-idempotent request could run twice)
- **A forwarded POST, PATCH or CONNECT was re-sent to another node after a hop timeout or a failure answer from the target**, so a slow write could execute on two nodes while the client got 504. Such a request is now re-sent only when the transport proves the frame never left this node: no candidate, target not connected, or the write refused before it was written. Idempotent methods (RFC 9110 §9.2.2) still retry as before. [verified: aether/aether-invoke/src/test/java/org/pragmatica/aether/http/forward/HttpForwarderIdempotencyTest.java]
- `ClusterNetwork.sendOutcome(NodeId, message, TimeSpan)` reports the TTL-bounded send's local outcome. Only a refusal counts as not sent, because a frame reported `Sent` or `ConnectionDead` may still be delivered from the offline buffer. [mechanism: QuicClusterNetwork.dispatchPayloadWithOutcome]
- A failed forward answers 503, following the 2026-10-07 ruling (know 14a3606152). The detail reads "outcome unknown, may have been applied; retry only an idempotent operation" when any attempt may have reached a node, and "nothing was applied; safe to retry" when none left this node. App routes answered 504 before; management forwards already answered 503. [verified: HttpForwarderIdempotencyTest, HttpForwarderDeadlineTest]
- A target that refuses a forwarded request before dispatching it (no local route, wire budget exhausted on arrival, request undecodable) now answers with a typed `HttpForwardNotApplied` message, outside the failure text a slice controls. The sender re-sends it to another node whatever the method. If every target answers that way, the client gets 503 "nothing was applied; safe to retry". [verified: aether/aether-invoke/src/test/java/org/pragmatica/aether/http/forward/HttpForwarderRetrySafetyTest.java, aether/node/src/test/java/org/pragmatica/aether/http/AppHttpServerForwardBudgetTest.java]
- The task-group management path now answers its budget exhaustion with the ruling's 503 instead of 504. It also remembers an earlier attempt that may have been applied. [verified: HttpForwarderRetrySafetyTest]
