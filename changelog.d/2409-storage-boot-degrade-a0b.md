### Changed (2026-10-25 — part of #2409: storage boot and degrade behaviour)
- **A `disk_path` the operator wrote that cannot be opened now refuses the boot**, naming the instance and the path. Before, the node came up on memory plus the shared tier, so writes were acknowledged without a local durable copy and the node reported healthy. **Config-breaking** for a node that booted degraded over a written `disk_path`: mount the path, or remove the key to use the default. [verified: `aether/node` `StorageFactoryBootDegradeTest`]
- **The synthesized default `artifacts` and `content` (and any instance that writes no `disk_path`) still degrade when their default path cannot be opened, now with a `storage-degraded` cluster event, a WARN and the `aether.storage.degraded` gauge.** [verified: `aether/node` `StorageAttentionWatchTest`]
- **Two nodes can no longer share one disk-tier directory.** The directory is claimed when the tier opens (a `.mount-claim` file holding the node id, host and process); a second live node refuses to boot with an error naming the holder. A claim whose process is gone is taken over; a claim written from another host cannot be checked and is refused until its file is removed. [verified: `integrations/storage` `MountClaimTest`, `aether/node` `StorageFactoryBootDegradeTest`]
- **Memory tiers are bounded by half of the maximum heap in total** (the `streams` tier counted); a configured size that does not fit is cut proportionally, with a WARN and a `storage-degraded` event. The defaults (528 MiB in all) are unchanged from 1.06 GiB of heap up. [verified: `aether/node` `StorageFactoryBootDegradeTest`, `MemoryTierBudgetTest`]
- **Every storage condition that needs an operator now raises `storage-degraded` and, when it ends, `storage-recovered`:** demotion refused because the only durable tier is over its watermark, a failing metadata snapshot write, an older snapshot restored. [verified: `integrations/storage` `StorageConditionsTest`, `aether/node` `StorageAttentionWatchTest`]
- **The storage readiness gate now reaches write-ready**: the node signals consensus sync when it reports ready, so `isWriteReady` in the storage status is true on a running node instead of false for ever. [verified: `aether/node` `StorageAttentionWatchTest`]
