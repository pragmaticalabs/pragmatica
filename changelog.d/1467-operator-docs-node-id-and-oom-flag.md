### Fixed (2026-09-29 — #1467: operator docs still reproduced #966 and taught a node id that can never rejoin)
- **`runbooks/deployment.md` no longer `systemctl enable`s a unit whose node id is the hostname (`%H`).** Start-on-boot relaunched a rebooted host under an id the cluster had already removed; the rejoin was refused and the node started but never joined. The runbook now starts the unit without enabling it, and says to bring a rebooted or rebuilt host back as a replacement with a new `--node-id`. [mechanism: terminal-removal membership — a removed NodeId is never re-admitted (`deployment-recovery.md` §1)]
- **Three copy-pasteable node launches now carry `-XX:+ExitOnOutOfMemoryError`:** `runbooks/scaling.md` (add a node), `aether-overview.md` (deploy to a cluster) and `ttm-guide.md`. Without the flag, an out-of-memory node keeps answering SWIM and holds its slot (#966).
- **`deployment-recovery.md` §4.1 describes the JVM launch that ships:** an `aether-node.service` unit with `Restart=no` and a flagged launcher, restarted by unit name (#1021), not `nohup java -jar` plus `pkill`. The same stale description in `feature-catalog.md` #221 is corrected and now says the systemd-unit launch has not been run on a live cloud host.
- Search space: every tracked `aether/docs/**/*.md` line matching `java .*(aether-node\.jar|org\.pragmatica\.aether\.Main)`. The remaining unflagged match, `reference/configuration.md:400`, is an argument illustration, as #1467 itself notes.
