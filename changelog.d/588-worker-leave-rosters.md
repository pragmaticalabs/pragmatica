### Fixed (2026-09-14 — #588: terminated workers lingered as UNKNOWN membership ghosts in cluster status)
- **A dead worker was never forgotten by the two rosters the status routes read, so it stayed listed with `derivedStatus: "UNKNOWN"` indefinitely.** A core node's death travels on `MembershipDecision.NodeRemoved`, which `ClusterSyncCollector.removeNode` (the pong roster — `allMetrics()` is the node list `GET /api/v1/cluster/status` serves) and `TopologyObserver.pruneDeparted` (the transport topology — the node list `GET /api/v1/status` serves, the discovery-gossip set and the dial set) both consume. A worker's death travels on the separate `WorkerLeaveDecision` channel (#731), and that channel reached only the cluster deployment FSM. Membership had already declared the worker dead; the rosters were simply never told. [mechanism: `MembershipDeltaProjector.emitWorkerLeave` emitted the leave and did not prune; `AetherNode` routed `WorkerLeaveDecision` to `clusterDeploymentManager::onWorkerLeave` only; `TopologyObserver.addNode` admits a worker from the same SWIM `JoinAnnounced`/`MemberDiscovered` edges as a core, with no role filter, and `removeNode` is reachable only through `pruneDeparted`]
- `emitWorkerLeave` now prunes the departed worker from the transport topology exactly as the core removal arm does, and `AetherNode` routes `WorkerLeaveDecision` to `metricsCollector.removeNode` alongside the existing `NodeRemoved`/`NodeDecommissioned` routes. [verified: `TerminatedWorkerGhostTest` (Heavy, 3 cores + one hard-killed worker, default detection timeouts) — red at `2005ea7d2` with `pongRoster=true topology=true statusRoute=true` 30s after the leader's FSM projected the worker as `Dead` and `Received worker leave` had been logged; green after, all three false within 0.5s of the verdict. Reverting the projector hunk alone reddens exactly the topology assertion (`pongRoster=false topology=true statusRoute=false`); reverting the route alone reddens exactly the pong-roster assertion (`pongRoster=true topology=false statusRoute=true`). Unit: `MembershipDeltaProjectorTest.workerRemoval_prunesTheWorkerFromTheTransportTopology` red/green on the projector hunk]
- The earlier projector test assertion that the prune "must not run for a worker" was wrong, not the code it now fails against: it described the prune as core-only, but the topology it prunes is not core-only. It is replaced by the test above; the core-channel emptiness assertions in the same test are unchanged.
