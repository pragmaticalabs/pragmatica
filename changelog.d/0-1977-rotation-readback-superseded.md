### Fixed (2026-11-08 — #1977: a gossip-key rotation was reported Superseded although it landed)
- **A rotation that landed is reported as landed when one later rotation commits before the re-read** (#1977, I-34). `GossipKeyRoutes.confirmLanded` now counts a rotation as landed when the committed record's `currentKey` OR `previousKey` is ours, and the response describes our rotation. A later rotation derives from the committed record, so its `previousKey` is ours only if ours was committed; a fenced-out competitor from the same base carries the base key and is still reported `Superseded`. [verified: `GossipKeyRoutesTest#rotate_laterRotationLandsBeforeReread_reportsOursLanded`, `#concurrentRotation_isFencedOut_andReportedRatherThanSilentlyLost` (mutation: `currentKey`-only, red)] This is a unit test against an in-process KV store, not a multi-node run.
- Limits: two or more later rotations committing before the re-read still report `Superseded` although ours landed (a false refusal; the operator recovery is to read the current key id before retrying, as the message says). The `NodeReplayCursor` half of #1977 was already fixed by `CommitWitness` and is not changed here.
