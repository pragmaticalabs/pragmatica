### Fixed (2026-11-26 — #3778: `HttpServerBindHostTest$OverHttp3` "nothing is listening" flaked)
- **"Nothing listens" is now decided by binding the address ourselves**, not by waiting for an ICMP port-unreachable. The old datagram probe read "no refusal" as "something listens", but the kernel can rate-limit the ICMP reply, and another process's UDP socket on the port (the port came from a TCP probe) receives the datagram just the same. The HTTP/3 failed-bind test now takes a UDP-probed port and asserts the loopback address can be bound; the HTTP/1.1 sibling uses the same bind check; the two HTTP/3 bind-host tests ask whether the non-loopback address is held (the wildcard listener holds it, the loopback one does not). Test-only change.
