### Fixed
- A wrong-typed config value (`port = "80x"`, `enabled = "yes"`) is now refused by name instead of silently taking the reader's default in the Aether config loaders (`ConfigLoader`, `WorkerConfigLoader`, `ClusterBootstrapConfigParser`), Ember config, blueprint deployment and stream-consumer parsing, JBCT slice config, route config and the record binder of `TomlConfigService`. `TomlDocument` records each present-but-wrong-typed typed read and `requireNoTypeMismatches()` fails the load with `TomlError.TypeMismatches`, naming section, key, expected type and value. The JBCT CLI's own `PartialConfig` layering, the standalone `fromClusterToml` readers, `IncludeResolver` and the CLI bootstrap formation still default wrong-typed values (#1455 stays open for them).
