### Added (2026-09-13 — #1060: CI never ran the Heavy forge tests or the cloud harness stub suites)
- **The auto-heal, drain and membership-chaos coverage ran in no CI job.** `forge-tests` excludes `@Tag("Heavy")`, and no workflow invoked the harness stub suites under `aether/tests/integration/test/`. A regression in either could merge with every check green.
- New `stub-suites` job in `ci.yml`, on every PR and push. It runs every `test/test-*.sh` through `test/run-stub-suites.sh`, which fails a suite that exits non-zero, prints no `passed:`/`failed:` summary, reports failures, or reports zero passes. A run that finds no suites exits 2, not green. `[mechanism: .github/workflows/ci.yml stub-suites job; aether/tests/integration/test/run-stub-suites.sh]`
- New non-required `heavy-forge.yml` workflow. It runs `-Dgroups=Heavy` nightly (on `main` only, because GitHub schedules only the default branch's workflows), on `workflow_dispatch`, and on PRs labelled `run-heavy`. It writes a per-class testcase table, counted from `<testcase>` elements, to the run summary. `[mechanism: .github/workflows/heavy-forge.yml]`
- `forge-tests`' failsafe fork timeout is now the property `failsafe.forkedProcessTimeoutInSeconds`, default unchanged at 1800. The Heavy workflow raises it because all Heavy classes share one fork.
