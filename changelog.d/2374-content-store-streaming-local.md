### Added (2026-10-27 — #2374: streaming, ranged object store replacing the whole-byte[] content store, local mode)
- **`ContentStore`: an object is written as a stream and read as a range, never as one `byte[]`.** `create` returns an `ObjectWriter` (`write(ByteBuffer)`, `commit(expected)`, `abort()`); `open(ref, range)` returns a pull-based `ChunkStream`. A writer cuts the bytes into chunks, hashes each chunk (its block id) and the whole object incrementally (SHA-256), and keeps at most `write_window` blocks being stored; a stream holds at most `read_ahead + 1` blocks. Each block is integrity-checked by the storage instance as it is read, and a failed block fails the `next` that reaches it. The whole-`byte[]` store it replaces is removed (see `2374-content-store-bytes-api-removed.md`). [verified: `ContentStoreLargeObjectTest` writes and reads a 384 MiB object in a JVM limited to 256 MiB of heap and compares the SHA-256 of the bytes generated, stored and read back, with ranges across a block edge, at the end and at the start; `ContentStoreFiveGiBTest` (tag `Slow`, excluded from the default build) does the same at 5 GiB]
- **Objects have ids, metadata and a namespace.** An object is an `ObjectId` (16 random bytes) with `ObjectMeta` (display name, content type, size, SHA-256, owner, creation time, expiry, attributes); `stat`, `update`, `bind`/`lookup` (one name per object outside a rename window, with a precondition; local-mode rename is never unnamed and may briefly carry both names), `delete` and `list` (name prefix, cursor, limit) work on it. A store is bound to one namespace when it is provisioned and cannot stat, bind, update, list or delete another namespace's object; reading by `ObjectRef` crosses namespaces. Every object, one-chunk objects included, has a manifest block and an object-entry block holding its metadata and the manifest id (ref `o/<namespace>/<id>`; a name is the ref `n/<namespace>/<name>`). The owner stamped on an object is its namespace. [verified: `ContentStoreObjectTest`]
- **A write that does not finish gives its credits back.** A writer that fails, is aborted, is committed with a digest or length other than the one expected, or fails to write its manifest or entry releases exactly the block credits it took; delete releases the chunks, the manifest and the entry once. [verified: `ContentStoreCreditsTest`]
- **New `ContentStoreConfig` keys, all optional:** `namespace` (default `default`, validated when the store is provisioned), `write_window` (4), `read_ahead` (2). An existing `[storage]` content section binds unchanged. [verified: `ContentStoreConfigBindingTest`, `ContentStoreFactoryTest`]
- **`StorageInstance.listRefs(prefix)`** lists the names of the references an instance holds under a prefix; the default lists nothing.
- **Local mode only.** `resume`, `link` and `checkpoint` answer `NotSupported`; `lookup` and `list` see this node, and `list` reads the namespace's entries to order them.
