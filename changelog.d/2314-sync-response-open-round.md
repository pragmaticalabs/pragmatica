### Fixed (2026-10-19 — stale input crossing a quorum-loss pause no longer changes a paused engine, #2314)
- **A sync response is accepted only into an open sync round.** `handleSyncResponse` took responses unless the engine was `Active`, so answers to a request sent before a pause, arriving after it, could call `activate()` and take a `Paused` voter to `Active` with no quorum ACTIVE while quorum was still lost; a settled observer could likewise re-adopt from a late third response. A `SyncRequest` going out opens a round, an activation completes it and a pause invalidates it. [verified: `RabiaStaleSyncInputTest`]
- **A paused observer stays paused when it applies a decision.** `advancePhaseAsObserver` set `Observing` from any state; it now leaves `Paused` alone, and the quorum ACTIVE resumes the node (as an observer when it is not a voter). [verified: `RabiaStaleSyncInputTest`, `V1796ProbeTest`]
