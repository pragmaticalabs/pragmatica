### Fixed
- A joining observer (such as an auto-heal replacement) no longer reports a false CRITICAL `QuorumLost` when a sync-retry tick queued behind its state adoption runs after the adoption. The tick found only a voter's `Active` state settled, moved the observer from `Observing` back to `Syncing` and published PASSIVE, which the application layer treated as quorum loss and answered by quiescing routing on a node whose cluster had never lost quorum.
- `QuorumLost` is now a statement about voters: a PASSIVE on a node that is not in the installed voter roster (an observer) raises no CRITICAL `QUORUM_LOST`. It raises a distinct WARNING `OPERATOR_WARNING` with the new code `observer-consensus-lagging` instead. This covers every way an observer can leave `Observing` (a catch-up resync of a far-behind observer included), not only the sync-retry tick. A voter's loss of quorum is unchanged. Routing on the observer is still quiesced.
