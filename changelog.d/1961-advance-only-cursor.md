### Fixed (2026-11-07 — #1961: a late periodic cursor commit could rewind a consumer group's cluster cursor)
- **A periodic cursor commit that outlived its 5 s bound could land late and step the group's committed cluster cursor back**, causing redelivery of already-processed events; the applier fenced the cursor checkpoint by assignment token and rewind epoch only, and compared no offsets (streams audit A-09).
- The consensus applier gains a scoped advance-only arm (`ScopedMonotonic`, overhaul PR-5a, invariant I-18): a stream cursor checkpoint is refused when its `(rewind epoch, owner epoch)` scope is lower than the committed one, or equal with a lower offset. An operator rewind (a strictly newer rewind epoch) and the KIP-320 re-seek (a strictly newer owner epoch) mint a newer scope and still move the cursor back. `[verified: aether/node/src/test/java/org/pragmatica/aether/node/stream/CursorCheckpointAdvanceOnlyTest.java, integrations/cluster/src/test/java/org/pragmatica/cluster/state/kvstore/KVStoreScopedMonotonicFenceTest.java]` (component level, the real applier; no multi-node failure-injection test pins it).
- **Flag day for consumer cursors:** the guarantee holds only when every node runs a build with this arm. In a mixed-version cluster an old applier can still rewind the cursor (the #1961 behaviour): an old replica admits a late lower same-scope checkpoint that a new replica refuses, so the KV value for that cursor key diverges until the next advancing commit, which both rules accept. Consequence: at most the earlier redelivery (at-least-once). Nothing refuses a mixed cluster (#666 is open, `Hello` carries no version field). Safe procedure the docs can offer today: replacement-based rolling upgrade (`aether cluster upgrade`), accepting that cursor regression is possible until every node runs the new build. Pre-GA there are no users to migrate. No new KV record and no wire tag: the checkpoint value's fields are unchanged. `[mechanism: the arm is a pure function of committed storage and the incoming value, evaluated inside the Rabia applier on every replica]`
- A refused late commit is reported to its (already abandoned) caller as `LocalOnly`, not `Persisted`, through the committed-state re-read. `[verified: CursorCheckpointAdvanceOnlyTest#lateCommitThroughTheStore_isRefused_andReportedAsNotLanded]`
