### Added (2026-11-20 — #3303: restore-rejection record primitives in the backup repository)
- **A restore candidate that was refused can now be recorded beside the backup file**: `GitBackupRepository.commitRejection` and `removeRejection` write and remove `restore-rejected.txt` as their own local commit and never push; `RejectionRecord` renders and parses the file. Each commit is scoped to that file, and a failed commit leaves no rejection change staged for the next backup commit `[verified: aether/node/src/test/java/org/pragmatica/aether/node/backup/GitBackupRepositoryTest.java]`.
- A record whose text does not parse (duplicate or unknown key, CR, missing trailing line feed, a number that is not plain ASCII decimal) reads as no record, and the factory refuses a value that would not survive the text form `[verified: aether/node/src/test/java/org/pragmatica/aether/node/backup/GitBackupRepositoryTest.java]`.
