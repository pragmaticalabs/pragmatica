### Fixed (2026-11-15 — #3271: EngineMarkerGuard: drained actions still run after the node refuses itself)
- **A node that refused itself could still run deployment work drained by an earlier opening.** When the guard opened, its parked actions moved to a pending drain while the opening thread queued behind a running action; a refusal before that thread got the lock cleared only the parked actions, and the drained `Activate` or `Deactivate` ran after the exit was requested.
- The refusal now drops the pending drain, and each drained action checks for a refusal just before it runs, so a refusal that lands mid-batch drops the rest of the batch. An action already started when the refusal lands still runs to completion. The `whenOpen` javadoc and the comment on the action lock are corrected to match.
