### Changed (2026-11-14 — #3269: inert [streams] config keys refuse the blueprint publish)
- **Behaviour change: a blueprint that published before is now refused.** A `[streams.X]` section carrying a key the runtime ignores (`compression`, a non-default `encryption_key_id`, `auto_offset_reset` other than `earliest`, the per-consumer tuning keys) used to drop that alias, report it under `rejectedStreamBindings` and publish; the consuming slice then failed at load with `UnboundStreamAlias`. The publish now answers HTTP 422 naming `inert-stream-config-key` or `inert-consumer-config-key`, and nothing is committed. A key leaves the refused set when it is wired. `unknown-stream-key` is unchanged (still drop-and-report).
