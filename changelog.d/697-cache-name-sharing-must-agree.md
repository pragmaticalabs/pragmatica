### Fixed (2026-10-11 — #697: `[cache.*]` sections sharing a `cache_name` could silently disagree about the one backend they share)
- **Sections that share a `cache_name` share ONE backend, built from whichever section provisioned first; the others' mode, TTL and capacity were silently ignored, and a different key or value type polluted the shared heap.** The factory now refuses a later section whose `mode`, `ttl_seconds`, `max_entries` or key type differs, or whose stored value type differs (for strategies that store: not `WRITE_AROUND`, whose return type is never cached). The failure names the cache name, the differing setting and both values, surfaced under the refused section by the resource provider. The check runs inside the per-name atomic registry update, and a refused section counts no hold.
- **Sharing a `cache_name` is still allowed and still intended** (the banking example's `CACHE_ASIDE` reader and `WRITE_AROUND` invalidators); `strategy` may differ. The issue's original ask, refusing every duplicate, would have refused that example, so it was narrowed to disagreement.
  [verified: `CacheNameSharingTest`, each check with a mutation going red]
- **Not detectable at provisioning:** the key/value type check only sees sections whose slice factory supplies `[key, response]` type tokens (key-bearing methods); a section without them is not compared on type. The first section is not named in the message (the factory does not receive section names). `[unverified: not detectable at provisioning]`
