### Added (2026-11-14 — #3009: core vo.Currency; #3008: core vo.Password with a policy)
- **`org.pragmatica.lang.vo.Currency`** (#3009) wraps `java.util.Currency`. `currency(String)` trims, upper-cases (`"usd"` is accepted) and looks the code up in the JDK's currency table; a blank input gives `CurrencyError.General.BLANK` and an unknown code gives `CurrencyError.UnknownCode(code)`, both `Cause.Validation`. [verified: `CurrencyTest`]
- **`org.pragmatica.lang.vo.Password`** (#3008) with the policy as data (`Password.Policy`: code-point bounds, a UTF-8 byte cap, optional `CharacterClasses`, optional Unicode normalisation; classes and normalisation OFF by default). `password(raw, policy)` is for register and change; `presented(raw)` is for login and checks non-blank only, so tightening the policy never locks out an existing user. `presented(raw, policy)` additionally applies only the policy's normalisation. Typed causes `TooShort(min)`, `TooLong(max)`, `TooManyBytes(maxBytes)` and fixed-text `General` constants; `toString` is redacted and no failure message carries the input. Core does no hashing. The default policy (8 to 64 code points, 256 bytes, no composition rules) is checked against NIST SP 800-63B-4 Sec. 3.1.1.2: 8 is the multi-factor minimum (15 is required when the password is the only factor, so such a deployment sets `minCodePoints = 15`), a verifier SHOULD permit 64, composition rules are SHALL NOT; NIST's NFC advice is not the default because the issue asks for normalisation OFF. [verified: `PasswordTest`]
