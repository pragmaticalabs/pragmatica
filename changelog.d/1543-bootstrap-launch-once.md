### Fixed (2026-10-06 — #1543 part B: CLI bootstrap relaunched nodes under the same NodeId)
- **A multi-core-source cloud bootstrap started every node in cloud-init and then restarted it** (`docker rm -f aether-node` + `docker run`, or `systemctl restart`) to inject the finalized PEERS — a same-NodeId restart, which membership refuses. Cloud-init now installs without starting, and the SSH push performs each node's first and only start. [verified: `aether/cli/src/test/java/org/pragmatica/aether/cli/cluster/BootstrapLaunchOnceTest.java` — `multiCoreSource_containerUserData_pullsButDoesNotStart`, `cloudPush_container_startsEachNodeExactlyOnce_andNeverRestarts`, `cloudPush_jvm_startsEachUnitExactlyOnce_andNeverRestarts`, `sshPush_startsEachNodeExactlyOnce_andNeverRestarts`]
- **The SSH source's "idempotent" `docker rm -f` is gone.** A host that already holds an `aether-node` (container in any state, or a unit that is active or failed) is refused with `NodeAlreadyStarted`, whose message names the way forward: destroy the cluster or replace the node under a fresh id. [verified: `BootstrapLaunchOnceTest.containerStartGuard_refusesAnExistingContainer_andStartsOtherwise` runs the generated command against a stub `docker`; `jvmStartGuard_refusesAnActiveUnit_beforeTouchingTheEnvFile`]
- **`--resume` keeps a per-node started ledger and never relaunches a started node:** healthy is skipped, unhealthy is refused by name. A resumed run also used to start with an empty node list (DEPLOY_RUNTIME iterated zero nodes and reported success); the list is now rebuilt from the state file. [verified: `BootstrapLaunchOnceTest.resume_*`, `deploy_recordsEachStartedNode_inThePersistedLedger`]
- **`cluster.genesis_voters` is rendered for the initial cores** — exactly the provisioned core ids across all sources, so a CLI-bootstrapped cluster forms one epoch-0 configuration. A CTM replacement render carries none. A core source of type DOCKER/FORGE renders no roster (its ids are not minted by this scheme). [verified: `BootstrapLaunchOnceTest.initialCores_renderGenesisVoters_equalToExactlyTheProvisionedIds`, `replacementRender_carriesNoGenesisVoters_evenWhenTheClusterHasInitialCores`]
- [unverified: a live two-provider cloud run — two core sources in one account forming a cluster — has not been executed for this change]
