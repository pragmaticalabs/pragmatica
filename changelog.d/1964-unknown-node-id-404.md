### Fixed (2026-11-24 — #1964: unknown node id answered 503)
- **A well-formed node id that is not a cluster member answered 503 `targetDisconnected`** (#1964) on the node-scoped management routes (`HEALTH_LIVE_GET`, `HEALTH_READY_GET`, `NODE_STATUS_GET`, `NODE_ENDPOINT_GET`, `NODE_SLICES_GET`, `NODE_ROUTES_GET`, `NODE_INFLIGHT_GET`, `NODE_METRICS_GET`): the forwarder sees only connected peers and cannot tell an id nobody knows from a member that is down. The management server now checks the id against the membership roster (`membershipFsm().memberStates()`) before forwarding and answers 404 for an id the roster does not list. A listed member that is not connected, dead ones included, keeps 503; `STREAM_REPLICAS` with an unresolvable owner keeps its 503 (#1039); a worker with a scoped roster keeps today's answer (follow-up). [verified: `ManagementServerForwardDispatchTest`]
