### Fixed (2026-10-25 — #2408: typed database causes did not reach callers; #2183: db-async dropped SQLSTATE and transience)
- **Database connectors replaced a typed cause with its message.** A row-decode failure (`RowDecodeError`) reaching a connector was rewrapped as `DatabaseFailure(new RuntimeException(message))`, so the caller could not tell it from a constraint violation or a dropped connection. Every connector now passes a cause that is already typed through unchanged, and no connector builds an exception from a cause's text. A guard test scans the connector and driver-adapter sources so the wrapping cannot return. [verified: aether/resource/api/src/test/java/org/pragmatica/aether/resource/db/MessageOnlyWrappingGuardTest.java]
- **SQLSTATE and transience now reach the caller.** `DatabaseConnectorError` constraint, query, connection and rollback failures expose the server's SQLSTATE through `sqlState()`, classified in one place (`SqlStates` in core), called by `fromSqlState` (JDBC, jOOQ) and by `R2dbcError` (R2DBC); each connector keeps its own error type, and postgres-async's `SqlError` keeps its driver-side sets, which a test holds to the same states: class 23 is a constraint violation, class 40 a transient rollback, connection loss (`08001/04/06`, `57P01-03`, class 53) a transient connection failure; `08007`, `08P01` and `57014` are never retried. The postgres R2DBC adapter used to reduce every driver failure to its message; it now sets the SQLSTATE, the exception class (integrity violation, rollback, transient) and the original cause. `RetryOn.TRANSIENT` therefore retries a lost connection and leaves a unique violation alone on every connector. [verified: *TypedErrorsTest in each aether/resource/db-* module]
- **JDBC connectors no longer turn typed failures into `DatabaseFailure(IllegalStateException)`.** `ResultNotFound`, `MultipleResults`, mapper failures and a failed transaction callback were thrown through `Result.unwrap()`; a failed callback surfaced as a transient `ConnectionFailed`, which a retry would re-drive. They now return as the same typed cause, and a mapper failure in `queryOptional` is no longer swallowed as an empty result.
- **Which errors a slice sees** is documented per connector in the resource reference. The jOOQ-over-R2DBC connectors are verified only at the error-mapping level until #2431 (they cannot run a query) is fixed; parameterised statements through the R2DBC adapter fail until #2432 is fixed.
