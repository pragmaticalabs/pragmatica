### Changed (2026-11-18 — #3334: ring geometry in one class, `maxEventSize` ring arity, index-capacity bound moves with the first segment)
- **The ring's geometry now lives in `RingGeometry`** (`aether/slice`): header and index-slot sizes, the 256 KiB segment unit, the first data region `min(dataRegion, max(256 KiB, maxEventSize))`, `maxCapacity(firstSegment)`, `floorBytes(capacity, maxBytes, maxEventSize)` and the hot-window default (16 384 entries, `max(4 MiB, maxEventSize)` bytes). `OffHeapRingBuffer` delegates to it and gains `offHeapRingBuffer(..., maxEventSize, ...)` arities; the existing arities mean `maxEventSize = 0` and keep today's values, so no ring is sized differently in production by this change. [verified: aether/aether-stream/src/test/java/org/pragmatica/aether/stream/OffHeapRingBufferFirstRegionTest.java]
- A first region above one segment is allocated as default-size segments (the last clamped to the data region), so the ring's `position / 256 KiB` addressing stays valid. [verified: OffHeapRingBufferFirstRegionTest#firstRegionAboveOneSegment_eventsStraddlingEveryBoundary_readBackIdentical]
- **`CLUSTER_EVENTS_MAX_COUNT` is bounded by the ring's capacity at the configured `CLUSTER_EVENTS_MAX_EVENT_SIZE_BYTES`** (`maxCapacity(firstSegmentBytes)`), not by the 256 KiB-first-segment constant. At the 64 KiB default the bound is unchanged; at 1 MiB it is 32 768 lower. [verified: aether/node/src/test/java/org/pragmatica/aether/node/ClusterEventsLimitsTest.java]
