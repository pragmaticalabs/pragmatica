### Fixed (2026-11-25 — #1400: the old assignee of a moved stream partition stayed REBUILDING)
- **A projection store leaves REBUILDING when its partition's assignment moved away** (#1400). The per-node REBUILDING state (`InMemoryProjectionStore`) was cleared only by a commit made on that node, and a node whose assignment moved away commits nothing more, so it reported REBUILDING forever. The node now reports every ACCEPTED cursor checkpoint, whichever node committed it, to the projection it hosts, stamped with the record's own rewind epoch; the new assignee resumes under the rewind's epoch, so the old store follows the group's committed cursor and goes LIVE once it passes the captured head. No `ProjectionStore` SPI change. Limit: a LATER rebuild requested elsewhere voids the old store's rewind token, and that store stays REBUILDING (truthful: it holds a generation nobody completes).
