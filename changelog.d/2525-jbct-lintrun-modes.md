### Changed (2026-11-17 — #2525: JBCT lints and formats per source root, all four modes honoured)
- **`lint`, `check`, `format`, `score` and the Maven goals resolve mode, `basePackage` and formatter settings per source root.** Files are grouped by the nearest `jbct.toml` and run through `LintRun`, so one invocation over a parent directory applies each module's own configuration; `testSourceDirectory` is declared as a test root. [verified: `jbct/jbct-maven-plugin/src/test/java/org/pragmatica/jbct/maven/MojoPerRootTest.java`]
- **`jbct.toml`, `--mode` and `-Djbct.mode` now accept `format-only` and `disabled`.** `format-only` formats and runs no rule, and the Maven goals now honour it (a module with `mode = "format-only"` used to fail the build with `JBCT mode "format-only" is not yet supported`); `disabled` formats nothing and lints nothing; `score` reports "not scored" for both. An unknown value is still refused, with a cause listing all four values. [verified: `jbct/jbct-cli/src/test/java/org/pragmatica/jbct/cli/JbctModeFixtureTest.java`, `jbct/jbct-maven-plugin/src/test/java/org/pragmatica/jbct/maven/JbctModeFixtureTest.java`]
- **The CLI and the Maven goals print what one shared resolver and run decide.** Each source root gets one summary line with its mode, where the mode came from, and its examined, format-checked and skipped counts; the run records what happened to each file and both front ends print its outcome lines (`N file(s) linted[, M file(s) not parsed]`, or `Nothing was linted: <root> (<reason>)`) without testing any mode themselves, so a run in which no rule ran says so instead of reporting a pass; a failing run names each failing root with its error and warning counts. A root's `[lint] failOnWarning` in `jbct.toml` fails the CLI and the Maven goals alike. [verified: `jbct/jbct-maven-plugin/src/test/java/org/pragmatica/jbct/maven/MojoSharedRunTest.java`, `jbct/jbct-cli/src/test/java/org/pragmatica/jbct/cli/CliSharedRunTest.java`]
- **Printed lines that changed, old and new.** `jbct check` reports a file it cannot read or parse once, as a parse error (it printed `format error: <f>: Parse error ...` and `parse error` for the same file); the Maven `check` goal reports it once, in the coverage reason, and `N format check error(s)` is gone from the failure reason. A failing `lint`, `check` or `process` names each failing source root (`JBCT failed in K source root(s): <root>: e error(s), w warning(s)`) where it printed totals (`N lint error(s)`, `N warning(s) (failOnWarning is enabled)`). The Maven `Processing N Java file(s)` and `Running JBCT check on N Java file(s)` lines and the `Linting`, `Checking format of`, `Formatting` and `Measuring N Java file(s)` lines count only files whose mode runs that activity and are omitted at 0. The Maven goals report a file that cannot be read as `Error reading <file>`, not as a parse error, and print the `Parse errors: N ... COVERAGE GAP` line also for `format` and `format-check`. [verified: `jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/RunLinesTest.java`]
- **New lines.** Every source root prints one `mode=<m> (<source>) root=<r>: N files; lint: ...; format: ...; test-root rule: ...` line before its other output (CLI: stdout for `format`, `check` and text `lint`, stderr for `lint --format=json|sarif` and `score`, so machine output on stdout still parses; Maven: INFO); a run that skipped files by mode adds `K file(s) skipped by mode: <root> (mode <m>)`, and an activity that ran on no file prints `Nothing was <linted|formatted|format-checked|scored>: <root> (<reason>)`. [verified: `jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/RunLinesTest.java`]
- **`jbct lint --format=json` gains `outcome` (an array of the run's outcome lines) and `skippedByMode`; no existing field changes. SARIF marks a run in which every file was skipped by mode as successful, with a note.** [verified: `jbct/jbct-cli/src/test/java/org/pragmatica/jbct/cli/CliSharedRunTest.java`]
- **`jbct lint`, `check`, `format` and `score` resolve a file under a package-directory argument inside a standard layout to the module's source root.** `jbct check m/src/main/java/com/x` with `m/pom.xml` is one source root, `m/src/main/java`, the root `jbct check m` gives (it was the argument itself); two package arguments of one module give one root and one summary line; with no `pom.xml` the argument stays the root. [verified: `jbct/jbct-lint/src/test/java/org/pragmatica/jbct/lint/cst/RootResolverTest.java`]
- Every other line the CLI commands print keeps the stream, the blank-line framing and the per-file detail (`check -v`: `✓ format: <n>`, `✓ lint: <n>`) of the release before the shared run.
