### Removed (2026-10-27 — #2374: the whole-byte[] ContentStore, StorageBackedPersistence and the legacy manifest readers)
- **Breaking, pre-GA, no users: the `byte[]` content store API is gone.** `ContentStore` (`put`/`get`/`exists`/`delete` by name on a whole `byte[]`) and its implementation `DefaultContentStore` are deleted; `ContentStoreV2` (streaming write, ranged read, ids, metadata, names) is the only content store, and the `ContentStoreFactory` / `@ContentStoreQualifier` resource now provisions it. Content stored through the old API is not read by the new one: object entries and name bindings are different blocks under different refs, and nothing migrates them.
- **Breaking: the `|`-prefixed trusted refs, the bare-name legacy refs and the pre-envelope text manifest (`AHSE-MANIFEST:` ...) are no longer read.** `ContentEnvelope.trustedRef`, kind `D` (direct content), `ContentManifest.fromLegacyBytes` and `MAGIC_HEADER` are removed. An upload is only ever chunk blocks, so no caller bytes are read as an envelope or a manifest. [verified: `ContentStoreManifestFramingTest`, `ContentStoreTrustedNamespaceRestoreTest`]
- **Breaking: `StorageBackedPersistence` (AHSE-backed Rabia snapshot persistence) is deleted.** Nothing wired it; consensus does not use snapshot persistence and nothing replaces it.
- The properties the old tests pinned are kept on `ContentStoreV2`: an overwrite or delete releases exactly the chunk credits it took (#981), a failed or aborted write gives back what it stored (#1437), deleting one of two objects sharing blocks leaves the other readable, no tier delete happens on delete, uploads that look like manifests read back verbatim (#2263, F7). [verified: `ContentStoreDeleteRefcountTest`, `ContentStoreReclamationTest`, `ContentStoreManifestFramingTest`, `ContentStoreTrustedNamespaceRestoreTest`]
