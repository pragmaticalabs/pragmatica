### Fixed (2026-11-03 — #2201: streams PR-2c, the ordered append section had no abort and the WAL accepted offset gaps)
- **A refusal inside a partition's ordered append section left the ring offset assigned while no WAL frame existed for it**, so replicas could pull an orphan and the next accepted frame landed past a hole (A-01).
- The section now admits an owner publish or batch through a guard evaluated under the ring's append lock before an offset exists: the owner-epoch fence, the provenance check against the log's cached last epoch, and the log's health [verified: aether/aether-stream/src/test/java/org/pragmatica/aether/stream/PartitionSectionTest.java, OwnerSectionFenceTest.java, OrderedSectionAbortTripwireTest.java `EpochRace`].
- A failed continuation (or a run that fails part-way) withdraws the offsets it took, so the next append takes the withdrawn offset; a withdrawal that itself fails halts the ring until the partition is re-materialized; the seqlock parity is restored on any exit [verified: aether/aether-stream/src/test/java/org/pragmatica/aether/stream/OrderedSectionRollbackTest.java, OrderedSectionAbortTripwireTest.java `RingContract`, `FailStoppedWal`].
- An ordered run that would evict its own members is refused `RUN_DOES_NOT_FIT` before any offset exists and the publisher falls back to single publishes; before, it was appended event by event and a part-way failure left part of it in the ring [verified: OrderedSectionRollbackTest.java `OversizeRun`, DefaultStreamPublisherBatchTest.java].
- A replica receive whose WAL write is refused now fails, so the ring withdraws the record and the sender's retry lands at the same offset [verified: OrderedSectionRollbackTest.java `ReplicaReceiveRollback`].
- The WAL validates offsets (I-04): `lastOffset + 1`, any offset on an empty log, or a forward jump across the partition's live sealed floor (installed where the manager opens the log); any other offset is refused with `OffsetRegression`, writes nothing and leaves the log writable [verified: integrations/storage/src/test/java/org/pragmatica/storage/AppendLogOrderRuleTest.java, aether/aether-stream/src/test/java/org/pragmatica/aether/stream/WalOrderRuleLivenessTest.java]. An in-section WAL refusal leaves the partition live after the rollback [verified: WalOrderRuleLivenessTest.java `refusedInSectionWalWrite_leavesThePartitionLive_afterTheRollback`].
- #1580 (an emptied partition reissuing offsets after a restart) is pinned: it was already fixed by #1278, which seeds the recovered ring at the sealed floor [verified: aether/aether-stream/src/test/java/org/pragmatica/aether/stream/EmptiedPartitionRestartTest.java].
