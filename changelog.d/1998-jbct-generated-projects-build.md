### Fixed (2026-10-07 — #1998: the projects `jbct add-*` generate did not build, and nothing built them)
- **`jbct add-persistence` and `jbct init --with-persistence` generated a project that did not compile.** The generated `SamplePersistence` imports `@Query` from `pg-codegen`, but the pom got `pg-codegen` only as an annotation-processor path: `PersistenceAdder` skipped the `provided` dependency whenever `resource-api` was in the pom, which a slice always has. It now adds the dependency unless a `pg-codegen` dependency is already there (the `<path>` and the `<dependency>` are checked separately).
- **The generated `SamplePersistence`, the `jbct add-event` annotations and the `jbct add-slice` slice failed the shipped `format-check`; the `add-slice` slice also failed `lint` (`JBCT-CAUSE-01/02`, a cause record with no components).** `SamplePersistence` keeps its examples in the doc comment (the formatter rewrites body line comments), `add-event` orders `java.*` imports first, and `add-slice` now uses the project initializer's own slice and test templates instead of a second copy that had drifted.
- **A gate builds every generated variant.** New module `generated-project-gate` runs the real `jbct init` (slice, `--no-slice`, `--with-persistence`) and `add-slice`, `add-event`, `add-persistence` (each alone, and all three together), then `mvn verify` on each generated project, which runs its own `format-check`, `lint`, annotation processing, tests and slice packaging. It is an integration test, so `mvn install` runs it (7 builds in parallel, about 45 s once the platform is installed) and `mvn test` does not. `GeneratedSliceComplianceTest` gains the fast in-process format and lint check of what the three adders write.
