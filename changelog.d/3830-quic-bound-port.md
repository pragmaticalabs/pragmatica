### Fixed (2026-11-27 — #3830: consensus QUIC tests picked a free UDP port, closed it, and handed it to the server)
- **`QuicLateDesignatedDialTest` failed intermittently with `Failed to bind QUIC server to port N: BindException`** because `freeUdpPort()` opened a socket on port 0, read the port and closed it before the server bound it; anything on the host could take the port in between (#1826 parts b and c). The five consensus classes that did this (`QuicLateDesignatedDialTest`, `QuicDialAttemptTest`, `QuicDialFailureMetricsTest`, `QuicClusterServerStopDuringBindTest`, `QuicClusterNetworkLifecycleTest`) now start the code under test on port 0 and read the port back from `boundPort()`, or hold it with `HeldPort` while the subject needs it. A peer that must be unreachable until it starts is reached through a held `UdpGate` that is pointed at the peer's reported port when it binds. [verified: 5 runs of the five classes on each of two hosts, 24 testcases per run, all green; consensus module suite 2218 testcases, 0 failures]
- The six `freeUdpPort` pick-then-close entries leave the port-bind gate's allow-list; the seven consensus entries that remain are ports that are the test subject or free-probes of a port the server bound itself. Re-adding a `freeUdpPort` pick-then-close to a consensus test fails the module's port-bind scan [verified: a mutant adding it to `QuicLateDesignatedDialTest` fails `port-bind-scan` on consensus with `QuicLateDesignatedDialTest:195 (freeUdpPort) calls java.net.DatagramSocket#<init>`].
- Test seam: `QuicClusterServerInstance.beforePublishForTest` now takes an `IntConsumer` that receives the port the channel bound, because `boundPort()` is empty in the bind-to-publish window the test exists to hold open. No production behaviour changes.
