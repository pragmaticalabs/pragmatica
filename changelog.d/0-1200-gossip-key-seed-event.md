### Fixed
- The seed nodes now report gossip they cannot decrypt for want of the key (#1200): the operator event `gossip-key-unknown-from-peer` (subject: the sender's address) when a peer's datagram arrives under a gossip key id they do not hold, and `gossip-key-peer-decrypted` when that sender's gossip next decrypts. Before, the only trace was one log WARN per datagram.
- Corrected the claim that a node booting after a gossip-key rotation is stranded in a deadlock (SECURITY.md, the failure almanac, and a comment in `AetherNode`). It seeds its SWIM protocol from its configured core peers, so it dials them, forms quorum and replays the rotation record. The limit that matters is stated instead: rotation protects only against a leaked gossip key, not a leaked `cluster_secret` (#2474).
