### Added (2026-11-14 — #2100: Postgres state-stored durable entity store, work package E-B)
- **New module `aether/resource/durable-entity-pg`**: `PgEntityStore` keeps one row per `(entity, key)` with version, state bytea and `updated_at`; `create`, `get`, `update`, `updateIfVersion` and `delete` run on `SqlConnector`. Timers are not in this module; `DeleteHook` is the seam for them.
- `update`: same-key updates are totally ordered and none is lost. `[verified: aether/resource/durable-entity-pg/src/test/java/org/pragmatica/aether/resource/entity/pg/PgEntityStoreTest.java]` (16 concurrent increments against PostgreSQL 16; removing `FOR UPDATE` turns it red). `[mechanism: SELECT ... FOR UPDATE row lock, then a version compare-and-set, in one transaction]`
- `create`: exactly one of N concurrent creates wins, the rest get `EntityAlreadyExists`. `delete` is idempotent (differs from the fenced-log `DurableEntity.delete`, which fails with `EntityNotFound`). Cluster-only `EntityError` members are never produced.
