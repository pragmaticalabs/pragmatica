### Fixed (2026-09-29 — #1139: pg-codegen generated repository methods Postgres rejects at their first call)
- **A `@Query` whose placeholders and method parameters disagree now fails the build.** It used to print a `PG-VALIDATE` WARNING and generate a method whose bind list and placeholder count differ, which Postgres rejects at the first execution: a declared parameter the SQL never names, or a `:name` placeholder with no parameter. Both are generation errors now. A query written with positional `$n` placeholders is no longer checked against named placeholders (it used to warn "not used" for every parameter); instead its highest `$n` must equal the parameter count, since `$n` binds the n-th declared parameter. A `$n` or `:name` inside a string literal, quoted identifier, dollar-quoted body or comment is neither counted nor rewritten, nor is the type name in a `x::text` cast, and a query mixing `:name` and `$n` placeholders fails the build, because the rewrite of `:name` to `$n` would bind it by an order neither check sees. Every `@Query` in this repository and in the ticketing demo (54 methods) passes.
