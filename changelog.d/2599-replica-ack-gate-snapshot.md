### Fixed (2026-11-06 — #2599: a publish to a fresh replica set was sometimes never acknowledged)
- **A fresh replica doubted the current owner's own first records.** Its ack gate fixes the copy's trust for an epoch at the first reading, from whether the head is still below the epoch's start, and the receive path read it only AFTER applying the batch. On an empty replica the owner's first batch had then reached the start, so the copy was marked unverified and the ack was left to a backfill; a live batch landing between that backfill's own ack and its verification had no ack at all, and the publisher's confirmation failed at its 5 s bound. The gate is now read on the head the batch found, before the apply, for a batch of the committed epoch [mechanism: a head below the epoch's start holds no record of an older lineage at or above it, and the apply stops at the first divergent record].
- **An ack the gate holds back is deferred, not dropped.** For a copy that is genuinely unverified, the held ack is kept per partition and sent once a compare verifies the copy (`StreamPartitionManager.onEpochVerified` → `ReplicationReceiveHandler.releaseDeferredAck`). The release reads the gate, goes through the durability barrier, and then, in the partition's section of the deferred-ack map, sends only the deferral it gated, after reading the gate again [mechanism: an identity check and a second gate read in the same `computeIfPresent`; a deferral that replaced it meanwhile (a batch of a newly committed epoch on a copy not verified for it) is kept for its own release]. It is dropped when its epoch is no longer the committed one, and it acks the head the verified copy held before the barrier, or the deferred offset if higher, capped at the head the copy holds at the send. Within one epoch it never lowers the owner's view: a live ack that covers it is sent in the same section and drops it, and the backfill's own ack, sent outside that section before the compare verifies, is not above the head the release acks [mechanism: the backfill acks a watermark it applied before verification; the release reads the head after it]. A repair that cuts the tail below that ack still lowers it, as a live ack after a divergence does. Of two deferrals of different epochs the newer epoch's is kept. A removed stream's deferrals are dropped (`StreamPartitionManager.onStreamRemoved` → `forgetDeferredAcks`).
- Residuals. (1) A compare whose response carries no records (an empty owner) never verifies the copy, so a deferred ack waits for a later carrying compare (pinned by `ReplicaAckGateTest.tripwire_R1_emptyCompare_leavesTheDeferralHeld`). Whether the next compare, driven by the gap repair or by the redrive every 5 s, releases it within the owner's 5 s await is [unverified]: by the code the bound is up to one redrive period plus one window fetch, which can exceed 5 s. (2) A deferral left when this node becomes the partition's owner is not cleared; it is bounded at one per partition and is sent only if a release runs while its epoch is still the committed one.
