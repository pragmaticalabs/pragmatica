### Fixed (2026-09-04 — #273: manual scheduled-task trigger could run concurrently with an in-flight execution)

- **`POST /api/v1/scheduled-tasks/trigger/...` invoked the task directly, bypassing the `inFlight` guard that already protected automatic fixed-rate/cron fires** — a manual trigger could run alongside an in-progress automatic (or another manual) execution of the same task, double-counting `totalExecutions`. The manual-trigger path now goes through the same `ScheduledTaskManager.tryClaim`/`release` guard, answering `409 Conflict` naming the task when a run is already in flight instead of executing concurrently
  [mechanism: `ScheduledTaskRoutes.invokeAndBuildResult` claims via `tryClaim` before invoking, releases on completion; pinned by `aether/node/src/test/java/org/pragmatica/aether/api/routes/ScheduledTaskRoutesTriggerTest.java#ConflictGuard` and `aether/aether-invoke/src/test/java/org/pragmatica/aether/invoke/ScheduledTaskManagerTest.java#TriggerGuard` — component-level against the real guard, not a live multi-node run].
- Docs updated: `aether/docs/reference/management-api.md` (`/trigger` 409 response) and `aether/docs/slice-developers/resource-reference.md` (Operational Controls, Manual trigger).
