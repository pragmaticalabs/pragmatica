### Fixed (2026-09-23 — #1481: the integration harness destroyed the evidence of a failed cloud run, and an aborted run reported success)
- **A failed cloud bootstrap deleted every VM before anyone could read why.** `run-tests.sh` called `aether cluster bootstrap` without `--keep-on-failure`, so on 2026-09-23 a formation that reached 4 of 5 cores was rolled back with its cloud-init and node logs. The new `--keep-on-failure` harness flag forwards to both bootstrap calls and, on any non-zero exit, skips teardown, prints the reaper commands (the kept VMs are billable), and still closes the PG firewall. A green run still tears down. [mechanism: the handler branches on the flag and the final status; observed on a failing run with the flag set — clusters preserved, reaper commands printed, firewall closed]
- **A run aborted by `set -u` exited 0.** The EXIT trap's own last command set the script's status, and macOS `/bin/bash` 3.2 enters an EXIT trap with `$?`=0 after an unbound-variable abort, so capturing `$?` could not catch it. Success is now proven only by reaching the final `exit`; a 0 without it becomes 1. [mechanism: three-arm run aborting at the same unbound expansion — the previous script exited 0, this one exits 1 with and without the flag]
- Limitation: on a full run cluster A is still reaped before cluster B's bring-up, so the flag cannot keep A after a failure in A's suites. [design intent — unverified]
