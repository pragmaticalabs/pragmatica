### Fixed (2026-09-14 — #882: a slice compiled before the #763 fix stayed silently PUBLIC when redeployed, and nothing could tell which)
- **The #763 fix is baked in at compile time.** `RouteConfigLoader.DEFAULT_SECURITY` yields `Unspecified` and codegen
  emits `.withSecurity(SecurityPolicy.unspecified())`, but that value is compiled into the slice JAR's `*Routes` class.
  A JAR generated by an older slice-processor carries `publicRoute()` for every route whose `routes.toml` had no
  `[security]` section, and the node reads the compiled value — it never re-parses `routes.toml` — so redeploying
  it onto an upgraded node left those routes open under an `API_KEY`/`JWT` global mode, with nothing recording it
  [mechanism: `HttpRoutePublisher.publishViaSliceRouterFactory` → `RouteMetadataExtractor.extract` reads
  `route.security()` off the compiled `Route`; a declared `public` and the old default are byte-identical there].
- **Generated factories now stamp the contract their GENERATOR implements.** `SliceRouterFactory.ROUTE_SECURITY_CONTRACT = 1`
  (the #763 contract) is what the node requires, with `default int routeSecurityContract() { return 0; }`;
  `RouteSourceGenerator` carries its own `ROUTE_SECURITY_CONTRACT = 1` and emits it as a **literal** (`return 1;`)
  into every `*Routes` class. The two are separate on purpose: `slice-processor` cannot see the adapter, and a
  symbolic `SliceRouterFactory.ROUTE_SECURITY_CONTRACT` in the emitted source would be resolved by javac against
  whatever adapter the SLICE compiles against — an old generator on a newer adapter would stamp a contract it does
  not implement, which is this defect's class recurring at the next bump. A JAR from before this change has no
  override and answers `0` — the stamp's absence is the evidence
  [verified: `jbct/slice-processor-tests/src/test/java/com/example/testslice/GeneratedRouteSecurityContractTest.java`
  — `RouteSourceGenerator.ROUTE_SECURITY_CONTRACT == SliceRouterFactory.ROUTE_SECURITY_CONTRACT` read as two
  independent constants (bumping either alone reddens it, and the regenerated class keeps the generator's number:
  adapter→2 leaves `iconst_1`); the generated source and compiled class return the generator's literal (emitting
  `return 0;` reddens); and the compiled `TestSliceRoutes.class` bytes contain no `ROUTE_SECURITY_CONTRACT`
  constant-pool name, with the method name as the positive control, so no `getstatic` reads the node's value at
  runtime (re-emitting the symbolic form reddens)]
  `[unverified: the adapter constant's own compile-time constancy is not pinned — nothing generated depends on it
  any more; a hand-written factory returning the symbol would read the node's value, and none exist]`.
- **Refusal, not a record.** At publish, a factory whose contract is below the current one AND that declares at
  least one PUBLIC route is refused with `SliceLoadingFailure.Fatal.RouteSecurityContractStale(artifact, contract,
  publicRoutes)` (logged at ERROR, naming the routes and the recompile); the failure propagates through the
  activation chain (`publishRoutesIfPresent` → `handleActivationFailure`) so the slice never reaches ACTIVE, and
  the cause is `Fatal`, so the leader records/rolls back rather than retrying (#922's shape avoided). Nothing is
  written to the route table for a refused slice, and the refusal is decided before the slice's router and
  observability cells are registered, so nothing is left for the activation-failure cleanup to race against. An
  old factory with no public route is not refused — every non-public policy was necessarily declared. A current
  factory's declared-public route publishes as before
  [verified: `aether/aether-invoke/src/test/java/org/pragmatica/aether/http/HttpRoutePublisherStaleContractTest.java`
  — `StaleRouteContractSliceRoutes` (no stamp, one public + one authenticated route, registered through
  `META-INF/services` like a real generated class) is refused: `Fatal`, message names the artifact and
  `GET /stale/items/` and not the authenticated route, zero consensus applies, zero cells registered (moving the
  refusal back below the registration reddens with 2 cells); `StaleNonPublicRouteContractSliceRoutes` (no stamp,
  two authenticated routes) publishes exactly its two `AUTHENTICATED` entries (dropping the "≥1 PUBLIC" guard
  reddens only this test); `CurrentRouteContractSliceRoutes` (stamped `return 1;` as the generator emits, public
  route) publishes exactly its one `PUBLIC` `/current/items/` entry — asserted on the published content because
  the test classpath's fallback `StubRouteHandlerFactory` also publishes one entry for the artifact, and it is
  `/stub/` (making the factory match never succeed reddens all three publish/refuse tests on content);
  `CURRENT_ROUTE_SECURITY_CONTRACT` in `slice-api` (which cannot see the adapter) is pinned equal to the factory
  constant. Red at the base (the stale factory published); reverting the publisher to the base reddens the
  refusal test and leaves the other three green].
- **Acceptance, restated for what this delivers.** "Which running slices were compiled before the fix?" — none:
  a stale build with a public route cannot become a running slice on a node carrying this change, and the
  deployment's FAILED/ROLLED_BACK record names it. The enumeration the ticket's direction (a) asked for is thus the
  set of refused deploys, visible where deployment outcomes already are. What is NOT provided: a listing of stale
  slices that were already ACTIVE before the node upgraded — they are refused on their next (re)deploy, not
  evicted `[design intent — unverified: no upgrade-in-place run; the pin is the publisher over a stub cluster]`.
- Scope: `SliceRouterFactory` (additive default), `SliceLoadingFailure` (new `Fatal` record + constant),
  `RouteSourceGenerator` (its own contract constant, six emitted lines), `HttpRoutePublisher` (the refusal, ahead
  of router/cell registration). Hand-written factories answer
  `0` and are refused only if they declare a PUBLIC route; none exist in this repository outside the two fixtures.
