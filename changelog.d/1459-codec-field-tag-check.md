### Fixed (2026-10-18 — #1459: generated record readers discarded the per-field type tags)
- **A generated record codec wrote a type tag before every primitive, string and codec-typed field, and the reader consumed it without looking.** A frame written with a different field layout (retyped, added, removed or reordered field, or a corrupt frame) therefore ran the wrong reader and decoded as garbage; for a codec-typed field the varint codec tag was read and the compile-time codec dispatched anyway.
- The reader now checks every one of those tags (`SliceCodec.expectTag` for the eight single-byte kinds, `SliceCodec.expectCompactTag` for codec-typed fields) and refuses a mismatch with the new `TagMismatchException`, which names the field (`Type.field`), the tag it expected and the tag it found. The wire format is unchanged: the tags were already written, so no frame changes and no regeneration is needed on the writing side. `BOOLEAN` (the tag is the value) and dispatched fields (checked by `lookupByTag`) already used theirs [verified: `CodecTagCheckTest`].
- This detects the mismatch; it does not make an incompatible layout decodable. #1450's shape rule is unchanged.
