### Added (2026-10-20 — jbct: every Promise on* callback is justified, checked after javac attribution)
- **New module `jbct-async-check`: `JBCT-ASYNC-01` (WARNING) reports a `Promise` `onSuccess`/`onFailure`/`onResult` callback, in every `*Run`/`*Async` form, whose effects are not justified.** These callbacks are events: each runs on its own virtual thread, concurrently with the promise's dependents (the awaiting caller, the next `map`/`flatMap`) and in no order relative to them, so anything a callback does can land after the code that follows the promise has already looked. `withSuccess`/`withFailure`/`withResult` and a plain chain step run in chain order, before any dependent sees the value; the message names that fix. A callback is accepted without comment when its effects are only logging (SLF4J, `System.Logger`, `java.util.logging`, `System.out/err`, `MDC`), scheduling (`schedule*`, executors) or resolving another promise (`succeed`/`fail`/`resolve`/`cancel`). Anything else is reported whether or not a write is visible: an assignment or `++` to a field or captured variable, a mutating verb on a shared receiver, a `void` call (or a call whose result is discarded) that is not one of those three, a callback that is neither a lambda nor a method reference. A call to a method of an enclosing class is followed three levels, so a delegate that only logs is clean; value-returning calls whose result is used, comparisons and the arguments of a logging call are reads. `Result.on*` runs inline and is never reported.
- **Exact receiver types.** The check is a javac annotation processor that installs a `TaskListener` running after attribution (the shape of the `@Json` local-type check), so `Promise` is identified by the resolved method symbol, across files and modules; the CST linter has no types and could prove a `Promise` receiver for only about half the sites. A module opts in with a `provided` dependency on `jbct-async-check`, as it does for `serialization-codec-processor`; nothing is opted in by this change. Options: `-Ajbct.async.severity=warning|error` (default `warning`).
- **Justification:** a comment `// detached: <why it may run late>` on the statement or directly above it (a reason is required, a bare `detached` does not count), or `@SuppressWarnings("JBCT-ASYNC-01")` on an enclosing declaration; `@Contract` does not suppress. Limits: a `void` method without source in the compilation (a jar, another module) is an effect by assumption; an effect hidden behind a value-returning call whose result is used is not seen.
