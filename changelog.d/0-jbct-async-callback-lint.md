### Added (2026-10-20 — jbct lint: Promise on* callbacks that write shared state)
- **`JBCT-ASYNC-01` (WARNING) flags a `Promise` `onSuccess`/`onFailure`/`onResult` callback, in every `*Run`/`*Async` form, whose lambda writes shared state.** These callbacks are events: each runs on its own virtual thread, concurrently with the promise's dependents (the awaiting caller, the next `map`/`flatMap`) and in no order relative to them, so a flag, map or counter written there can still be unwritten when the code that follows reads it. `withSuccess`/`withFailure`/`withResult` and a plain chain step run in chain order, before any dependent sees the value; the message names that fix. A write is an assignment to a field or captured variable (`done = true`, `this.last = v`, `total += n`, `failures++`), a mutating call on one (`put`, `add`, `remove`, `clear`, `set`, `incrementAndGet`, `compareAndSet`, ...) or a setter-named call, found in the lambda or in a method of the same file it calls or references (followed three calls deep; a callee parameter bound to shared state counts as shared). A callback that only logs, schedules, or resolves another promise is not reported, and `Result.on*`, which runs inline, is never reported.
- **Escape hatch:** an effect that is deliberately detached keeps `on*` and records why in a comment on the statement, `// detached: <reason>` (a reason is required, the bare word does not suppress); `@SuppressWarnings("JBCT-ASYNC-01")` works as for every rule but carries no reason. The rule ships as a WARNING while existing sites are converted and becomes an ERROR candidate afterwards (`[lint.rules] JBCT-ASYNC-01 = "error"`).
- **Limits, from a linter that sees one file's syntax and no types:** the rule reports a site only when it can prove the receiver is a `Promise` (a `Promise.`/`.async()`/`.timeout()`/`.with*()` chain, a name declared `Promise<...>` or `var`-inferred from one in the same file, a call to a method of the file declared to return `Promise<...>`, or a `return` of the chain from a method declared to return `Promise<...>`) and can see the write; a receiver typed in another file and a write made by a method in another file are missed. It does not report `Result`: the carrier is unknown unless proven. Catalog verbs are matched by name, so a non-mutating method that shares one is a false positive.
