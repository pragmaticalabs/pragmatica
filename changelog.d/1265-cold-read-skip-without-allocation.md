### Performance (2026-09-19 — #1265: cold stream reads allocated and copied every payload before skipping records below fromOffset)
- **`SegmentReader.deserializeAndFilter` allocated and copied each record's payload before checking its offset**, so every record below `fromOffset` cost a payload allocation that was then discarded. A consumer reading a segment of S events m at a time decoded that segment about S/(2m) times over.
- The record header is now parsed first, and a record below `fromOffset` is skipped by advancing the buffer position, with no allocation. Measured by the thread allocated-bytes counter for `deserializeAndFilter(bytes, 999, 1)` over 1,000 records of 1 KiB: 2,112,976 bytes before, under the 16 KiB budget after. [mechanism: `SegmentReaderTest.AllocationAndAccumulation.deserializeAndFilter_allocatesUnderBudget_whenSkippingRecordsBelowFromOffset`, which goes RED when the skip is reverted to allocate-then-discard]
- **A record whose declared length is negative or exceeds the remaining bytes now fails the read with `SegmentError.CorruptRecord`**, which carries the segment, the record's byte position and the declared length. It fails before any allocation and logs an ERROR naming the segment and position. Before, it threw `NegativeArraySizeException` or `BufferUnderflowException` out of the read. The read never returns the records decoded before the corrupt one: stopping there would let the read continue into the next segment and silently drop the offsets in between. [mechanism: `SegmentReaderTest.CorruptRecordLength.readEvents_failsWithCorruptRecord_whenALengthMidSegmentIsCorruptAndAHealthySegmentFollows`, which returned `[0, 3, 4]` when the decode stopped instead of failing, and `deserializeAndFilter_failsWithoutAllocating_whenLengthExceedsRemainingBytes` / `..._whenLengthIsNegative`]
- Multi-segment reads accumulate into one list and copy it once at the end, instead of an immutable concatenation per segment. [mechanism: `readEvents_returnsAllEventsInOrder_acrossFiftyOneEventSegments` pins order and count across 50 segments. It is a correctness guard only. No test measures the reference copies this removes] [unverified: the reference-copy saving is not measured]
- Not changed, and still the larger cost: every cold read fetches the whole segment from storage, and decryption makes another full copy of the ciphertext. A per-segment decoded cache or an offset index is the follow-up.
