### Fixed (2026-09-24 — #1475: a replacement core node spent 5 minutes in provider discovery it did not need, and below a quorum exited instead of joining)
- **A node started with an explicit peer list still ran cloud provider discovery.** Peer resolution tries `--peers=`, then `CLUSTER_PEERS`, then provider discovery, then config. The later sources were evaluated eagerly (`Option.orElse(Option)`), so discovery ran even when `--peers=` had already won. Every CTM replacement carries `--peers=`, so each one blocked for up to 300s polling for a full core set it could not find while drained or killed nodes were down. If it found a quorum it joined about 5 minutes late. If it did not, it exited with "Peer discovery found only N of M expected core peers" despite holding a valid peer list, and the leader kept counting it as in flight and never provisioned another. After a drain the cluster could therefore stay one core short indefinitely. Each source is now consulted only when every earlier one is empty.
