### Fixed (2026-11-20 — #3303: an entity checkpoint block that a committed pointer names could read as "no checkpoint")
- **Entity checkpoint loads name a lost block instead of reporting none** (#3303, A0b). When a committed pointer named a checkpoint block, and that block was lost, failed to read or did not decode, the load used to collapse to "no checkpoint". The entity then re-folded from an older point without saying why. `loadCheckpointOutcome` now answers `Loaded`, `Absent` or `Unreadable(cause)`, and the fold WARNs with the cause. The root decision is unchanged. [verified: `StreamEntityLogSubstrateCheckpointOutcomeTest`, `SealedHistoryRecoveryTest`]
