### Added (2026-11-13 — #2981 step 3a: move fence data layer)
- **An epoch start now names the node whose lineage write recorded it** (`EpochStart.owner`, `Option<NodeId>`; empty = recorded before the field existed). `withEpochStart` and `restarted` record the record's own owner, and the bounded-history fold keeps the oldest kept entry's owner. The two-argument `EpochStart` constructor is gone; `EpochStart.epochStart(epoch, offset, owner)` is the only unfolded constructor. The owner joins record equality, which the exact-record lineage guard compares. [verified: `EpochStartOwnerTest`, `EpochStartCodecTest`]
- **`FenceTarget`**: the node a new owner's move fence must reach is the owner of the newest STARTED epoch older than the record's own, read from the record alone (never the live placement). `NoFence` (no older start, or it is this node), `Probe(owner)`, `Unknown` (older start with no owner: wait the full deadline). [verified: `FenceTargetTest`]
- **`FenceDeadlines`**: the deadline base is captured once per `(partition, ownershipTerm)` at the first delivery naming this node owner (`renewalApplied[L]` if present, else the delivery time), never moved by a later record of the term; deadline = base + `ownerLeaseWait`. [verified: `FenceDeadlinesTest`]
- **Nothing consumes `FenceTarget` or `FenceDeadlines` yet**: the activation gate (3b) and the probe protocol and wiring (3c) are later steps, so this change alters no runtime behaviour except that new epoch starts carry the owner.
- **Upgrade hazard (pre-GA):** the `EpochStart` wire encoding gains the owner field. A record written before it fails LOUDLY on decode (it never reads as an ownerless start); a mixed-version cluster is unsupported, as for the other #2981 wire changes. [verified: `EpochStartCodecTest`]
