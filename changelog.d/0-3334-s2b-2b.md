### Changed (2026-11-18 — #3334: entity logs created by this build refuse records above 1 MiB)
- **The entity-log `max_event_size` is 1 MiB for entity logs created by this build, down from 4 MiB** (#3334). The bound is on the stored record: the serialized entity record with its envelope (6-byte header, key bytes, encoded state), not the user payload. A `DurableEntity` update whose stored record is larger than 1 048 576 bytes is refused before anything is stored, and the caller sees `EntityError.StorageFailed` wrapping `EventTooLarge(size, 1048576)`; a record of exactly 1 MiB is acked. Updates of 1 to 4 MiB that worked before now fail on a new entity log.
- **An entity log created by an earlier build keeps its committed 4 MiB limit**: its committed config is adopted, never re-proposed, when the log is ensured again (`StreamPartitionManager#createAbsentStream` / `adoptCommittedLife`). Replay and fold never check record size, so nothing already written becomes unreadable. This change adds no way to bring an existing entity log to 1 MiB, so entity logs with different limits can coexist until such a way exists. The entity ring window (10 000 entries, 64 MiB, finite max age) now lives in `aether-stream` as `EntityRingWindow`.
