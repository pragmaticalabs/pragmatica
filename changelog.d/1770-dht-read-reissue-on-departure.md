### Fixed (2026-09-30 — an in-flight DHT read no longer waits out its timeout when a target leaves the ring)
- **A DHT `get` whose R-set target departed the ring mid-read (killed, not yet removed from membership when the request was sent) never received that reply and hung until the operation timeout; the artifact resolve failed at its 15 s bound and the slice load surfaced "Artifact not found".** `DistributedDHTClient.get` now watches the ring for the life of the read (`ConsistentHashRing.onNodeRemoved`) and, when a target that still owes a reply leaves, re-issues to the first current-ring replica not yet addressed. Quorum is unchanged (same R, same slot count; a departure is never an empty answer). At most 3 re-issues per read and none past the read's original deadline; when no replacement is allowed the slot fails through the existing `QuorumCollector.onFailure` accrual, so a second lost slot fast-fails with `QuorumNotReached`. A replacement replica holds no copy yet (it is asked before the survivor rebalance starts), so its empty answer is a failed slot, never a quorum vote; only a present answer counts. Only `get` is covered; `put`/`remove`/`exists` are unchanged. `[verified: DistributedDHTClientTest$DepartureReissue, InFlightReadTest, ConsistentHashRingRemovalListenerTest — each pin reddens under its named mutation]` `[unverified: not run on a real cluster; the S' cloud failure was not reproduced]`
- **A DHT `get` answered "absent" as soon as two of three R-set replicas answered empty and discarded a later reply that carried the value, so live artifact metadata read as missing (#1775).** `DHTClient.get(key, ReadOptions)` adds an opt-in `absentGrace`: after R empty answers from original R-set replicas, the read waits up to the grace (capped by the read's own deadline) for the remaining replica; a present value in that window wins, and all replicas answering empty ends the read at once. The default is zero grace, exactly the previous rule, so every existing caller (cache, idempotency, storage tiers, boot marker) is unchanged. Only `ArtifactStore`'s artifact-metadata resolve opts in (1 s, inside its 15 s resolve bound). The DHT keeps no tombstones, so a grace window can resurrect a value removed at W quorum from the replica that missed the remove; that is why it is opt-in, and artifacts are write-once. The one exposure is artifact deletion followed by a re-resolve inside the window. `[verified: DistributedDHTClientTest$AbsentGraceWindow, QuorumCollectorTest$GraceMode, ArtifactStoreTest$MetadataAbsentGraceTests — each reddens under its named mutation]`
