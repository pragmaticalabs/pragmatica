### Fixed (2026-09-30 — an in-flight DHT read no longer waits out its timeout when a target leaves the ring)
- **A DHT `get` whose R-set target departed the ring mid-read (killed, not yet removed from membership when the request was sent) never received that reply and hung until the operation timeout; the artifact resolve failed at its 15 s bound and the slice load surfaced "Artifact not found".** `DistributedDHTClient.get` now watches the ring for the life of the read (`ConsistentHashRing.onNodeRemoved`) and, when a target that still owes a reply leaves, re-issues to the first current-ring replica not yet addressed. Quorum is unchanged (same R, same slot count; a departure is never an empty answer). At most 3 re-issues per read and none past the read's original deadline; when no replacement is allowed the slot fails through the existing `QuorumCollector.onFailure` accrual, so a second lost slot fast-fails with `QuorumNotReached`. Only `get` is covered; `put`/`remove`/`exists` are unchanged. `[verified: DistributedDHTClientTest$DepartureReissue, InFlightReadTest, ConsistentHashRingRemovalListenerTest — each pin reddens under its named mutation]` `[unverified: not run on a real cluster; the S' cloud failure was not reproduced]`
