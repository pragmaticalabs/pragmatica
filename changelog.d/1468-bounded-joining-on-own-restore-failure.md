### Changed (2026-10-18 — #1468: a failed consensus own-restore wedged the node in JOINING forever)
- **The fail-closed stop is now bounded and ends in a distinct exit code.** A node whose own persisted consensus history cannot be restored never activates (unchanged); it used to sit in `JOINING` with `start()` unresolved indefinitely. `Main` now arms `OwnRestoreWatchdog` before awaiting `start()`: once `RabiaEngine.ownRestoreFailure()` has been continuously present for 120 s the process logs a FATAL naming the cause and halts with exit code `74` (`EX_IOERR`). 120 s is a chosen bound, not a recovery window, because the engine's fence is permanent within the process. The save-failure arm (re-persist after a restore) and responder-snapshot failures are not covered, and both are pinned as not setting the failure. The failure is never cleared in-process: the own-restore arm runs only after a genesis has resolved, and none installs afterwards. The wiring is pinned too: the arming call in `Main`, both accessor hops, the bound, exit code 74 through an injected halt, and the log flush before the halt.
