### Fixed (2026-11-14 — #3263: stream publisher and access routed by the declared partition count)
- **A stream publisher routed keys by the partition count its slice declared, not the count the existing stream enforces** (#3263). Declared higher than enforced, appends to partitions at or above the enforced count failed `PartitionOutOfRange`; declared lower, keys mapped to different partitions than every producer using the enforced count, breaking per-key order with no error. The publisher and the consumer access now take ONE count from the stream's COMMITTED config (the one `STREAM_CONFIG_CHANGE_NOT_APPLIED` says keeps being enforced) and log a warning that the declared count was not applied. The count is captured when the binding is provisioned; only destroy + recreate changes it. A non-system stream with no committed config on this node is refused retriably (`StreamConfigNotYetVisible`) instead of routing by the declared count; a `system:` stream routes by the count this node enforces for it (the runtime-owned config `createStream` used), never by a slice's declaration, and is refused the same way when this node holds no entry. A slice declaring a different count over an uncommitted local stream no longer republishes that count: the life keeps its own, so the committed count always equals the rings' count. [verified: `StreamPublisherEnforcedPartitionsTest`]
