### Fixed (2026-09-24 — #1482: cloud integration runs kept no evidence of their failures, and the restore gate accepted a 4-member cluster as whole)
- **Failed cloud suites captured no node logs.** `capture_node_logs` had no `cloud` branch: it wrote a "captured" manifest and returned, so all 8 failed suites of the 2026-09-23 rc4 run had a manifest and nothing else, and the VMs that ran them were reaped by mid-run recovery before the run ended. The cloud branch now ssh's to every VM of the cluster at the moment of failure (seeds by IP, CTM replacements by node-id name) and saves each node's last 5000 log lines plus the leader's provisioning snapshot; zero VMs or a missing `AETHER_SSH_KEY` is stated in the manifest and as a WARN. [mechanism: stubbed enumeration and ssh under `set -euo pipefail` — 2 VMs give 2 logs and a manifest with line counts, 0 VMs give the explicit "nothing captured" line] [design intent — unverified: not yet exercised on a live cloud run]
- **The restore gate passed a cluster with a core missing.** Its "whole" test was `deficit == 0 && reachedFullMembership`, but the product's `deficit` subtracts an `effective` count that includes a dispatched-but-not-joined replacement, and `reachedFullMembership` is a latch. Four members plus one in-flight replacement therefore passed and logged "5 cores present", while the following suites measured 4. The gate now also requires the leader's `countedCoreMembers` to reach the target. A cluster stuck below target now fails restore with the provisioning snapshot in the message, so later destructive suites may be quarantined where they used to run degraded. [mechanism: old vs new gate on stubbed snapshots — the in-flight 4-of-5 snapshot passes the old gate and fails the new one; a whole cluster passes both]
- **Partition firewalls leaked where no reaper could see them.** They were created without labels, and `cloud-reaper.sh` selects on `aether-cluster`; two were left behind on 2026-09-23. They now carry `aether-cluster=<cluster>` and `aether-role=partition`. [verified: real Hetzner API — a firewall created with these labels is listed by `cloud-reaper.sh --cluster <name>`]
