### Fixed (2026-11-15 — #2402: async Postgres statement cache keyed by SQL text only)
- **A cached prepared statement is now reused only when the parameter types match.** `PgConnection.prepareStatement` returned the cached statement on an SQL-text hit and ignored the requested types, so whether a bind was accepted depended on which earlier call had prepared that SQL. On a type mismatch the cached statement is evicted, closed on the server and the SQL is parsed again with the requested types; a match still reuses the cache. The cost of the extra `Parse` on alternating types is unmeasured [unverified]. [verified: `StatementCacheParameterTypesTest`, red on the SQL-only key]
