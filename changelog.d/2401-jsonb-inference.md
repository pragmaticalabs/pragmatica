### Changed (2026-10-23 — #2401: infer the json/jsonb document mapping from the schema; refuse String binds to json/jsonb)
- **No `@Jsonb` where the schema knows the column.** A record, or `Option` of one, without a `ValueMapping` is read and written as a JSON document when the schema knows its column is `json`/`jsonb`. That covers CRUD row-record components and condition parameters, `@Query` `column <op> :param` pairs, and components of a record expanded into `VALUES (:record)` / `SET :record`, and the values of a plain explicit-column `INSERT INTO t (c1, .., cn) VALUES (:p1, .., :pn)` (one row, every value a bare `:param`, equal counts), paired with their columns by position. Any other insert shape (an expression or cast among the values, several rows, `INSERT .. SELECT`, `ON CONFLICT`, `RETURNING`) is unchanged. `@Jsonb` stays required where the schema cannot tell: `@Query` results, a record parameter bound whole, `@>` and other expression operands, and enums. `[verified: aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/JsonbMappingTest.java, aether/pg-tools/pg-codegen/src/test/java/org/pragmatica/aether/pg/codegen/processor/JsonbPostgresRoundTripTest.java]`
- **A `String` bound to a known json/jsonb column is a compile error.** A `String` is sent as `varchar`, which `json`/`jsonb` refuse, unless the driver happens to reuse a statement prepared for the same SQL with an untyped parameter. That cache behaviour is fixed separately in #2402. Bind a record, `JsonText`, or cast in SQL (`:doc::jsonb`, `CAST(:doc AS jsonb)`). `String` reads stay allowed. **Breaking:** an interface that binds a `String` into such a column no longer compiles. The `comprehensive-persistence` and `pg-showcase` examples did, and now map their jsonb columns to records. `[verified: JsonbMappingTest.java]`
