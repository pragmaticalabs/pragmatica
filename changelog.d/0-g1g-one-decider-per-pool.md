### Changed
- **`aether cluster apply --resume` no longer creates nodes beside the leader's auto-heal** (G1-g, owner ruling: one decider per pool). Before a scale-up or add-role action creates nodes in a cloud or Docker source it asks the cluster who fills the `(source, role)` pool. A core pool with auto-heal enabled, and every worker or spot pool, is the leader's: apply creates nothing, reports `waiting for the leader to provision <role>: N live of M`, and continues when the cluster reports M live. A core pool with auto-heal disabled is apply's, as before. A pool the leader was not given at the needed count, or a cluster that cannot be read, is refused with a named cause and nothing is created. Apply and auto-heal mint different node ids, so neither the KV reservation nor the provider's name uniqueness refused their double-fill. `[verified: aether/cli/src/test/java/org/pragmatica/aether/cli/cluster/PoolGateTest.java, ClusterPoolAuthorityTest.java]`
- Plain `apply` is unchanged: it already commits the scale and leaves the creating to the leader (#686).
