### Fixed (2026-10-18 — #2242: AWS DescribeInstances read only the first page)
- **Past one page the client saw a silent prefix of the fleet.** `AwsClient.describeInstances()` and `describeInstances(tagKey, tagValue)` issued one call and dropped `nextToken`; the list feeds the capacity ledger and the core-replay set. Both now follow `nextToken` to the end (tag filter kept on every page) and return one response with every page's reservations in order; a failing later page fails the call, and so does a token that repeats any token already sent (a cycle of any length) or a listing past the 100-page cap (`AwsError.PaginationFailed`, naming the action and the pages read); a truncated fleet is never returned as success. A blank token ends the walk. `[verified: integrations/cloud/aws/src/test/java/org/pragmatica/cloud/aws/AwsClientTest.java DescribeInstancesPagination]`
- `describeSecurityGroups` (used before `deleteWhenEmptied`, and by the tag-filtered ingress lookups) follows `nextToken` the same way; a group on a later page no longer reads as absent.
