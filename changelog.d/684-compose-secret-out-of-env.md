### Security (2026-09-04 — #684: generated docker-compose wrote the cluster secret in plaintext)
- **The `aether cluster scaffold` compose template baked `AETHER_CLUSTER_SECRET` into the generated file as a literal value**, readable by anyone who could read the file. It now emits `AETHER_CLUSTER_SECRET: "${AETHER_CLUSTER_SECRET:?export AETHER_CLUSTER_SECRET before docker-compose up}"` instead — the same shell-substitution reference the hand-written `aether/docker/docker-compose.yml` already used — so the generated file itself carries no secret value [verified: aether/cli/src/test/java/org/pragmatica/aether/cli/cluster/ClusterScaffoldCommandTest.java].
- **This does not close the running-container exposure.** Once `docker compose up` resolves the reference, the container's environment carries the actual value and remains visible via `docker inspect`, exactly as for any env-var-delivered secret [mechanism: shell substitution resolves before container start; the resolved env var is still process-visible after it].
- **Operators with a compose file generated before this fix** must migrate: export the real secret, regenerate or hand-edit the file to the `${...}` reference form, and never commit the exported value. See `SECURITY.md`'s `cluster_secret` hygiene section for the full steps.
