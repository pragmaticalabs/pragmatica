### Fixed (2026-11-13 — #3065: jbct-lint ARCH-04 and TOT-02 false positives)
- **JBCT-ARCH-04 no longer reads the doc block after an import as part of it.** The import node carries the following `///` block; comments inside the import are stripped and the imported package is then cut at the declaration's first `;` (a `;` inside a comment no longer hides the import), so a doc mentioning `usecase` no longer reports a slice root such as `org.pragmatica.lang.Option;<newline>/// ...`, and a real cross-slice import followed by a doc block reports its clean package.
- **JBCT-TOT-02 no longer flags a method reference whose target guards `getFirst` / `getLast`.** A `getFirst` / `getLast` on a plain identifier receiver that is reached only on the non-empty side of an earlier `<receiver>.isEmpty()` or `<receiver>.size() <cmp>` check in the same body is not partial; the exemption is polarity-checked and applies only on the non-empty side, anything the text analysis cannot decide keeps firing (compound or negated-compound conditions, a guard that is the operand of a comparison or of arithmetic, a receiver reassigned or mutated after the guard, an early exit crossing an old-style `case` label, guard and accessor in separate call arguments), and any other partial operation in the body (`throw`, `orElseThrow`, indexed `get`) still flags. The lambda rule TOT-01 is unchanged. The per-module warning pins for both rules in `jbct-core`, `jbct-lint` and `jbct-parser` are removed.
