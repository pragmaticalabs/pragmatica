### Fixed (2026-11-13 — #3065: jbct-lint ARCH-04 and TOT-02 false positives)
- **JBCT-ARCH-04 no longer reads the doc block after an import as part of it.** The import node carries the following `///` block; the imported package is now cut at the declaration's first `;`, so a doc mentioning `usecase` no longer reports a slice root such as `org.pragmatica.lang.Option;<newline>/// ...`, and a real cross-slice import followed by a doc block reports its clean package.
- **JBCT-TOT-02 no longer flags a method reference whose target guards `getFirst` / `getLast`.** A `getFirst` / `getLast` on a plain identifier receiver that an earlier `<receiver>.isEmpty()` or `<receiver>.size() <cmp>` in the same body guards is not partial; guard polarity is not checked, and any other partial operation in the body (`throw`, `orElseThrow`, indexed `get`) still flags. The lambda rule TOT-01 is unchanged. The per-module warning pins for both rules in `jbct-core`, `jbct-lint` and `jbct-parser` are removed.
