### Added (2026-11-13 — #3157: embedded TLA+ models with an on-demand model-check job)
- **Protocol models now live next to the code they describe**: SharedPools (#2978) and the owner catch-up stalled warning (#2967) are TLA+ specs in doc comments, extracted and checked by `tools/tla/` against an expected verdict per config (`tools/tla/models.tsv`). Results are bounds over the stated constants, not proofs.
- Known-bad configs must fail in every run, and only by violating the property the row names (`models.tsv` `property` column); a TLC error reads `ERROR`, never `fail`. An expected failure cites an open issue (#3155, #3156) and flips to `pass` when it is fixed. `tools/tla/runselftest.sh` checks that logic on a fixture with wrong expectations and runs before the model rows.
- `run.sh sim`: every config as written under TLC random simulation with a time budget per config; prints wall time, trace count and mean trace length per row. Sampling, not a proof.
- `SharedPools` gains a test-only trace hook; with no sink installed each region runs its body and nothing else. `SharedPoolsTraceTest` is opt-in (`-Dtla.traces=<dir>`): it records the closeAll/acquire race and asserts the traces are non-empty; with `-Dtla.spec=<extracted spec dir>` it also runs `tools/tla/trace.py` and fails when a trace is REJECTED (an empty trace, an event the spec cannot take, or a run that ends with a close the spec still owes). It is not run by the default test suite or the workflow.
- `.github/workflows/tla-models.yml` runs on `workflow_dispatch` only; it is not a required check.
- Trace validation found a model/code gap and the model was fixed: `closeAll`'s lock-free key walk cannot see a key whose insert is still inside the admission `compute` (the node is linked only after the mapping function returns), while the model's `CA_Check` saw it at once. `CA_Check` now reads `Visible(k)`; the 2000-round trace run is accepted (9 distinct traces, 0 rejected). Refs #3161 #3166.
