### Fixed (2026-10-18 — #1966: cluster apply: profile-content change = empty plan; runtime-ref change = 501)
- **Editing a runtime profile's contents produced an empty plan, and switching a role's runtime answered a bare 501.** `ClusterBootstrapConfigDiff` never compared the `[runtime.<name>]` profiles both configs declare, so a change to `type`, `image`, `jvm_args` or `jar_url` was "nothing to apply"; a role's `runtime =` change was classified as the generic unsupported action (501, "escalate rather than retry"). The diff now emits `DiffAction.RuntimeProfileChange` naming the changed keys, and the applier refuses both cases with a typed 409 that names the supported path (`ClusterConfigError.RuntimeProfileChangeViaApply`, `ClusterConfigError.RuntimeChangeViaApply`), mirroring `VersionChangeViaApply`. The CLI wave executor refuses the profile change by name instead of logging it. Applying the edit is not implemented: replacements are provisioned from the committed config, which apply does not rewrite for profile content. `[verified: aether/aether-config/src/test/java/org/pragmatica/aether/config/cluster/ClusterBootstrapConfigDiffTest.java RuntimeProfileContent, aether/aether-deployment/src/test/java/org/pragmatica/aether/deployment/cluster/ClusterConfigApplierTest.java UnsupportedActions]`
