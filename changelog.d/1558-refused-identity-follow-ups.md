### Fixed (2026-09-27 — #1558: #1545 follow-ups — refused-identity exit code, retired-peer eviction)
- **A refused identity exits with its own code, 78 (`EX_CONFIG`)**, distinct from a completed drain's exit code 2, so orchestration and the CTM can tell "refused — replace with a fresh NodeId" from "drained" by exit status alone. [verified: aether/ember/src/test/java/org/pragmatica/aether/ember/EmberSameIdentityRelaunchTest.java] (in-JVM; the harness records the exit code the node would exit with)
- **A NodeId retired by a boot-token conflict is dropped from the survivors' connected peers at once** (permanent departure), instead of lingering until the liveness TTL. [mechanism: the transport's retirement listener on the shared boot-token registry calls `departurePermanent`]
- `connectPeer` and the missing-peer reconciler's refusal to dial a retired NodeId are now pinned by tests; `EmberSameIdentityRelaunchTest` scans ports 23000–23300, below the Linux ephemeral range, and is registered in `TEST_PORT_ALLOCATION.md`. `TEST_PORT_ALLOCATION.md` now also registers five forge-tests classes that bound 22000–23702 without a row, and states that the table is not exhaustive.
- **`node-operations.md` documents exit code 78**, the refused-identity exit. A supervisor must not restart under the same NodeId on 78, and should exclude it from restart-on-failure policies. The guidance for code 2 now also says to bring capacity back under a fresh NodeId.
