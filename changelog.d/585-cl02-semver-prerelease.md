### Fixed (2026-09-04 — #585: CL-02 rejected valid semver pre-release versions, including the project's own current version string)
- **`[cluster] version` at bootstrap VALIDATE required a bare `MAJOR.MINOR.PATCH` triplet**, rejecting semver 2.0.0 pre-release and build-metadata suffixes — an operator pasting the real Aether version (`1.0.0-rc3`, `1.0.0-rc4`) into a bootstrap config got refused with `CL-02: ... must be valid semver X.Y.Z`. `ClusterBootstrapConfigValidator` now accepts the full semver 2.0.0 grammar (`-pre-release` and `+build` metadata), while still rejecting what semver rejects: leading zeros in numeric identifiers, empty identifiers, and characters outside `[0-9A-Za-z-]` [verified: aether/aether-config/src/test/java/org/pragmatica/aether/config/cluster/ClusterBootstrapConfigValidatorTest.java — `validate_semverPreReleaseVersion_succeeds`, `validate_semverPreReleaseWithBuildMetadata_succeeds`, `validate_semverDottedPreReleaseIdentifiers_succeeds`, `validate_semverTrailingDashNoIdentifier_returnsError`, `validate_semverLeadingZeroInPreReleaseNumericIdentifier_returnsError`, `validate_semverInvalidCharacterInPreRelease_returnsError`].
- `aether/docs/specs/cluster-bootstrap-spec.md`'s `[cluster]` field table and CL-02 row described a bare `X.Y.Z` grammar (the doc's own §14 references section already cited semver 2.0.0 as the intended source of truth) — both now state the accepted grammar plainly.
- Out of scope, unaffected: `aether cluster upgrade --version` keeps its own separate bare-`X.Y.Z` restriction (a distinct command targeting published release tags, not bootstrap config) and `NodeUserDataRenderer`'s jar-tag derivation, which already handled non-plain-semver versions gracefully via a `-candidate` tag fallback.
