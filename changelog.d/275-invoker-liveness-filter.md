### Fixed (2026-09-14 — #275: slice-to-slice routing had no liveness filter, so a call to a dead node hung for the invoker timeout)
- **Slice-to-slice endpoint selection never consulted membership.** `SliceInvokerImpl` picked from `EndpointRegistry`, a projection of committed `NodeArtifactKey` rows that outlive a dead node until the cluster deployment manager's removal cleanup lands, so a new invocation was round-robined (or affinity-pinned, or failed over) onto a node membership already knew was gone and waited out the 20s `DEFAULT_TIMEOUT_MS`. The HTTP forward path had `AccessibilityFilter` (`MembershipFsm.reachableMembers`: every member not co-confirmed DEAD) since the H7 fix; the facade path had nothing. [mechanism: `SliceInvokerImpl.selectEndpoint` / `selectEndpointWithAffinity` / `selectEndpointWithFailover` at `2005ea7d2` read the registry only; `handleNodeDeparture` retries only in-flight invocations, after `NodeRemoved`]
- `SliceInvoker.setAccessibilityFilter(AccessibilityFilter)` (default no-op on the interface, overridden by the production invoker) is wired in `AetherNode` to the same filter the forwarder uses. Every selection path now skips a registered endpoint whose node the filter rejects: plain selection becomes the excluding round-robin (the precedent the failover arm already set — once anything is excluded, the weighted-routing pick is bypassed), an affinity target that is inaccessible yields to that filtered selection, and failover excludes inaccessible nodes together with the ones that already failed. Computed per call from the registry's current rows, so a node's return is seen on the next call. [verified: `SliceInvokerLivenessFilterTest` — four cases (request/response, fire-and-forget, affinity, failover) red without the filtering logic, green with it; removing only the affinity filter reddens exactly the affinity case, removing only the failover exclusion reddens exactly the failover case]
- Bound, stated: the filter cannot beat detection latency. A silently dead node is still selectable until SWIM co-confirms it DEAD, exactly as on the HTTP forward path; what closes is the window between DEAD and the KV row cleanup, and the affinity/failover arms that previously ignored liveness altogether. `[unverified: end-to-end on a multi-node kill — pinned at the invoker's transport boundary only]`
- Not changed (findings 2 and 3 of #275, both API/wire design): remote failures still collapse to `RemoteInvocationError(String)` — a typed cause across `InvokeResponse` is a wire-format change; timeout/retry are still not caller-configurable on `SliceInvokerFacade` — a public API change. Both left for a ruling. `[design intent — unverified]`
