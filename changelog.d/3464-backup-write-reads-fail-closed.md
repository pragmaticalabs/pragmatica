### Fixed (2026-11-21 — #3464: the backup write path takes an unreadable git for an absent branch or file, and can drop queued commits)
- **A backup flush over a git that cannot be read commits and pushes nothing, and retries**: the local branch, the declaration and document at the local and fetched heads, the remote-head ancestry check and the head a rejected push was refused against go through the three-valued git reads. A failed command, timeout or lost output fails the flush with a typed reason; it no longer reads as "no branch", "no declaration" or "not contained" (which reset the local branch and dropped queued commits). [verified: aether/node/src/test/java/org/pragmatica/aether/node/backup/KvBackupServiceTest]
- **A brand-new remote keeps its "no remote head" identity for a rejected push** (a marked guess: an absent tracking ref is the definite "no such branch yet"; any other read failure fails the flush). The superseded two-valued reads in `GitBackupRepository` are removed.
