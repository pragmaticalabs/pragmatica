### Fixed (2026-09-19 — #1308: a node whose SWIM listener failed to start kept running and announced its join)
- **A node whose SWIM UDP port could not be bound booted anyway, with no failure detection.** `AetherNode.startSwim` discarded the result of `CoreSwimHealthDetector.start` and ran the join announcement unconditionally. A failed bind (e.g. `BindException: Address already in use`) left the detector `Stopped`, while the node kept running as a cluster member with no SWIM listener, reported only by one ERROR line from the detector. `[mechanism: start()'s Promise was never read; the announce trigger ran after the call regardless]`
- `startSwim` now acts on the start result. On success it announces the join. On failure it logs an ERROR naming the SWIM UDP port and the cause, does **not** announce, and fails the node through its per-node `jvmExit`: `Runtime.halt(2)` in production, and in Ember/Forge a graceful stop of that one node rather than the whole JVM. **Recovery action:** free the SWIM port (node port + 100) or move the node's port, then restart the node. `[mechanism: AetherNode.startSwim → onSuccessRun(announceJoin) / onFailure(refuseToRunWithoutSwim)]`, pinned by `AetherNodeStartSwimTest` against a real detector binding a real, deliberately held UDP port.
- The same change closes the SWIM transport in two paths that left resources with nothing owning them: `stop()` arriving while the detector was still `Starting` left the bound UDP port orphaned (the late `ProtocolReady` was ignored in `Stopped`, measured 181/181 leaked), and a **failed bind** left the transport's DNS resolver and, for a detector owning its own event-loop group, that group's thread alive (measured +20 threads over 20 failed binds, now +0). `[mechanism: Stopped handles ProtocolReady by stopping its protocol and transport; createAndStartProtocol stops the transport on any start failure, which closes the resolver and an owned event-loop group]`, pinned by `CoreSwimHealthDetectorStartLeakTest` (the post-bind arm through a gated seam — a defensive branch with no production producer today) and `SwimHealthFsmTest.protocolReady_inStopped_stopsTheOrphanedProtocolAndTransport` (a started fixture protocol, so the protocol half of the cleanup is pinned too).
- **In a single-JVM host (Ember/Forge), a SWIM start failure no longer hangs the host's `start()`.** The per-node `jvmExit` stopped only the failed node, whose own `start()` — settled only by consensus formation — then never settled, so `EmberCluster.start()` waited forever (the #727 shape). The SWIM start outcome is now joined into the node's `start()`: it fails with the bind failure, Ember takes its existing first-failure abort, and a held-back node released into a taken SWIM port is stopped rather than left running SWIM-less. `[mechanism: AetherNode.startClusterUnlessSwimFails / formationUnlessSwimFails; EmberCluster.stopFailedHeldBackNode]`, pinned by `EmberClusterSwimStartFailureTest` and `EmberClusterHeldBackSwimStartFailureTest` against real clusters with a deliberately held SWIM port. Production is unchanged: `Runtime.halt(2)` runs first.
