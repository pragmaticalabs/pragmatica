### Fixed (2026-09-14 — #276 R20: the legacy `ConfigService` facade threw on a malformed numeric value)
- **`NodeDeploymentManager.ConfigServiceConfigFacade` parsed `requireLong`/`requireDouble`/`getLong`/`getDouble` with `Long.parseLong` / `Double.parseDouble` inside `.map`**, so a config value that is not a number (`pool.size = "twelve"`) escaped as `NumberFormatException` out of a facade whose whole contract is `Result`/`Option`. `ConfigService` exposes no numeric getter beyond `getInt`, so the adapter must parse; it now parses through core's `Number.parseLong` / `Number.parseDouble`: a malformed value is a named failure on `require*` (the message carries the offending text), distinct from the absent-key failure, and reads as absent on the `Option`-returning `get*` — the same behaviour `ConfigurationProvider`'s own `getLong`/`getDouble` give the slice-api `ConfigProviderFacade`. This facade is what `NodeDeploymentState.buildConfigFacade` hands a slice when its per-slice config service is absent.
