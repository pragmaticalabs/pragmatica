### Added (2026-11-08 — #2879: slices can read request headers)
- **A slice method can declare a `RequestHeaders` parameter** (`org.pragmatica.aether.http.handler`) and receives the headers of the HTTP request that reached its route: `first(name)` gives an `Option<String>`, `all(name)` a `List<String>` with every value in arrival order; names are case-insensitive (RFC 9110) and the value is immutable. It may stand anywhere in the parameter list beside the request record, `Principal` and `SecurityContext`, on every route shape (no params, path, query, body, merged, multipart) and on both Aether and Terra, which serve the same generated routes. [verified: `GeneratedRequestHeadersRouteTest` in `slice-processor-tests`]
- **Mechanism.** `MethodModel.isInjectedParam` is now the single predicate that decides which parameter types a route supplies (`Principal`, `SecurityContext`, `RequestHeaders`); the exactly-one-request-record rule and the business-parameter selection use it. The generated route passes the request context captured at the edge straight into the route handler (`Route.withRequestContext`); the headers are never read from a `ScopedValue`. [mechanism: `RouteSourceGenerator.generateInjectingLambda`]
- **Edge only.** Nothing carries the headers across a slice-to-slice call: a callee that declares `RequestHeaders` receives the argument its caller passes. Slice methods without the parameter generate byte-identical routes.
