### Fixed (2026-10-18 — #2192: wait_for_cluster_ready fast-fail cannot tell operator-network loss from a dead cluster)
- **A ~30 s receive blackout on the operator host was reported as a dead cluster and turned the suite red against a healthy cluster.** When no core answered `/health/live`, `wait_for_cluster_ready` failed fast with "cluster appears down". Before failing fast it now probes a reference endpoint outside the cluster (cloud runs: the Hetzner API host; `OPERATOR_REFERENCE_URL` overrides, and other environments have none): if that is unreachable too, it logs `operator network unavailable` and falls through to the normal bounded `wait_for`, which passes once the link is back and times out if it never is. Any HTTP answer from the reference counts as a working link, so a genuinely dead cluster with the operator's network up still fails fast with the old message. The optional publish-ack check from the ticket is not part of this change. `[verified: aether/tests/integration/test/test-wait-ready-operator-network.sh]`
