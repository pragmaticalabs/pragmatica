### Fixed (2026-11-25 — #3698, #3691: jbct formatter drops a comment before the `;` of a chain, and in other token gaps)
- **`jbct:format` deleted comments in token gaps that no placement rule covered**: before the `;` of a chained statement, between a local's name and `=`, inside a ternary, an argument or parameter list, an array initialiser, between imports and after the last type of a file.
- The printer now holds one rule at one place: before each code token is printed, every comment of the source that precedes it and is not printed yet is printed there, in source order. Files without comments format exactly as before. [verified: `jbct/jbct-format/src/test/java/org/pragmatica/jbct/format/flow/FlowCommentGapSweepTest.java`]
- **Layout change**: a comment inside an argument list (on an aligned continuation) used to print a blank line and lose the column of the next token; the next token now keeps its column. 18 files that carried the old layout are reformatted in one mechanical commit (whitespace only; every lexeme and comment is byte-equal).
- **Comment order is enforced, not assumed**: every comment is printed through one operation (`CommentCursor.print`) that first prints every earlier unprinted comment, so comments come out in source order, each exactly once. The printer holds no comment text: the cursor is the only code that reads a comment's text and writes it. If a printer rule ever asks for comment N while an earlier comment is unprinted, the format is refused (`ContentChanged`) naming both comments, instead of writing a misordered file. This also formats what the first revision refused: an empty body whose first comment trails the `{` line followed by another comment (`void m() { // a` then `// b`), and a block comment then a line comment after a chain link. [verified: `jbct/jbct-format/src/test/java/org/pragmatica/jbct/format/flow/FlowCommentOrderTest.java`, `FlowCommentGapSweepTest.java` (pair forms), `FlowCommentBeforeOperatorTest.java`]
- Removed the uncalled `FlowPrinter.saveState`/`restoreState` and the `AlignmentContext.Snapshot` that only they used: they were a second route to the comment cursor's state.
