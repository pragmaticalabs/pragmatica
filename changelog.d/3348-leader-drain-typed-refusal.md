### Fixed (2026-11-18 — #3348: an operator drain of the current leader gets a typed refusal)
- **`POST /api/v1/nodes/drain/{id}` for the current leader answers `409 Conflict`: the node is the current leader, a leader is not drained, and leadership must move first** (Refs #3348). Before, the answer was `404 Node lifecycle not found` on every node, because the route reads the receiving node's reported lifecycle states and the leader has no row for itself; that 404 was the only thing between the operator and a half-applied drain. The leader check is decided from the leadership state the receiving node holds, so the leader's route and a follower's route answer alike, and it runs before the readiness lookup, the budget read and any dispatch. The product has no step-down command, so the text names what exists: stop the leader's process, the cluster elects another leader, then drain the node. Drain followed by a hand-over is not part of this change. With no leader known to the receiving node the answer is unchanged. `shutdown` is unchanged.
