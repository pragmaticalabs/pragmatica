### Fixed (2026-11-05 — #2115: core auto-heal picked the first cloud source declaring the role, not the source of the node that departed)
- **A core auto-heal replacement is made in the source of the node it replaces** (#2115). The 4-argument `provisionReplacement` stamped every heal with the first CLOUD source declaring the role, else "default", so in a mixed docker and cloud configuration (or with two cloud sources) a departed node's replacement could be created, and billed, at the wrong provider. The `LeaderReconciler` now names the departed node (an installed voter that is no longer a member) for each missing seat, and the manager resolves the source committed for it (its capacity reservation, placement or membership descriptor), as the node-replacement record does. A node that carries no committed source is resolved the way the replacement record resolves a sourceless node: the one source of the committed configuration declaring the role, "default" when there is no committed configuration. There is no preference between source types.
- **An unresolvable source is refused, named and announced** (#2115). When several sources declare the role, or the configuration does not parse, nothing is provisioned: the pass is a deferral (`SOURCE_UNRESOLVED`) counted as a refused provision, and the operator event `core-replacement-source-unresolved` (subject `core-replacement`) is raised once per run of refusals; its recovery `core-replacement-source-resolved` follows when a heal resolves its source.
