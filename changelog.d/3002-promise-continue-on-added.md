### Added (2026-11-12 — #3002: Promise.continueOn thread hop)
- **`Promise.continueOn(Executor)` and `Promise.continueOn()`: an explicit, unconditional thread hop.** The returned promise is resolved, with the source's result unchanged (success value or failure cause), only by a task submitted to the executor once the source settles, whether the source was pending or already resolved when `continueOn` was called. Dependent steps chained on the returned promise before it resolves therefore start on the executor; a step attached after it has resolved runs on the attaching thread, as for any resolved promise. Two `continueOn` branches from one promise have no mutual order, and continuations attached elsewhere to the source are unaffected. A rejected submission fails the returned promise with `CoreError.Exception` carrying the `RejectedExecutionException`; the result is never delivered inline and the promise never stays unresolved. The no-arg form uses the built-in virtual-thread pool that `Promise.async(...)` uses. `async()` still returns the same instance and does not hop. [verified: core/src/test/java/org/pragmatica/lang/PromiseContinueOnTest.java]
