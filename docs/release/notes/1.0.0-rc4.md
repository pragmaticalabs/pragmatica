# Pragmatica 1.0.0-rc4

rc4 (2026-10-17) is a release candidate. It is not production-ready. It carries the rc3-to-rc4 work: cluster membership, replacement and rolling-upgrade machinery, a reworked streams and durable-entity layer, a closed set of route-security gaps, and a large test-and-documentation correction pass. Read **Upgrade hazards** and **Known limitations** before you run it on anything you care about.

## Upgrade hazards

1. **Wire and storage formats changed with no migration path.** Stop the whole cluster, upgrade, start clean. Mixed-version clusters are not supported. Backups and KV snapshots written by earlier builds (the `StreamConfig` and `ClusterConfigValue` shapes changed) do not restore: wipe the cluster state and recreate it.
2. **`content` storage becomes encrypted on upgrade if `[storage.encryption]` is configured.** Existing content blocks become unreadable (typed `LegacyPlaintextBlock` error per read); detection ships, migration does not (#831). Before upgrading, set `[storage.content] encrypted = false`.
3. **`security_mode = "jwt"` with no `jwks_url`.** Non-public app routes that answered `200` now answer `401`, and a node with `[app-http] enabled = true` and no `jwks_url` refuses to start (exit 65). Set `[app-http] jwks_url` (plus `issuer`, `audience`) or change `security_mode`.
4. **Blueprint `[security.overrides]` now apply on every node.** Callers that relied on the gap now get `403`. Review each override against its callers (grant the role or withdraw the override) before upgrading. Re-verify any lockdown you previously checked through `GET /api/v1/routes`.
5. **Routes with no `[security]` section inherit the global `security_mode`** (`401`/`403` instead of `200`). A route whose policy credential type does not match the node's mode (`bearer_token` on `api-key`, or the reverse) now returns `401`.
6. **Replication default.** A stream that declares no factor now acknowledges at confirmation factor 2; with no registered peer the publish fails `NOT_ENOUGH_REPLICAS`, including the first publish to an API-created stream. Declare `replication_factor` and `confirmation_factor` explicitly.
7. **Instance floor.** A blueprint slice runs at least 3 instances (omitted means 3, was 1). `POST /api/v1/scale` and `aether scale` refuse fewer than 3 with `400`.
8. **Cluster size.** `aether cluster init` takes `--core-nodes` and `--worker-nodes` (supported minimum 5 core, default 7, maximum 9; `--nodes` is gone). A node configured for fewer than 3 peers refuses to boot.
9. **`POST /api/v1/cluster/upgrade` requires `expectedVersion`.** A stale value is a `409`; an omitted value is a `400`.
10. **Config keys now refused at load:** `[dht.replication] target_rf` and `[worker] max_group_size`. Remove them.
11. **The built-in artifact store is write-once and refuses `-SNAPSHOT` (`400`).** It archives instead of deleting. Push release versions.
12. **The published node image ships no administrative key.** Management routes are refused until you supply a credential.
13. **Compose files from `aether cluster scaffold` generated before this release hold the cluster secret in plain text.** Regenerate them with the `${AETHER_CLUSTER_SECRET}` reference form.
14. **SWIM pins each member's address to its process identity.** A container that gets a new IP is no longer adopted; replace the node under a fresh NodeId.
15. **`jbct lint` exits `2` when it finds no Java files, and `--format json` is one object, not an array.**
16. **Stream settings that were ignored now take effect** (retention, event-size limits, `time`/`size` caps). Check `examples/notification-hub`-style declarations.
17. **A fresh `aether cluster bootstrap` refuses a name that already exists.** Use `--resume`, or `destroy` first.

## Security

- SWIM: a member's address is pinned to its process identity; a conflicting ANNOUNCE is refused and reported.
- `security_mode = "jwt"` without `jwks_url` is refused at config load (#909).
- `jwt` mode with no JWT config installed a permit-all validator: every caller received ADMIN and SERVICE authority (#888). Now `401`.
- Blueprint security overrides now reach every node and survive a restart (#887).
- Route security failed open on nodes that do not host the route (#1659).
- Sibling routes of one slice were authorized by one sibling's policy (#1678).
- An OPERATOR key executed the ADMIN-only `CONFIG_NODE_DELETE` by appending a path segment (#1101).
- The published node image carried a built-in ADMIN credential (#1016).
- Cloud bootstrap put the cluster secret on the remote `docker run` command line; it is now read from `AETHER_CLUSTER_SECRET_FILE` (#828). Stated limit: an environment-variable secret stays visible via `docker inspect`.
- Generated docker-compose wrote the cluster secret in plain text (#684).
- Also fixed under Fixed: `public` routes treated as undeclared (#763), a request authorized under one slice's policy and answered by another (#884), a default-ALLOW security interface (#876), anonymous callers answered as VIEWER during pre-bootstrap boot (#908).

## Removed / breaking changes

- `PassiveNode` (#2033), `EntityError.TimerNotSupported` (#1381, source-breaking: delete that match arm), `StreamConsumerAdapter` and `@Sql("name")` surface (#577), `WorkerCodecs` (#503), `QuicDisconnectListener` (#691), `GENERATION_CHANGED` (#722), `AuditLifecycleStreams` (#734), the DHT `ReplicatedMap` routing plane (#943), the dead worker group-splitting chain (#673), `DockerComposeGenerator` (#684), the dead `[operations.tls] cluster_secret` key (#854, now silently ignored).
- The backup API and CLI could never be enabled and are removed; git-backed persistence is the backup (#676).
- Same-NodeId restart is gone from the product surface and the test harness: a core is replaced by a fresh-id node (#1543).
- Library API: `RouteSecurityPolicy` loses its default `ALLOW` method (source-incompatible for external implementors, #876); `RateLimiter` factories return `Result<RateLimiter>` (#1316); typed `get*` config readers return `Result<Option<T>>`.
- Management API: `GET /api/storage/retention` fields changed (`walRecoveryHeadGapsAccepted` becomes `walRecoveryHeadsLost`; rows gain `reclaimedThrough`).
- BSL 1.1 is narrowed to ten runtime modules; everything else is Apache-2.0, with a CI gate checking the boundary (#1989).

## Known limitations

- **A network cut that leaves no core majority halts every core (#2214).** Each core drains and exits with code 2 and is not restarted; a heal after draining began does not cancel the halt. Consensus state is memory-only, so blueprints, slice targets, API keys, cluster and stream configuration and entity state are lost. Measured with every core isolated from every other on five cores: a 10 s cut halted 0 of 25 core-runs, 15 s halted 2 of 25, and 20 s, 25 s and 30 s halted 25 of 25 each; the drain began 18-19 s after the cut; 77 of 77 cores that fired exited with code 2. `[measured: five-node Ember probe on the rc4 tip, loopback on one host; the probe is not in the repository]` `[unverified: a 2/2/1 split, cut lengths of 16-19 s, other split_timeout values, a production-mode halt]`
- **Mitigation.** Configure `[backup]` with a `remote` on every multi-core production cluster. The backup holds declared state up to the last successful push, not entity state or acknowledged stream records. Recovery is the fresh-NodeId restore in `runbooks/backup-recovery.md` and the "No-majority partition / every core halted" section of `runbooks/incident-response.md`.
- **The fresh-bootstrap name check (#2213) has gaps.** SSH and Docker hosts are not listed; a cluster known only to another workstation is seen only through cloud labels; no lock is taken between two concurrent bootstraps; `destroy` of a name still removes every machine labelled `aether-cluster=<name>` on a Hetzner source.
- **Streams and durable entities (#2201):** a lagging declarative consumer stalls on `CursorExpired`; sealed-tier retention is a node-wide 24 h; the default 128 MiB stream memory budget fits about 50 partition rings per node; production replication is not batched; a retried durable-entity `update` that missed its replication barrier applies twice; the transactional cursor path is unwired.
- **Whole-cluster restart** restores declared state from `[backup]`; entity state and timers restart empty.
- **Dashboard against a real node:** it calls unversioned `/api/...` paths, the node serves `/api/v1` only, so REST-only panels are empty; WebSocket-fed panels work (#300).
- **Overrides match on the base path** (#1681), so an override covers every sibling route under that base.
- Mixed-version clusters are not supported; there is no join-time version check.

## Added

- **Replacement and upgrade:** fresh-id replacement of cores and workers, paired with the node it replaces (#1543); a serial rolling-upgrade run with pause, resume and abort (`/api/v1/upgrade/*`), cores first and the leader last.
- **State and backup:** change-triggered, leader-only KV backup with a lineage gate and restore (#1532, #1533); cluster incarnation key (#1529); atomic guarded KV mutations (#1379); at-rest storage encryption through the SecretsProvider SPI (#253).
- **Streams and entities:** durable projections wired to the runtime and rebuildable by an operator (#1333); owner-epoch provenance for partition logs (#1596); caller-stable durable-topic message IDs (#1237); checkpoint-lag metric (#1302); explicit `partition` on Management-API publish (#524).
- **Operability:** node-health alerting (#926); threshold alerts on the cluster event log; operator warnings in the event log (#1574); consensus stall diagnostics (#1117); community state read route (#1652); emergency gossip-key rotation (`aether cluster rotate-gossip-key`, #683); an operator clear path for an unconfirmed-termination mark (#2062).
- **Artifacts:** `DELETE /repository/{group}/{artifact}/{version}` archives a version; retention is configurable (#1778).
- **Tooling:** documented CLI invocations are diffed against the live command spec in CI (#944); a JBCT lint rule for try/catch (#1247); a `Cluster-tested` maturity tier in the feature catalog (#945).
