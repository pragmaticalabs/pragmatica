---

## 1. Overview

The CLI generates a complete per-source `aether.toml` during `aether cluster bootstrap` by composing four layers: global default → per-source-type default → operator source override → CLI-computed overlay. Deep merge with lowest-to-highest precedence. The resulting file is deployed via the appropriate mechanism per environment (file mount for Docker, SCP for SSH, cloud-init for cloud, in-memory for Forge). Nodes read a single `aether.toml` as before — all composition happens at bootstrap time in the CLI.

This closes a gap: today's bootstrap has no mechanism to pass cluster-specific operational config (network name, image, API key) from CLI to nodes. It also gives operators a clean way to customize per-source node config (timeouts, memory, logging) without bloating the cluster-bootstrap-config schema.

---

## 2. The Four Layers

Precedence order (highest wins):

```
Layer 4: CLI bootstrap-time overlay      ← generated by CLI
Layer 3: Operator per-source override    ← from cluster-bootstrap-config
Layer 2: Per-source-type default         ← shipped with distribution
Layer 1: Global default                  ← shipped with distribution
```

### Layer 1 — Global default

**Location:** `aether/aether-setup/src/main/resources/defaults/aether-default.toml`

Baseline config applicable to any node regardless of source type. Example fields:
- `[cluster]` non-source-specific defaults (peer discovery timeouts, sync parameters)
- `[slice]` defaults (repository paths, memory)
- `[app-http]` defaults (default port, security mode)
- `[logging]` default level, pattern

Must be a syntactically valid, self-contained TOML. Does NOT include source-specific sections like `[cloud.compute]`.

### Layer 2 — Per-source-type default

**Location:** `aether/aether-setup/src/main/resources/defaults/aether-{type}.toml` where `{type}` ∈ `{docker, cloud, ssh, forge}`.

Source-type-specific defaults. Example differences:
- `aether-cloud.toml`: `[cluster] tls = true` (production security)
- `aether-docker.toml`: `[cluster] tls = false` (dev convenience)
- `aether-ssh.toml`: `[app-http] bind = "0.0.0.0"` (bare metal)
- `aether-forge.toml`: `[slice] repositories = ["local"]` (dev)

One file per supported source type. Missing file is a distribution error, not a user error.

### Layer 3 — Operator per-source override

**Location:** Inline in `cluster-bootstrap-config` under `[source.X.node_config]` OR via `inherit` from `[template.Y.node_config]`.

**Inline example:**
```toml
[source.hetzner-eu]
type = "cloud"
provider = "hetzner"

[source.hetzner-eu.node_config.app-http]
timeout = "30s"

[source.hetzner-eu.node_config.logging]
level = "DEBUG"
```

**Template inheritance example:**
```toml
[template.prod-defaults]
[template.prod-defaults.node_config.app-http]
timeout = "60s"
[template.prod-defaults.node_config.logging]
level = "WARN"

[source.hetzner-eu]
inherit = "prod-defaults"
# Can still add source-specific overrides
[source.hetzner-eu.node_config.logging]
level = "INFO"   # overrides the inherited WARN
```

The `[source.X.node_config]` subtree is an **arbitrary TOML fragment** — any fields that would normally appear in `aether.toml` are valid here. The parser does NOT validate its structure; validation happens when the composed output is loaded by the node.

### Layer 4 — CLI bootstrap-time overlay

**Generated by:** CLI, per source, during `aether cluster bootstrap`.

Contents depend on source type:

**Docker/SSH:**
```toml
[cluster]
name = "<cluster-name>"          # from cluster-bootstrap-config.cluster.name
peers = "<PEERS-list>"           # computed from provisioned nodes

[node]
id = "<node-id>"                 # assigned per node
role = "<role>"                  # core/worker/spot

[cloud.compute]
network_name = "<per-source>"    # e.g., aether-a-network
image_name = "<per-source>"      # e.g., aether-node:local
api_key = "<cluster-api-key>"    # generated during bootstrap
docker_gid = "<host-docker-gid>" # from bootstrap env
management_port_base = <port>    # from cluster-bootstrap-config.operations.ports.management
app_port_base = <port>
cluster_port = <port>
socket_path = "/var/run/docker.sock"

[database]                        # if [databases.X] in cluster-bootstrap-config
username = "<resolved>"
password = "<resolved>"
async_url = "<resolved>"
```

**Cloud (Hetzner/AWS/GCP/Azure):**
```toml
[cluster]
name = "<cluster-name>"
peers = "<PEERS>"

[node]
id = "<node-id>"
role = "<role>"
zone = "<zone>"                  # from source profile

[cloud.compute]
provider = "hetzner"              # from source.provider
api_token = "<from-operator-env>"
image = "<ami-or-image-ref>"
network_id = "<private-network-id>"

[tls]
auto_generate = true              # cloud defaults to true
```

**Forge:** empty or near-empty (everything comes from layers 1-3).

The CLI generates this layer deterministically — no operator input, no templates. It reflects what the CLI knows at bootstrap time.

## 3. Merge Semantics

**Deep merge, layer-by-layer, Layer 1 → 4.**

Rules:
- **Tables merge recursively.** `[cluster]` in layer 1 and `[cluster]` in layer 2 merge field-by-field.
- **Leaf values replace.** If `[cluster].tls` is `false` in layer 1 and `true` in layer 2, the result is `true`.
- **Arrays replace entirely.** If `[slice].repositories = ["a"]` in layer 1 and `= ["b", "c"]` in layer 2, the result is `["b", "c"]` (not `["a", "b", "c"]`).
- **Inline tables replace entirely.** (TOML inline tables `{ k = v }` are treated as opaque values.)

**Rationale:** Tables merge to enable progressive refinement. Arrays replace to allow operators to cleanly override (if they want to ADD, they'd need explicit `append` support — YAGNI for now).

**Consistency:** Same rules as `[template.X]` inheritance in cluster-bootstrap-config (§5.3). One mechanism, one semantic.

## 4. Module Responsibilities

### 4.1 `aether/aether-setup`

Owns the shipped defaults (Layers 1 and 2).

**New files:**
- `src/main/resources/defaults/aether-default.toml`
- `src/main/resources/defaults/aether-docker.toml`
- `src/main/resources/defaults/aether-cloud.toml`
- `src/main/resources/defaults/aether-ssh.toml`
- `src/main/resources/defaults/aether-forge.toml`

**New class:** `DefaultNodeConfig` — loads defaults from classpath, exposes `globalDefault()` and `sourceTypeDefault(SourceType)` returning `TomlDocument`.

### 4.2 `aether/aether-config`

Owns the merge logic and Layer 3 parsing.

**New class:** `NodeConfigComposer` — takes four layers as `TomlDocument`s, returns merged `TomlDocument`.

**Extended class:** `SourceProfile` — add `Option<TomlFragment> nodeConfig` field. Parser populates from `[source.X.node_config]` subtree.

**Extended class:** `TemplateInheritanceResolver` — existing deep-merge logic applies to the new `node_config` subtree automatically if it uses the same `TomlDocument` model.

### 4.3 `aether/cli`

Owns Layer 4 generation and deployment.

**New class:** `BootstrapOverlayGenerator` — given `ClusterBootstrapConfig`, `SourceProfile`, node index, and bootstrap context, returns a `TomlDocument` for Layer 4.

**Modified:** `BootstrapPhaseDeploy` — calls composer, writes result to file, deploys per environment type:
- **Docker:** writes to `aether/tests/integration/configs/aether-{cluster}-{source}.toml`, compose file mounts it.
- **SSH:** existing SCP mechanism via `NodeConfigTemplate` — replace the template with composed output.
- **Cloud (cloud-init):** write_files directive in user-data.
- **Forge:** in-memory pass to EmberInstance (tbd — Forge out of scope for first impl).

### 4.4 Node side

**Unchanged.** Node reads a single `aether.toml` from the path it already uses. All composition is bootstrap-time.

## 5. Data Model

### 5.1 SourceProfile changes

```java
public record SourceProfile(
    String name,
    SourceType type,
    // ... existing fields
    Option<TomlFragment> nodeConfig  // NEW — arbitrary TOML subtree
) {}
```

`TomlFragment` is a new type (or reuse existing `TomlDocument`/`JsonNode` abstraction) representing a parsed TOML subtree that the validator doesn't inspect. It's carried through to composition time.

### 5.2 Template changes

Templates already support `[template.X]` with arbitrary fields. The new `node_config` sub-section inherits naturally — `TemplateInheritanceResolver` walks the whole template tree.

## 6. CLI Layer 4 Generation — Rules

The CLI MUST only set fields it knows deterministically from bootstrap context. It MUST NOT:
- Set fields that operators typically customize (timeouts, memory, logging levels)
- Guess defaults for things not covered in `ClusterBootstrapConfig`
- Resolve `${env:...}` placeholders outside `databases.*` (spec REQ-4.2.3)

It MUST set:
- `[cluster].name` — from config
- `[cluster].peers` — computed PEERS list in 3-part `nodeId:host:port` format
- `[node].id` — per-node
- `[node].role` — from source profile (core/worker/spot)
- `[cloud.compute]` — all fields known at bootstrap (network, image, api_key, docker_gid, ports, socket_path, provider)
- `[cloud.credentials]` — if applicable to source type (resolved from operator env at CLI time, excluded from export per spec)
- `[database]` — if `[databases.X]` declared in cluster-bootstrap-config; URL kept as `${databases.X.url}` placeholder per spec §4.2.1, resolved by node at access time
- `[tls]` — if explicitly opted in via source profile (e.g., cloud sources default to `tls_auto_generate = true`)

## 7. Deployment Per Environment

### 7.1 Docker

**File output:** `aether/tests/integration/configs/aether-{cluster-name}-{source-name}.toml` (path parameterizable).

**Compose integration:** compose file mounts the composed file into the container:
```yaml
volumes:
  - ./configs/aether-test-a-docker.toml:/opt/aether/aether.toml:ro
```

### 7.2 SSH

**Existing path:** `NodeConfigTemplate.render()` currently generates a minimal aether.toml inline. REPLACE its body with the composer output.

**SCP:** existing `RemoteCommandRunner.scp()` copies to `/opt/aether/config/aether.toml`.

### 7.3 Cloud (cloud-init)

**user-data write_files directive:**
```yaml
write_files:
  - path: /opt/aether/aether.toml
    content: |
      <composed TOML content>
    permissions: '0644'
    owner: aether:aether
```

Exists partially in `UserDataTemplate`; extend to use composer output.

### 7.4 Forge

Deferred. Ember runs in-process; we'll pass the composed config as a Java object, not a file. Detailed design deferred until first implementation pass.

## 8. Validation

**CLI-side, at bootstrap time:**
- After composing, validate the result via the same loader the node uses (`ConfigLoader` or similar). Catches operator errors early.
- Produce clear diagnostics: "Field `[app-http].timeout` invalid: expected duration, got 'forever' (from source override `hetzner-eu`)."

**Node-side, at startup:**
- Existing validation applies as-is. No new node-side code needed.

## 9. Implementation Layers (ordered)

### Layer A: Infrastructure (no feature change)

1. Create `DefaultNodeConfig` in `aether-setup` with classpath-loaded defaults.
2. Write the five default TOML files (global + 4 source types).
3. Create `NodeConfigComposer` in `aether-config` with pure merge function.
4. Unit tests for merge: table merge, leaf replace, array replace, edge cases.

### Layer B: Data model

5. Add `nodeConfig: Option<TomlFragment>` to `SourceProfile`.
6. Extend `ClusterBootstrapConfigParser` to parse `[source.X.node_config]` subtree as opaque `TomlFragment`.
7. Extend `TemplateInheritanceResolver` to carry node_config through inheritance (may already work if using generic tree merge).
8. Update `ClusterBootstrapConfigValidator` — ensure `node_config` is NOT validated against strict schema (it's operator-defined).

### Layer C: CLI Layer 4 generator

9. Create `BootstrapOverlayGenerator` in `aether/cli`.
10. Per source type, implement the "what CLI knows" section (Section 6).
11. Wire into `BootstrapPhaseDeploy`.

### Layer D: Per-environment deployment

12. Docker: volume mount wiring + compose file updates for integration tests.
13. SSH: replace `NodeConfigTemplate` body with composer output.
14. Cloud: integrate with `UserDataTemplate`.
15. Forge: defer (document as TBD).

### Layer E: Integration + migration

16. Update `aether/docker/aether-node/aether.toml` — minimize, move most to defaults.
17. Update integration test compose files to mount composed overlays.
18. Update `cluster-config.toml` seed to use the new source-based format (already done).
19. Delete any now-dead config files.

## 10. Migration

**Backward compatibility:** Nodes still read a single `aether.toml`. No node-side changes. Current deployments continue to work if the CLI generates the composed config with sane defaults.

**Operator migration:** Operators who customized `aether.toml` manually should move customizations to `[source.X.node_config]` in cluster-bootstrap-config. The global `aether.toml` in the distribution becomes minimal/purely defaults.

**Environment variables:** The current `${env:...}` substitution in `aether.toml` for things like `DOCKER_GID` is REMOVED. Those fields are now populated by the CLI via Layer 4.

---

## 11. Decisions Locked

| Decision | Value | Rationale |
|----------|-------|-----------|
| Layer count | 4 | Future-proof; layers 2-3 optional in practice |
| Source override | Inline + template inheritance | Unifies with existing template mechanism |
| Merge semantics | Deep merge | Consistent with template inheritance |
| Output location | Single `aether.toml` per source | Simplifies node side |
| Node-side changes | None | Composition is bootstrap-time only |
| CLI Layer 4 scope | Bootstrap-known fields only | Operators own everything else |
| Secrets in overlay | Accept risk; RC2 ticket for secret refs | Pragmatic, document limitation |

## 13. Verification

**Unit tests (Layer A):**
- Merge two TOML docs, assert expected output
- Edge cases: empty docs, missing sections, array replacement, nested tables

**Integration tests (Layer E):**
- Bootstrap a Docker cluster, verify composed aether.toml has correct network, image, api_key
- Bootstrap with source override, verify operator field appears in output
- Bootstrap with template inheritance + override, verify precedence
- Scale test passes on both cluster A and cluster B (each gets its own network)

- `aether cluster bootstrap` produces per-source files
- `docker compose up` with mounted files
- Nodes start, join cluster, CTM provisions on correct network during scale
